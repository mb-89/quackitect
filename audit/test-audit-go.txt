# Go test audit: over-coverage, duplication, dead targets

Tree: /home/user/quackitect on `main` at 376fa3024. Read-only audit: no repository files or git state were changed.

## How the evidence was gathered

- **Line counts:** test and code lines were counted per directory. Each test's span, including its doc comment, was measured with a small script.
- **Unreachable code:** `deadcode` from golang.org/x/tools v0.42.0, the version go.mod already pins, was run over the three `main` packages (src/quack, src/tui, src/front/cmd). It reported 105 unreachable functions. The test files calling each one were then traced.
- **Full test run:** `go test -count=1 -json ./src/...` ran 1880 top-level tests. All passed and one was skipped (a Windows drive-letter case). The run took 54 s wall time. The slowest packages were branches (45 s), quack (31 s) and index (13 s). Afterwards `git status` was clean.
- **Migration switches:** `spec/config/level0.json` switches on every phase from phase0 through phase11, and sets `sidebar` and `lsp` to `new`. The schema's built-in modes for config, log, guidance, check, prose, verbs, cage, window, processes and opentasks are `new`, and each of these has `enum: ["new"]`. So every shadow or parity test below guards a phase that is already switched on.
- **Ticket states:** every ticket the scaffolding cites is `state: closed`. These are the-guidance-topic-lands, the-log-topic-lands, cfg-topic-holds-one-resolver, check-names-meet-their-goldens, twin-goldens-walk-every-twin, the-queue-becomes-a-module, tickets-becomes-a-module, the-lens-reads-v1, the-tui-data-paths-leave, the-verbs-run-in-go and agents-call-quack-directly.
