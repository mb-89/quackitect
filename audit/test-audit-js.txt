## How "no production path runs it" was established

1. **Entry points, from the configs that start JS.** These are `.claude/skills/level0/hooks/hooks.json` → `pull-tool.js` (`register`); `.claude/settings.json` SessionStart → `src/scripts/boot.js`; `.githooks/pre-commit` → `src/scripts/precommit.js`; `.githooks/pre-push` → `src/scripts/prepush.js` (install.sh sets `core.hooksPath`); `.github/hooks/level0.json` and `copilot-setup-steps.yml` → `src/scripts/copilot.js` (modes `hook`, `setup`, and the person-run `dispatch`); and `src/quack/probe_verb.go` → `src/scripts/probe-dry.js`. `src/quack/check.go` loads `src/scripts/battery-reporter.js` as the `node --test` reporter. The VS Code extension `src/extension/extension.js` dynamically imports `src/bridge/vehicle.js` and `src/doors/{proc,disk,clock}.js`, and its webview loads `webview/clicks.js` and the `webview/route/*.js` bundle. The stub bridgehead imports nothing.
2. **RUNME.sh starts no JS verb.** It execs `.se/.runtime/bin/se-index verb src/scripts <verb>`. Its fallback, `node src/scripts/verbs/$1.js`, finds nothing because `src/scripts/verbs/` is gone. `package.json` has no scripts. In Go, `roadOf` in `src/quack/verbs.go` sends every registered verb to Go, and the `node` IO module (`nodeAccept`, `src/quack/twins.go`) answers through Go twins and refuses anything else. No other non-test Go file names a JS file to run: the only hits for a `.js` string are `probe-dry.js`, `battery-reporter.js` and the `node src/scripts/copilot.js` runner that the Copilot setup writes into the hook registrations.
3. **Symbol-level reachability.** A TypeScript-AST pass over all 598 JS files walked from the entries' exported or top-level code through named, namespace and dynamic imports and re-exports. Inside a module it followed the top-level declarations each function references. It found 123 of 231 source modules loaded and 1,522 symbols live. Each test's imported subjects (taken directly or through its helper files, with fakes excluded) were checked against that set. Two dispatcher overrides were applied: Copilot `dispatch` reaches `work()` only with `["take"]`, and `pull-route.js` reads only `Object.keys(WORK_VERBS)`. Without the overrides every JS pull and ticket function would count as live, through a key listing.
4. **Go duplicates.** Go test files that say they port a JS test (`grep 'test/level0/' src/**/*_test.go`, 55 files) and Go tests that read the same `test/replay/cage/*-cases.json` as a JS test.
5. **Phase keys.** These come from `src/modules/migration/migration.go` and `spec/tickets/*`: phase3 read topics, phase4 quack verbs ("cli.js leaves"), phase5 Go cage ("bridge server leaves the tree"), phase6 TUI, phase7 LSP door, phase8 sidebar on the index, phase9 module processes, phase10 "Go prose checks become the only copy", and phase11 "programOf hands no verb to node".

## Caveats

- Liveness is static. A function counts as live if any live function references it, so a few KEEP and REWRITE verdicts may still drive code that never runs in practice. The opposite error is unlikely for named imports. Strings built into dynamic `import()` calls were resolved by hand: the extension's three doors and `bridge/vehicle.js`.
- Copilot `dispatch` is a person-run, documented entry (`spec/design_output/copilot.md`), so the `work take` chain was treated as live. If it should leave too, M1 (2,780 lines) becomes DELETE, along with about 5.3k lines of `src/scripts/{work,pull,ticket}*` source.
- A deletion here leaves the dead source behind. 108 JS source modules (14,737 lines) are loaded from no entry, chiefly `src/bridge/*`, most of `.claude/skills/level0/lib/*` and most of `src/scripts/*`. They should leave with their tests. Otherwise `c/real-git` and the `tested.js` rule ("every module tested") will flag the orphans.
- MERGE means the behavior is worth one test, and the surviving copy is named above. Where that Go test already exists (M1, M3), the JS file can go as soon as the production thread named in the evidence is cut.
