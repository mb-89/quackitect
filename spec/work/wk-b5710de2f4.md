## detail

Claude Code carries function hooks from version 2.1.260.
This box runs 2.1.263 with `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` set, and `src/cage/funchooks-probe.mjs` says so.

A hooks module returns `{ deny: reason }` from a `tool.call` hook, which refuses the call and hands the model the reason.
It runs in the harness process, so it needs no build and no lane.

The engine takes minutes to build on a cold clone and today it fails.
A plugin is up at `session.start`, before the first prompt.
So the voice gate reaches turn one of a cold box, which the engine has never managed.

## approach

One plugin, one hooks module, hooking `tool.call` matched on `Write` and `Edit`.
It runs the patterns from `spec/config/voice-rules.json`, so the rules stay in one file and the engine keeps reading the same one.

A breach returns `{ deny }` naming the file, the line, the phrase and what to write instead.
The declarations are generated by `/plugin-types` and describe the running build, so regenerate them each time.

This is a spike on this branch.
It answers whether a refusal at the write path teaches the agent, which is the owner's reason for putting the cost there.
`claude --plugin-dir <folder>` loads it for one session, and `claude --debug` says what the engine refused.

## done when

- the plugin loads and lists its hooks, decided by `claude plugin validate <folder>`
- a `Write` carrying a caps-lead paragraph is refused and the reason names the line, decided by driving one write under `claude --plugin-dir`
- the same text without the breach is written, decided by the same drive
- the rules come from `spec/config/voice-rules.json` and are not copied into the module, decided by reading the module
- a run with the plugin absent writes both, decided by the same drive without the flag
