## detail

`spec/config/voice-rules.json` holds four regular expressions and one word limit.
Vale holds twelve extension points: existence, substitution, occurrence, repetition, consistency, capitalization, readability, spelling, conditional, metric, script and sequence.

Four of those reach rules this project cannot write today.

| need | Vale point |
|---|---|
| active voice, noun clusters, a verb used as a noun | `sequence`, over part-of-speech tags |
| the same word for the same thing | `consistency` and `substitution` |
| the technical English word limits | `metric` and `readability` |
| anything else | `script`, in Tengo |

Vale lifts comments out of source with tree-sitter, so it reaches the 22635 comment lines this tree's own check cannot see.

## approach

Vale is Go, and `github.com/errata-ai/vale/v3` carries an importable `lint` package split into core, `code.go` and `markup.go`.
So `se lint` calls it in the engine's own process, with no program to find on the box.

The rules move to a style folder under `spec/config`, one YAML file per rule, replacing `voice-rules.json`.
A rule carrying an `action` gets a quick fix in the editor, which is what `se format` applies in a batch.

Two rules stay behind, because they need the note's schema: a field whose schema describes it takes no comment, and a section's tense.
Those stay in `ValidateNote`.

## done when

- the style folder holds one file per voice rule a pattern can express, decided by reading it against `spec/guidance/voice.md`
- `se lint` reports a Vale finding with its file, line and rule, decided by running it over a fixture holding one
- a breach inside a Go comment is reported, decided by running it over a Go fixture
- a breach inside a Go string literal is not, decided by the same run
- `spec/config/voice-rules.json` is gone and nothing reads it, decided by `se find` over the tree
