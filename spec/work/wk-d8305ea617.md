## detail

The owner asks that the rules reach what the agent writes in the chat.
Three levers exist and they differ in strength.

The `Stop` hook refuses, and `src/engine/hook.go` line 1405 already refuses a stop.
`turn.complete` draws a text beneath the answer and never rewrites the record.
`ui.render` on `AssistantMessage` rewrites what is drawn, which hides the text and keeps the record.

So the refusal is the `Stop` hook, and `turn.complete` shows what was caught.
The engine already refuses a helper stop whose answer is over budget, at line 683 of the same file.

## approach

`decideStop` gains the voice check over `in.LastAssistantMessage`, beside the claim rule it holds.
A breach blocks the stop, and the reason carries the same rows the write path returns.

`AHelperAnswerStillRefused` already bounds this: refuse once, relent the second time, record both.
The main agent takes the same bound, so a rule the agent cannot satisfy costs one round.

`turn.complete` in the plugin draws the breach list under the answer, so a person sees what got through.

## done when

- a stop whose answer breaks a voice rule is refused and the reason names each breach, decided by a Go test over `decideStop`
- the second stop with the same answer is allowed and both are recorded, decided by the same test
- a clean answer stops at once, decided by the same test
- the breach list is drawn beneath the answer, decided by driving one turn under `claude --plugin-dir`
