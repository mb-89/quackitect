## detail

1756 comment lines stand inside the front matter of 300 notes.
Each one repeats a `description` from the schema that reads the note.
`# which schema reads this note` stands in 245 files and in `spec/schemas/work-token.schema.yaml` line 39.

The engine writes them.
`src/engine/schema_test.go` line 237 asserts a new token opens with that comment.

So this is the tree's own generator teaching the pattern the owner wants gone.
A field whose schema carries a description takes no comment beside it.

## approach

The rule is a lookup, so a reworded copy is caught too.
For each comment line in a note's front matter, read the key below it and ask the schema.
A key with a description refuses the comment, and the refusal quotes the description.

The writer stops emitting them, and `schema_test.go` asserts the new opening.
The 1756 already written come out in the same change, because a rule with a backlog is a rule nobody trusts.
A person who wants a comment writes it about something the schema does not say.

## done when

- a write whose front matter comments a described key is refused, decided by a Go test over one such note
- a comment above a key with no description passes, decided by the same test
- a minted token opens with `---` and the `kind` line, decided by `se work` and reading the file
- no note under `spec` carries a front-matter comment on a described key, decided by running the check over the tip
