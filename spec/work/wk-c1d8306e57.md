## detail

`spec/guidance/software-development/writing-go.md` holds 15 rules.
14 of them are rules golangci-lint already implements.

The tree carries no golangci configuration.
`src/engine/lintreadsformatting_test.go` line 15 says so, and `src/engine/format.go` line 206 says so again.
So golangci runs its default set: errcheck, gosimple, govet, ineffassign, staticcheck and unused.

None of the 14 is in that set.
Each one is written for an agent to remember, while a program on this box could refuse it.

## approach

A `.golangci.yml` at the root enables the linters those rules name.
Each enabled linter is written beside the rule number it holds, so a reader sees which rule a finding belongs to.

The rules the config now enforces come out of the guidance file and become a link to the config.
That is `engine_design_principles` rule 2 applied: a rule a program can check is a check.

A rule with no linter stays written, and the file says which those are.

## done when

- `.golangci.yml` exists and enables a linter for each rule it can hold, decided by reading it against `spec/guidance/software-development/writing-go.md`
- `se lint` reports a finding from a newly enabled linter, decided by running it over a fixture breaking one rule
- the tree passes, decided by `se lint` over the tip
- each rule the config now holds is a link in the guidance file, decided by reading it
