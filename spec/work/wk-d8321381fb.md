## detail

A token whose snapshot names a commit this clone does not carry cannot be worked at all, and the engine answers in git's voice rather than its own. Measured here on 2026-09-04. wk-1c9dc4ef28 carries began 8a4035249805dd9d745118bd13c10b3724210f32, f68049b3a3f5d35efd361f2a94b2f47480058ee3 and 05adfb8a10366d136a5f5c1967b76bc2c7fc2c06. Running ./RUNME.sh test --on wk-1c9dc4ef28 --by worker-opus answered exit 1 and the whole body was git diff: fatal: bad object 05adfb8a10366d136a5f5c1967b76bc2c7fc2c06. WHY IT HAPPENS. A token travels in doc/work, and the snapshots the engine writes into began and ended are commit ids on the box that wrote them. A clone that fetched one branch, or a box whose commits were never pushed, carries the token and not the commit. The token then names a tree nobody can reach. WHAT IT COSTS. se test is how every done-when line is decided, so the criterion the work step demands, se test --on this token answered ok, can never be answered. The token is unworkable and nothing says why. The agent is left reading a git error and guessing whether its own tree is broken.

## proposed action

se test reads the delta against the newest began commit it can actually resolve, and says which one it used. Where no began commit resolves it falls back to HEAD, which is what a token with no began already does, and says so in the answer. The refusal an agent sees is the engine's own sentence naming the token, the unreachable commit and what it fell back to, rather than a raw git line. A commit that cannot be resolved is a fact about this box, not a broken token, so it never stops the work.

## approach

This has landed. The shape is a reading rather than a change.

src/engine/deltamissesbadobject_test.go holds TestADeltaAgainstAHashThisBoxDoesNotHold, which drives deltaSince over a hash naming nothing and asserts it is no error. Beside it are TestTheSinceFallsBackToASnapshotThisBoxHolds and TestTheSinceFallsBackToHeadWithNoTakeUp.

src/engine/snapshotnevertravelled_test.go carries the rule in its own words. The fallback is the newest began this box holds, then HEAD, and the answer says which was used.

So the four criteria here are answered by tests already in the suite. Whoever takes this runs them, names what each said, and closes it as work another hand did.

One thing is worth reading rather than assuming. The fourth criterion asks that a token whose began all resolve is read against the same tree as before. That is what the second of those tests holds, and it is the one to run first.

## done when

- se test --on a token whose began names an unresolvable commit answers ok and names the commit it could not reach
- the same run says which tree the delta was read against, either a began commit that resolved or HEAD
- no answer from se test carries a raw git line as its whole body, proved by a Go test in src/engine over a token with a fabricated began
- a token whose began all resolve is read against the same tree as before this change, so nothing already working moves
