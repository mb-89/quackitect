## detail

THE SEARCH GUARD CUTS A COMMAND AT A SEPARATOR THAT IS INSIDE QUOTES, AND REFUSES THE HALVES.

pipeline in src/engine/search.go splits a command on the shell's separators before anything reads quotes. A pipe or a semicolon inside a quoted pattern is one of those separators, so the pattern is cut in two and each half is judged as its own program.

Measured on 2026-09-05 against ASearchOverTheTree, work root /home/user/quackitect. A search whose quoted pattern held a pipe, over /root/.ccr/README.md, answered refused=true. A search whose quoted pattern held a semicolon, over /tmp/somewhere, answered refused=true.

Every path in both is outside the tree, so both are refused by a message whose last line promises they would not be. That is the same broken promise wk-7bab432426 closed by another road, and this road is still open.

wk-7bab432426 taught a quote-aware word split to the guard. It did not teach quotes to pipeline, because pipeline is shared with ARecursiveSearch and with withoutHereDocs, so moving it needs its own red and its own battery.

## proposed action

Teach pipeline the same quote scanner the word split uses: walk the command once, track the open quote, and split only at a separator seen outside one. Run it against the recursive-search and here-doc cases first, because both read pipeline.

## done when

- a quoted pattern holding a pipe does not cut the command, decided by ASearchOverTheTree over a path under /root answering refused=false
