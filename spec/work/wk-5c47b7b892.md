## detail

A close writes archive rows for tokens it does not close, and every queue on every clone then hides them. Commit 21c1f52d on origin/v4 says it closes wk-19c445440b and wk-07c2d80710. It deletes one note file, wk-19c445440b.md, and appends nine rows to doc/work/archive.jsonl. Six of those rows name tokens whose notes it leaves standing, three open and three done. Commit b7e17ef2 does the same, two rows for one close. src/engine/pullbehind.go reads the archive list off the fetched branch and takes every id in it out of the queue. So forty-two tokens are passed over here, and the answer blames the clone for being behind. Thirty-five of the forty-two are byte-identical to origin/v4 once line endings are set aside, so no fetch, merge or fast-forward reaches them. Across origin/v4 the disagreement is one hundred sixty-one ids: archived in the list, still a live note in the folder. Five of the hidden tokens read done and owe a verdict no reviewer can be handed.

## approach

Three parts, in this order, and each is a change a reader can weigh on its own.

The writer first. A close writes one archive row, for the token it closes and no other. The extra rows come from the close walking a list rather than the one id. So the fix is at that seam, watched on a case that writes extra rows today.

The check second, because it decides the third part. It names any id the archive list holds while doc/work still carries its note. It is red on the hundred and sixty-one this token measured.

The reconciliation last, one id at a time, driven by that check's output. Each id is either closed properly or its row is taken out. The five that read done keep the verdict they owe, rather than being closed to shorten a list.

The queue is what proves it. A reviewer pull on this clone answers work rather than passing over the tokens the detail names.
