## detail

Every group test drives real git, and most of them do not need to.

[[testing]] 11: "Fake the world at the boundary you own, with a fake that behaves. A mock that scripts the answer tests the script." And 13: "A fake with nothing behind it drifts, so one test drives the real tool."

MEASURED 2026-09-08: the group set takes about fifty seconds, one test 4.55 seconds alone. Almost all of it is subprocesses: init, config, commit, push to a ref, fetch, push again, per box, per test.

TWO KINDS OF TEST ARE MIXED HERE, and only one needs the real tool.

Where git is the SUBJECT, the behaviour under test is git's own: a push refused because the ref moved is the compare and swap the whole group system rests on. Those stay real, and there should be few.

Where git is SCAFFOLDING, the test wants a tree with two boxes and some entries, and reaches for git only to build one. Those are the many, and they belong on a fake.

## approach

A fake behind the boundary this program owns: the ref reads and writes the group and claim code already goes through. It keeps the contract, including the refusal a moved ref gives, and holds its state in memory.

One test drives the real tool against the same contract, so the fake cannot drift.

Sorting the existing tests into subject and scaffolding is the first work, and the token says which is which before any test moves.

## done when

- one test drives real git against the contract, and the fake answers the same for every case in it: a table both run
- a test on the fake needs no subprocess: a run that starts no git process, counted
- the group set is faster, and both numbers are on the token: the same go test run before and after
- no test that is about git's own racing was moved to the fake: each moved test names why git was scaffolding for it
