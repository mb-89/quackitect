## detail

Four tokens carry a tool call's own markup inside the reason field in their frontmatter. It is text in the file, not markup anything reads.

Each one ends its reason sentence with a closing reason tag written out, then a newline written as two characters, then an opening parameter tag naming the next field, then that field's whole value as a string. So one field swallowed two.

The four are doc/work/wk-07df68aa8e.md, doc/work/wk-5fadd939e1.md, doc/work/wk-65364638ee.md and doc/work/wk-6fc2999d16.md, each at line 25 or 27. Measured at 2ddcfe4c with se find over doc/work.

Three swallowed an evidence object and one swallowed a successors list. So a verdict's evidence and a token's successors are sitting in a field nothing reads them from, and the record shows a reason far longer than any reason.

wk-8e411b7407 fixed the same leak in a detail chapter, and named the second half: whether the mint can take markup as a value at all. These four are that half's evidence, from four different calls.

The fix on each file is the same two cuts and a move, into the field the parameter tag names. Whether the door should refuse a value carrying its own markup is the question behind them, and it is worth one look before this closes.

## proposed action

Cut the leaked markup out of each reason and put each swallowed value into the field its tag names.
