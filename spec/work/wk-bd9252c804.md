## detail

limits.pulls_before_hold_is_stale is declared, defaulted, loaded from a config file and given a floor by the linter, and nothing reads it to decide anything.

It was the staleness measure. wk-48e28eb9c2 replaced that measure: a holder is gone when nothing of theirs has reached the record for SilenceBeforeGone, which HasGone in src/engine/gone.go answers, and quietHold and the start sweep both go through it. The pull count went with the old measure, and the knob stayed.

Every reader today, from `se_find --regex PullsBeforeHoldIsStale --path 'src/**/*.go'`:

- src/engine/config.go:432, the field
- src/engine/config.go:474, the default of 10
- src/engine/config.go:532, read out of the config file
- src/engine/lint.go:136, a floor the linter enforces

So a person can set it in a config file, the linter will argue about its value, se status prints it among the rules in force, and no behaviour follows from any of that. The floor is the worst of it: the linter refuses a number for a knob that decides nothing.

Either take it out, with its default, its config read and its floor, or make it the name of something real.
