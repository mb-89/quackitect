## detail

Four grammars reach the engine and two of them have already drifted apart once: the HTTP hook door, the verb socket, the command-line flags, and the lane's tools.

The engine gets ONE API and clients speak to it through adapters. The format is JSON-RPC 2.0. NOTHING IS INVENTED: that is what MCP is and what the lane already speaks, so this adopts a shape already in the tree rather than authoring one.

The transport is a loopback HTTP door. The module has no other pipe, since `$.http.fetch` is what the plugin surface offers it. The extension and the command line use the same door, so a person, an editor and a module are three clients of one thing.

WITHOUT THIS THE MODULE CARRIES THE DRIFT. It needs hook decisions, which the hook door serves, and verbs, which the lane serves. Two grammars inside one module is the same defect moved somewhere harder to see. So this lands before [[wk-5d193fcbc1]] rather than after it.

## approach

One request shape, one response shape, one error shape, named once. Every verb the engine answers is a method on it.

The engine writes its port under `.se` and every client reads it there. A port in a settings file was what made the cage two files.

The command line becomes a client of the door rather than a second entry into the engine, and starts the engine when nothing answers.

The hook door's own shape is folded into the method set rather than kept beside it.

## done when

- the engine answers one request shape on one door, and every verb is a method on it: a test that calls each verb and asserts the envelope
- no caller reaches the engine except through that door: a search that answers nothing outside the client
- the command line answers the same as the door for every verb it offers: a test driving both and comparing
- a client that does not know the port finds it: a test that starts the engine, reads the file under .se, and calls
- the tree is sound: `sh util/checks/battery.sh` is green
