## detail

The running engine is build 7f22e1a3.210143, built from commit 7f22e1a3. src/engine/pull.go and src/engine/investigate.go are both modified against that commit in the working tree, so the binary does not carry what its own source says.

The visible effect is that the queue hands nobody work. Every worker pull is answered investigate, naming wk-191014c633 and the worker that held it, and pulling again does not release the hold as the notice promises. src/engine/pull.go:150 calls TakeBackWhatWasLookedAt before quietHold, and src/engine/investigate.go:155 releases a hold when the walker comes back and the holder is still not pulling. That code is correct and it is not running.

Five walkers are parked on that one look in .se/looked.json. worker-dane watched the pull count go 11, 14, 21 with nothing moving, and I added three more. investigate.go records the same loop measured once at twenty-eight pulls.

## proposed action

Rebuild the engine from src/engine and put the new binary in place through whatever door the engine gives for it. Then let the engine release the stale holds itself, one walker ruling at a time, which is what it is written to do.

Two earlier hands put wk-212909368a back saying they were barred from rebuilding .bin, so find out what the door is before deciding this cannot be done.
