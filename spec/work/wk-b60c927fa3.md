## detail

The language server publishes diagnostics at `src/engine/lsp.go` line 448.
It publishes what the schema says and nothing else.

The owner asks that every rule a program can find reaches the problems panel.
A rule found at the write path alone is found once the agent has already written it.
A rule found in the battery alone is found once the change is whole.

The panel is where a person sees it while the line is still under the cursor.
`vale-ls` gives diagnostics, hover and quick fixes over the same protocol, so the shape is settled.

## approach

The server's diagnostic pass gains the voice rules beside the schema rules.
One diagnostic per breach, carrying the rule name as its code, so the panel groups by rule.

A rule carrying a fix publishes a code action, which is the quick fix in the editor.
`textDocument/codeAction` is not served today, so it is new.

The severity follows the rule: a refusal is an error and a rule the write path allows is a warning.

## done when

- a voice breach in an open file appears in the problems panel, decided by `node util/checks/drive-editor.mjs`
- the diagnostic carries the rule name as its code, decided by reading the published message in that run
- a rule carrying a fix offers a quick fix, decided by the same drive asking for a code action
- applying the quick fix clears the diagnostic, decided by the same drive
