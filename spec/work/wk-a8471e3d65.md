## detail

A rule that cannot be switched off is switched off everywhere.
The owner rules that a line may be exempted, and that the exemption names its reason.

`spec/config/voice-rules.json` already carries this shape in prose.
Its `$omitted` block says why `just` is not a rule, in 90 words, and that block is the only record of the decision.

An exemption without a reason is a rule nobody trusts, because nothing says whether it was thought about.
The reasons are what the retro reads to decide whether a rule earns its place.

## approach

One marker, on the line it exempts, naming the rule and the reason.
Vale reads `<!-- vale RuleName = NO -->` already, and the engine's own rules take the same shape.

The engine records each exemption as it passes one: the file, the line, the rule and the reason.
So a count per rule exists without a person collecting it.

An exemption naming no reason is refused, the same as a rule breach.
A rule exempted more than a handful of times is a finding about the rule.

## done when

- a line carrying an exemption marker passes the rule it names, decided by running `se lint` over a fixture holding one
- an exemption naming no reason is refused, decided by the same run with the reason removed
- an exemption for one rule does not exempt another, decided by the same fixture with two breaches
- each exemption passed is recorded with its file, line, rule and reason, decided by reading the record after that run
- a count per rule is answered by one command, decided by running it
