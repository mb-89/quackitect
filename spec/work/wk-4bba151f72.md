## detail

The same folder is two identities when its drive letter is spelled two ways.

MEASURED 2026-09-08 in the harness's own per-project store. It holds c:/Users/mb/Desktop/ai/quackitect-v4 and C:/Users/mb/Desktop/ai/quackitect-v4 as separate records, each with its own trust flag, allowed tools and MCP approvals. The same split exists for the v3 tree. The path string is the key and the drive letter is not normalised.

This engine derives the guard's HTTP door port from the folder path. If that derivation is case-sensitive, one tree answers two doors and can raise two engines, decided by how a shell spelled the drive. Two engines on one tree is the condition the claim system exists to prevent, reached without any of it noticing.

The harness's own store cannot be fixed here. Every place this engine turns a path into an identity can be.

## approach

One function that takes a path and answers an identity, used by every caller that derives a port, a key or a name from a location. It resolves the path and answers one spelling. Nothing else compares raw paths.

Where the answer has to match a key the harness itself wrote, it matches that spelling and says so at the call site.

## done when

- two spellings of one tree derive one port: a Go test naming both spellings and asserting one answer
- no caller derives an identity from a raw path: a search that answers nothing outside the normaliser
- the normaliser answers one string for a trailing separator, mixed separators and a different drive-letter case: `./RUNME.sh test --on this token --propose TestOneTreeIsOneIdentity`
