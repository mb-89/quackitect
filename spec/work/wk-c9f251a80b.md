## detail

`se lint` reads notes against their schemas, at `src/engine/lint.go`.
The voice rules are read at the write path and nowhere else.

So a rule lands, the tree keeps its backlog, and nothing counts it.
770 sentences run past 25 words today and 370 paragraphs run past six.
A person who wants that number runs a script somebody wrote in a scratchpad.

The owner rules that lint reports what format could not fix.

## approach

`se lint` gains the voice rules over every file the write path would check.
It reports the file, the line, the rule and the phrase, one row each.

It runs after `se format`, so every row it reports is a thing a person decides.
The exit code is non-zero where a row stands, so the battery can read it.

A count per rule closes the report, which is the number the retro will want.
`spec/config/voice-rules.json` stays the one place the rules are written.

## done when

- `se lint` reports every voice breach in the tree with its file, line and rule, decided by running it over the tip
- it counts the breaches per rule, decided by reading the last lines of that run
- it exits non-zero where a breach stands and zero where none does, decided by running it over the tip and over a clean fixture
- a file the write path would skip is skipped here too, decided by a Go test naming one
