## detail

A person cannot talk to a bound agent without it being told to spawn subagents first.

The staffing shortfall holds eight tools, in src/engine/staffing.go line 206: Bash, Write, Edit, MultiEdit, NotebookEdit, se_apply, se_run and se_test. That set is doing anything at all, not taking work from the queue. So the main agent is refused a shell command, a file edit, or a test, until it has spawned the hands the queue wants.

THE OWNER'S WORDS: even if you are bound, I do not want the agent to have to spawn subagents just because I want to talk to him.

The one measured here, on 2026-09-06. The owner asked a question. The agent's next call came back with THE QUEUE WANTS MORE HANDS, and the answer waited on a spawn nobody had asked for. It happened twice in one session.

The rule the guard is for is that the main agent must not hoard the queue while hands are missing. That rule is about the pull. Holding every write and every run reaches past it, and the cost lands on the thing a person does most, which is ask.

The binding is not the fix. This holds at every rung, so unbinding was the only way to have a conversation, and climbing a rung to ask a question is the wrong shape.

## proposed action

Hold the queue, not the work.

1. heldDuringShortfall becomes the pull and nothing else: se_pull through the lane, and a Bash command that is a pull on a box with no lane.
2. Everything else goes through at every rung. A write, a run, a test and a read are not the queue.
3. The header on staffing.go says why it narrowed and names what was measured, so nobody widens it back on the reasoning that made it wide.

The existing carve-outs stay. A shell command that only asks the engine something is already exempt, and a held or finishing tree already answers no shortfall.

## done when

- a bound main agent with a shortfall standing is not refused a shell command, decided by: a Go test calling AStaffShortfall with tool Bash and a command that is not a pull
- the same agent asking for a pull is refused and told to spawn, decided by: the same Go test with the pull tool
- no tool outside the pull is named in heldDuringShortfall, decided by: se find --regex over src/engine/staffing.go
- the existing shortfall tests still pass, decided by: se test naming the staffing tests
