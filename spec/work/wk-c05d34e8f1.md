## detail

The owner rules that code holds no comments.
One exception stands: a header of at most two lines at the top of a file.

The tree is 25.8 percent comment lines in Go and 31.9 percent in mjs.
289 doc comments run to eight sentences or more.
`src/engine/store.go` opens 30 paragraphs of argument before the first statement.

An argument belongs in `spec/rationale`, which the header names by link.
Three open tokens already do this one file at a time: wk-86bc02c843, wk-2d6e10c446 and wk-88f5e77313.

## approach

The check reads each file under `src` and refuses a comment below the header.
The header is the comment block starting at line 1, and it holds two lines at most.

One question needs the owner before the work starts.
`spec/guidance/software-development/writing-go.md` rule 12 asks for a doc comment on each exported name, and the lint refuses the bare form.
Either the exported names keep a one-line doc comment, or that lint comes off.
The token carries `needs_human` until that is answered.

Machine directives stay: `//go:` lines and the build tags are not prose.

## done when

- the check refuses a comment below the file header, decided by running it over a fixture holding one
- it allows a two-line header, decided by the same fixture with the comment moved to the top
- it allows a `//go:` directive anywhere, decided by the same test
- the owner has ruled on the Go doc comment, decided by reading the ruling on this token
- no file under `src` breaks the rule, decided by running the check over the tip
