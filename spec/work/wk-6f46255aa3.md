## detail

The newest tests in the tree break a starred actionable of the guidance they were written under.

[[testing]] 14: "Every test runs in parallel and shares nothing: no file, no port, no order." Its own section carries the measurement: the suite ran serially while seven of eight cores idled, and the parallel call brought forty-nine seconds to seventeen.

MEASURED 2026-09-08: 278 of 873 tests in src/engine do not call t.Parallel. Forty-nine of those are the group, claim and branch tests, every one written in the last two days.

They are the slow ones. One of them takes 4.55 seconds on its own and the group set takes fifty, because each drives real git through subprocesses. Serial is where that cost is paid twice.

WHY IT IS NOT ONLY SPEED. The rule says shares nothing. A test that cannot run beside another is a test sharing something, and the sharing is what makes it flaky later. Marking them parallel is how the sharing is found.

## approach

Mark them, run them, and let the ones that redden name what they share. Each one that cannot be parallel says on its own line why, so a reader is not left guessing whether it was tried.

The known sharer is already named on [[wk-b59230aa63]]'s neighbour: anotherBoxOverTheSameTree puts two boxes over one .se, and a fixture that shares state two clones never share is the first place to look.

## done when

- every test in the group, claim and branch files calls t.Parallel, or carries one line saying what it shares: a search that answers nothing without one or the other
- the group set is faster than it was, and the number is on the token: the same go test run before and after, both times quoted
- nothing reddens intermittently: the group set runs ten times and is green ten times
