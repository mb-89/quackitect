## detail

Two voice rules link to files that were never written, and nothing said so.
A link resolves as a path first and then as a note name, so both forms have a target to check.

`util/checks/no-private-links.mjs` refuses a link to a private file.
No check asks whether a link reaches anything.

A rule pointing at nothing reads as a rule with detail behind it, which is worse than a rule with none.

## done when

- a check names every link in the tree that reaches no file and no note, decided by running it over the tip
- it exits zero over the tip once the two known links have targets, decided by the same run
- it fails over a fixture holding a link to a name nothing carries, decided by running it there
- it is named in the method where the battery reads its checks, decided by `se test --propose checks-live-in-the-method`
