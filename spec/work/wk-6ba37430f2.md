## detail

Minted working wk-98fc8ebb08, which asked for the check that finds these.

util/checks/a-count-names-its-command.mjs refuses a sentence in an open note that states a count of something the tree holds with no command beside it. Voice rule 13 is what it enforces: a number something else answers is never written down, and the tree's count is the command that answers it.

se test --propose a-count-names-its-command answers how many it refuses, and names each file, line and sentence.

So the check is written and cannot be listed. Every sentence it refuses sits in an open note belonging to another token. A red check in the battery is a wall every agent waits behind. It is declared out in battery.sh against this token instead, which is the door the battery gives for exactly this.

They are not all the same thing. Some are plainly the defect: a note saying how many test files a folder holds, with nothing to answer it. Others are a bound the schema sets rather than a measurement taken, as in what a rationale allows. A third kind quotes the very sentence being reported as wrong. That is a receipt rather than a claim, and the check cannot tell the two apart.

So the sweep needs a person to say which of the three each one is, and whether a quotation counts as its own command.

## proposed action

The fourteen sentences name their command or lose their number, and the check is listed rather than held out.

## approach

Read the fourteen the check names. Where the number is a measurement, put the command that answers it in the same sentence, or drop the number and name the command alone. Where it is a bound the schema sets, or a refusal quoted verbatim, decide whether the rule should reach it at all and narrow the check instead. Then move the name out of the battery's out line and into its list, and checks-live-in-the-method decides that half.
