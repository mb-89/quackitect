What goes, what stays, what moves

This is a folder-by-folder inventory of quackitect against the target (the index as the central model, one-file modules, doors on both sides). Seven readers covered every source folder, the plugin, the specs and the tests. Line counts are from wc -l; everything else is their reading of the code, checked against it.

In numbers

~50klines of source code today: about 24k JS in scripts, bridge, engine and the plugin lib, and about 24k Go
~10kof them only move data between processes and languages (ports, standing files, spawns, stdout JSON, caches). They go without replacement
~2.3klines of JS checks that already exist in Go. The JS twin goes

Two rules added today

Both came from the owner's earlier "wirings" system, which let every part read and write every variable. Both change how a module is written, so they are fixed before any code is ported.

Input, processing, output

A provider or an action declares its inputs up front. The index hands it one consistent snapshot of all of them, taken at one model revision. Processing is pure and cannot call the index. Output is one atomic commit: the names it provides, or the list of door calls an action makes.

Inputs become a struct whose fields name the values they read (`q:"work/places"`), in place of q.Get during the computation. Each run costs one round trip, which matters now that modules are separate processes. A run never mixes an old value with a new one. Outputs carry the revision they were computed from, and a change during the run simply triggers the next run.

The wiring analyzer

The agent can ask any name: who writes it, who reads it, where it comes from, and where the function behind it lives. Unlike the old system, only one part can write a given name, and the analyzer makes that visible.

Declared inputs make the whole wiring known without running anything. The index records the file and line of each registration. quack why work/open-tasks (also an agent tool and an index-tab view) prints the provider and its file, the inputs down to files, git and events, and every reader.

// modules/work/open_tasks.go, rewritten for input · processing · output
type openTasksIn struct {
	Places Places `q:"work/places"`            // input: declared, delivered as one snapshot
}

var OpenTasks = q.Derived("work/open-tasks", 0,
	q.Doc("The tickets this box can take: the number in the work tab's brackets."),
	func(in openTasksIn) (int, error) {     // processing: pure, no index access
		return in.Places.Takeable, nil          // output: committed at once, with the snapshot's revision
	})

What goes without replacement

  • Process lifecycle. The bridge server's start, takeover, reload, self-test and respawn. Four standing files with ports (index.json, lsp.json, panel.json, vehicle.json), plus show-panel. The server is started three ways and its health probed three ways. Binaries are swapped in two ways and checked for staleness in two ways, one by mtime, one by source hash.
  • Verb plumbing. The cli.js dispatch table, usage texts and hand-written flag parsing. The stdout JSON protocols: branch list --json, ticket yours, route and fill JSON, --judge, and the "spawn" text the hook parses. The sidebar count's four-process chain on every redraw.
  • Caches and change detectors. Four separate mtime:size detectors, caches.js, projection and Vale-style staleness checks, the LSP parse cache, and the hash-diff caches in the LSP and the TUI over a long-poll changes call. Dependency tracking in the index replaces all of them.
  • Code that exists only because the server restarts. The marks file, the canary debt rebuilt from the log, fillsBox, and about 20 cache fields on the box.
  • The second cage. copilot-runtime.js (313 lines) re-implements the write door, the trunk refusal, the stop checks and handover for Copilot. Copilot then gets the same rules through the hooks door.
  • Twins. About 2.3k lines of JS checks (tree rules, schema, size, magic, names, paths, private, slug, the Vale and Biome parsers) whose Go twins already run in src/lsp. Also every "spelled again here" constant in Go.
  • install.sh. Three Go builds become one go build. The Zig download (~90 lines) goes too if the index moves to pure-Go SQLite (see gaps).

Gaps the inventory found in the design

These are cases today's code handles and the target design didn't cover yet. Each needs a decision before the phase that meets it.

State folded from events

About 25 session values (demand, grace, handover, claims, marks, calls, helpers…) are reducers over the event stream, not functions of files.

A third provider kind, q.Fold(name, default, func(state, event) state), over the session/ input. It still has one owner, and the IPO rule applies per event.

Git is not a file

Origin refs, blobs by ref, merge-base and log change on fetch and commit. The file watcher doesn't see them.

Decided: git is never live input. A group in the cloud is marked in its ticket on main, so the queue reads only files. Reading the archive is an explicit operation through the git door, outside the index.

Actions are transactions

A hand-back writes, stages, commits (the git hook may refuse and trigger a revert), pushes with a rebase retry, and runs the check first on trunk.

An action's output is an ordered list of door calls with an undo per step. The index runs one writing action at a time. Git hooks only read names, so they can never deadlock against a running action.

Unsaved editor buffers

The LSP checks open buffers, not only what's on disk.

A buffers/ input owned by the LSP door. Check names read the buffer where one is open and the file otherwise.

Time and identity

Stale claims and queue ages depend on the clock. Which hand is calling depends on the caller's environment and box.json.

A clock/minute input from the clock door. Every inbound call carries a session id, and per-session names live under session/<id>/.

NLP in the checks

The tense, sentence-length and vocabulary vetoes use wink-nlp (JS). Go has no tagger that tags the same way.

Keep wink behind a small "prose" outbound door running as a Node sidecar. Findings stay identical, and a Go port can be considered later.

The hook protocol is bigger than "forward, register, spawn"

The answers also cover streaming, context fill, transcript rows, clear plus resubmit, model.classify and ui.log, and tools must be registered before the index answers.

Write the answer-verb spec before phase 5. The tool list is generated at build time into a file the hook reads at session start.

Cold start

Git hooks run with no index running, and a fresh cloud clone has no binary. Copilot command hooks time out after 60 s.

One quack binary. quack hook starts the index if none answers. The cloud setup builds the binary, or downloads a pinned release build.

cgo, Zig and several Go modules

The index needs cgo SQLite with FTS5 (and Zig on Windows). The LSP promises no cgo. There are seven go.mod files, and the TUI is on Go 1.27 while the rest are on 1.24.

One Go module and one Go version. Test pure-Go SQLite (modernc, FTS5 support to verify) in phase 1. If it holds, Zig and cgo leave the install.

Byte-identical outputs

Ticket frontmatter rewrites and the generated Vale rules must not churn.

The Go writer becomes the only writer, preceded by one normalising commit over all tickets. The Vale output is compared byte for byte in CI.

Twins that differ

Pointer resolution, config env naming, skip lists and the schema subset differ between their copies, so picking one changes findings.

For each twin, run both over the whole tree and compare (golden files). The owner decides each difference before the JS copy goes.

Architecture guards

DoorsOnly, FakeDoorsInTest and OutsideInDoors are Vale scans of JS imports.

A go/analysis check over the import rules (modules import no doors, doors and renderers import no modules), run by the check.

Bugs found on the way

  • The judge switch does nothing. hooks/pull-tool.js reads the tracked level0.json directly, but /se-config-judge-enabled-false writes the local layer.
  • Lost log lines. extension/lib/logbook.js rewrites the whole session.jsonl for every line, so it races the other writers.
  • Config differs by reader. The bridge's asks and the extension's valuesOf skip the env layer.
  • Windows gaps. trust.js reads only HOME. Drive-letter normalising (rooted) exists only in the index, so the LSP roots paths differently on Windows. Four places pick the home directory with conflicting precedence.
  • Drift already visible. pull-route.js BRANCH lists new and lacks open and unblock. The TUI's ticket links ignore .se/tickets. A second vehicle's port 6511 collides with the window door's.
  • Dead code. readThroughTheReader, prepush.lintedBy, work-stands branches/frontField/ticketsOn, freeNow (tests only), unused env constants in lsp/config.go, and the inset-probe skill.

Decisions needed from the owner

  • The prose door. Keep wink-nlp as a Node sidecar door, or re-baseline the tense and vocabulary rules in Go?
  • SQLite. If pure-Go SQLite holds up in phase 1, drop cgo and Zig?
  • One writer for frontmatter. Accept one normalising commit over all tickets?
  • Twins. Review the golden-file differences per twin (pointer resolution, config env naming, skip lists) as each is merged?
  • Fix now or later. Fix the judge switch and the log race now, before the migration reaches them?
