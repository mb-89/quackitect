The bench reruns design inputs

Funnel page. It stands beside spec/funnel/the-bench-reruns-design-inputs.md, which carries the short form.

Bottom line. A desk cuts a start commit, and a cloud box reruns a group of tickets from it. Every run gets the same design input, and each run changes one setup. The box learns that it works in a sandbox. The transcript shows whether it stays inside. A desk grades the design output against a reference.
  • Stands: one repo, runs side by side, detection in place of prevention, the design input as the task.
  • Waits: the ship door for the transcript, the two bench verbs, a stub on a cloud box, and the first bench project.

1The question

The owner reads the agent as less able under a short context window. The owner sees a dull zone at the start of a conversation, and one at its end. At handoverAt: 300000 the owner sees better work at once.

Daily logs mix the work and the days, so they cannot hold one variable still. A bench holds the work still and moves one setup.

Out of scope: the finish mode past the threshold ("start nothing new"). A fix there changes daily work. It gets its own item.

3What the box gets, and how it is graded

Every run gets the same design input and the same tickets. The box gets no test from the reference implementation. The desk runs those tests after the box finishes.

recordthe conditions stamp over every folder that moves a runWhich runs compare. The median over three runs or more is the result.
