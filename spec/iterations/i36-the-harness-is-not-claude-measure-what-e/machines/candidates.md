# The candidate drawing

One compose state per line drawn on the chart at build_chart. Two lines were
drawn there.

- THE ADOPTED BASELINE, REFINED keeps every function this iteration's
  requirements already assume: handshake-based harness identity, the
  blocking stop hook, evidence-based interruption diagnosis, shape-level
  failure routing, and tolerant reading of old test records.
- THE TRIMMED SPREAD answers the same row two ways differently: no
  per-harness identity at all (one fixed lowest-common-denominator bound),
  and failure routing left to the retro's existing periodic mining instead
  of a dedicated function. The stop hook, diagnosis and test-record reading
  stay unchanged from the baseline.

They are independent and both hang off start; the join waits for both.

## What each state writes

It writes back into the candidate note its line already created, and mints
nothing:

- How it works - the whole architecture, and especially the seams between the
  chosen options.
- What it costs - rough feasibility checks, proportional and no more.
- What it leans on - what has to be true for it to work.

Nothing here is scored. Judging stays at evaluate-set, because an agent that
knows the score while it writes the description writes a description that
earns the score.
