### Hostile FAQ

### Is this just more prompt text?

No.

Prompt text cannot prove which host limit applied or which process stopped.

The lane must measure and report those facts.

### Are we weakening boot checks to make boot faster?

No.

The iteration keeps the checks.

It removes hidden recovery steps and oversized payloads.

### Why not fix only the Copilot overflow?

The prepared evidence shows five independent breaks.

Today's session also reproduced metadata coupling and an undiagnosed cancellation.

A one-host patch would leave the same class of failure elsewhere.

### How do we know the stop hook works?

We do not know from a cancelled call alone.

The current system does not distinguish stop-hook action from host cancellation or MCP loss.

That diagnostic gap is now a RAID issue.

### What if the MCP server really stopped?

The lane should emit lifecycle evidence.

The evidence must identify the process exit, transport loss and restart outcome.

Without that, recovery remains guesswork.

### Does every failed call become a feature request?

No.

Each failure is classified first.

Agent misuse may need no product change.

An unclear schema, bad remedy, host behavior or engine defect becomes improvement work or an explicit carry-forward item.

### Is the iteration too large?

It is major by design.

The five prepared breaks share one harness measurement surface.

Downstream design should split implementation chunks without splitting the evidence model.

### What would make this the wrong effort?

The kill criterion is that the failures cannot be reproduced or measured on supported hosts.

That criterion is not met.

The prepared report contains arithmetic measurements.

This session reproduced payload offload and boot metadata coupling.
