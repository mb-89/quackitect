## built

THE SWEEP IS GREEN. `node deliverable/engine/bin/sweep.ts` exits 0 with "markers green / widget guard green / sweep green" over 2687 nodes.

### The three, each decided

`deliverable/engine/mirror.ts` BUILT AN ANCHOR ITSELF. It turned `[[refs]]` in rendered prose into `<a class="doclink">`, which made the server a place markup comes from. That is now `linkDocRefs` in `render.ts`, and the server calls it. The surface makes the link.

`deliverable/engine/tools.ts` WAS A FALSE POSITIVE. A tool description writes a payload shape in angle brackets to tell the reader what to send. The predicate now treats a tag preceded by a quote as a placeholder rather than markup, which is the one shape that was left after the reachability rule landed.

`deliverable/engine/bin/mermaid-check.ts` IS THE ONE REAL EXCEPTION. It builds a diagnostic page a maintainer opens to see whether a document's diagrams parse. It renders nothing about the walk and the panel never reaches it, so it is declared in `deliverable/machines/widget-exemptions.md` with that reason.

### Why the new rule needs no list

`surfaceFiles()` FOLLOWS THE IMPORTS from `deliverable/engine/render.ts`, which is where the panel's page is built. A hand-kept list of the surface's parts would be a second place holding one truth and would go stale the first time a file was added.

THE EDITOR REGISTRY NEEDED NO SPECIAL CASE after the change. A form editor is reached from the renderer like everything else the panel draws.

THE OTHER EIGHTEEN NEEDED NO ACTION AT ALL, which is the finding. They were never a second surface; the old rule simply could not see that they were the first one.

## follow_up

THE GUARD STILL CANNOT SEE A DERIVER. It finds files that produce markup, not files that work out their own answers about the walk. A registered editor that starts deciding what a state's colour means passes it. An import rule would catch that — a surface module may import the view model and nothing else about the walk — and it is not built.

THE CLOSURE FOLLOWS STATIC IMPORTS ONLY. A file reached by a dynamic import, or by a string path the engine resolves at runtime, is invisible to it and would be reported as a stray. Nothing does that today.

THE BROWSER-ONLY QUESTION IS ANSWERED SIDEWAYS AND SHOULD BE ASKED DIRECTLY. Nothing that emits markup now sits outside what the panel reaches, which is the property the owner asked for. Whether there is browser-only code that emits NO markup is a different sweep, and this round did not run it.
