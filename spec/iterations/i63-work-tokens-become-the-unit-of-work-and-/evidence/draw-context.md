## excluded_use

UNCHANGED, and the standing exclusions carry over intact. Three are worth restating because this round could be misread as touching them.

IT IS NOT A PROJECT TRACKER FOR A TEAM. One engine walks one record. Tokens make work countable and visible, which is exactly what a tracker looks like, and it is still not one: there is no assignment to people, no sprint, no board shared between hands. A token has a place and a status, and nobody holds it.

IT DOES NOT REPLACE VERSION CONTROL. Tokens are files under version control rather than a store beside it.

IT DOES NOT PUSH. Landing work on a remote stays the person's act, on every machine except a cloud run where the standing exception already applies. Nothing about tokens changes that.

AND ONE ADDED BY THIS ROUND'S OWN SHAPE. A work token is not a private note. Notes stay machine-local and a token lands on trunk where it cannot be taken back. The owner's direction is that if notes ever become tokens they become PRIVATE tokens in a separate store, and until that is ruled the two remain different objects.
