A: Nobody, today, and that is the sharpest thing in this packet. It is registered as a risk with four path kinds and a test per kind, and as an assumption with a probe. Neither is a substitute for a live product running it. IF ONE ANSWER IN THIS FAQ SHOULD WORRY A READER, IT IS THIS ONE.

Q: YOU MEASURED EIGHT STEP-OUTS. Would the binding have prevented them, or would it have blocked work that then found another way round?

A: It would have blocked most of them, and the work still needed doing. THIS IS THE FINDING OF THIS STATE and it is folded upstream below.

Q: THE SHELL LEAK IS THE REAL DEFECT AND YOU ARE FIXING IT SIDEWAYS. Why not a better guard?

A: Because a guard enumerates doors and this removes the destination. Ours already watches five tools and missed the sixth. That is the strongest argument for this shape, and it survives.

Q: WHY IS THE STATE MODEL IN THIS ITERATION AT ALL? It has nothing to do with path resolution.

A: It rides because the binding BREAKS the old model, not because they are the same idea. What counts as open is whether a worktree directory exists, and this product will stop making worktrees. Left apart, the archive swallows the record being walked. It is the main reason the size is major rather than minor, and the packet says so.

Q: A FRESH CLONE ALREADY SHOWED NINETEEN RECORDS AS ARCHIVED. That is a bug you could fix in an afternoon without any of this.

A: True, and it is the fair version of the previous question. The state model could ship alone. It is bundled because both halves touch the same three call sites, and doing them apart means reading and re-reading the same code twice.

## findings_folded

ONE FINDING, AND IT WEAKENS THE BUSINESS CASE I WROTE AT frame-delta.

WHAT I CLAIMED THERE: eight step-outs in one session, each re-walking the machine from its start, as cost the binding buys back.

WHAT THE HOSTILE QUESTION EXPOSED: the binding prevents the ACCIDENT and not the WORK. A step-out taken to edit method deliberately still has to happen — the method write is refused from inside a record whether or not the root has moved, and its remedy is the same escape, edit, aim back. So those step-outs are not saved by this change at all.

WHAT IS ACTUALLY SAVED, stated correctly: the writes that landed on trunk WITHOUT anybody intending it. That is the feature built twice on two branches, the trace edits that triggered a mid-walk sync and felled four signed claims, and the diagnostic that read the wrong tree and reported a defect that did not exist.

HOW MANY OF THE EIGHT WERE WHICH: not counted, and I am not going to guess. The log can answer it and the requirements state should, because the business case now rests on a split nobody has measured.

WHAT THIS DOES NOT CHANGE. The accident class alone is worth the work — it is the class that costs signed claims and duplicated features rather than minutes. And the deliberate step-outs get their answer from the fan-out that replaces the guard, which is already ruled and already a non-goal here.

SO THE UPSTREAM CORRECTION IS ONE SENTENCE: the binding buys back unintended writes, not step-outs. The frame-delta business case overstates it and the requirements state owes the measured split.
