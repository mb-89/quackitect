## anything_else

THE PRIOR-ART COMPARISON IN FULL, because the option node that named these systems says in its own text that the gate should check them.

WHAT WAS CHECKED AT THE PRIMARY.

nginx, at nginx.org/en/docs/control.html. One master process and N workers is confirmed, with the process listing in the document. Two things it does better than ours.

- On HUP the master "first checks the syntax validity, then tries to apply new configuration" and "If this fails, it rolls back changes and continues to work with old configuration." Our supervisor stops the record at entry instead. It never validates the composed machine and never falls back.
- On USR2 the old and new master processes both run and both sets of workers accept requests, and if the new binary is unacceptable the old master starts its workers again. Ours retires the old satellite with nothing kept alive behind it.

What ours sheds against nginx: nginx workers are interchangeable and stateless, so any worker serves any request. Our satellites are not interchangeable — each is bound to one record — which is what buys the isolation nginx has no need for.

PostgreSQL, at postgresql.org/docs/current/tutorial-arch.html. The doc says it "starts ('forks') a new process for each connection" and that "the supervisor server process is always running... whereas client and associated server processes come and go." That is the shape, and the doc names the supervisor.

What PostgreSQL does better: it splits per CONNECTION over shared data, so many backends work the same database at once. It pays for that with MVCC and shared buffers.

What ours sheds: we split per RECORD, so no two satellites touch the same data and none of that machinery is needed. The cost is the mirror image — two agents cannot share one record, and the claim ledger enforces it.

WHAT WAS NOT CHECKED, said plainly. Erlang OTP supervisor trees, browser process-per-site renderers and per-workspace language servers are named from working knowledge and the primary was not read this session. The option node opt-a-core-and-a-satellite-per-agent already carries that caveat, and it stays true.

WHY THE COMPARISON WAS WORTH RUNNING. It produced a register entry nobody had. The nginx rollback is a property our supervisor's four acts do not have and did not name as missing, and it took reading the primary to see it.

WHAT A READER SHOULD BE MOST SCEPTICAL OF HERE. Not the shape — the shape is ordinary server software and the primaries confirm it. The unmeasured throughput argument, which is the only reason to pay for the split at all, and which flatters the answer that won.
