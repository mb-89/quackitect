## prfaq

### The press release, from the ship day

QUACKITECT NOW SIZES ITS OWN WORK BEFORE IT ASKS ANYBODY TO DO IT

Every one of the fifty-three states in Quackitect's development process now
carries a complexity rating, and the machine reads it before a milestone is
walked.

WHAT SHIPPED. Each state declares how hard its work is on a five-rung ladder,
from a step the engine computes outright to one where the agent must find the
frame rather than fill it. One list in the repository maps each rung to a
model name, and it is the same list on every machine.

Before a milestone opens, the machine names the driver that milestone needs
and hands the name outward; whatever is driving performs the spawn. Every call
the lane serves now records which model answered it and which state it was
made in.

WHO BENEFITS AND HOW. The owner, who pays the token bill, stops paying
frontier prices to transcribe decisions that were already made. The agent,
which now arrives at a state knowing whether the work in front of it is a
lookup or a judgment. And the reader of a finished record, who can ask which
states were walked by what and get an answer from the log rather than from
memory.

WHAT IT DOES NOT DO. It does not predict anything. The same milestone names the
same driver every time, on every host, and the answer can be read off a file a
person edits.

THE OWNER'S WORDS: "The machine already reads what each state produces, what
bounds the answer and who reviews it. It knew how hard the work was all along.
It just never used it to decide who should do it."

### The hostile FAQ

THE QUESTIONS COME FROM SOMEWHERE OTHER THAN THE DRAFTER. Two independent
adversarial passes fed this: a reviewer with no shared context reading the
gate brief against the tree, and a prior-art scan of what shipped systems
actually do. A third pass, writing questions with no knowledge of the answers,
was commissioned for this state; anything it raises that is not answered below
folds into the risk log rather than into a rewrite of this form.

Q: WHY NOT JUST BUY A ROUTER? Cursor, Bedrock and OpenRouter all ship one, all
fit the individual item, and all learn from outcomes. Why hand-maintain a table
that can never learn it was wrong?

A: Because the output of this system is an auditable record, and a router's
answer is not reproducible. Cursor hides the routed model by default;
Copilot's review path does not disclose it at all; both accept the model
varying between turns. A walk that cannot be replayed is worth less here than
a walk that is occasionally over-driven.

THE ANSWER IS NOT THAT ROUTERS ARE WORSE. They are better at the thing they
optimise and we are giving that up on purpose, with the cost registered as a
standing risk rather than argued away.

Q: EVERY SYSTEM THAT HAS RUN DECLARED RESOURCE CLASSES FOR A DECADE LEARNED
THE SAME LESSON AGAINST YOU. Kubernetes refuses to let anyone declare a QoS
class and computes it instead. Google measured hand-managed jobs at twice the
slack. Twenty-three thousand clusters, sixty-nine percent of requested CPU
unused.

Why will yours be different?

A: IT WILL NOT BE, ON THE CURRENT DESIGN, and that is registered rather than
denied. The way out is the same one Kubernetes took and it is named in the
requirements as a candidate: derive the rung from something testable — what
will judge this state's output — so a machine checker caps it and only reader-
judged work reaches the top.

THE HONEST POSITION TODAY is that we are shipping the declared version first
because it is the one that can be shipped at all, and the derivation is a
change to what a matrix row must declare.

Q: YOUR OWN SEED SAYS THE ENGINE CANNOT SPAWN AN AGENT AND IT CAN. If the
iteration's design input is wrong about the code it claims to have searched,
why should anyone trust the rest of it?

A: THEY SHOULD TRUST THE RULINGS AND CHECK THE FIGURES, which is what
happened. Two issues stand in the register saying exactly this, and both were
found by reading the files the seed cited. The rulings survived because they
rest on the lane's grain rather than on the false premises; the figures did
not, and every one has been recounted.

THE UNCOMFORTABLE PART OF THE ANSWER: nothing in the process caught them. A
count in prose has no way to go loudly wrong, and that is now written down
where the next record will meet it.

Q: YOU ARE PROUD OF THE MACHINE-NAMES-DRIVER SEPARATION, BUT THE ENTRYPOINT
ALREADY SPAWNS AN AGENT WITH A ONE-ARGUMENT ADAPTER. Is the separation a
principle or a rationalisation of not wanting to build it?

A: IT IS A PRINCIPLE AND THE ARGUMENT FOR IT WAS RE-GROUNDED. The lane does
not push, does not open records unasked and does not reach the screen;
starting a process is that class of act. THE COST ARGUMENT IS GONE — the
adapter exists and is one flag wide — so the separation now stands on the
grain alone, which is where it should have stood.

Q: THE TWO-AXIS SPLIT SOUNDS TIDY, BUT AUTONOMY AND COMPLEXITY BOTH ANSWER
"HOW MUCH DO I TRUST THIS ANSWER". Is dropping the grid a real simplification
or a way of avoiding the cells you could not fill?

A: THEY ANSWER DIFFERENT QUESTIONS AND THE PRIOR ART AGREES. Autonomy decides
whether a person or a reviewer must LOOK; complexity decides how strong the
HAND is. Stakes want a second reader, not stronger hands, and a reviewer is
cheaper because it reads one artifact rather than carrying the context.

GitHub Actions has shipped exactly this split for years — runner selection in
one place, human approval rules in another, configured separately. A
combination that cannot occur simply never arises, rather than needing a cell
marked not-applicable.

Q: YOUR SUBMACHINE RULE TAKES THE MAXIMUM AND WALKS EVERY ITEM ON IT. Have you
noticed you have built the over-provisioning failure into the algorithm rather
than merely risking it?

A: YES, AND IT IS REGISTERED WITH THE ARITHMETIC SPELLED OUT. A ten-item fan
whose hardest item is C4 costs ten C4 walks. The rule is still right, because
splitting the fan across strengths means the weak walker meets the hard item
and fails silently.

WHAT MAKES IT BEARABLE is keeping and SURFACING the per-item values, so an
expensive fan names itself and the question becomes answerable instead of
invisible. That is the difference between a cost and a cost nobody can see.

Q: THE ONE SAFETY RULE — A WEAKER MODEL NEEDS A RECORDED REASON — ASKS THE
UNDER-POWERED WALKER TO NOTICE IT IS UNDER-POWERED. Is that not the definition
of a rule that fails exactly when it is needed?

A: IT IS, AND IT IS REGISTERED AS A CRIPPLING RISK. There is no field declared
for the reason, no clause covering its absence, and no comparison between the
recommended rung and what walked. Every other rule in this system that matters
has a mechanism; this one has a sentence.

THE ROUTE TO A MECHANISM is named: a declared field so its absence is a shape
the engine can see, then a comparison once the served model is trustworthy,
then a refusal.

Q: YOU CANNOT EVEN TELL WHICH MODEL ANSWERED. The transport hands you a client
name. Is the fourth goal not simply undeliverable?

A: THE HONEST ANSWER IS THAT IT IS DELIVERABLE ONLY AS A CLAIM TODAY, and the
form will say so rather than reading like an observation. WORSE THAN SELF-
REPORT, and this is the part that surprised us: this harness moves a session
to a different model on a classifier flag and suppresses the notice under
machine-readable output, so an honest agent reporting the model it was started
with can be wrong.

The route out is that whoever performed the spawn knows what it spawned and is
not the party being measured.

Q: SO YOU ARE SHIPPING A STAMP THAT SAYS WHO, ON A RECORD THAT CANNOT SAY
WHERE. What question does that answer?

A: NONE, WHICH IS WHY BOTH COORDINATES ARE IN SCOPE. Measured live on this
box: grouping the call log by state or by visit puts every record in a single
bucket, while grouping by actor separates cleanly — the mechanism works and
the field is absent.

The record grows two fields in one edit or it grows neither, and shipping half
would look like progress and move nothing.

Q: WHY IS THIS WORTH A DAY WHEN NOTHING IN IT MAKES THE PRODUCT DO ANYTHING NEW
FOR ANYBODY OUTSIDE THE TEAM?

A: BECAUSE THE TOKEN BILL IS WHAT CAPS HOW MUCH WORK GETS SENT, and that is
already a standing value proposition rather than a new claim. A process that
spends frontier capability transcribing settled decisions spends its budget on
the cheapest half of its own work.

THE WEAKER PART OF THIS ANSWER: the saving cannot be quantified from this
system today, because nothing can attribute a call to a state. That is
precisely what this iteration adds, so the first honest number arrives after
it, not with it.

Q: AND WHY NOW RATHER THAN AFTER THE THINGS PEOPLE ARE ACTUALLY WAITING ON?

A: NOTHING HERE CLAIMS PRIORITY OVER THE OPEN RECORDS. What makes now the
right time is that the three mechanisms it needs all landed recently and
independently — one file per matrix row with per-column cells, the read-live
machine file as a settled pattern for both existing dials, and the ruling that
split the two axes instead of crossing them.

Before those, this change had nowhere to live.

Q: IF YOU ADD A STATE TO NAME THE DRIVER, YOU EDIT A DEPENDENCY, AND TWO OTHER
LIVE ITERATIONS REOPEN ALONG WITH THIS ONE. Is the whole third goal not simply
unaffordable?

A: IT MAY BE, AND THAT IS THE OPEN QUESTION THIS MILESTONE HANDS DOWNWARD
rather than one it settles. The tripwire is written into the risk: if the
driver can be named inside a row that already exists, with no new state and no
changed dependency, the cascade never happens and this column was too heavy.

If it cannot, the cone is declared before the edit rather than discovered at
the next pull. WHAT IS NOT ACCEPTABLE is finding out by doing it.

Q: WHAT WOULD MAKE YOU ABANDON THIS?

A: A DERIVATION THAT WORKS. If the rung can be computed from what a state
already declares, the fixed table is a worse version of a better thing and
should be dropped rather than shipped and maintained. The scan's first
recommendation is exactly that, and it is carried into the requirements as a
candidate rather than dismissed — which means this design has to beat it
there, not here.

Q: YOU FIRST WROTE THAT QUESTION AS "THIRTEEN OF FOURTEEN PINNED RECORDS
REOPEN". Which was it?

A: TWO OTHERS, AND THE FIRST FIGURE WAS MINE AND WRONG. Fourteen records carry
a seeded column and thirteen carry a comparable shape, but eleven of the
fourteen are SHIPPED. Cross-checking status against pins gives three both open
and pinned — i9, i36 and this one — so the live exposure is two other
iterations.

THE UNCOMFORTABLE PART IS HOW IT HAPPENED. The kickoff had estimated four. I
counted, believed I was sharpening the estimate, and inflated it roughly
sixfold by counting the wrong population. A number arrived at by measurement
is not automatically better than one arrived at by reading, and this one was
worse.

Q: YOUR OWN PRESSURE TEST DID NOT FIND ANY OF THIS. What is the test for?

A: IT DID NOT, AND THE GATE DID. Three states were reopened on findings this
form's FAQ never raised: a register sweep that had not happened, a measurement
that proved nothing, and the figure above. THE PATTERN IS THE ANSWER — every
question that landed came from outside the packet, and the ones written from
inside it were the comfortable ones. This form said so before the gate proved
it, which is worth something and is not worth much.

Q: A STANDING ENTRY SAYS WEAKER MODELS CANNOT PRODUCE THE BOOT READING PROOF AT
ALL. Why are you routing cheap models toward states they cannot reach?

A: BECAUSE THE TWO ENTRIES WANT EACH OTHER, and that is the honest sequencing
argument rather than a dodge. Until something names which states are cheap,
there is no case for spending effort on the boot door, because nobody can say
what opening it would buy. Until the door opens, naming them buys nothing.

WHAT CHANGES BECAUSE OF IT is the pitch, not the plan: the payoff waits on
somebody else's open issue and the case now says so where a reader meets it.

## findings_folded

THREE THINGS THE TEST CHANGED, AND ONE IT DID NOT.

CHANGED — THE SUBMACHINE RULE GAINED A CONDITION. The fan-out question could
not be answered cleanly without saying that the per-item values are SURFACED
rather than merely consumed. That is now part of the scope's sixth item and
part of the risk's way out, where before it was an implementation detail
nobody had committed to.

CHANGED — THE FOURTH GOAL'S HONESTY CLAUSE. "You cannot tell which model
answered" could not be answered cleanly as written. The answer that survives is
that the field is a CLAIM rather than an observation and must be read as one
until the value comes from the spawner. That sentence now stands in the
assumption node and it is the thing the design state must either accept or
close.

CHANGED — THE WHY-NOW GOT ITS WEAK HALF. "Why is this worth a day" could not be
answered with a number, because nothing in this system can attribute a call to
a state. Rather than reach for a router's published figures, the frame now says
the first honest number arrives after this iteration and not with it. The
business case field says the same and skips rather than projecting.

NOT CHANGED — THE VISION. Every question above lands on the mechanism, the
cost, or the order of work. None of them lands on the axiom that the machine
should know how hard its own work is, and no question the two adversarial
passes produced argued that it should not. So the vision packet stands
inherited, and the findings folded into the register and the scope instead.

THE ONE THING WORTH SAYING ABOUT THE TEST ITSELF: the questions that hurt most
came from outside. The reviewer found the shape cascade and the scan found the
scheduler literature; neither was reachable from inside the draft. The
questions written from within the packet were the comfortable ones.

AND THREE MORE, FOLDED ON RE-SIGN AFTER THE MOTIVATION GATE FAILED.

CHANGED — THE CASCADE FIGURE. Thirteen of fourteen became two other live
iterations, because eleven of the fourteen pinned records are shipped. The
question that quotes it is rewritten and a new question asks which it was, so
the correction is visible rather than tidied away.

CHANGED — THE PAYOFF'S DEPENDENCY ENTERS THE FAQ. The register sweep that this
milestone owed and skipped turns up an open, crippling entry saying weaker
models cannot boot at all. A new question asks it directly and the answer is
sequencing, not denial.

NOT CHANGED, AND WORTH SAYING PLAINLY — THIS TEST DID NOT CATCH ITS OWN
PACKET'S WORST ERRORS. The gate did, on an adversarial pass with no shared
context. The form had already observed that the questions written from inside
the packet were the comfortable ones; being right about that in advance did not
make the test work.
