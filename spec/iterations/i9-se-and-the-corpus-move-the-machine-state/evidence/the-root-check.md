# Evidence form / the-root-check

## current_situation

THE CONSENT ROW HAD FOUR RED CASES AND NOTHING TO AIM AT. They failed saying so in their own words: the system does not yet decide its own root.

THE DECLARATION COULD NOT HOLD IT. It carries two facts and nothing else, and deciding a root is a third. So the check is its own module and the cases were re-pointed at it in the same commit, which is what the test-first note at observe-red said would happen if a name moved.

## built

`enginerootcheck.ts`, one function and three outcomes.

- NOUGHT CARRIERS: it refuses, and the refusal says plainly that this folder is not a project of this system and that nothing has been written to it.
- ONE CARRIER: it binds to that folder.
- TWO OR MORE: it refuses AND asks, naming the carriers. Choosing between two projects on somebody's behalf is exactly the guess this check exists to avoid.

A FILE-EXISTS CALL, NEVER A SEARCH, as the chunk demands. It runs once per opened folder, and a search would cost whatever that folder happens to contain.

IT WRITES NOTHING ON ANY PATH. That is not a comment, it is what the third case pins: the folder's whole listing and every file hash are taken before and after, and asserted identical. An assertion that no machine-state folder appeared would have been weaker, because the row forbids writing ANYTHING.

THE ARGUMENT IS WHAT THE HOST HANDED OVER, one folder or several, which is why counting carriers is the shape rather than testing one path.

MEASURED: the four consent cases were red before this chunk and are green after it, and no other case moved.

## follow_up

### What is left red, and whose it is

THREE DESK-CLOCK CASES remain, and both names they want belong to other work: something that writes a measurement where the timings log reads it, and something on the surface that says a part is still starting. The second is the half the architecture deck ruled at risk because no candidate answered it.

### The two-carrier case has no test

THE CASES THIS CHUNK ANSWERS COVER NOUGHT AND ONE. Two or more is written, reasoned and unexercised, because the spec that drove these cases describes one opened folder and says so.

IT IS THE BRANCH A HOST ACTUALLY PRODUCES. Adding a folder to a workspace is an ordinary act, and the host restarts every extension when the first one is added. The case belongs with the host behaviours the desk spec set aside, and it is named here so the next sweep meets it rather than rediscovering it.
