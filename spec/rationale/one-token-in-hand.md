## decided

Naming a token puts back whatever else that actor holds.
An agent holds one token at a time.
The take-up verb stays, because a person picks work up from the panel.

## why

Taking up is not a call an agent makes any more.
The write verbs call it with the name on the write, so naming the work and doing the work are one act.
The verb stayed for the person at the panel, and because a write has to say what it did.

One thing in hand at a time keeps the queue honest.
It never shows an agent working on two.
Changing what you work on is then one word on the next call, rather than a put-down and a take-up.

## costs

An agent that wanted two tokens in hand cannot have them, so work spanning two is two visits.
The put-back is quiet apart from a line in the session log, so an agent can lose its place by naming another token.
A long-running job under one token is put back the moment its agent names another.

## revisit when

- an agent can honestly work two tokens at once, and the queue can draw that
- the put-back costs more than it protects, because agents name tokens oftener than they change work
