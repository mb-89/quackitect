# Actionables

1. Ask of every bad output which rule, prompt or tool makes it, and what change stops that. A bad output with no cause named comes back. *
2. Rank the log's refusals and failing calls by rule, and name what each one stands in for. A refusal read alone looks like noise, and the rank shows the rule that bites. *
3. Read a retry in both records: the log shows it, and the transcript says why. A retry read in one record alone shows the fact and hides the cause. *
4. Read the agent's thinking for doubt, worry, a guess, and a plan it drops. The actions hide these, and each one marks a place the machinery let the agent down. *
5. Mark every place the owner corrects the agent, repeats an ask, or pushes back. Each one is a rule or a prompt that fails once, and unmarked it fails again. *
6. Count the shell commands, and name the missing verb each group stands in for. A command a hand types ten times is a verb nobody builds. *
7. Name a script a hand writes twice as a capability asking for a home. A script written twice gets written a third time. *
8. Compare the chapter's first and last hours for errors and thinking length, so a tiring worker shows. A worker tiring unseen ships its last hour's mistakes. *
9. Rank by what repeats. One shape three times is a property of the machinery, and a shape seen once is weather. *
10. Name the cheapest change that stops a pattern: a check, a refusal, a gate, a prefill, then a sentence. A sentence where a check fits asks the reader to hold what a program holds. *
11. Record what goes well too, and name the practice behind it. A practice nobody names goes with the next change. *
12. Read every failed review on its own, and name the shape of the mistake beneath it. A failed review read as one more count hides the shape it shares with the next. *
13. Name a tool nobody calls, and a tool a hand calls and then corrects. The first costs context for nothing, and the second costs a round each call. *
