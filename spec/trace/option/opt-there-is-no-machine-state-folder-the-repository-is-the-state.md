## Mechanism

REMOVE THE PART AND SEE WHETHER THE NEED GOES WITH IT. The machine-state folder
holds four things, and version control can hold three of them.

- The record a walk is bound to becomes a branch. That is already an option on
  its own chart, [[opt-the-branch-is-the-record]].
- What happened becomes commits and notes. [[opt-claim-as-git-note]] and
  [[opt-claim-as-ref-cas]] are the two shapes.
- The declared roots become a committed file in the tree, like any other
  configuration.

## Two things kill the pure form, and both are files

A RAW NOTE MAY CARRY ANYTHING. It is captured mid-thought and never reviewed
before it lands, so a standing rule keeps it out of version control entirely.
Putting it in commits would publish whatever somebody happened to type.

THE READING IS THE SECOND, AND IT WAS MISSED WHEN THIS NODE WAS WRITTEN. The
reading file exists so a person with no lane can open what the walk owes them.
It is session state rather than corpus, so version control was never going to
hold it either.

SO THE HONEST VERSION OF THIS OPTION IS NOT ZERO FILES. It is TWO files, held
outside version control, and nothing else.

THIS SAID ONE FILE UNTIL COMPOSING FOUND THE SECOND. Drawing a line that took
both this cell and the drawn-surface cell produced a contradiction: one says
there are no plain files to open, the other stops drawing things BECAUSE a
person can open them. Keeping both true is what surfaced the reading.

## Why that is worth having on the chart anyway

THE WHOLE ITERATION IS ABOUT WHERE A FOLDER SITS. An option that removes the
folder is the null option for this delta, and the null option has the highest
value and the lowest proposal rate of any option there is.

IT ALSO SHRINKS EVERY OTHER PROBLEM HERE. Two files are easier to exclude from a
package than a folder whose contents grow. Two files are easier to hide in an
editor. Neither has an interesting answer to the branch question, because
neither was ever going to be committed.

## What it costs

THE WALK STOPS BEING READABLE AS PLAIN FILES. A blessed outcome of this
iteration is that a person can open the folder and read the reading loop.
Commits and refs are not that, and reading them needs a tool.

IT ALSO MAKES EVERY WRITE A VERSION-CONTROL WRITE. The iteration's own inputs
name the invariant that made this work in the predecessor: engine writes into
the repository are exactly four named mutations, so the tree stays clean after
anything else. Reaching that from here is a large piece of work, not a switch.

VERSION CONTROL IS THEN A HARD DEPENDENCY. Today a folder is a folder. Under
this option a tree with no repository cannot hold a walk at all.
