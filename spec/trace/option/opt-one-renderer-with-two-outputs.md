## The contradiction it dissolves

DELETING THE SECOND SURFACE MAKES THE SYSTEM SIMPLER AND LESS VERSATILE AT THE
SAME TIME. One rendering means one place to change and one thing to be wrong.
It also means the only way to see the walk is to have the editor.

SEPARATION IN CONDITION IS WHAT BREAKS IT. The duplication people actually pay
for is duplicated WIDGET CODE, not a second destination. Those were welded
together by accident and they need not be.

## Mechanism

ONE RENDERER OWNS EVERY WIDGET. There is exactly one implementation of the
state drawing, the log, the work table, the details and the trace.

AN OUTPUT ADAPTER DECIDES THE DESTINATION. The editor view is one adapter. A
standalone page, if anybody ever wants one, is another, and it adds no widget.

A SECOND DESTINATION THEREFORE COSTS AN ADAPTER. It cannot drift from the
first, because there is nothing to drift: both render the same widget code.

## Why it is not the surface we have today

TODAY'S TWO SURFACES SHARE NO WIDGET CODE. Every widget the mirror emits is
built and consumed inside one file and nothing outside it reads one. That is
measured, not assumed.

SO THIS OPTION IS NOT THE STATUS QUO RENAMED. Reaching it means moving the
widgets into one place first, which is the same work as the collapse.

## What it costs

THE ADAPTER BOUNDARY HAS TO BE REAL, and a boundary that exists only in
intention decays into a second renderer again. The cost is a discipline, and
disciplines need a check or they lapse.

## Not established

WHETHER A SECOND DESTINATION IS WANTED AT ALL. The owner has ruled the HTML
surface obsolete residue. If nobody wants a second output, the adapter split
buys nothing and the simpler option wins.
