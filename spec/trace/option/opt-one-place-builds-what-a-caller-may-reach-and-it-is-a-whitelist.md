## Mechanism

The door does not filter what is forbidden. It CONSTRUCTS what is allowed, in
one function every caller goes through.

THE PREDECESSOR PAID FOR THIS ONE. Three separate defects were traced to a
single cause on one day, and every one was fixed by deleting a variable as it
was found. The entry names that shape for what it is — "That is a blacklist,
and it grows only when something breaks."

TWO OF THE THREE FAILED SILENTLY, which is the part worth carrying. One suite
declined to run any file and exited reporting zero passed and zero failed,
which reads as green. Another inherited a live session's admission, so a test
asserting a refusal saw an admitted world.

WHAT IT BUYS. It converts an open-ended class of defect into a closed one,
which is that entry's own phrase for it.

WHAT IT COSTS HERE. An allowlist has to be complete on the first day or the
door blocks real work, so somebody must enumerate before anything can pass.
That is the same enumeration
req-the-reachability-guard-enumerates-exports-from-the-source already demands,
which is why the two belong in one candidate rather than two.

THIS IS THE OWNER'S OWN LAW, recorded in the predecessor, and it is the same
claim as req-absence-from-the-exemption-list-means-not-exempt reached from the
other direction.
