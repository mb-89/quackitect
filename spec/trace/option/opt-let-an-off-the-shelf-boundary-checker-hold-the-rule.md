## Mechanism

Nothing here is built. A checker already in the ecosystem is configured with a
rule saying which modules may import which capability, and it runs where the
other checks run.

WHY THIS IS THE STRONGEST OPTION ON THE CHART UNTIL IT IS ANSWERED. Two of the
six systems already compared do most of this. They enforce module boundaries,
they carry a baseline for a codebase that cannot comply on day one, and
somebody else maintains them.

If it covers the demand, this record is a reimplementation, and that is the
first kill criterion the gate named.

WHAT IT DOES NOT COVER, and this is the whole case against it.

- IT CANNOT REFUSE THE WRITE. Every compared system enforces at build or review
  time. This record's own dry well says the write-time half has no incumbent
  at all, so trimming to the environment trims that half away entirely.
- IT SHEDS THE AUTHOR. dependency-cruiser documents its comment field as not
  used in any rule logic, so the reason is decoration by construction. The
  reason being worth reading IS the differentiator, and this option gives it up.
- IT IS A DEPENDENCY IN THE GUARD THAT DECIDES WHAT IS LEGAL, which
  raid-asm-the-toolchain-here-enumerates-exports-with-no-new-dependency was
  written to avoid.

WHAT IT COSTS IF CHOSEN. One configuration file and a place to run it.
Genuinely almost nothing, which is why it has to be answered rather than
waved past.

THE HONEST READING. It is not the null option and should not be scored as one.
It is the SWEEP half bought instead of built, with the write-time half deleted.
