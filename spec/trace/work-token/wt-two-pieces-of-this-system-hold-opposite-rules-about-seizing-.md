## Why it stands

Two pieces of this system hold opposite rules about seizing a held network address, and one of them can destroy a session that is working.

The launcher script refuses outright. Its comment says whatever holds that address may be somebody mid-task, so it asks the person to clear it deliberately.

The server does the reverse. Finding the address taken, it kills whatever owns it, together with everything that process started, then tries again.

Only an accident of ordering prevents harm. The folder claim happens first, so a duplicate exits before reaching the killing code. A crash frees the folder claim while leaving the address occupied, and then the kill fires at whatever is listening.

Both rules cannot stand. Choose one and delete the other.
