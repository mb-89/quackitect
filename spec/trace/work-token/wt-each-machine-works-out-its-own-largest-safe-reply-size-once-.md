## Why it stands

Each machine works out its own largest safe reply size once, at start-up, and remembers it under a key that identifies that machine. Finding no entry, the opening sequence climbs a short ladder itself: double until a reply stops arriving whole, halve the step, keep the biggest that survived. Finding one, it reads the number and moves on. A guess is announced rather than applied quietly. On a cloud box the measured figure was more than six times the cautious default, and on this Windows machine no figure has ever been taken, so every reply of a whole session was chopped and handed back in slices.

## The owner refined it on 2026-08-25

THE KEY IS A CATEGORY WHERE ONE CAN BE FOUND, not one machine. A container in
the cloud is rebuilt for every session, so a key tied to that single instance
never finds its own entry and pays the ladder every time.

CATEGORIES THAT WOULD WORK are the kinds of place the system runs: a cloud
container of a given shape, a laptop under a given editor. Two runs in the same
category share the number.

MEASURING EVERY TIME IS ACCEPTABLE AND NOT PREFERRED. Where no honest category
key can be found, a cloud start-up may climb the ladder on each run. The owner
said plainly that this is fine and it is the second choice.

THE FIRM HALF, IN THEIR WORDS: any host that does not know its own limit
measures it during start-up. That part is not conditional on the key working
out.
