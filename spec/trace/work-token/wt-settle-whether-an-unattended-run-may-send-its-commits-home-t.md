## Why it stands

Settle whether an unattended run may send its commits home. The owner has ruled that it must, because a disposable box is reclaimed and a commit nobody sent is a commit nobody has. The engine rules the opposite way, without exception, and the guidance card carries both halves and says which one is unbuilt. Every unattended run therefore ends with work sitting on a machine that will be thrown away. The decision is the owner's: either the engine grows the exception with its own guard, or the guidance stops promising it and the handover moves to something else.

## When it comes back

THE OWNER HAS RULED, on 2026-08-28, and the ruling is that the run pushes.

Their words were that they hold no controls while the session runs in the cloud, so the push cannot be theirs to make. A rule written for an owner with a hand on the repository has no owner to hand it to here.

WHAT ACTUALLY HAPPENED. The lane refused on its clause. The push then went through the declared exception, with the owner's instruction logged as the reason, and seventeen commits reached the branch.

SO THE DECISION HALF IS CLOSED and the build half is not. The engine grows the exception with its own guard, and the guidance stops describing the push as something nobody has built.

UNTIL IT IS BUILT, every unattended run pays the same toll. A refusal, then the same exception, then the same reason typed again.

Ready when the record takes the git lane.
