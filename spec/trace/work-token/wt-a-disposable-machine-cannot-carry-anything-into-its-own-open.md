## Why it stands

A disposable machine cannot carry anything into its own opening look-back, so that step can only ever examine the minutes that just passed.

WHY, MECHANICALLY. Both the pending-item file and the call trail sit in machine-local storage that is never committed. A freshly cloned box starts each of them at zero. The window therefore opens at that box's very first call, always, and not by chance.

WHAT THE OWNER ASKED FOR is a mechanism, not another paragraph of advice. Some way to mark a position skippable when the instance meets a stated test, so a throwaway box passes it by with nobody having to remember.

WHY NOT PROSE. Telling an agent to walk past somewhere the router sent it contradicts how the walk works. The router decides; the agent works what it lands on. A skip has to come from the drawing or from a gate condition, or it is the agent overruling the router.

THE FIRST THING TO CHECK. The cloud method card already declares a session kind in its header. Whether anything reads that when drawing a route is unknown, and settling it may be most of the work.

THE LOOK-BACK IS STILL WANTED AT THE END OF A CLOUD RUN, where it carries findings home before the box is reclaimed. It is only the opening one that has nothing to work on.
