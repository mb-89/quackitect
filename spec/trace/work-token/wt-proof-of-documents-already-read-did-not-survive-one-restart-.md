## Why it stands

Proof of documents already read did not survive one restart, though it survived several others the same day. THE OBVIOUS EXPLANATION IS ALREADY DISPROVED: the proof is written to disk synchronously at the instant it is granted rather than on a timer, so a restart cannot outrun the write. The mechanism is there and a test covers it. What happened on that one occasion is unexplained, and nothing captured at the time can settle it now.

## When it comes back

ready when the reading is demanded again after a restart — capture the settings file and the session id at that moment, since the observation cannot be reproduced without them
