## Why it stands

The disk rule watches one folder, and it does not say so anywhere a reader would meet it.

WHAT IS UNWATCHED. Its coverage test demands a path under the engine directory. Four other parts of the product fall outside it.

- the test suite
- the editor plugin
- the tool-blocking configuration
- the repository root

One test file opens the disk directly and no rule sees it.

WHAT THE RULE DOES ADMIT. Its own description names exactly one gap, where code launches a separate process to do the reaching. The folder boundary is the larger gap and goes unmentioned.

TWO HONEST ENDINGS, and either closes this. Widen what the rule watches. Or write the boundary into the rule's own account of what it governs, so a reader stops assuming the ground is covered.

The four defects this was found alongside are all fixed; only the boundary stands.
