## Why it stands

The turn-ending guard reports a check still running that nothing else can find. Half the repair shipped: any record still saying it began is stamped ended when the engine starts, so a killed run stops haunting the folder. The other half stands. The guard reads only the folder and never asks the live table, so a record and a process are never compared. A thirty-minute window caps the damage rather than removing it.

## When it comes back

ready when the turn-ending guard can read the live job table without calling the surface over the network, since comparing a folder record against a running process is what the fix needs
