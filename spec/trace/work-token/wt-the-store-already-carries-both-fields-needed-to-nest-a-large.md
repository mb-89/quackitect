## Why it stands

The store already carries both fields needed to nest a large piece of work under its parts, and the editor reads neither. A parent field and a children field are declared on the item and the only code touching them splits paths. So there is no preview, no collapsing and no nesting on any surface. Planning a big item by breaking it into its parts is expressible in the data and invisible to every reader.

## When it comes back

ready when the editor gains a row-content preview, which the note names as the prerequisite and which is wanted on its own account anyway
