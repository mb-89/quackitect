## Why it stands

One step of the looking-back procedure cannot close on a cloud host. It wants the stored notes of a previous session, which live outside the project and are reachable only once that folder is declared. A fresh container declares none, and the file holding such declarations could not be created: the harness's permission layer refused the write, so the project's own rules never got a say. Two repairs are wanted. Say what an agent should do where the surrounding tool refuses that declaration. And give a container carrying no earlier session at all its own branch, so the step reports emptiness rather than failure.

## When it comes back

ready when the looking-back card's memory step is next edited, or when a run on a host that forbids writing engine dotfiles needs that step to close
