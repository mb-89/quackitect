## Scope

An hour of ordinary driving, with the clock read afterwards. Step three of the
demo drawing at `machines/demos.md`.

WHY A DEMONSTRATION AT ALL, when this pass line is instrument-readable. It is
the one of the three whose measure a program CAN take. A clock and a list of
interfaces answer it with no watcher needed.

WHAT THE PERSON ADDS IS THE DENOMINATOR. The clock reports on the interfaces
somebody modelled. Whether that list covers the interfaces anybody actually
touches is a judgment, and a reading over a list with holes in it proves less
than it looks like it proves.

## The hole this procedure exists to find

THIRTEEN BOUNDARIES ARE MODELLED AND TWELVE HAVE NO CALLS ATTRIBUTED TO THEM.
Nine were timed directly at the time of modelling. Since then, the instrument
can speak for one crossing: the agent harness reaching the entrypoint.

SO A CLOCK RUN TODAY WOULD REPORT ONE INTERFACE AND READ LIKE A VERDICT ON
THIRTEEN. That is the failure this procedure is built to catch, and it is why a
person is still owed on a measurable story.

## Approach

DRIVE FIRST, MEASURE SECOND, JUDGE THE LIST LAST. In that order, so the person
is not looking at the list while they choose what to do.

## Procedure

1. DRIVE THE MACHINE FOR AN HOUR of ordinary work. Not a scripted route — the
   work that was going to be done anyway.
2. WRITE DOWN, FROM MEMORY, EVERY BOUNDARY THAT WAS CROSSED. Do this before
   opening the modelled list, because reading the list first makes it look
   complete.
3. COMPARE that written list against the thirteen modelled interfaces.
   - PASS: every boundary the driver names is already modelled.
   - FAIL: any boundary they touched that nothing models. That is a hole in the
     denominator, and it is the finding.
4. READ THE CLOCK over the hour, per modelled interface.
   - PASS: every interface with calls attributed answers inside its bound.
   - PARTIAL, AND SAID AS SUCH: an interface with no calls attributed is not a
     pass. It is unmeasured, and the report says how many of the thirteen were
     actually read.

## What makes this pass or fail

PASS when the modelled list holds no holes the driver can name, AND every
measured interface answered inside its bound.

FAIL on either half. A clean clock over an incomplete list is a fail here, and
that is the whole reason this is a demonstration rather than a check.
