## The hinge

A DRAWN VALUE HAS TWO HONEST READINGS and nothing today says which one a field
is. It can be a SNAPSHOT taken when the question was answered, or a LIVE
reading recomputed whenever anybody asks. Both are legitimate and they behave
completely differently.

## What was measured, on the machine this round is redesigning

THE KICKOFF GATE REFUSED TO SIGN TWICE in one session, and the onboarding
retro was reopened twice, all for the same cause. Each refusal followed the
capture of a note during the walk, because the field listing what happened to
each pending note is drawn from the live inbox rather than answered once.

CLEARING IT COST A ROUND TRIP EACH TIME. Judging a note belongs to the retro
alone, and that retro was already signed, so it had to be reopened, worked,
and re-signed before the gate could stamp.

## Why it is graded plausible

THE FIX IS ALREADY SPECIFIED: a mechanical token runs its script when it is
asked, then settles. What is not specified is what happens to a settled token
when its source moves afterwards, and that gap is one ordinary step away from
reproducing the old behaviour.

## What closes it

EVERY TOKEN THAT CARRIES A DRAWN VALUE DECLARES WHICH KIND IT IS, in its own
frontmatter, and the engine honours the declaration.

A SNAPSHOT NEVER RE-OPENS ON ITS OWN. If a moved source should re-open it,
that is a dependency edge somebody wrote down, not a side effect of asking.
