## REOPENED, 2026-08-26 — there are TWO editors and only one of them is markdown

THE OWNER'S CLARIFICATION, and it is the whole answer.

- THE WORK TOKEN ITSELF is markdown. It opens in whatever opens markdown, and
  there is nothing to build.
- THE BUCKET EDITOR is where work tokens are put into buckets. That is something
  we have to build.

THIS ROW IS ABOUT THE SECOND ONE. Its measure asks somebody to narrow a list,
fold a group and move a row, and its body names four things with no precedent
anywhere in the tree: grouping rows into folding buckets, two panes side by
side, dragging a row between them, and a plus that mints from a template.

A MARKDOWN EDITOR DOES NONE OF THOSE. Closing this issue on the first ruling was
stretching it onto a row it does not reach, and a review caught that.

## The allocation, made rather than deferred

NO NEW ELEMENT IS NEEDED. Three that already stand carry it between them.

- THE SURFACE is drawn by the mirror, which draws every surface.
- THE CONTENT it draws comes from the work offer, which already publishes what
  is ready and what a position owes.
- A MOVE IS A WRITE and goes to the work store, which is the only element that
  writes a piece of work. Moving a row changes that work's PLACE, and placing is
  a function the store already implements.

WHAT THAT CREATES: a crossing from the mirror to the store that did not exist,
because no surface wrote a piece of work before. [[if-mirror-to-work-store]]
carries it.

## What is still open, and it is not the allocation

THE FOUR NOVEL AFFORDANCES ARE UNBUILT and the row's measure is a watched
attempt: one person, three tasks, no instruction, hesitations recorded. That is
an M7 measurement rather than an architecture one.

SO THIS STAYS OPEN UNTIL SOMEBODY WATCHES SOMEBODY USE IT. The structure now
says who builds it; nothing yet says it is usable.

## What the first closing said, kept because it was wrong in a useful way

THE RULING: a work token is a markdown file, and it opens in whatever opens
markdown.

SO THE ELEMENT IS NOT MISSING. It was never owed. The question this entry asked
— which element draws the work editor — has no answer, because there is no work
editor in the design.

WHAT SATISFIES THE ROW. Its demand is that somebody opens the thing for the
first time and needs no instruction. An editor they already use, opening a
format they already read, is the strongest answer available to that: no new
surface, so no new instruction.

WHAT STILL HAS AN OWNER. The COUNT per slot is drawn by the surface from a
figure the work offer publishes. Clicking it opens the file. Neither half needs
an element nobody has.

WHAT WAS WRONG WITH THE FINDING. It read the goal's word "editor" as naming a
surface this system would build. It named the one the person already has.

## What was missing, as it was first written

THE ROW IS ABOUT A SURFACE: a person opens the work editor for the first time,
narrows the list, folds a group and moves a row, with no instruction.

NO ELEMENT IN THIS STRUCTURE DRAWS THAT SURFACE. The front desk carries the
offer; nothing carries the editor.

## Why it is unaddressed rather than at risk

A RISK NAMES A CHOICE AND ITS COST. There is no choice here, because the thing
the row measures does not exist in the structure to be measured.

## Why the honest verdict is not "addressed by the mirror"

THE MIRROR DRAWS SURFACES, so it would be easy to say the row lands there. That
would be a label standing in for an allocation, which is the shape of failure
this milestone's reviews have caught five times.

NOTHING IN THE ELEMENT MATRIX ALLOCATES THE EDITOR, so nothing is claimed for
it.

## What it is waiting for

A MILESTONE THAT DESIGNS THE SURFACE. Until then this stands as a finding the
gate can see rather than a gap nobody wrote down.
