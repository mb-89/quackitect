THE SPLIT RULE IS THE MITIGATION and it is written into both records rather
than held in conversation.

One record holds what needs the owner's judgment. The other holds what is
already ruled and shaped like a defect. The renderer work is ruled, so it
belongs to the panel round and the UI record keeps only the argument.

THE DEPENDENCY WAS ALREADY DECLARED before the split, which is evidence the
overlap is real rather than invented: the UI record names the panel round in
its depends_on.

WHAT WOULD BREAK IT is either record quietly widening. The left-out list is
binding for exactly that reason.
