## Rationale

ELEVEN NODES ALREADY BELONGED TO THIS CLUSTER and it was never declared. Eight
functions under `fn-the-benchmark-run` name it, and the benchmark elements name
it as their group.

SO THIS NODE IS WRITTEN FROM WHAT THEY SAY, not from a fresh judgment. The
grouping already existed in the corpus; only its declaration was missing.

## What holds it together

EVERY MEMBER SHARES ONE TREE AND ONE RUN. Standing the throwaway tree, locating
the rewind point, refusing what that point cannot reach, concealing the history
for the length of the run, deriving what the walk cost, and filling the report
all read or write the same bound run.

THE COUPLING IS THE RUN ITSELF, which is why it is graded shared-data rather
than a call order. Nothing here decides for anything else; they all read the
same conditions and write the same account.

## Why it was missing

THE GUARD'S OWN COMMENT NAMED THIS CLASS. A function could name a group nobody
had declared, and nothing said so, because `cluster` was added to the swept
reference keys after these nodes were written.

Arming the sweep is what surfaced it, and it is the first thing the widened
key list found.
