## Rationale

COUNTING IS NOT DRAWING. `show-where-it-stands` puts the standing position in
front of a person. This function produces the number it draws, and the two
fail differently: a wrong count drawn beautifully is worse than a right count
drawn plainly.

NOBODY HAS EVER HAD THIS NUMBER. Every size question so far has been answered
by estimate or by feel, because a position's work tokens were fields in a
form and nothing counted them.

IT COUNTS RATHER THAN ESTIMATES, and the difference is worth stating. The
figure falls out of the work tokens that stand, so it moves when they move
and it needs nobody's judgment.

WHAT IT IS NOT IS A SIZE. The count tracks how finely a method card's author
cut their headings, so it says what a position owes right now and must not be
used to compare two records.

## Solution neutrality

COULD TWO HONESTLY DIFFERENT DESIGNS BOTH DO THIS? Yes. A tally kept as
statuses change, a count computed on every look, or a query. The statement
names none of them.
