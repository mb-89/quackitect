## Why this one

The fatal risk on this iteration's register is a ceiling that fails open and reports a confident wrong answer. This curve attacks that risk everywhere it appears rather than once.

## How it works

The run is drawn or named, and the draw records its seed. The content subtree is exported into a source whose newest commit IS the rewind point, so a request for anything newer cannot be formed. One visibility predicate decides what every path-taking verb may see, keyed on the binding. Each run issues one request that must be refused and records the refusal; a run whose forbidden request succeeded is discarded. The report is written as the walk goes, so a run that dies still leaves what it measured.

## What it costs

THE MOST EXPENSIVE CURVE IN THE BOX, and two of its cells may not be reachable.

MATERIALISING A HISTORY THAT GENUINELY ENDS at the rewind point is more than an export, and nothing has probed whether the lane's verbs can read from such a source at all.

THE SINGLE VISIBILITY RULE is a standing work token, not this iteration's to finish. Taking this curve makes that token a dependency rather than a neighbour.

WRITING THE REPORT INCREMENTALLY means a corpus node exists in an incomplete state for the length of a run, which the report requirement has to be phrased to allow.

## What it leans on

A work token this iteration does not own. An unprobed claim that a truncated history is readable through the lane. It leans hardest of the three on things not yet run.
