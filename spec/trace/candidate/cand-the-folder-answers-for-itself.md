## Why this one

IT IS THE REFERENCE LINE. The iteration's blessed goals, read literally and
built as written, with nothing added and nothing traded.

EVERY OTHER LINE IS PRICED AGAINST IT. A chart for a delta has no incumbent on
most of its rows, so something has to play the part, and the plainest reading
of the goals is the honest choice.

## How it works

ONE DECLARATION SITS AT THE CENTRE and everything else reads it. It says what
the machine-state folder is called, and which files inside it have a structured
door. Four consumers are generated from it rather than written beside it.

- The host's activation pattern, so a folder without it never wakes us.
- The lane's read exclusion, so only the three files with a door are withheld.
- The producing acts' exclusion, so no copy carries the folder out.
- The editor's own hide rule, so a person sees what they are allowed to see.

WHAT HAPPENS ON AN OPEN, END TO END.

- The host tests its declared pattern against the opened folder. No match, and
  nothing of ours runs at all.
- On a match the host starts the extension and hands over the folder it opened.
  We take that handle rather than searching for a root.
- The lane comes up rooted at that folder. Path resolution reads the same
  declaration to know what the machine-state folder is.
- The corpus is read once through the one reader and stamped, so every later
  question inside that pass is answered without touching the disk again.

### Before any of that, the first install

ONE COMMAND AND NO WIZARD. Nothing stands between a bare machine and a running
product, and the command installs whatever it needs itself. That is the plain
reading of the goals, the same way every other cell on this line is.

IT MEETS THE OPEN ROW CLEANLY. The install runs once and leaves an editor that
knows about us; every later open is the host testing a pattern. The two acts
are separate and neither needs the other to have thought about it.

WHAT IT DOES NOT INHERIT FROM ANY INSTALLER. The check that stops before a
partial install. Homebrew's own script aborts on architecture, operating system
and permissions before touching anything, then creates and chowns its tree, and
only then aborts on missing git. That is failing halfway, in the most-used
installer on the platform.

BUT IT DOES HAVE A MODEL, and this line said otherwise until 2026-08-19. A live
scan at the candidates gate found `mason.nvim`'s health check doing exactly what
the row asks: every check run, each tool named with its version, required split
from optional, the remediation command carried in the source, and nothing
changed. `flutter doctor` is the same shape. So the mechanism is copyable and
this line's cost for it was overstated.

### The seams, which are where this line is actually decided

TWO HOST MECHANISMS MUST NAME ONE FOLDER. The pattern test decides WHETHER we
start; the handover decides WHAT we hold. They are separate host features and
nothing forces them to agree. If a workspace has several folders, the pattern
can match one while the handover offers another.

THE SHARPEST SEAM IS THE EDITOR'S HIDE RULE AGAINST THE READABILITY GOAL. The
declaration generates a hide rule, and this line ALSO wants the person's editor
to show the machine state so the drawn surface can stop drawing it. Those pull
opposite ways.

IT RESOLVES, AND THE RESOLUTION IS THE ITERATION'S OWN GOAL. Hiding is split by
FILE rather than by folder. The three files with a structured door are hidden;
the rest of the folder is shown. So one declaration serves both, because it
names files and not a directory.

THE CLUSTER SPLIT AND THE OPEN ROW MEET CLEANLY. Splitting the bootstrap puts
`bring-the-product-up` in a cluster of its own, and that function is exactly
what the open row is about. The split is a spec change with no code behind it,
and it makes the open path nameable.

THE CORPUS READER TOUCHES NOTHING ELSE HERE. It answers questions about trace
nodes, which live in the tree rather than in the machine-state folder. It is on
this line because the iteration demands it, not because the folder question
needs it.

## What it costs

ROUGH CHECKS ONLY, AND TWO OF THEM ARE ALREADY MEASURED.

- PERFORMANCE, MEASURED. A full corpus read is 359 ms over 1097 nodes, and the
  stamped repeat is 11 to 13 ms. The open bound is five seconds. The corpus is
  not what threatens the bound; the host's activation timing is.
- THE PRODUCING EXCLUSION IS ALREADY BUILT, MEASURED. `travels` withholds the
  folder by name at any depth and `package.ts` shares that list. The cost here
  is the test the M2 gate asked for, not the mechanism.
- MAKE, REUSE OR BUY. The activation pattern is BUY, one line in a manifest the
  host already reads. The exclusion filter is REUSE, unchanged. The declaration
  and its four generators are MAKE, and they are the bulk of this line.
- THE STOP-BEFORE-PARTIAL CHECK IS STILL WORK TO MAKE, and it is cheaper than
this line first said. A named implementation exists to copy, so what remains is
building it rather than inventing it.

THE STALENESS CHECK IS NEW WORK NOBODY ASKED FOR. Generating four consumers
  means a check that each is current, and that check has to run somewhere a
  person will see it fail.

FAILURE MODES, AND HOW EACH SHOWS ITSELF.

- A generated consumer drifts from the declaration. Silent, and the staleness
  check is the whole answer to it.
- The pattern matches a folder that is not a project. Loud, because the code
  that runs next looks for the machine state and stops.
- The two host mechanisms disagree about which folder. Silent and the worst of
  the three, because the lane comes up rooted somewhere nobody chose.

TESTABLE, and each demand has an obvious shape. Open a folder with no machine
state and assert no byte was written. Package a tree and assert the folder is
absent. Assert each generated consumer matches the declaration.

## What it leans on

THE HOST IMPLEMENTS A CONTENT TEST AND RUNS IT EARLY. Both halves are the
host's to change, and neither is ours.

THE MACHINE-STATE FOLDER IS RECOGNISABLE FROM OUTSIDE, by a name a pattern can
match. That is a marker by another name, and the M2 comparison noted we claim
not to need one.

THE THREE DERIVED CONSUMERS CAN BE GENERATED. An editor's settings file and a
packaging manifest each have their own format, and a declaration only helps if
something can write into both.

A PERSON HAS AN EDITOR OPEN. The drawn-surface cell hands the stored half to
it, which is no answer at all on an unattended machine.

ONE COMMAND CAN RUN ON THE TARGET MACHINE, and the runtime it installs is one
the engine runs on. The second half is already in the register as an
assumption rather than a fact.

THE PATTERN TEST AND THE HANDOVER NAME THE SAME FOLDER. Unprobed, and the seam
above says why it matters.

## What a probe already settled for this line

THE COLLAPSE COSTS THE EXCLUSION NOTHING. Probe P3 measured that every producing
act withholds the folder by name at any depth, and that the two producing paths
already share one list. So the exclusion cell here is cheaper than it was
argued to be.

THE CACHE IS NOT WHAT MEETS THE CLOCK. Probe P2 measured a full corpus read at
359 ms against a five-second bound. This line takes the cache for agreement and
for repetition inside a pass, not to make the open fast.
