# Why

The findings form a matrix. Each chapter is a column, and ten rows cross it:
five questions about what happened, and five kinds of change that answer
them. One reader fills one column, so the readers run side by side and each
holds one chapter whole.

## 1. The chapter's lines alone

A reader wandering past its chapter reads what another reader covers, and the
two report the same thing twice. The engine hands each reader its lines, so
the columns stay apart.

## 2. One verb reads the lines

A retro reads its transcripts through prompts, faults and commands. A reader
writing its own parser reads each chapter its own way, and the columns stop
comparing. So `retro read` hands every reader the same rows, with the file and
the line each stands on.

## 3. The starfish questions

Start, stop, keep, more and less come from the starfish retro. They ask about
what went well as much as what went wrong. A retro asking only for faults
throws away the practice worth keeping.

## 4. The five improvements

A question names what happened, and an improvement names what changes. The
five kinds cover every place a change lands in this project: the engine, the
guidance, a route, the code and the tools around it. A finding fitting none of
them says a kind is missing.

## 7. Questions and changes

A change nobody can trace to an event gets argued from taste. A stop finding
and the mechanize finding answering it name each other, so the report shows
why each change stands.

## 8. Scripts climb or go

A script a hand writes ad hoc is a sign of a missing verb or a missing rule.
The retro reads each one and decides where it goes. It climbs toward the
official scripts or the engine, or the guidance changes so no hand needs it
again.
