# Why

The owner decided this for the target design of the migration, and the decision
is final. While the index or the engine stands down, the cage refuses the calls
it guards. An agent reads this note before it asks again.

## 1. A loud fault gets fixed

The owner wanted a fault loud. A session passing every call while its engine
stood down looked healthy, so nobody fixed the engine until the damage showed.
A refusal names the fault on the first call, and a person fixes it then.

## 2. What it reversed

v4 ruled that a box with no engine was neither guarded nor blocked. The target
design reverses that ruling, and the cage blocks a box with no engine.

## 3. What it gave up

A session on a box whose engine will not start does no work until a person
starts it. The refusal names the command that starts it, so the wait costs a
read and a command.

## 4. What would make it wrong

A down engine the person cannot bring back, on a box where the work matters more
than the cage. A cloud box nobody watches is the case to measure: a refusal
there must reach a person, or the branch stalls in silence.

## 5. What still passes

The bridgehead passes every call while the server stands down, and says so once.
The index falls back to reading the files. The migration changes these
chapters:
