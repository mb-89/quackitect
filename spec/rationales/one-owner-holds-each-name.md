# Why

The owner decided this for the model, and the decision is final. The index owns
every value, and each name has one provider and a built-in value. The index adds no
name at runtime, and a broken catalog stops the start. An agent reads this note
before it asks again.

## 1. What it measured

The sidebar badge and the work tab's brackets counted the open tickets in two
places, and the two numbers disagreed. The fix reached eleven files across two
languages. The design input tells the chain, in
[[spec/design_input/the-index-holds-the-model#why-one-model]]. A value
computed twice drifted, so the model gave each value one place.

## 2. Why the catalog stood fixed

A reader saw the whole catalog, so a check at start proved every name had a built-in value and one provider. A name added at runtime escaped that check. A family
such as `ops/` stood in the catalog once, and its keys stayed inside it.

## 3. What it gave up

A module could no longer answer a name it had not declared. So a value for one
screen cost a declaration and a built-in value. A second calculation stood as a module type of its own, and the wiring picked
one of the two, per [[spec/rationales/modules-stay-local]].

## 4. What would make it wrong

A value whose readers needed two meanings under one name. Two readers then fought
over the provider. The answer was two names, and a ruling that forced one name
would be wrong.
