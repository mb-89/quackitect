# Why

A retro reads a window that ends before it starts. Work lands between the
window's end and the reading, and the tree itself moves under the findings.
So every class meets the tree once more before it earns a ticket.

## 1. The tree as it stands

This retro read thirteen days, and its own session fixed a dozen of the
faults it names. A ticket minted for a fix already standing costs a hand the
reading, the check and the close.

## 2. Fixed, and where

A class whose fix stands names the place. The next retro then measures the
rate again, and the name says what to look at where the rate holds.

## 3. Past, and why

A class the tree moves past says what moved it. Silence there reads as an
oversight, and the same class forms again next retro.

## 4. The ask a ticket carries

A ticket the retro mints reaches a hand that stands outside the window. So
the class hands it the gain, what breaks without it, and a done_when a
command decides.

## 5. A standing rule

Where the rule already stands and the defect keeps coming, writing the rule
again changes nothing. The test-first rule stands in the code guidance, and
the audit still found code landing without a test. So the fix names the check
that holds the rule, and the ticket carries that check.
