# Why

The owner decided this for the model, and the decision is final. Go held the
core, and JavaScript stayed where the host ran JavaScript alone: the extension
and the hook module. Linux and Windows behaved the same, over loopback TCP and
the standing file, and CI ran both. An agent reads this note before it asks
again.

## 1. What it measured

The tree ran a fact in Go and again in JavaScript, and the pairs disagreed, as
[[spec/design_output/migration#the-duplications]] lists. One language for the
core left one copy.

## 2. Why loopback TCP

A Unix socket and a named pipe each worked on one platform, so each doubled the
code and the tests. Loopback TCP worked the same on both, and the standing file
named the port.

## 3. What it gave up

A contributor fluent in JavaScript alone read Go for the core. A port on
loopback was reachable by every local user, so the standing file carried a
token the peers checked.

## 4. What would make it wrong

A host that ran the core in JavaScript alone, such as an editor with no way to
start a binary. The core then needed a second build, and the ruling bent there.
