# Why

The matrix holds every finding, and no reader takes it in at once. A retro
changes the machinery through a handful of classes. So the report opens on
those, and the matrix stands below as the evidence behind them.

## 1. One defect, one cause

A lesson minted per occurrence schedules the same fix ten times, each reading
as a good idea alone. The same shape across chapters no reader shares is a
property of the machinery, and one class names it once.

## 2. Category, defect, fix, pattern

The category places the fix: the engine, the guidance, a route, the code or
the tools. The categories come from the improvement rows, so a new row brings
a new category with no change to the report.

## 3. A pattern the engine counts

A rate a hand estimates drifts with the hand. A pattern over the record
counts the same way twice, so the next retro compares two rates on one scale.
For details, see [[spec/rationales/effect]].

## 4. Every finding answers

A finding with no disposition drops out between the matrix and the fixes,
and nobody can tell whether a hand weighed it. So every finding joins a class
or carries its reason to drop, and the engine refuses a retro leaving one out.

## 5. Promotions

A script climbs toward the official scripts and the engine, and a sentence
climbs toward a check. The report lists each promotion, so the ladder shows
where the retro moved work out of a hand's reach and into the machinery.

## 7. The engine counts

The rate is a count of pattern matches per active hour of work. The engine
computes it and checks the dispositions, so a hand writes the judgment and
the engine does the arithmetic.

## 9. One ticket per class

An improvement written only into a report is one nobody schedules. So each
class gets one ticket, small enough for a stranger to act on. The class names
its ticket, so the next retro finds it.
