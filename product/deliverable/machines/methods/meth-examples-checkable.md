## Situation
One example thread runs the whole machine; the stages before scripting live INSIDE stories and use cases - an example node mints only when scripted (M6) or wrapped (M7).

## The lifecycle
- intent (M1): the to-be world and validation signals - germs, nothing minted.
- formulated (M2/M3): story slides, use-case paths, requirement boundary cases, quality scenarios - roles, not artifacts.
- exercised (M4/M5): the formulated set walked analytically through candidates and the baseline.
- scripted / checkable (M6): a defined procedure + pass criterion. The procedure kind is the verify_method taxonomy: a test run, an FEA load case, a tolerance-stack sheet, an interference check, a gauge procedure, a stranger's read for documents.
- assertive (M7): the check wraps the example - the example teaches, the check defines pass/fail, evidence records the run. Regression authority accrues where re-running is cheap (tests, simulations, calc sheets, cold reads); one-shot physical checks stay inspection evidence.
- demonstration (M8): killer use cases run end to end; story slides' evidence_refs point at the runs.
- catalogued (M9): the example browser is a projection, never a hand-maintained gallery.

## Rules
- Stories are never executable; the example node is the runnable derivative, linked both ways.
- Edges: exemplifies (example to requirement), exercises (against candidates), demonstrates (use case, end to end).
