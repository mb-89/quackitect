## To-be world
The owner redlines a machine drawing over morning coffee; the change IS the process change - no code, no prompt edits. A session boots, names its project, and the machine hands it packets. On parallel branches two agents hold two states of one iteration, both tokens visible side by side on the board. Long work runs in the background; no call blocks past a second. When a gate ripens, the offer surfaces on the board (later the phone); one bless advances the machine, and the commit lands right after - never in between. A new iteration opens with the retro: the inbox drains, one generic log query shows where the process rubbed, and the kickoff handover carries the whole plan in one brief.

## Goal system
- G1 executor: the drawn machine runs - tokens, joins, parallel activation, sub-machine seeding.
- G2 owner control: gates as states, board visibility, one-brief handovers.
- G3 working rhythm: 1s interactive law, updates on submit, milestone-scoped verification, gate-bound commits.
- G4 self-improvement: retro-first onboarding fed by the full call log.
Conflicts, named: enforcement vs agent flexibility (ruled for enforcement); parallel speed vs serial adjudication (the offer queue serializes owner attention); iteration scope vs engine-law breadth (split triggers armed on the build plan).

## Moore pitch
FOR a solo engineer driving AI agents on serious projects, WHO needs day-scale iterations to stay controlled without babysitting, quackitect v2's SE machine IS a process engine THAT compiles hand-drawn state machines into mechanically enforced agent workflows; UNLIKE prompt-discipline harnesses that ask the model to behave, the engine refuses illegal moves at the tool boundary.
