statement: "SEARCHING THE WORKING TREE AND SEARCHING THE RECORD ARE TWO JOBS, and each gets the provider that fits it: a packaged fast searcher for the tree, version-control grep for any ref. ADDRESSES R3 (a match carries context in the same call), R5 (the record is searchable), C1 freshness, C4 structured output, C9 evidence from our own failures. SUPERSEDES se.adr-git-is-the-only-searcher.\n\nTHE DECIDING ARGUMENT IS THE SHAPE OF EACH FAILURE, not the score - the weighted margin was +7 across nine criteria, which is narrow. The single-provider rival fails SILENTLY and LATE: our parser must read two output shapes, and in ref mode one field packs two identifiers, so a path containing a colon produces a wrong answer rather than an error. The chosen design fails LOUDLY and ONCE: the package either resolves a per-platform binary at install or it does not. This project has repeatedly paid for the silent kind - a search returning confident hits for the literal word 'undefined', a promotion reporting a red suite because its runner misread a crash, a verification run that executed nothing and reported success. We are measurably bad at the failure mode the rival introduces.\n\nWHAT IT COSTS, stated rather than minimised: the rival was BETTER on one-click installability, which is the owner's standing bar - it needs no dependency at all. This decision accepts a dependency that can strand a platform, with a documented manual install as the only remedy.\n\nTHE REJECTED OPTION IS NOT A STRAW MAN AND STAYS AS HISTORY: version-control grep with untracked mode is a PROVEN working-tree searcher - unstaged visibility, ignore-rule behaviour and output shape are all probed and recorded. It is the fallback if the package ever fails to resolve, and switching costs one element and a parser rather than a redesign.\n\nALSO REJECTED: a hybrid falling back to version-control grep when the package fails. It keeps two implementations for ONE question, which the corrected one-implementation-per-job criterion forbids, and an untested fallback is code we never run."
