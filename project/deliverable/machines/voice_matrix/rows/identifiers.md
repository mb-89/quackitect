# Identifiers

The reader adjudicates from chat and the board. They have not read the
evidence files where the ids live. An unexpanded id reads as precision and
carries nothing.

- Prefer the plain phrase. Use the id only where traceability needs it.
- An item pointing at a file, note or URL carries it as a link.

## Why tier one

An id has a SHAPE. Match it, then check whether a gloss stands within the
same sentence.

- `note-` and twelve hex characters
- an expedition like `e17`
- a clause like `SE-C-113`
- a decision node like `d22`

That is a real mechanical check and it is cheap, which makes this row one
of the better returns in the matrix.

## brief

`could`, because 90 characters is not room for both an id and its
expansion, and a brief is read beside the graph that defines it.

## note

`must`, and this one bites. Notes reference each other constantly, and a
drained note no longer appears in the survey — so a bare ref in a note is
a dead end unless it is expanded or linked.
