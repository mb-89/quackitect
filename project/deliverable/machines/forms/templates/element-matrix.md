# element-matrix

A READING with one click of judgment per owed cell.

## What the field declares

```
- name: allocation
  template: element-matrix
  of: element
```

## What is computed

Everything drawn, from three node sets, on every look:

- ALLOCATION off the element nodes' `implements` — with the holes named:
  functions nothing implements, elements implementing nothing.
- OWED CELLS off the flow crossings: a flow produced by a function in one
  element and consumed by a function in another crosses that boundary, and
  the pair owes an interface.
- THE DECLARED SIDE off the interface nodes — each cell shows the
  interfaces naming it, and an interface on a pair no crossing demands is
  flagged the other way.

## The one click

An accented cell owes a contract. The NAME button mints the interface node
skeleton server-side — source, destination, and `carries` prefilled with
the crossing flows; the statement and form arrive as comments, and
answering them is the authoring. A standing node is never overwritten.

## What the section stores

Only the argued spread — why a function is implemented in several places,
where that needs saying. The matrix itself would drift the moment a node
moved, so it is never written down.
