# Evidence form / decompose-structure

## current_situation

The delta decomposes into ONE new element, el-arrival, in the existing group the-bootstrap.

It implements all seven functions of the-arrival cluster. No existing element was extended, and no function is left unimplemented.

el-entrypoint is its sibling and four of the seven functions are implemented in both.

## elements

## allocation

THE MATRIX IS COMPUTED FROM el-arrival's `implements`, and the spread it draws is the argued part.

ALL SEVEN FUNCTIONS LAND ON ONE ELEMENT, and that is the decision worth defending. The alternative spread was three elements — a repo-preparer, a lane-raiser and a reporter — and it was rejected for one reason: every one of them would have to run in the same process, in a fixed order, with the next depending on the last having succeeded. That is a sequence, not a boundary, and drawing element boundaries through it would invent interfaces nothing crosses.

NO BOUNDARY-CROSSING CELLS ARE OWED WITHIN THE DELTA, and the flows say so. Of the six, five move between functions inside el-arrival: flow-arrival-request, flow-repository-refs, flow-runtime-verdict, flow-placed-cage and flow-arrival-account. Only flow-live-lane leaves the element, and its consumer is the agent rather than another element — the lane it names is el-walk-engine's, already interfaced and not this delta's to redraw.

THE HOLES, NAMED RATHER THAN LEFT FOR THE MATRIX TO FIND. No function in this cluster is unimplemented. No element implements nothing. The one asymmetry is that el-arrival implements seven functions while sharing four of them with el-entrypoint, which the matrix will show as a duplicated implementer rather than as a hole.

THAT DUPLICATION IS THE REAL ALLOCATION FINDING. It is not a spread this iteration chose; it is one it created and filed. The correct spread is a fifth element holding the shared four, with el-arrival and el-entrypoint each implementing only what is genuinely theirs — the hand-over on one side, the launch on the other. That is written into raid-iss-two-entrypoints-place-the-cage-and-nothing-compares-them as its repayment, and it is deliberately not done here, because folding el-entrypoint changes the unattended start path and deserves its own verification.
