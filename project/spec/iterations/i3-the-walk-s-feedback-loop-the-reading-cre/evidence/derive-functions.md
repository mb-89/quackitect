## neutrality

The test this state sets: could two honestly different designs both do this?

YES FOR ALL SEVEN, checked one at a time.

- The reading credit says the credit survives a reload. It names no file, no process id and no hash. This build uses all three; a daemon or a content-addressed store would satisfy it equally.
- The reopen frontier says where the walk stands. It names no token set. A design holding a single position and a queue of owed steps would satisfy it.
- The placeholder guard says entry refuses. It names no flag on a compiled machine. A design that checked the drawing on the way in would satisfy it.
- The field trim says a size may drop a question. It names no key called omit. A design with a separate per-size form file would satisfy it.

THE ONE I CALL BORDERLINE, and I would rather name it than let it pass. req-the-size-is-read-by-one-extractor says ONE extractor, which is closer to a structure than a behaviour.

It survives because what it protects is that the validated choice and the recorded choice cannot disagree. One extractor is the argument for that, not the only mechanism - a design running two and comparing them would satisfy the requirement, and would be worse. The requirement is honest about which of those it wants.
