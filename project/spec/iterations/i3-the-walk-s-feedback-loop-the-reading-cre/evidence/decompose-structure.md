## anything_else

THE ESCALATION QUESTION, asked properly rather than answered by relief.

I looked for a reason this should be a major, and the honest candidate is the field trim. It adds a key to the evidence field type and a filter to the compiler, which is new capability rather than a repair.

It stays a minor because it adds no element, no interface and no function. [[el-method-compiler]] already compiles a size into a machine; deciding which questions that machine asks is what compiling a size MEANS. The trim makes the compiler do its stated job with one more input from the row.

WHAT WOULD HAVE MADE IT A MAJOR: a separate per-size form store, or a new element deciding form shape. Both were possible designs and both were rejected in favour of the compiler doing it, precisely because the compiler already owns that responsibility.

I record this because the judgment is close enough that a reader deserves to see it made rather than assumed.
