# Evidence form / model-the-boundaries

## current_situation

The elements existed and the neighbours existed. The edges between them did not, and that is what this chunk closes.

EVERY STANDING INTERFACE NODE WAS ELEMENT-TO-ELEMENT. Forty of them, all internal. The OUTSIDE boundary — where the product meets something it does not own — had never been drawn, which is exactly what the vision said in its own words.

## built

THIRTEEN INTERFACE NODES, one per element-to-neighbour crossing that carries traffic. All eleven neighbours are covered.

THE FOUR THE MEASUREMENTS NAME:

- if-agent-harness-to-entrypoint — the lane's door, and the busiest outside edge in the product. Bound 1 second, currently missed: 1834 of 8424 calls over it, worst single answer 33,461 ms.
- if-engineer-to-mirror — the only place a person touches the product. The look is inside its bound at 113 ms; the ACT is the half that fails, and it fails silently.
- if-test-runner-to-toolchain — the battery. Bound honestly NOT one second.
- if-account-to-git — commits. Bound 1 second, ordinarily met.

THE REST: if-vscode-to-mirror, if-walk-engine-to-web, if-record-store-to-git, if-account-to-obsidian, if-record-store-to-origin-remote, if-bootstrap-to-toolchain, if-mirror-to-output-tools, if-satellite-supervisor-to-cloud-host, if-satellite-supervisor-to-peer-machine.

EACH CARRIES A BOUND, and the bound is argued rather than defaulted. Five say ONE SECOND. Six say NOT one second and say why. One says NONE, because nothing is served across it. That spread is the point: a single flat rule applied to all thirteen would be unkeepable at six of them and would quietly stop meaning anything at the rest.

THE PAIR THAT PROVES THE MODEL EARNS ITS KEEP: if-account-to-git and if-record-store-to-git are the SAME NEIGHBOUR with different bounds. Commits meet a second; raising a worktree copies and cannot. One node for both would give a bound that is either wrong for commits or unkeepable for trees, and would hide which half a breach came from.

THREE FINDINGS FELL OUT OF THE MODELLING ITSELF, which is the argument for doing it at all:

- if-vscode-to-mirror is where the falsified assumption lives. Drawing the person and the editor as ONE edge is what hid a defect living between them, and it had three recorded sightings before anybody wrote the edge down.
- if-satellite-supervisor-to-cloud-host is why notes never travel. That was a ruling in prose with nowhere in the spec explaining it; now it is a property of a crossing.
- if-test-runner-to-toolchain exposes that the engine has no file-to-test mapping, which is why every run this session chose the full battery.

## follow_up

THE DENOMINATOR NOW EXISTS. Both pass lines take a share over the set of modelled interfaces, and that set is thirteen nodes rather than a question.

WHAT UNBLOCKS: bind-the-bound-per-interface can now attach each bound mechanically, and breaches-reach-the-reviewer has something to enumerate.

ONE THING TO WATCH. if-satellite-supervisor-to-peer-machine carries no traffic today. A measured zero there means nobody used it, never that it is fast, and the node says so rather than leaving a later reader to infer it.
