## prior_art_positioned

THREE COMPARISONS WERE MADE, AND ONE WAS NOT. Saying which is which is the point.

GIT WORKTREES — what we are removing, and it is the fairest comparison because we have run it for three weeks. WHAT IT DOES BETTER: genuine parallel checkouts over one object store, at zero fetch cost between them, with no risk of one record's edit landing in another's tree. That is real and we are giving it up. WHAT OURS SHEDS: the question of which tree answers a path. With one tree there is nothing to resolve, so the class of bug disappears rather than being guarded against.

OUR OWN v1 — checked at ref main rather than remembered. It kept all fifteen iterations as folders on one branch, `spec/iterations/i0001_reporting` through `i0015_mobile_adapter`, each with an archive.md. Its engine carried 2 worktree mentions across the whole Go product against 159 across 26 TypeScript files here. WHAT IT DOES BETTER: it simply worked, for fifteen iterations, with no resolution layer at all. WHAT OURS SHEDS RELATIVE TO IT: nothing — we are returning to it. THE FINDING THAT MATTERS MORE: v1's own decision file says the opposite of v1's practice. `spec/decisions/versioning.md` line 3 reads "An iteration is a git branch or worktree... Parallel iterations run as worktrees." A decision nobody exercised for fifteen iterations propagated into v3 and got built.

GITHUB'S PUBLISHED GUIDANCE on repository size, read 2026-08-16: "We recommend repositories remain small, ideally less than 1 GB, and less than 5 GB is strongly recommended." Ours is 26.63 MiB compacted. WHAT THIS SETTLES: storage was never the constraint and the archive can stay on disk indefinitely. The constraint was always the working tree, and nobody had measured it.

THE COMPARISON NOT MADE, stated rather than left blank: trunk-based development as an industry practice, and the monorepo tooling built around it. I did not fetch a primary source for it this session, so nothing here rests on it. It would likely strengthen the case rather than weaken it, which is exactly why it should not be asserted without the source.
