# i36-the-harness-is-not-claude-measure-what-e

## Goal

The harness is not Claude: measure what every host actually gives us, close the five breaks the measuring found, and make the lane say which harness it is talking to.

## Rough vision

FOR THE AGENT THAT FIXES ITS OWN HARNESS. The whole brief is committed at project/spec/harness-portability.md, with its outward scan and citations at project/spec/references/ref-agent-harness-portability-2026.md. READ BOTH BEFORE DESIGNING. Read them in parts: the report is over 20 KiB and on Copilot CLI a tool result that size is written to a temp file and handed back as a path, which is itself one of the findings.

WHAT WAS FOUND, IN ONE PARAGRAPH. The harness coupling is not one problem but three, and they have different cures. A mechanism resting on a CONFIG SLOT is a file away, and nearly everything already built is that tier. One resting on a HOST FEATURE exists or it does not. One resting on THE AGENT CHOOSING TO COMPLY does not port at all: it varies by model and it fails silently, which is what runs worse feels like from outside. The reading proof, the pull-first rule and the serial-call rule are all in that third tier.

FIVE BREAKS, EVERY ONE ARITHMETIC RATHER THAN OPINION.

- se_pull's own description is 2,425 bytes against Claude Code's 2 KB truncation, so 377 bytes of the explanation of read, fill, choose, do and wait have never reached any model on any host. This one is broken on the HOME harness.
- Boot's fourth document goes over Copilot CLI's 20 KiB offload threshold: refusals.md weighs 21,675 bytes on the wire, so the model is handed a file path and then asked to quote three phrases out of it.
- craft/software.md is 27,130 on the wire and retro.md sits at 19,460, one paragraph from crossing, with nothing measuring any of it.
- AGENTS.md projects 43,008 bytes against Codex's 32 KiB project_doc_max_bytes, so a third of it is never read there.
- Five documented Copilot built-in tools are outside the cage, and bash and rg are the two that matter: the whole lane, available beside the lane, unlogged.

THEY SHARE ONE CAUSE. Every number is one this repository already produces, measured against a threshold the host already documents, and nothing in the tree compares the two. The missing mechanism is one preflight check, not five fixes.

THE FINDING THAT MAKES THE REST MEASURABLE. The engine does not know which harness is calling it, and it is handed the answer on every connect and throws it away. MCP initialize carries clientInfo; engine/mcp.ts declares the field on TransportRequestMetadata and on RequestContext and copies it in the adapter, the initialize handler never reads msg.params.clientInfo, and both transports call handle(msg) with no metadata at all. The call log's record carries no client field. So every refusal rate and every slow call in the whole log is pooled across harnesses, and the complaint this iteration exists to answer cannot be shown or closed.

CAN ONE CONFIG FORMAT SERVE EVERYTHING? PARTLY, and the line is clean. VS Code already reads CLAUDE.md, .claude/rules, .claude/agents, .claude/skills and .mcp.json BY DEFAULT with no setting to turn on, and .mcp.json is genuinely shared across Claude Code, Copilot CLI and VS Code 1.118 and later. So the declarative half is nearly free, and cage/mcp.json and cage/copilot-mcp-config.json are byte-identical duplicates today that can collapse to one file carrying type stdio.

HOOKS ARE THE HALF THAT DOES NOT PORT. chat.useClaudeHooks exists, defaults to false, is preview, and is declared disallowConfigurationDefault so it CANNOT be committed as a workspace default. Worse, VS Code SILENTLY IGNORES HOOK MATCHERS, and two of this repository's four hook entries then misfire: the PostToolUse entry matched WebSearch fires the web-search recorder after EVERY tool call and writes false records into the feed, and the two SessionStart entries both fire so the start notice runs twice, the second claiming a compaction that did not happen. VS Code also maps 8 of Claude's roughly 31 hook events and drops the rest with no warning.

THE STRUCTURAL MISMATCH IS BIGGER THAN ANY BREAK. An iteration is ruled at roughly a day of agent work. The Copilot cloud agent caps a session at 59 minutes and one pull request, over one repository, on a filesystem it destroys at the end. The last is fatal and is not about time: the walk's whole memory is .se/, so a record there cannot be resumed, only restarted. Deciding what that surface is for is milestone seven and it is a decision rather than a build.

THE EIGHT MILESTONES ARE PART 10 OF THE REPORT and they are not repeated here, because a copy goes stale. In order: the lane learns who is calling it; host limits become data that preflight checks; the five breaks close; one config format for what is declarative; the matcher hazard is removed rather than documented; the conformance statement lands on if-agent-harness-to-entrypoint; the cloud agent's role is decided; and the installer is built. A NINTH GOES AHEAD OF ALL OF THEM, added by Part 11 after the owner said a Copilot run had not been caged: THE VS CODE CAGE IS INERT. The extension hands workbench.action.chat.open the COPILOT CLI's tool names, on a host whose tools are called create_file and replace_string_in_file, so an exclusion list of names VS Code does not have excludes nothing. The play button tries chat FIRST and only falls back to the correctly-caged CLI. So rule 1 has been advisory on a host in real use, every native write taken there is absent from the call log, and raid-asm-the-cage-holds-so-every-write-passes-the-lane is a standing assumption that has been failing. That is not a portability improvement and it goes first.

THE OWNER RULED ON 2026-08-18 AND PART 13 CARRIES THE WORDS. Install-time generation is ADOPTED: RUNME installs the extension and the generated documents, and the shims are emitted from what it finds, copying the pattern from spec-kit or BMAD. So milestone eight is a BUILD rather than a question. The agent-agnostic source stays in project/guidance/ and placeProtocol is already that shape for three targets. The verb count is ruled too, and Part 14 has the arithmetic: eight bundles take 34 verbs to 19, which takes the headroom under Cursor's 40-tool ceiling from 6 to 21. Two things are not in question and were not before the ruling: refusals travel as isError results carrying clause and remedy, and se_pull is the single-tool loop. The scan names both as best practice, and an installer changes neither.

WHAT NOT TO REBUILD. cage/copilot-cage.json is the Copilot CLI cage as data, verified against a live CLI 1.0.76 on 2026-07-30, and it carries the three corrections that probe produced. Re-verify with the probe command it already contains rather than patching it from this brief. cage/vscode-instructions.md already records two observed VS Code behaviours. .github/hooks/se-stop.json already uses Copilot's Claude-compatible PascalCase hook mode. engine/bound.ts already holds answers under a threshold and spills with a cursor. None of that is greenfield.

AND ONE STANDING CLAIM IS WRONG. raid-obsidian-and-harness says caging a second host proves the coupling is configuration rather than architecture. That is true of the first tier and false of the other two. Correcting it is part of this work.

FOUR MORE OWNER RULINGS, 2026-08-18 EVENING, and the report carries them as Parts 15 to 17.

THE WORD RECORD GOES. An iteration is not a record: a record is a passive account of something that already happened, and this is the work itself in progress. It keeps coming back because the SYSTEM teaches it, not because agents remember it — 1,944 hits in the trace corpus, 204 in the machines whose guidance rides every pull, 72 in guidance, 14 in the prompt layer that is projected verbatim every turn, 8 in tool descriptions. Telling an agent to stop using a word the machine uses at it cannot work. RENAME TO WORKPIECE: zero existing hits anywhere, so grep proves the sweep finished, and it joins the machine metaphor the system already speaks. NOT vehicle, which front-desk.md already uses for this category AND i16 uses for a downstream product embedding the engine — 77 hits, two meanings, and a third would make it permanent. Second best is undertaking, also zero hits. DO THE MACHINES AND THE PROMPT LAYER FIRST because those two re-teach every turn; the trace corpus is the biggest number and the least urgent. AND DO NOT OVERREACH: of the engine's 796 hits, 466 are TypeScript's own Record<K,V> and 28 are CallRecord and its siblings, where the word is doing its real job. The real exposure is about 300.

se_house WAS A BAD BUNDLE, NOT A BAD NAME. It merged two jobs: se_reload and se_prompt_place both make the live system take up what changed on disk, while se_panel opens the mirror and points a highlight at a surface for a person. Replaced by se_refresh {what: engine|prompt} and se_mirror {op: open|point|shoot}, the second absorbing se_shoot, which stood alone only because nothing else did. The verb count is unchanged at 19.

THE 2 KB CAP AND BUNDLING ARE TWO DIFFERENT PROBLEMS AND THE REPORT RAN THEM TOGETHER. The cap is PER TOOL, so merging five verbs ADDS their descriptions: bundling does not remove one byte, the total stays 19,538 at 34 tools or at 19, and it makes the cap HARDER to meet. Bundling buys COUNT against Cursor's 40 across all servers. Shortening descriptions is the independent fix and it helps everywhere at once. THERE IS A PRINCIPLED WAY TO SHORTEN: the same rules are delivered twice today, once in the 43,008-byte prompt layer and again in the tool descriptions. se_pull's 2,425 bytes re-teach the whole loop, and walking.md and lane.md already teach every part of it. So the tool description becomes a SCHEMA NOTE — arguments, answer names, what a wrong call gets — and the loop stays in the prompt layer, which is not capped. That takes se_pull under 2 KB without losing a rule, and the same argument covers se_run, se_test and se_file_read, which are over half the budget between them.

THE HOOKS ANSWER IS BETTER THAN THE EARLIER PART SAID, and Part 9 is corrected. First, the MODEL never decides which files are read: running Claude inside Copilot changes nothing, because the HARNESS reads files and the model only reasons. Copilot CLI DOES read .claude/settings.json for a documented cross-tool subset that includes hooks, with PascalCase events and Claude's payload shape — se-hook-stop.ts already relies on it. VS Code DOES run .github/hooks/*.json BY DEFAULT: chat.useHooks defaults true and chat.hookFilesLocations ships .github/hooks true. The preview flag chat.useClaudeHooks gates only the .claude-format files. So no single hook file reaches all four surfaces, but TWO FILES REACH ALL FOUR BETWEEN THEM and both are committable: .claude/settings.json for Claude Code, .github/hooks/*.json for the whole Copilot family. Generate both from one source. AND MAKE EVERY HOOK SCRIPT IDEMPOTENT, because Copilot CLI reads BOTH and fires the same script twice — that is happening today and only se-hook-stop.ts survives it, on a bites-once valve keyed on stop_hook_active. se-hook-start.ts and se-hook-websearch.ts have no such valve.
