## business_case

THE COST IS ALREADY BEING PAID, and it is measured rather than argued.

WHAT IT COSTS TODAY. The i15 cloud run on 2026-08-16 filed a debt note for the blocker that stopped it. That note is gone — a search of the whole call log for its ref returns nothing, because .se/notes.jsonl is machine-local and never committed. A hand-written field report was the only thing that carried the findings back, and writing one is an act nobody in the machine asks for or checks.

IT HAPPENED AGAIN IN THIS SESSION'S FIRST TEN MINUTES. Three findings were captured as notes at boot: the lane dying on NaN, the identity check's 64 false reds, the reading probe refusing a verbatim answer. Had the box been released before the retro drained them, all three would have gone with it, and the next cloud run would have rediscovered all three from scratch — which is exactly what the cloud-validation debt says happens: "another cloud run repeats the same seven discoveries".

SO THE UNIT OF LOSS IS A RE-DISCOVERY, and its price is the walk that hits the same wall again. This session spent roughly the first quarter of its calls on three defects, two of which a surviving note would have named in advance.

WHAT IT COSTS TO BUILD, against that: the drain already exists, already has four dispositions, and already REQUIRES a re-entry condition on backlog. The corpus already stores typed nodes and already sweeps them for leaked identities. The build is a write at a door that is already there — which is the whole argument for minor, and it is what makes this case easy rather than close.

THE ONE COST THAT IS NOT SMALL is the migration of 205 parked options, and it is deliberately not in this iteration. It runs where the notes are, and its first act is a report of what did not fit.

WHAT WOULD MAKE THIS NOT WORTH DOING: if the owner would rather every unattended finding came back as a written report to a person, which is what happens today. That is a real alternative and it is cheaper to keep than to replace. IT LOSES ON ONE POINT: a report is read once. A pool item is offered by the desk every time somebody asks what to do next, which is the fourth success criterion on the prop.
