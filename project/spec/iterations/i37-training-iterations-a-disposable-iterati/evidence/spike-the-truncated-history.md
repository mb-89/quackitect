## anything_else

THE SPIKE ANSWERED MORE THAN IT ASKED, AND THE EXTRA ANSWER CHANGES THE DESIGN.

The question was whether a truncated history is possible. It is. What came free is that it is BETTER than the export this iteration had already chosen.

`git archive` was probed at find_by_probing and won its morph-box row. It gives content and no `.git` at all, which means every git verb is dead inside the tree — including the ones an agent legitimately uses to read the past.

A DEPTH-1 FETCH GIVES BOTH. 1723 files of working tree, and a history exactly one commit deep. `git log` works. `git show` works. `git rev-parse` on i33's own start commit does not resolve, because the object is not there.

THE FUTURE IS ABSENT RATHER THAN REFUSED, which is what the heuristic asked for and what no checked ceiling can reach.

ONE MEASUREMENT IN THIS SPIKE EXISTS ONLY AS A CONTROL. Searching the tree for the walked iteration returned 0 files. That is the answer the design wants, and a search that failed to run returns the same 0. Searching for a different iteration at the same tree returned 71. The 0 means something because the 71 is beside it.

THAT IS THE CALIBRATION RULE FROM find_analogy, applied to the spike that decides the iteration.
