## anything_else

WHICH ITEMS HAVE A STORY, AND WHICH CANNOT.

ONE ITEM HAS A REAL PASS. The version flag is something a person does: they unpack a release, run the installer, and ask what they got. It has an actor, an order, and a result that answers the problem. It is written as a deck.

FIVE ITEMS HAVE NO PASS, and forcing one would be fabrication.

- The actor stamp changes a column in a log a person reads. Nobody DOES anything; a rendering stops being wrong.
- The preflight path check moves where a string lives. Nothing observable changes until a file moves, and that is a maintenance event rather than a journey.
- The empty-source hint changes what one field says in one condition. It is a sentence, not a pass.
- The paint pins add assertions. Nothing user-facing moves at all.
- The test split changes how long a battery takes, and the person waiting for it is not walking anywhere.

THE METHOD'S OWN TEST SETTLES IT. If any two sentences could swap without loss, it is not a story. Every one of the five above fails that test, and four of them would come out as capability statements wearing a story's frontmatter — which the method names explicitly as the thing not to write.

WHY THE NEW STORY IS A MUST. The owner ruled that a package proves itself with a version flag. A should or a could would leave the proof optional, which is the opposite of the ruling. It also costs almost nothing to demonstrate: one command, one line of output.

WHAT THE MUST GRADE OBLIGES. M8 demonstrates it end to end. i16's own evidence says zero of 21 must stories have a demonstration report anywhere in the corpus, so this record adds one to that count — and it is the one must in the corpus whose demonstration is a single command.
