## gap_claim

THE GAP, AS A CLAIM: every mechanism we have governs WHAT an agent may do and none governs WHERE the result lands.

THE ALTERNATIVES, AND WHAT EACH SHEDS.

A GUARD THAT REFUSES WRITES OUTSIDE THE RECORD — which is what stands today. It sheds COVERAGE, because a guard must enumerate the doors it watches. Ours watches five write tools and not the shell, and the shell is what got used: refused at the write, a walk reached for it with a stated reason and the write landed on trunk anyway. Every new tool is unguarded by default, which is the shape v1 recorded as its own lesson — guards belong in one dispatch pass, and a rule table past ten per-command entries has become per-command logic in disguise.

GIT WORKTREES ALONE — the substrate we already run on. They shed ENFORCEMENT entirely. A worktree isolates a checkout and nothing stops a tool writing to a different one; that is exactly the state measured today, with the same feature built twice on two branches.

WORKSPACE-ROOTED TOOLING — the monorepo family, where a tool resolves paths against a package root rather than the repository root. NOT RUN, and said plainly: this is what the documentation of that family claims, not something observed here. WHAT THEY PLAINLY DO BETTER: their resolution is mature, widely exercised and understood by the people who use it, where ours would be new. WHAT THEY SHED: they resolve at BUILD time for declared inputs. They do not govern an arbitrary write by an arbitrary agent mid-session, because nothing in that world is trying to.

PROCESS ISOLATION — a container or a jail per record. It sheds SELF-HOSTING outright, and cheaply nothing else. It is the strongest answer and it makes the engine unable to run in-process against the tree it is serving, which is the one thing this product needs.

OURS SHEDS SOMETHING TOO, and it is not small. Removing the destination removes the escape-edit-return move, so a method change cannot be made mid-walk. This product keeps that ability only by being exempt from the whole mechanism, which means the rule ships largely unexercised by its own author. That is the honest cost and it is registered as a risk, not argued away.

## why_now

THREE THINGS MATURED, and none of them existed when the fixed root was chosen.

THE COST IS MEASURED RATHER THAN SUSPECTED. Eight step-outs in one session, three inside a single verification, one incident where a mid-walk sync pulled 26 commits and felled four signed claims, and one feature built twice on two branches. Before this week the step-out was an irritation nobody had counted.

THE OLD MODEL BROKE ON ITS OWN. What counts as an open record is whether a worktree directory exists, and that already failed on a peer — a fresh clone showed all nineteen pushed records as archived, none ever started. So the state model has to move whether or not the root does, and moving both at once is cheaper than moving them apart.

A SECOND MACHINE ARRIVED. Until a cloud agent shipped a record this week, one machine meant one tree and the fixed root was harmless. Concurrency is what turns a shared root from a simplification into a collision, and the ledger closes only half of that — it stops two agents taking one record, and nothing stops two records reaching one tree.

AND ONE THING THAT DID NOT MATURE, said so the why-now is not overstated: nobody has run a bound record with a moved root, on any product. The case is built on the cost of the present, not on evidence that the future works.

## business_case

THE CURRENCY IS AGENT TIME AND REWORK, and there is no acquirer to price it for.

WHAT IT BUYS, from measured numbers rather than estimates. Eight step-outs in one session, each re-walking the machine from its start. One feature built twice, with three merge conflicts to reconcile it. Four signed claims felled by a mid-walk sync and re-earned by hand. Twenty-four trees standing half-synced, found and repaired in one pass that should never have been needed.

WHAT IT COSTS. The engine's path resolution changes at its root, which is the highest-blast-radius change available in this system, and a wrong resolution is silent. That is the whole reason the size is major.

WHY NO FURTHER CASE IS MADE. The product is not sold and has no acquirer, so a case in money would be invented. The rule is that where no acquirer exists the case is skipped with a recorded reason, and this is that reason.
