## follow_up

TWO FINDINGS, both outside this change's cone and neither fixed beyond the placement.

THE DSM PARTITIONS THE ROOT ALONGSIDE ITS OWN CHILDREN. meth-function-structures says the root is the overall function and sub-functions hang beneath it. The item list here contains all 21, root included, so the search must place the parent in a group of its children. The placement made here is defensible on its one flow and the shape is still wrong. It wants either the root excluded from the item list, or the card saying why a root is a cluster member.

A CLUSTER KEY POINTED AT A NODE THAT WAS NEVER MINTED, for a whole iteration, and no check caught it. `cluster: self-description` was written at i8 and cluster-self-description does not exist. The orphan check runs over refines and satisfies; a dangling cluster reference is the same class and is not covered. It surfaced only because the picker could not offer the value.

Goes to i6, conformance goes mechanical, beside the satisfies and flow-closure gaps already carried there in note-06b29e231b80. This is a third edge family with no continuous guard.

## anything_else

- cluster-the-account - shared-data. What the system writes down and puts in front of a person.
