## goal_system

THE GOALS THIS ITERATION SERVES, most important first.

- A BROKEN RULE IS HEARD AT THE WRITE. That is the goal. Everything below is what it costs.
- A CHECK BINDS TO A NAMED THING. It enforces an `el-` element or a `dsp-` design spec, never a rule somebody typed into prose.
- A CHECK ASKS A QUESTION A LISTING CANNOT SATISFY. The record's own test: could an agent pass it while examining nothing?

FOUR CONFLICTS, EACH RULED. A goal list with no named conflict is hiding one.

### 1. The write hears it, against the call answering in a second

THE PULL. A bound check reads the trace corpus to know what it enforces. `req-call-answers-in-one-second` is a standing requirement over every call, and a write is a call.

THE RULING: THE SECOND WINS. A check that makes a write slow is not a better check, it is a worse write verb.

WHAT THAT MEANS CONCRETELY. The measurement decides the architecture, and it is taken at the first build chunk rather than argued about. `raid-asm-a-bound-check-runs-inside-the-write-budget` carries the probe.

THE FALLBACK IS NAMED NOW, not improvised later. If a bound check cannot fit inside a write, the checks move to a batched runner and the write REPORTS the break instead of refusing it. That is weaker than the goal and still better than a review.

### 2. The check refuses, against the walk never being trapped

THE PULL, and it is this project's own shape. Quackitect is its own product. A check that refuses a write refuses the write needed to FIX the rule it is enforcing.

THIS IS NOT HYPOTHETICAL. observe-red's own exit script blocked its own iteration on re-entry, in i11, and had to be given a signed-evidence escape.

THE RULING: THE WALK WINS, and `raid-dec-the-walk-never-reaches-a-state-it-cannot-leave` already says so.

THE SHAPE OF THE FIX, so it binds every check rather than being remembered per check: a refusal must leave a legal way forward, and naming that way is part of writing the check. A check with no named escape is an unfinished check.

### 3. Refusing, against the orphan not being chased

THE PULL. This iteration's thesis is that a rule wants a refusal. But the register-versus-folder check is ruled to REPORT a named difference rather than refuse, because the owner ruled an orphan is not chased.

THE RULING: BOTH WIN, SCOPED, and the scope is the seam.

- A CHECK REFUSES where the WRITE ITSELF is wrong. The author is present, the fix is theirs, and it is cheapest now.
- A CHECK REPORTS where the CORPUS disagrees with itself. The break predates this write, the author did not cause it, and refusing would make an unrelated edit carry somebody else's debt.

WHY THE SEAM IS THE RIGHT ONE. `req-no-agent-act-destroys-work` and the pace complaint point the same way: a refusal aimed at the wrong person is a tax, not a check.

### 4. depends_on required, against capture staying cheap

THE PULL. Making an argument required adds friction to seeding, and this system's standing bias is that capture is cheap.

THE RULING: REQUIRED WINS, and it is the owner's, 2026-08-13.

THE REASONING IS NOT ABOUT FRICTION. The two answers the key distinguishes are I FORGOT and I DECIDED NONE, and today they look identical on disk. The container is a DAG and this key is its only input, so an unset key is a missing EDGE rather than a missing note.

THE MEASURED COST OF GETTING IT WRONG: 27 iterations seeded, the key set on 7. Three stated a wait in their own prose and carried no edge for it.

### No new goal is needed

CHECKED DELIBERATELY, because the state guidance says a delta needing a NEW goal is arguing for a new vision and must escalate.

Every goal above is a standing one. This iteration changes WHEN they are enforced and by WHAT, never what they are.
