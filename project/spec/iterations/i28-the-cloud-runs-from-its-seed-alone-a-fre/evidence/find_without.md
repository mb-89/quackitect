## anything_else

### The trim that matters

EVERY OTHER OPTION IN THIS ITERATION REFINES HOW FOLDERS ARE CREATED AND REMOVED. Materialise on entry. Remove at close. Sweep what earlier closes left. Make the folder a side effect of a claim.

THIS ONE ASKS WHETHER THE FOLDER WAS EVER THE RIGHT IDEA. If a machine works one record at a time on trunk, there is no folder lifecycle to get right, no stale folder after a crash, no sweep, and no second definition of what open means.

WHAT MAKES IT CREDIBLE RATHER THAN CLEVER: this product has run exactly that way since 2026-08-14, by i27's own ruling. The option is that exception generalised, which REMOVES a special case instead of adding one.

WHAT MAKES IT COSTLY IS ALSO CLEAR. One machine holds one record, a tree switch costs whatever the tree costs to write, and work left mid-walk must be committed before the machine can touch anything else.

### Why the holding pen was not trimmed

IT IS THE CHEAPEST CLUSTER AND THE EASIEST TO REMOVE, which is precisely the failure mode the method names: trimming what is cheap feels productive and saves nothing.

Two functions, and what it prevents is a stray disappearing. That is a failure nobody notices at the time, which is the kind worth keeping a mechanism for.
