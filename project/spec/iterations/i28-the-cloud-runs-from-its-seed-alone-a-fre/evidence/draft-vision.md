## to_be_world

A MACHINE NOBODY HAS TOUCHED gets a repository address and a seed id. One command later it is walking, and no person typed a step.

WHAT IS ABSENT FROM THAT WORLD is the point of it.

- No handover document is read. Procedure is run, not interpreted.
- No folder is repaired, no dependency is inferred, no port is guessed at.
- Nobody asks which iterations exist, because git already answers.

A FOLDER ON DISK MEANS SOMEBODY IS WORKING THAT ITERATION RIGHT NOW. Nothing else. It appears when a walk enters and it is gone when the walk closes, so the disk stops being a second, disagreeing copy of what git already knows.

AND WHEN SOMETHING IS GENUINELY WRONG, the machine says so in one sentence carrying the remedy. A door is never silently missing from an offer.

WHAT IT FEELS LIKE FROM THE OTHER SIDE. The owner opens a cloud machine, pastes one line, and closes the laptop. Work happens. That is the whole to-be world, and everything in this iteration is a step toward it.

## goal_system

THREE GOALS, and two real conflicts between them. The conflicts are named rather than smoothed, because each one has already bitten in this record's own first hour.

THE GOALS

- START WITHOUT A PERSON. A seed id and one command produce a walking agent.
- NEVER LOSE WORK. Nothing the machine does destroys what somebody wrote.
- STAY LEGIBLE TO A PERSON. Somebody who is not the agent can see what is going on.

CONFLICT ONE: STARTING WITHOUT A PERSON AGAINST NEVER LOSING WORK.

An entry that repairs itself and a close that cleans up are both acts taken with nobody watching. i27's folder held 34 uncommitted paths and looked exactly like waste. It was waste, and that was established by comparing every path byte for byte, not by assuming.

THE RESOLUTION TAKEN: automatic acts may CREATE freely and may never DESTROY blind. The close commits or refuses. Speed is bought on the create side and never on the destroy side.

CONFLICT TWO: A DISPOSABLE WORKSPACE AGAINST STAYING LEGIBLE.

A folder on disk is browsable by any tool and survives an engine that will not start. Removing it makes the engine the only door, which sits badly beside the contract's own rule that the lane is the only door.

THE RESOLUTION TAKEN, and its cost is accepted rather than denied: the branch is the record, so `git show it/<id>:path` reads any of it with no engine at all. The property survives. It costs a person one more command, and that is a real loss.

NO CONFLICT WITH THE RESIDENT PACKET. Neither tension is new to the vision. Both are this iteration's local shape of the standing trade between autonomy and evidence that [[vp-autonomy-range]] already holds.

## moore_pitch

FOR AN ENGINEER OR AN AGENT starting work on a machine that is not the one they used yesterday,

WHO NEEDS the process, the record and the position to be there without assembling them by hand,

QUACKITECT'S BOOTSTRAP IS a one-command entry that turns a seed id into a walking agent.

UNLIKE Codespaces and Gitpod, which solve the same shape with a hosted control plane and a container per workspace, this needs neither. A seed is a git branch. A machine that adopts one needs git and node and nothing else.

UNLIKE a written handover, which is how this is done today, nothing is interpreted. The steps are run, and a step that fails says which one and why rather than reporting that the server is not there.

AND THE HONEST HALF OF THE COMPARISON. Codespaces and Gitpod are better than us at this right now, because a workspace's absence is never mistaken for the work not existing. That is precisely the defect that blocked this iteration's own entry, and copying their shape is the point.
