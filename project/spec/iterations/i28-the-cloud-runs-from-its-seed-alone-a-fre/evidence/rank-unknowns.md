## anything_else

### Why these three and not the register's worst

THE CHART'S WORST ENTRIES ARE NOT ALL PROBE-SETTLEABLE. A timeboxed probe answers a question about the world. It cannot answer a question about what somebody should decide.

SO TWO TESTS DECIDED THE PICK.

- Does it block the coming build?
- Can a bounded run settle it?

BOTH MUST HOLD. An unknown that fails either is a risk to carry, not a spike to run.

### The three, and what each would settle

[[raid-asm-a-host-keeps-a-backgrounded-lane-alive]] is graded fatal. The entrypoint starts the lane and then walks away. If the host reaps the process when the starting command returns, the whole seven-step shape is wrong rather than incomplete.

[[raid-asm-the-installed-runtime-is-one-the-engine-runs-on]] is graded crippling and is partly probed already. The floor is declared: `package.json` line 8 says node >=22.6. What no host has confirmed is that a default install reaches it.

[[raid-lane-works-on-posix]] is graded crippling. Every path in the lane was written and exercised on Windows, and the cloud host is Linux. This is the assumption most likely to be quietly false.

### What the three share

NONE OF THEM CAN BE ANSWERED ON THIS MACHINE. All three need a Linux host that nobody has prepared, which is precisely what [[raid-debt-cloud-validation-needs-a-machine-this-one-cannot-make]] already says the owner owns.

SO THE SPIKES ARE REAL WORK WITH A REAL BLOCKER. Saying that here is better than seeding three probes and discovering it at run-spikes.

### The claim questions are absent on purpose

NOTHING ABOUT CLAIMS IS SEEDED. The owner ruled today that a claim runs until a person releases it, and that removed the only unknown the claim design had: how long a timer should be.

A DESIGN WITH NO TIMER HAS NO WINDOW TO PROBE. That is the reversal paying for itself.
