# Evidence form / scope-non-goals

## current_situation

The delta is framed and signed. Two value props stand, nine register entries stand, and the change size is pinned at major.

ONE REAL DECISION SITS IN THIS STATE and everything else follows from it: whether the model stamp ships alone or with the coordinate that makes it mean something.

It is decided below, with the reasoning, and it is flagged as the one place in this milestone where a reasonable owner might rule the other way.

## scope

1. RATE EVERY STATE IN THE MATRIX on the five-rung ladder, with evidence per rating rather than a table filled in one sitting. Fifty-three rows, read live and never pinned into a record's demands.

2. PUBLISH ONE FIXED MODEL LIST in the repository, following the pattern both existing dials already use: a machine file a person edits, read live by the engine, with its own contract stated at the top.

3. NAME THE DRIVER OUTWARD, so whoever is driving can act on it. The machine says; the spawn stays outside the lane.

4. STAMP THE ANSWERING MODEL ON EVERY CALL, taking the value from what served the call rather than from what was asked for.

5. AND STAMP THE STATE THE CALL WAS MADE IN, which is the decision this state takes.

WHY FIVE IS IN SCOPE, stated as an argument rather than asserted. The record's fourth goal does not say "record the model"; it says record it "so a walk can be attributed after the fact". Attribution is the goal and the stamp is one of its two coordinates. READ FROM THE RECORD SHAPE, which is the only thing that settles it: engine/calllog.ts:11-24 declares CallRecord and its fields end at actor and se_version. There is no state, no visit, no step. THIS FIELD FIRST CITED A MEASUREMENT THAT PROVES NOTHING and the correction is kept rather than hidden — it said grouping the log by visit or by state put every record in one bucket while grouping by actor separated cleanly. calllog.ts:289-292 digs a dotted path and falls back to (none) for ANY key it cannot reach, so group_by "banana" returns the same shape, measured at 285 records in one bucket. The conclusion was right and the evidence could not have established it. Shipping four without five delivers a field that answers no question anybody asked, and it would read as done.

IT IS ALSO ONE CHANGE RATHER THAN TWO. Both values are known where the call is served, which is exactly where the actor is already stamped and for the reason the call-log design gives: the code that knows stamps it, and nothing downstream infers it. The record grows two fields in one edit or it grows neither.

AND IT IS WHAT THE LADDER WILL NEED LATER. Every route out of the standing drift risk — comparing a declared rung against what the work turned out to need — is a per-state comparison. Without the coordinate there is nothing to join on, so a rung could never be shown to have been wrong.

6. THE SUBMACHINE RULE lands with the ratings: the maximum over items, with the per-item values kept and surfaced rather than merely consumed.

## non_goals

- ANY RUNTIME PREDICTION OF DIFFICULTY. No score per request, no classifier, no learned router. Deliberate: it is what buys the determinism this process exists for, and the cost is registered rather than hidden.
- PER-HOST MODEL RESOLUTION AND RUNTIME DISCOVERY. Ruled out on the record. The open assumption about alias drift across hosts is answered inside the one list, never by asking the box.
- THE ENGINE SPAWNING AN AGENT MID-WALK. The machine names; something outside performs. Starting a process sits with pushing and opening records, outside the lane.
- THE RECONCILIATION REPORT that would compare a declared rung against what the work needed. It is a whole mechanism, it needs the state coordinate this iteration adds plus outcome signals it does not, and it is its own record. Named in the drift risk as the way out rather than built here.
- DERIVING THE RUNG FROM A DECLARED CHECKER. The strongest recommendation the gate's scan produced, and it is a change to what a matrix row must declare, not a rating pass. It goes to the requirements as a candidate and is not assumed.
- MAKING A RUNG A (MODEL, EFFORT) PAIR. Same reason: it widens what the list holds, and the list has to exist before it can be widened.
- CORRECTING THE SEED'S OWN FALSE STATEMENTS. Two issues stand against the record's design input. Rewriting a record's rulings is not M1's act, and they are registered so the correction is not lost.
- FIXING THE THREE ENGINE LEADS AND THE STALE TOUR COUNT this run found outside i38. They are in the iteration's field report with their durable homes named.
