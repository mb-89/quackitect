### The dead function is still dead and it no longer shows a conflict

`reduce-a-milestone-to-one-difficulty` SITS ON el-sizing AND NOTHING CALLS IT. That is unchanged: this architecture publishes per state, so there is no milestone to reduce over.

WHAT CHANGED IS WHY. It was allocated deliberately so that a conflict between a standing must and the declared design would show rather than hide behind a tidy matrix. `req-a-milestone-takes-the-maximum-complexity-over-its-rows` demanded a reduction; the design performed none.

THE RESTATED MUST DEMANDS NO REDUCTION. It asks that the engine name, for every unit of work it sizes, a difficulty no weaker than the hardest step that unit contains, with the distance to each step readable. NAMING PER STATE SATISFIES IT WITH A UNIT OF ONE AND A SPREAD OF ZERO.

SO THE FUNCTION STAYS ALLOCATED AND STAYS UNCALLED, and the allocation now records a design choice rather than a defect. It is kept because the function serves a demand that other designs meet by reducing, and this architecture meets by never grouping. Leaving it off the element would say this design cannot reduce; leaving it unallocated would say nothing at all.
