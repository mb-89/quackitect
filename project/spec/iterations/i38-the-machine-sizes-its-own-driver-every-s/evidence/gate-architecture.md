# Evidence form / gate-architecture

## current_situation

M5 asks to be blessed and it should not be. The architecture it produced is coherent, evidenced and internally consistent, and it does not satisfy the requirements this iteration wrote.

THE CHECK THAT SETTLES IT WAS NEVER RUN UNTIL NOW. A must gates a candidate and a should scores one — cut-criteria says so, gate-candidates repeated it, and no state held a must against a candidate. Run at M5, it returns that the declared architecture violates five of the five musts that bear on it, and that every rejected candidate violates at least one.

THE CAUSE IS IN THE REQUIREMENTS RATHER THAN IN THE ARCHITECTURE. They name the seed's mechanism — a milestone maximum, one file mapping rung to model, a loader that refuses a row without a five-rung value — rather than the need behind it. A design that improves on the mechanism necessarily fails the demand encoding it, so M4's whole search was excluded a priori by M3's own output.

## round_2_red_team

- The declared architecture violates five of the five musts that bear on it => VERIFIED BY READING EACH REQUIREMENT AGAINST THE CANDIDATE FILES. It publishes two figures where a five-rung value is demanded; it reduces nothing where a milestone maximum is demanded; it holds no roster where one file mapping rung to model is demanded; it cannot record what answered where that is demanded; and it cannot detect a weaker driver, so it cannot mark one unreasoned. A must is a constraint — a candidate satisfies it or is not a candidate — and this one satisfies none of the five.
- Every rejected candidate also violates at least one => cand-the-seed-made-total violates one, cand-the-reader-beside-the-walk two, cand-the-derived-ladder three, cand-the-receiver-decides five. The candidate violating fewest is the one the comparison eliminated. There was no eligible candidate on the chart and no state noticed.
- The requirements name mechanisms rather than needs => THAT IS THE ROOT AND IT IS REPAIRABLE. "Derived from the maximum complexity over the rows" is a reduction step. "Shall be ONE FILE in the repository" is a file layout. "Shall refuse any row that does not DECLARE a five-rung value" is a declaration mechanism that forbids derivation by construction. Each passed the EARS shape check, carries a breaks_if_removed and is graded. No check a requirement faces catches a design wearing a demand's clothes.
- The gate before this one deferred the check to a state that does not exist => gate-candidates' follow-up reads "the musts are not absent from the comparison, they are prior to it ... checked as constraints at gate-design". There is no gate-design in the rigor matrix. The sentence was written by this walker, it reads like diligence, and it is why the check was never run.
- Passing this gate would push the conflict three milestones downstream => M7 verifies the build against the requirement set. Every must this architecture violates would fail there, after the build. The same finding costs one gate here and a milestone of implementation there.
- The architecture itself is not the defect and should not be discarded => Its costs are recorded rather than argued away: two standing requirements newly unaddressed and graded CERTAIN because they are consequences it chooses; a bound it worsens, measured; a dead function allocated so that the conflict shows rather than hidden by leaving it unallocated. That is what a well-made architecture record looks like. It is measured against the wrong ruler.
- One thing this gate cannot settle and says so => whether the repair is to amend the requirements to state needs, or to accept that the seed's mechanism was the requirement all along and declare the candidate closest to it. The first reopens M3 and its gate; the second makes M4 a search whose outcome was fixed before it started. Both are legitimate and the choice is not a gate's to make.

## verdict

fail — the declared architecture violates five of the five must-priority requirements that bear on it, and a must is a constraint rather than a criterion: a candidate satisfies it or is not a candidate. Every rejected candidate violates at least one, so no eligible candidate was ever on the chart, and the check that would have shown it was deferred by the previous gate to `gate-design`, a state the rigor matrix does not have. THE ARCHITECTURE IS NOT THE DEFECT. It is coherent, its costs are recorded, two of its consequences are graded certain rather than expected because it chooses them, and it beats every rival on the axes anybody scored. What is wrong is the ruler: `req-a-milestone-takes-the-maximum-complexity-over-its-rows`, `req-one-model-list-is-read-live-from-the-repository` and `req-every-matrix-row-declares-its-complexity` name the seed's mechanism rather than the need behind it, so any design that improves on that mechanism fails the demand encoding it. PASSING WOULD MOVE THE CONFLICT TO M7, where the same requirements are what verification checks the build against, and it would surface after the build instead of before it.

## follow_up

THE REPAIR IS AT M3 AND THIS GATE NAMES IT WITHOUT CHOOSING IT.

WHAT MUST BE RE-EARNED, in order. write-requirements is the root: three musts state mechanisms and need restating as needs — "a milestone's driver is strong enough for the hardest work it holds" rather than "derived from the maximum over its rows"; "a rung resolves to a worker by one rule every host reads the same way" rather than "one file in the repository"; "every applying row carries a complexity the loader can check" rather than "declares a five-rung value". gate-requirements falls with it, and M4 re-scores against a requirement set that admits more than one design.

WHAT SURVIVES THE REPAIR UNTOUCHED, so nobody re-does it. The seven finders and their twenty-nine options; the function structure and its clusters; the four candidates and their compositions; the element decomposition and its interfaces; the four decisions. All of it was work against a design space, and the space does not change — only the constraints that admit or exclude its members.

WHAT THIS GATE WILL NOT DO. It will not choose between amending the requirements and accepting that the seed's mechanism was the demand all along. The first says M3 wrote design decisions and calls them back; the second says M4 was decorative. Both are defensible, both are expensive in different currencies, and the choice belongs to whoever owns the record rather than to the gate that found the conflict.

AND ONE THING TO CARRY WHATEVER IS CHOSEN: hold every must against every candidate before scoring. A must that no candidate but the incumbent can satisfy is a must that encodes the incumbent, and that is a mechanical test costing one pass.
