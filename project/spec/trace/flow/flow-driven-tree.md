## Why it is a second tree rather than another worktree

[[flow-worktree]] IS WHERE UNFINISHED WORK LIVES, and since i34 it carries a
constant: the one tree. This flow is a different tree entirely, named by
somebody rather than assumed, and the system did not come from it.

SO THE TWO CANNOT BE ONE FLOW. `resolve-a-path` has to tell them apart to
answer its own question, and a resolution that could not would put a driven
product's records in the system's tree or the system's notes in somebody
else's repository.
