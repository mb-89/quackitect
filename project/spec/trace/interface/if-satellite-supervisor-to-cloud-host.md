## What crosses

- a record handed out to be walked elsewhere
- the tree that comes back, and the commits on it

## Not measured, 2026-08-17

NO CLOUD RUN CROSSED THIS EDGE TODAY. A measured zero would mean nobody used
it, never that it is fast, and this node says so rather than leaving a later
reader to infer it.

## Why the bound is a different clock

A CLOUD RUN IS MINUTES TO HOURS. Nobody is watching it the way they watch a
pull, so the one-second rule does not reach here at all — this edge is
supervised rather than driven.

## What does not cross, and why it is a property of the edge

NOTES NEVER TRAVEL (owner ruling 2026-08-17). A stray captured on the far side
stays there, because the inbox is per-tree and nothing merges inboxes.

SO A FINDING FROM A REMOTE RUN REACHES US ONLY BY BEING COMMITTED. That is a
real limit of this crossing, not a bug in the note system, and the work-token
system the owner has described is what will carry across it.

MODELLING IT MAKES THE LIMIT VISIBLE. Before this node, "notes never travel"
was a ruling in prose with nowhere in the spec that explained why.
