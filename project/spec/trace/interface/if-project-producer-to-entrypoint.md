The crossing where a produced project becomes an ordinary one.

## What crosses

A FOLDER, AND NOTHING ELSE. That is the demand rather than an economy. The
entrypoint must not be able to tell how the tree arrived, because the folder
answering for itself is the whole rule this iteration settled.

## Why indistinguishable is the requirement

A PRODUCED TREE THAT ANNOUNCED ITSELF would give the bring-up path a second code
path, and a second code path is what the merge decision one element over exists
to remove. The same argument, one boundary along.

## What it must not carry

NOTHING OF THE PRODUCING TREE. A produced project starts empty, with zero records
or notes inherited, and this crossing is where that is either true or quietly
false. The include-list decision is what makes it checkable.
