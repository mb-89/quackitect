## What was already decided

raid-dec-two-layer-auth, minted at i1, status DECIDED:

Authorisation splits in two - which tools a step exposes, and whether
this call's path is allowed here - so a write is judged by its path.

Its trigger is, word for word, any write landing outside the record from
inside a bound walk. That is this milestone's whole subject, ruled on
months of work earlier.

## Why that is a problem for this packet

The delta positioned itself against four alternatives, all external: a
guard that enumerates tools, git worktrees alone, workspace-rooted build
tooling, and process isolation.

IT MISSED THE ONE IN THIS REPOSITORY. The comparison rule says prior art
is a comparison rather than a citation, and the nearest prior art was
our own decided decision.

## The two answers, and they are not the same size

MOVE THE ROOT. Every path resolves into the record's tree. Trunk is
unreachable, so the shell hole closes by construction. Costs a change to
the engine's resolution at its deepest point, where a wrong answer is
silent.

JUDGE THE PATH. The root stays fixed and every write is checked against
one rule: inside the record is writable, outside is not. Costs one
predicate in one dispatch pass. The decision's own note says the thin
worktree is what makes it a one-line judgment.

BOTH CLOSE THE SHELL HOLE, because a path judgment in the dispatch pass
covers every tool including the shell. That is the v1 guard lesson this
record already cites: guards belong in ONE dispatch pass, never per
handler.

## What is not settled

Whether the path judgment covers READS. Today's newest pain is a read in
the wrong tree that produced a convincing false finding, and a rule about
where a write may LAND says nothing about where a read may come FROM.
Moving the root covers both by construction; a path judgment needs the
read case stated separately.

That may be the honest argument for the expensive answer. It was not the
argument the packet made, because the packet never met the alternative.

## What closes this

The architecture milestone compares them properly, with the read case as
the deciding question. Until then the iteration is building one of two
answers without having priced the other.
