## The assumption

SWEPT FROM THE ENVIRONMENT SOURCE. It is about the shape of our own corpus,
which is the world this delta's requirements sit in.

THE ITERATION'S VISION CALLS MILESTONE ONE SMALL, in its own words: the
elements exist, the neighbours exist, and what is missing is the edges. That
is a claim about a count, and the count has not been taken.

WHAT IS KNOWN. The trace holds 40 interface nodes and every one is
element-to-element. A search of every interface and element file for `nbr-`
returns zero. Four neighbours exist as nodes: nbr-engineer, nbr-agent-harness,
nbr-vscode, nbr-obsidian.

WHAT IS NOT KNOWN. How many element-to-neighbour pairs actually carry traffic.
Four neighbours against an unknown number of elements is a product, not a
list, and nobody has multiplied it.

## Probe

COUNT THE PAIRS BEFORE MODELLING ANY. Walk the element nodes, and for each ask
which of the four neighbours it actually exchanges anything with.

- Under about thirty pairs, milestone one is the small thing the vision says
  it is and the assumption holds.
- Past that, it is a corpus rather than a milestone, and the iteration says so
  at once rather than discovering it three states later.

THE COUNT IS CHEAP and it is milestone one's opening act rather than a
separate errand.

## Why it matters more than it reads

THE BLESSED COLUMN RESTS ON IT. The kickoff argued minor on the ground that
this adds instances of an existing node type rather than moving the
architecture. That argument survives a handful of new instances and does not
survive hundreds.

THE COLUMN CHOICE IS A PREDICTION AND THE WALK ESCALATES VISIBLY when the work
outgrows it. This row is the tripwire for that escalation, and having it means
the escalation is a recorded decision rather than a drift.
