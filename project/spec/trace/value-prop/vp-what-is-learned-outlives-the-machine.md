## Success criteria

- A finding captured on a machine that is then released is still readable from another clone.
  Metric: findings captured on a released box that survive it. Target: all of them.
- Nothing that travels carries private data.
  Metric: identity needles found by the corpus sweep in minted options. Target: zero.
- An option in the pool says what it is and when it comes back, without opening anything else.
  Metric: pool items with no statement or no re-entry condition. Target: zero.
- The pool is what a person is offered when they ask what to do next.
  Metric: sources the desk reads for open work that are NOT the pool. Target: zero.

## Unlike

EVERY ISSUE TRACKER KEEPS ONE OBJECT END TO END, because its capture is already
inside the shared system. Linear's triage accepts an issue into a workflow;
GitHub Projects converts a draft issue into a real one. Neither has a privacy
boundary to cross, so neither rewrites anything
(ref-triage-and-option-pools-2026).

THE DIFFERENCE IS WHERE THE CAPTURE LIVES. Ours is a dump on a machine, written
mid-walk by an agent that was not stopping to think about who would read it. It
may carry anything. So the crossing is an authoring act, not a status change,
and that is the proposition: the thing that travels was WRITTEN to travel.

THE SECOND DIFFERENCE IS THE STORE. A tracker's pool lives in the tracker. Ours
is files on trunk, so it survives a discarded branch and a released box, which
is the failure this proposition is named for.
