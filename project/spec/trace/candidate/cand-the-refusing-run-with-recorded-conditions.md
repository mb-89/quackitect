## Why this one

IT WAS NOT DRAWN AT build_chart AND IT SHOULD HAVE BEEN. evaluate-set found it
by reading the scores rather than by drawing a curve: the refusing run loses
one axis on one cell, and that cell is the thin run's.

THE THREE DRAWN CANDIDATES WERE NEVER SEALED ALTERNATIVES. Nine of the ten
rows have at least two of them sharing a cell, and cand-the-refusing-run's own
compose state said so before the scores were written.

## How it works

A person names an iteration. Before anything binds, the run exercises its own
ancestry test and refuses to bind if the test cannot be run. Once bound, the
ceiling is the checked ancestry test, and one forbidden request per run proves
it is still watching.

The content subtree is exported at the rewind commit. The benchmark history is
invisible for the length of the binding. The three conditions that no log holds
— the model, the reasoning effort and the harness — are written when the run
binds.

## What it costs

THE GUARD IS STILL CHECKED RATHER THAN UNREPRESENTABLE. Refusing to bind is a
better default than failing open, but between bind and stop the ceiling can
still error. The forbidden request bounds that, per run, at the moment the
numbers are taken.

IT DOES NOT CLOSE THE VISIBILITY DRIFT. Concealment rides the binding over the
three lists that already disagree, so it inherits that weakness rather than
fixing it.

## What it leans on

NOTHING UNPROBED except one claim: that a run can exercise its own guard before
it opens. Every other cell is either measured in this iteration — the export,
the ancestry primitive — or already ruled by the owner.

THAT IS THE WHOLE ARGUMENT FOR IT over cand-the-guarded-run, which wins on
paper and rests on a mechanism nobody has run.
