## Why this one

IT IS THE NULL OPTION, AND A DELTA ABOUT WHERE A FOLDER SITS OWES AN ANSWER TO
WHETHER THE FOLDER SHOULD EXIST. No finder proposed it until the transforming
sweep forced Eliminate onto the incumbent.

IT IS THE ONLY LINE THAT CAN LOSE ON THE ITERATION'S OWN TERMS and still be
worth drawing. Losing tells the reader what the goals are actually protecting.

## How it works

THE REPOSITORY CARRIES THE STATE. The record a walk is bound to is a branch.
What happened is commits and refs. The declared roots are an ordinary committed
configuration file, like any other.

WHAT HAPPENS ON AN OPEN, END TO END.

- The root is found by walking up from wherever the caller is, until a
  repository is found. Absence is a loud refusal that names what it looked for.
- That is the whole check the open pays. Nothing else runs until something asks
  for it.
- The same path serves a machine with nobody at it, because walking up needs no
  editor and no host feature.

WHAT A PRODUCING ACT WITHHOLDS. Two files, declared per act. Everything else
either belongs in the copy or is not on disk at all.

### Before any of that, the first install

THERE IS NO INSTALLER. The product is a repository template, so standing one up
is a clone and one dependency install, and both are things the person already
has.

IT COSTS THIS LINE NOTHING THE LINE HAS NOT ALREADY PAID. Version control is
already a hard dependency here, for the machine state rather than the install.
Every other line would be adding a requirement; this one is reusing the
requirement it already made.

THE OPTION NODE NAMES A LOSS AND THIS LINE HAS THE ANSWER. A clone gives the
tree and loses the purpose the scaffold used to record, so whoever takes the
cell has to say where the purpose goes. Here it goes in the first commit, which
is coherent rather than convenient, because records are already branches and
what happened is already commits.

### The seam that had to be resolved, and how

TWO OF THIS LINE'S OWN PICKS CONTRADICTED EACH OTHER when it was drawn, and the
contradiction is resolved here rather than carried.

- The machine-state cell says there are no plain files, only commits and refs.
- The drawn-surface cell stops drawing things BECAUSE they are plain files a
  person can open in their editor.

BOTH CANNOT BE TRUE OF EVERYTHING, and dropping either half would make this line
say nothing. So the resolution keeps both, over a smaller set.

THE READING IS A FILE, AND IT HAS TO BE. `.se/reading.md` exists so a person
without a lane can open what the walk owes them. It is session state, not
corpus, so version control was never going to hold it.

SO THE HEADLINE NUMBER MOVES FROM ONE FILE TO TWO. The raw note, because it may
carry anything and a standing rule keeps it out of the repository. The reading,
because the drawn-surface cell is meaningless without it.

AND THE DRAWN-SURFACE CELL DELIVERS LESS HERE THAN ELSEWHERE. On the other two
lines the editor shows the whole stored half. On this one it shows two files,
and everything else the surface must draw because it lives in refs a person
cannot read by opening them.

THIS WAS FOUND BY COMPOSING AND NOT BY DRAWING, which is what composing is for.
The option node has been corrected to say two rather than one.

### The other seams

THE MARKER QUESTION DISAPPEARS. Walking up needs a marker, and the repository
is one that every checkout already has. This line is the only one where the
root cell costs nothing to build, because git found the root before we existed.

THE MERGED ARRIVAL HAS A WAY IN ON ANY MACHINE, which is where this line beats
the loudness line directly. That line takes the host's pattern test as its way
in and then merges the unattended path into it, leaving a machine with no editor
with no way in at all. Walking up works everywhere.

THE PER-ACT EXCLUSION GETS EASIER AS IT GETS NARROWER. With two files to
withhold rather than a growing folder, a table per producing act is a short
table. It is still needed, because a producing act copies the WORKING tree and
neither file is committed.

DEFINING THE AMBIGUOUS CASE LEAVES BOTH READERS STANDING. This line does not
delete the second reader; it writes down what a malformed node IS and what every
reader must do about it. That is compatible with the corpus living where it
already lives, which this line does not move.

## What it costs

THIS IS THE LARGEST COST ON THE CHART, and the pieces below are why.

ENGINE WRITES HAVE TO BE HELD TO A SMALL NAMED SET. Otherwise every ordinary
command dirties the tree and the walk becomes unusable beside real work. The
predecessor did this with four named mutations, which is evidence it is possible
and not evidence it is cheap.

THE WALK'S HOT PATH BECOMES VERSION CONTROL. Nothing here measures that, and no
probe was run on it. A stamped corpus read is 359 ms and a repeat is 12 ms;
what a ref write costs on this machine is unknown, and it is the number this
line most needs.

MAKE, REUSE OR BUY.

- BUY: the root, entirely. Walking up to a repository is what git already does.
- REUSE: nothing of the machine-state folder survives to reuse.
- MAKE: the record-as-branch mapping, the log-as-refs mapping, the four-mutation
  discipline, and a per-act exclusion table.

THE STOP-BEFORE-PARTIAL CHECK SURVIVES THE TRIM AND IS STILL OWED. Deleting the
installer removes everything around that check and leaves the check itself
standing, unbuilt.

IT IS WORSE FOR THIS LINE THAN FOR THE OTHERS, and the reason is structural.
The copyable implementations are HEALTH CHECKS that a tool runs about itself,
and this line has no installer for one to live in. A clone and a package-manager
command have nowhere to put a preflight, so the check would have to arrive as a
fourth thing the person runs.

THE INSTALL CELL IS ALSO THE CHEAPEST TRIM ON THE CHART, which the option warns
about in its own words: the cluster holds one function and couples to nothing,
so removing it saves the least of any trim here. It is on this line because it
fits, not because it is a prize.

TWO FILES STILL NEED A HOME OUTSIDE THE REPOSITORY, so this line does not remove
the placement question. It shrinks it from a folder to two files.

FAILURE MODES.

- Version control becomes a hard dependency. LOUD: a tree with no repository
  refuses rather than half-works.
- Ref writes are slower than files. Unknown, unmeasured, and the largest open
  risk on this line.
- A person without a lane loses most of the readable walk. Quiet, and it is the
  cost the iteration's own goal was written to prevent.

TESTABLE, and one test decides most of it: run an ordinary command and assert
the tree is clean afterwards.

## What it leans on

EVERY TREE THAT HOLDS A WALK IS A REPOSITORY. Today a folder is enough.

ENGINE WRITES CAN BE HELD TO A SMALL NAMED SET, so an ordinary command leaves
the tree clean. The predecessor did exactly that with four mutations, which is
evidence it is possible and not evidence it is cheap.

REF AND COMMIT WRITES ARE FAST ENOUGH FOR THE WALK'S HOT PATH. Unmeasured, and
this line's biggest unknown.

THE READABLE-IN-THE-EDITOR OUTCOME IS A MEANS RATHER THAN THE POINT. If it is
the point, this line is already refuted and its only value is the price it puts
on the alternatives.

THE LANGUAGE'S OWN PACKAGE MANAGER IS PRESENT. A clone plus one install command
assumes the second half is already on the machine, which the setup floor of an
editor and a shell does not promise.

WALKING UP TO A MARKER IS ACCEPTABLE HERE. Every command-line tool sampled at
the M2 gate does it, and the one system that matches our root-equals-opened-folder
shape owns a folder handle a terminal never has.

## What it is genuinely a test of

WHETHER THE FOLDER IS THE POINT OR THE MEANS. If the readable-in-the-editor
outcome is what matters, this line loses on its own terms and the chart is
better for having priced it. If the folder was only ever a place to put things,
this line removes four problems at once.
