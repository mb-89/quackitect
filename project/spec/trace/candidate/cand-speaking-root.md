## Why this one

IT IS THE SMALLEST STEP FROM WHAT ALREADY RUNS. The probe of 2026-08-14
measured the root moving on binding in both the lane and the shell. This
candidate does not introduce that behaviour - it finishes it.

Three things are added to what stands. The move becomes total, so no verb
resolves against the old root. The rare reach out of the tree gets a named
form, so the retro and the overhaul keep their reach without a hole. And
every answer says which tree it used, which is the one thing missing today.

## What it sheds

The ability to reach another tree without saying so. That is the point, and
it will break call sites that relied on the ambiguity.

It also keeps the moving root's worst property: a log line still means
different things depending on what was bound when it was written. Only the
new envelope field makes that recoverable, and only for calls made after it
ships.

## How it works

The lane holds ONE resolver and every verb calls it, se_run included. That is
the seam, and it is the part that does not exist today: SE-C-134 names five
write verbs and cannot watch a shell, which is how the same feature was built
twice on two branches.

The resolver answers from the bound record. An unqualified `project/...`
reaches the bound tree. Anything else needs a named form, joining `ref` and
`@name` as a third explicit door.

THE SEAM THAT MATTERS IS THE RETRO'S. A total confinement would bar the state
whose whole job is method, so the reach is a property of the STATE rather than
of the walk - the same list that already carries legal_tools carries how far
the state may reach. Nothing new is invented; one more column joins one that
already refuses.

Method reaches every tree by a reconcile pass at entry and at reload rather
than by N writes. Half of that already runs: the engine levels worktrees at
entry since 2026-08-13.

Every answer carries the resolved tree on its envelope. The claim file gains a
second field saying which tree holds each record, so a peer that clones the
repository can answer the same question without local disk.

## What it costs

SMALLEST BUILD ON THE CHART, because the root already moves. Measured
2026-08-14: se_file_list on "." returns .worktrees and dist at the desk and
neither inside the bound record. This candidate finishes a behaviour rather
than introducing one.

The resolver seam is the real cost. Every verb changes to call it, and the
seam becomes the quietest line in the engine.

The envelope field is tens of bytes per answer, which is why it is on the
envelope. The body is what reaches 300KB.

The per-state reach column is one field on the rigor matrix row plus a
refusal when it is undeclared.

## What it leans on

- THAT THE MOVING ROOT IS SAFE ONCE TOTAL. Unproven. raid-asm-engine-serves-
  from-the-bound-tree asks whether an engine loaded from trunk can serve a
  bound tree, and it cannot be probed from this repository.
- THAT ONE SEAM CAN BE MADE UNBYPASSABLE. If any verb resolves for itself the
  confinement is decoration, and the i8 field report of 2026-08-12 records a
  bypass being used within days of the guard landing.
- THAT THE PER-STATE REACH IS ENOUGH for the retro and the overhaul. Not
  checked against every state that writes method; note-430f3af449b8 names the
  bound retro and may not be the only one.

## What happens when the engine changes

ADDED 2026-08-14, when the chart gained a row it was not drawn against.

ONE ENGINE, SO ONE RELOAD. This line keeps a single process and moves its
root. An engine edit takes effect when that process restarts, and every open
record restarts with it.

The record's own text already said so: method reaches every tree by a
reconcile pass at entry AND AT RELOAD. The reload was always in the design.

AGAINST req-an-engine-change-applies-in-its-own-record THIS FAILS BOTH
HALVES. The walker steps out to reload, and the change reaches every other
open record whether they wanted it or not.

NOTHING IN THE SHAPE FORBIDS A BETTER ANSWER. The row is orthogonal to the
moving root, so this line could take the in-place swap instead. It is drawn
with the reload because that is what its own record described.

## Answers to the demands this record had not addressed

WRITTEN 2026-08-14, when the owner ruled that an unanswered demand is an
incomplete line rather than a weakness. Each answer is what THIS design
gives.

### A resolution is proven by read-back

NOT A PICK ON THIS LINE, AND ADOPTABLE WITHOUT CHANGING IT. The confinement
holds the bound tree as a capability, so a read-back after a write reads
through the same capability and proves the landing. Nothing in the shape
resists it; it is a test discipline this line can carry.

### Version control resolves like every call

THE MOVING ROOT IS THE ANSWER AND ALSO THE DIFFICULTY. Version control
resolves against whatever the root currently is, which is exactly what every
other call does, so consistency is free.

WHAT IT COSTS: a commit is bound to the record the root is bound to. Reaching
trunk means the rare-reach form this line already defines, and that form has
to cover version control or the two disagree.

### A surface resolves to what it shows

ONE ENGINE, ONE ROOT, SO A SURFACE SEES WHAT THE WALK SEES. That is the
simplest answer on the chart and it is also the weakest guarantee: the
surface is correct because it shares the walk's binding, so a surface showing
a DIFFERENT record than the bound one cannot be served at all.

THE ENVELOPE FIELD CARRIES THE NAMING. Every answer already says which tree
it used, so a surface has the datum; showing it is new work.

### A write lands where it is meant

CONFINEMENT IS THE ANSWER. The bound tree is held as a capability and every
path resolves beneath it, so a path naming another tree cannot be expressed.
An escaping relative path is not a special case here - there is nothing
outside the capability to escape to.

WHAT IT LEANS ON, unchanged and recorded: that the seam cannot be walked
around. The i8 field report of 2026-08-12 records that bypass being used.
