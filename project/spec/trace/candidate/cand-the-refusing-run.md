## Why this one

It buys most of the guarded run's protection for most of the thin run's price, by testing the guard once at the start rather than making the guard structural.

## How it works

A person names an iteration. Before anything binds, the run exercises its own ancestry test and refuses to bind if the test cannot be run. Once bound, the ceiling is the same checked test the thin run uses, and one forbidden request per run proves it is still watching. Conditions are derived from the call log where they can be, and the run refuses rather than writing a blank where they cannot.

## What it costs

THE CONDITIONS CELL IS THE WEAK ONE. The model, the reasoning effort and the harness are properties of a session and appear in no call record, so deriving them from the log cannot work for those three. Taking this curve means either finding them elsewhere or accepting a refusal on every run.

AND THE GUARD IS STILL CHECKED. Failing to bind is a better default than failing open, but between bind and stop the ceiling can still error.

## What it leans on

The same probed primitives as the thin run, plus one claim that has not been tested: that a run can exercise its own guard before it opens.
