## Deck

A fresh agent boots into a walk it knows nothing about. It has no memory of yesterday and no idea which method this step wants.
|||
Lived twice on 2026-08-11: a compaction and an engine reload, each leaving the agent with nothing but the repository - reports/rpt-the-agent-proves-it-read.md.

---

It pulls. The answer is not the work. It is one document, whole, inside the reply — no path to open, nothing to skim past.
|||
The walk-back served eleven documents this way, each riding whole in the pull's reply (req-owed-reading-is-served).

---

At the end the pull names what to quote back: the words that FOLLOW a phrase near the document's end. A host that cut the text short cannot produce them, because cutting eats the end.
|||
The prove blocks in the log: three probes per document, each naming the four words that follow an anchor near the tail.

---

The agent answers. It is wrong by four words. Nothing is credited and the same document comes back.
|||
Observed live, twice: meth-morphological-analysis and meth-prior-art re-served with "that did not answer every probe - here is the document again."

---

It answers correctly. The next pull hands over the next document, and the one after that. One at a time, on purpose — a single document cannot be eaten by a host that moves large replies to disk.
|||
The remaining counter walked 11 to 0 across the pulls; the one-at-a-time rule is the reading contract's own.

---

The reading stops. No more documents come. The state opens, and the work in front of it is a form the agent now has the method to fill.
|||
The walk reopened only at remaining 0 - the next pull answered `do` at the standing state (req-reading-proof).

---

The agent held everything the step needed, and the machine knew it rather than believed it. When the context is compacted an hour later, the same loop hands it all back.
|||
req-compaction-reowes-the-reading, demonstrated by the same day's compaction: the hook said the reading was gone, and the loop re-served it.
