## The contract check

WALKED RULE BY RULE against what the lane recorded.

WHAT HELD. Every act went through the lane and every call is in the log. Seven
shell runs that a lane verb could have done were warned and then paid for with
an honest reason under `no_tool_reason`, and the reasons are in the log. No
refusal was worked around with a second lane.

WHAT DID NOT. Early in this window a handful of file reads and one file edit
were made with the host's own tools rather than the lane. The edit was reverted
and re-applied through `se_file_patch` the moment it was noticed, so the change
is in the call log — but the first version of it is not, and nothing in the
machinery caught it. An agent whose harness offers its own file tools has to
choose the lane every single time, and a rule that depends on remembering is
the weakest kind.

THE ONE STRUCTURAL BREACH IS ON THE REGISTER ALREADY. Every gate in i5 was
blessed by the agent that filled it, on the owner's explicit instruction:
[[raid-risk-every-gate-in-this-record-is-blessed-by-its-own-author]].
