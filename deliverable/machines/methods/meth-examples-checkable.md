## Situation

One example thread runs the whole machine.

The stages before scripting live INSIDE stories and use cases. An example node
mints only when it is scripted (M6) or wrapped (M7).

## The lifecycle #work

- intent (M1). The to-be world and the validation signals, as germs, with
  nothing minted.
- formulated (M2 and M3). Roles, not artifacts.
  - Story slides.
  - Use-case paths.
  - Requirement boundary cases.
  - Quality scenarios.
- exercised (M4 and M5). The formulated set walked analytically through the
  candidates and the baseline.
- scripted, or checkable (M6). A defined procedure with a pass criterion.
  - The procedure kind is the verify_method taxonomy.
  - A test run.
  - An FEA load case.
  - A tolerance-stack sheet.
  - An interference check.
  - A gauge procedure.
  - A stranger's read, for documents.
- assertive (M7). The check wraps the example.
  - The example teaches.
  - The check defines pass and fail.
  - Evidence records the run.
  - Regression authority accrues where re-running is cheap: tests,
    simulations, calc sheets, cold reads.
  - One-shot physical checks stay inspection evidence.
- demonstration (M8). Killer use cases run end to end, and story slides'
  evidence_refs point at the runs.
- catalogued (M9). The example browser is a projection, never a
  hand-maintained gallery.

## Rules #work

- Stories are never executable. The example node is the runnable derivative,
  linked both ways.
- Three edges carry it.
  - exemplifies, from example to requirement.
  - exercises, against candidates.
  - demonstrates, a use case end to end.
