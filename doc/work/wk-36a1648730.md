## detail

Found reviewing wk-70dde20ba7 (delta is the token's).

thePathsWrittenOn in src/engine/tests.go reads and unmarshals every .json under undoDir on every se test call, to collect a set of path names.

MEASURED on this tree, 2026-09-05: .se/undo holds 289 entries and 3.2 MB, the largest a single 74 KB entry. Every one is read whole and parsed on every call, because an entry carries what each file held before the apply, which is the file's whole content. The comment above the function says it reads the names and not the content; the code reads the content and throws it away.

The folder grows with every apply any hand makes on the box and is only drained by a retro, so the cost of asking se test what a token wrote climbs with how much work the box has done, for an answer that is a handful of strings.

The entry name is a UTC timestamp, so the folder sorts newest first by name, and a token carries the snapshot it began at. An apply written before a token began cannot be that token's, so the walk can run newest first and stop at the first entry older than the token's began. That reads a few entries instead of all of them, and the answer does not change.

## proposed action

Walk the undo folder newest first and stop at the token's snapshot, instead of parsing every entry on every call.
