## detail

Publish in src/engine/claim.go and SyncClaims in src/engine/claimsync.go both run `git fetch --quiet origin refs/se/claims:refs/se/claims`. That writes the remote's ref over the local one, and git refuses it as soon as the local ref holds a commit the remote lacks, which is the state of every box that has claimed anything and not yet pushed.

Reproduced on a cloud box on 51b0d06: local refs/se/claims at 3e09c740, remote at ec254bab, merge-base ec254bab. `git fetch --quiet origin refs/se/claims:refs/se/claims` exits 1 and prints nothing. Without --quiet it prints `! [rejected] refs/se/claims -> refs/se/claims (non-fast-forward)`. The engine's answer is therefore "The push did not run: git fetch: " with nothing after the colon, on every claim.

Two consequences. Publish never reaches its rewrite-on-top step, so a push that failed once never recovers. SyncClaims stops reading other boxes' claims the moment this box has one unpushed claim of its own, and says "no claims reached this box" with an empty reason.

## proposed action

Fetch into a ref of the remote's own, not the local one: `fetch origin +refs/se/claims:refs/se/remote-claims`, then writeTheClaims builds on that head and moves refs/se/claims to it. SyncClaims lists refs/se/remote-claims. The error string carries git's stderr, so --quiet goes, and the test that drives the real git holds the case where the local ref is ahead.

## done when

- a Publish whose local refs/se/claims is one commit ahead of origin reaches its second push, decided by: go test -C src/engine -run 'Publish.*Ahead' ./... answers ok
- a SyncClaims on a box with one unpushed claim lists the claims another box pushed, decided by: go test -C src/engine -run 'SyncClaims.*Ahead' ./... answers ok
- a fetch git rejects reports git's reason after the colon, decided by: the same tests assert the string contains 'non-fast-forward'
- sh util/checks/battery.sh reports no new failure against the run before the change
