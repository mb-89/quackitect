## detail

The schema gives every frontmatter field a description, and the generated template writes it as a comment above the field (src/engine/template.go, Template). A token minted through se work writes bare frontmatter, so a minted file loses the comments: .se/work tokens carry no field guidance, and the ruling in cross-cutting 4d says the description belongs where the field is. The checklists already ride along on a mint (work.go, Checklists). The comments do not.

## proposed action

Have the mint write its frontmatter through the same writer the template uses. Each field it writes is then preceded by its schema description as a comment, and the two outputs cannot drift.

## done when

- a token minted by se work carries each frontmatter field's schema description as a comment above it. A test mints a note token and reads the file
- one function writes the frontmatter for both the template and the mint, checked by reading template.go and the mint path
- the test was seen red against the current mint before the change
