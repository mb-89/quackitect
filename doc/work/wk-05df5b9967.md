Measured here on 2026-09-05. A stop refused twice with "1 NOTE(S) ARE STILL OPEN, AND THEY DIE WITH THIS BOX", naming wk-ac18ea020a. A claim on that id answered "it is claimed by aeaf7bd9/reviewer-nono, wait for that claim to lapse". So the gate demands the note be turned in, and the claim refuses the only call that turns it in. No session on this box satisfies both.

Two faults, and they are separable.

One, the count is not true. The gate says the note dies with this box. This one does not. It lives in doc/work, which git carries, and its own detail records that an earlier session moved it there from .se/work for that reason. The gate counts by kind, note, rather than by where the file sits.

Two, a claim outlives the box that took it. A reclaimed box cannot release what it holds, so every note it claimed is frozen for the rest of the window. That is the shape of the claims problem on wk-4759d90994: a cloud box cannot publish, and it cannot release either.

The note's content is not urgent. It carries a verdict for wk-fc6b6c5aa7 that reviewer-hazel is giving live, so dropping it loses nothing.

## proposed action

Decide which half to fix. The narrow fix stops counting a note against the gate once it sits in doc/work, because the gate's reason for counting is that notes die with the box and a tracked one does not. The wider fix lets a claim be broken when the box holding it is gone, rather than only when the window runs out. A person picks, because the wider one changes what a claim means.
