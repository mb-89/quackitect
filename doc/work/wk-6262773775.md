## detail

CLASS: A CRITERION WRITTEN AFTER THE CHECK IT IS SUPPOSED TO DECIDE, SO THE
SENTENCE DESCRIBES THE CHECK INSTEAD OF DEMANDING SOMETHING OF IT.

The bug is urgent, the work lands first, and the spec is drafted afterwards
from the thing that was built. The criterion then reads as a demand and it is a
description, and the gate cannot tell one from the other because the command is
green either way. A drafter who has the check open writes the sentence the
check almost satisfies, and the words that carry the gap are the reviewer's own
words from the last round, borrowed because they read well.

TWO SHAPES, AND BOTH ARE ON ONE TOKEN. The sentence says every over a set the
check samples: the check walks eight functions, the sentence says every notice
the engine builds, and the engine builds eighteen. And the sentence names the
rule the check does not implement: the sentence says a rule rather than a list
of messages, and the check is three strings.

WHY IT IS WORSE THAN AN ORDINARY DRIFT. Nobody is going to write the check
afterwards, because it is already written and green, so the gap never gets a
second chance to be noticed. And the criterion carries a recorded red, taken on
the half that was built, so the record says somebody watched it fail.

MEASURED ON wk-40ae28cd1a. I put one bad command into a notice a name-matched
builder returns and the check went red naming it. I put the same command into a
notice written as a literal at its construction site and the check answered 8
notice builders, 2 commands run, and passed. Then I put the command back inside
the walked builder and changed one word of the engine's refusal, read to
recognised, and the check passed again.

WHAT TO DO INSTEAD.

WHAT WOULD HAVE STOPPED IT BEING MADE. Write the criterion from the token's
sentence and not from the file that is open. Say what has to be true, then read
the check and ask what it would take for the check to be green while the
sentence is false: name that case out loud in the draft. Where the work is
already built, say so at the top of the detail and mark every criterion the
build already satisfies, so a reviewer knows which sentences were written
backwards and reads those first.

WHAT WOULD HAVE CAUGHT IT. For every criterion whose command is green on the
day the draft is written, construct one input that passes the command and
breaks the sentence, and either fail to construct it or fix the criterion. That
is the only test a green criterion has. Take the reds on the half the sentence
claims rather than on the half the check covers: if the sentence says every,
break a member the check was not built around, and if the sentence says a rule,
change the wording the rule is supposed not to depend on.
