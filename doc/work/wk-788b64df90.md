## detail

CLASS: TWO CRITERIA, ONE COMMAND, SO THE SECOND SENTENCE IS AGREED AND NEVER DECIDED. A drafter splits one property into two lines because the two really are different claims, which is right, and then puts the same command under both, because one test is going to cover them. The list reads as two decided things. The gate has one. Whatever makes the first green makes the second green, so the second sentence can be false at every moment of the token's life and no run will say so. IT IS DIFFERENT FROM COPYING A COMMAND OFF A NEIGHBOURING TOKEN, which doc/guidance/specifying.md already names as BORROWED, because there the command names a stranger's deliverable and a reader can see it does. Here the command is correct, current and green for a real reason, and the only thing wrong with it is that it is already spoken for. Nothing on the page marks it: the duplicate is visible only by putting the commands side by side, and a reader goes down the page sentence first. THE COST LANDS HARDEST ON THE SECOND OF THE PAIR, which is usually the subtler property, the one about HOW the check asserts rather than about what exists. MEASURED ON wk-2fb5bf5bb1: criteria 2 and 3 carry byte-identical commands, and criterion 3's sentence is the anti-vacuity rule that a refusal must be asserted on what only it can say. INSTEAD, AND THE FIRST HALF IS WHAT STOPS IT BEING MADE: write the command as you write each criterion, not in a pass at the end, and when you find yourself about to reuse the command above, stop and ask which of the two sentences it decides. One command decides one sentence. If a single test really covers both properties, they are one criterion and the second sentence belongs inside the first, and if they are two criteria they need two test names, which costs one function. THE SECOND HALF IS THE CHECK THAT CATCHES IT, and it is one line anybody can run on their own draft before submitting: pull the commands out of the done-when list and compare them for duplicates. Any repeat is either two criteria that should be one, or a criterion whose command has not been written yet. Do the same for the test names inside them, because two different commands running the same -run pattern is the same defect wearing different clothes.
