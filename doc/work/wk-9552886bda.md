## detail

Found reviewing wk-808abd40a4 (archive without a ref).

That token turned doc/work/archive.jsonl from a rendering of the tags into the record, and its own doc comment on WriteArchiveList says so: "A row naming a blob has no tag to be rebuilt from, so the list is where it lives." Its new test TestTheArchiveListRebuildsFromTheTags proves the rest of it: delete the list, call WriteArchiveList, and the file does not come back.

The comment on SweepClosed (src/engine/archive.go, around line 396) was left saying the opposite: "THE LIST IS LEFT RIGHT WHETHER OR NOT ANYTHING MOVED. A sweep with nothing to sweep is how the list is put back after it is deleted, and that is the whole claim that it is a rendering." That is no longer true and the code under it is worse than stale: SweepClosed ends with an unconditional WriteArchiveList(r), so a reader who follows the comment and sweeps to put a lost list back writes a list holding only what the tags carry, and every row naming a blob is gone for good.

Either the comment goes and the unconditional rewrite goes with it, or the sweep learns to refuse to write a list shorter than the one it read.

## proposed action

Rewrite the SweepClosed comment to say the list is the record. Drop the trailing unconditional WriteArchiveList(r), or guard it so a write that would shorten the list is refused. Cover with a Go test in src/engine that sweeps after the list is taken away and asserts no blob row was lost.

## done when

- the SweepClosed comment no longer claims the list is a rendering that a sweep puts back
- a sweep cannot replace an existing archive.jsonl with one holding fewer rows, or the unconditional WriteArchiveList at the end of SweepClosed is gone
- watched red first: a test that deletes the list, sweeps, and asserts the rows naming a blob are still readable, failing before the change
- TestASweepStillFilesWhatIsFinished and TestTheArchiveListRebuildsFromTheTags still pass
