## detail

The engine is a program that starts, answers one question and dies. It runs
five times per tool call. Nothing survives between calls, so every fact it
needs to remember becomes a file: the hold, the calls it is pairing up, the
active token, the claim, and now an owed answer. Each of those files is an
invention, and each one is a place two readers can disagree.

A resident engine on a local port would hold that state in memory. The guard,
the VS Code window and the MCP stub become three clients of one thing instead
of three programs reading the same folder and hoping.

WHAT TO SETTLE BEFORE BUILDING ANY OF IT:
- who starts it, and what happens to a hook that fires when it is not running
- whether the command line stays as a client of the same API
- which port, and how a second project on one machine does not collide
- what is still on disk, because the record must survive the process

The owner asked for this to be discussed rather than built.
