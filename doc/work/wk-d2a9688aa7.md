## detail

Found reviewing wk-212909368a, one build door. answersForItself at src/engine/swap.go:94 starts a binary with --version and reads it in a goroutine. When the budget at src/engine/swap.go:108 runs out it answers the error and returns, and nothing kills the process it started or waits for it. On the built path planSwap then removes .bin/se.next while a process is still running from it, and on Windows that removal fails, so the abandoned program keeps an open handle on a file in .bin. That handle is exactly what PutAside and SweepWhatWasReplaced are built around: a file that will not move is one a process is still running from. So one binary that starts and never answers leaves the tree unable to replace its engine until somebody finds the process and kills it by hand, which is the ritual this token exists to end. The goroutine holding the pipe is left behind with it. The fix is one line: kill the process on the timeout branch before answering, and let the goroutine finish.

## proposed action

On the timeout branch of answersForItself, kill the process it started and drain the goroutine before returning the error, so nothing is left running from a file the swap is about to move.
