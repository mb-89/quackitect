## detail

CLASS: ONE FIELD WITH TWO WRITERS, EACH TESTED ALONE, SO THE SECOND WRITE
REPLACES THE FIRST AND NO CHECK RUNS BOTH.

A round widens a rule to a second path. The refusal is added there, the write
is added there, and each gets a test of its own that starts from an empty
record and ends with one value in it. Both tests are honest and both pass. The
work then goes through both paths in order, and the second write is a plain
assignment, so what the first path recorded is gone. Nothing sees it, because
no test runs the paths in the order the work does.

WHAT MAKES IT INVISIBLE. The pair of tests looks like thorough coverage: one
per path, one per refusal, one per keep. Coverage per path is exactly what
cannot see a collision between paths. And an assignment reads as the obvious
way to store a value, so nobody records a decision about what happens to what
was there.

MEASURED ON wk-7f0b46d99f, round 4. The spec acceptance and the implementation
acceptance both refuse when nothing is re-watched and both write the map to the
token. I drove one token through both in order: the spec reviewer's observation
is written, and the implementation acceptance replaces it with its own. With
nothing sent at the second acceptance, which is legal when the token owes none
there, the record is left empty and the first reviewer's observation is gone.

WHAT TO DO INSTEAD.

WHAT WOULD HAVE STOPPED IT BEING MADE. A field written by more than one path
has a merge rule, and an assignment is a merge rule chosen without deciding.
When you give a second path the same field, ask what the first one wrote and
write the answer into the token: the second replaces it, the second is added to
it, or the second is refused while the first stands. Say which, and say it
where the field is declared, because the next path added to that field will be
written by somebody reading the declaration.

WHAT WOULD HAVE CAUGHT IT. Write one test that drives the paths in the order
the work actually goes, from a token at its first state to its last, and
assert what the record holds at the END rather than after each step. A test per
path starts from an empty record every time, so it can prove each write happens
and can never prove they survive each other.
