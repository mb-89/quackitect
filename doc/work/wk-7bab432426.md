## detail

THE SEARCH GUARD REFUSES A SEARCH OUTSIDE THE TREE, AND ITS OWN REFUSAL SAYS IT WILL NOT.

Its last line reads: OUTSIDE THIS TREE THE DISK IS YOURS: a search naming a path outside it is not refused. Measured here on 2026-09-05, through se run: a call naming rg, a pattern and the path /root/.ccr/README.md was refused with exactly that message. The path is outside the tree.

So the guard reads the tool name and refuses, without asking where the paths point. A reader who does what the refusal tells them gets the same refusal again, which is the worst shape a guard can have: it teaches nothing and there is no next move.

It cost a criterion here. wk-5b5ede3926 asks that a command naming rg run through the engine and resolve, and the only way left to answer it was command -v rg, which proves the PATH and not the run.

The guard is right about the tree, and that half should not move. A search over the tree goes through the index, and se find is the door.

## proposed action

Ask where the paths point before refusing. A search whose paths all lie outside the work root goes through. One naming a path inside it, or naming none, is refused as now and still names se find. The refusal's last line then stops being a promise the guard breaks.

- a search naming a path outside the tree runs through the run verb, decided by: rg with a pattern and a path under /root or /tmp answers rather than being refused
- a search naming a path inside the tree is still refused and still names se find, decided by: the same call with a path under src/ answers with the index refusal
- both cases are a test in src/engine, seen red first on the outside case
