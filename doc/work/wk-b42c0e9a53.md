## detail

A write into util/checks/ is refused, the way a write onto a projection is refused. It is a refused destination and not a refused form: the file is fine, the place is not. The refusal names where it goes instead, which is .se/scratchpad/. The retro is the one moment the guard opens.

THE RETRO DRAINS THE SCRATCHPAD AND FILLS THE CHECKS. That is one act with an order, not a sweep. It reads what is in the scratchpad, judges each script, writes what earns its place into util/checks/, and clears the rest. Nothing standing is ever at risk, because the promotion happens before the clearing.

That corrects wk-964cd3a1d4, which moved the standing checks out of the scratchpad because a sweep would take them. The premise was a retro that deletes blindly. A retro that fills before it drains does not need the checks kept somewhere else to be safe.

THE RETRO DECIDES THE FORM AS WELL AS THE FATE. A script that earns its place does not have to stay a script. It may be rewritten in Go, folded into the battery, or turned into a rule se lint already carries. What an agent wrote in an afternoon to answer one finding is a sketch of a check, and the retro is where it becomes one.

THE ONE-TIME CORRECTION. Nothing now in util/checks/ arrived through a retro. Every file there was written by main, the worker, promoted by hand, mid-work. counts-are-derived.py was written straight in on 1 September and is already gone. no-lone-escape.mjs appeared during a single conversation on the same day and its name was added to the battery in the same stretch. So the whole folder goes back into .se/scratchpad/ and the first retro judges it properly, one script at a time.

THE REFERENCES MOVE WITH IT, and se move is the verb: it moves a file and rewrites every reference. It covers .md, .canvas, .base and .txt, which is what the token criteria, the battery list, AGENTS.md and doc/guidance/behaviour.md are. Know its edges before relying on it: source files are rewritten in the path form only, and a file with no extension has been reported unrewritten and left, which util/checks/trycmd is.

So this migration is the first act of the first retro, not a change made underneath agents mid-round.

A GAP IN THE PRECONDITION, WORTH DECIDING. The intended rule is that a retro cannot run while work is open. The engine refuses only while somebody HOLDS a token, and retro.go says that narrowing is deliberate, because a refusal covering everybody who has pulled would refuse nearly always. Escaping a scope leaves its tokens open and visible, so an escape followed by a retro runs a sweep over open work. If the rule is meant to be no open work at all, that is a change, and escape is the hole to close.
