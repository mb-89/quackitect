## lesson 1 · round 2 · by reviewer

**the class:** A value keyed by identity, written through a helper whose identity argument has a default. Keying the store was the fix and it is a real one, but a default turns the key into a constant everywhere the caller does not know its own name, which is precisely the callers that needed the key. So the data structure says per actor and the behaviour says main, and the two disagree only on the path everybody actually uses, which is why the tests around the structure stay green.

**instead:** Where a value identifies who is acting, refuse rather than default. A missing actor is a caller that does not know who it is, and guessing on its behalf writes somebody else's record under their name. Make it required, or make the operation a no-op without it and let the layer that does know do the write. Then trace it from the outside in: find the path a real agent takes, which here is the stub shelling out to the engine, and check what that path passes rather than what the function signature allows, because the default is invisible at every call site that relies on it.

## lesson 2 · round 3 · by reviewer3

**the class:** A store given a key and never a lifetime. The work here was all about the key: one flag became a map from actor, the defaulted actor was taken out of the two verbs that could not know who was calling, and each of those was right. What nobody asked is when an entry stops being true. A fact about a running agent, kept in a file, is only true while that agent is running, and the file cannot tell: it holds the name and the words and nothing that decays. So the same store that stopped blocking everybody on one message now blocks a name that will be handed to somebody else on a message from three hours ago.

**instead:** For every fact written to a file, write down two things beside the key: what makes it true and what makes it stop being true. If the second answer is nothing, the fact is permanent, and almost nothing about a running process is. Then look in the same tree for a fact of the same lifetime that has already been solved - here arrivals.json is a per-session fact in the same folder with the reset written into its loader - and use its shape rather than inventing a second answer. And when the file's own comment names a failure it prevents, go and check whether that failure is happening now, because a comment records what was fixed once and not what the system does today.

## lesson 3 · round 4 · by reviewer4

**the class:** One fact with two writers, and a round that fixed the writer it was looking at. The obligation is written from three places. Round 2 correctly took the wrong key away from the verb that could not know it, on the stated promise that the guard would write it instead, and that promise is now a comment in owed.go. Nobody checked that the guard's write was reachable for the same input. It is not: it sits behind a de-duplication against the very record the removed writer had just populated, so taking the bad write out took the only write out. The tests around each writer stayed green because each writer is right about itself. What is wrong is the handoff between them, and no test looks at a handoff.

**instead:** When you take a write away from one place because another place does it better, do not stop at the removal. Enumerate every writer of that fact in one pass, put them in a table with the input each one sees and the condition each one is gated on, and hunt for an input that now reaches none of them. If the writer you are relying on has a guard clause of any kind, and especially a de-duplication against a record the removed writer still populates, then the removal and the guard clause cancel each other out and the fact is never written at all. Then write the check as a handoff check and not a unit check: drive both writers over the same input in both orders and assert the fact is written exactly once, because a defect that lives between two correct components is invisible to a test of either one. And when the project's own guidance names a path as the fallback for the case the automatic writer cannot cover, that path is the first input you try, not the last: by definition it is the one the automatic writer will not reach.
