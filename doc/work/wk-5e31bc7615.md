## detail

The cage rests on a table nobody on this box can read, and two open tokens ask for that table to be corrected.

.claude/settings.json and util/cage/claude-settings.json both end their comment with: what each event fires was measured off the record, and the table is on wk-218e541ec2. That token is nowhere. Measured on this box: no note under doc/work or .se/work names it, no row in doc/work/archive.jsonl carries it, no commit message on any branch mentions it, and no tag under archive names it. The spike was a private note on another box, so it never travelled, and the measurement it carried went with it.

So the shipped cage cites a source that cannot be reached, which is the same fault wk-8ab502ee9d and wk-977319bccb were minted about. wk-8ab502ee9d asks for a third legend mark and a desktop Code tab column in that table, and wk-977319bccb asks for the query behind its counts. Neither can be worked while the table is gone, and neither can be closed by inventing numbers.

The counts cannot be recovered by reading. wk-977319bccb already measured that the record carries the engine's own kinds and not the harness event names, so the mapping from a kind to an event was the measurement and it is written down nowhere.

## proposed action

Decide first whether the measurement can be had at all, because everything else waits on that.

If the spike's box can still be reached, recover the note and commit it under doc, then do the three corrections wk-8ab502ee9d asks for. If it cannot, re-drive the events under each harness and write the table fresh, with the query beside it.

Either way the cage comment must stop citing an id that resolves to nothing. Until the table is back, the honest sentence names what is unmeasured rather than pointing at a note.
