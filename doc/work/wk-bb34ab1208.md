## detail

A PRESS ON A ROW TICKS IT. Every column ticks, the first one included: not
being editable is not a reason not to be selectable, and somebody ticking four
rows should not have to aim at the second column.

THE TITLE TEXT IS THE DOOR, and only the text. It underlines under the pointer,
and that underline is the promise: press the underlined words and the note
opens, press anywhere else on the row and the row ticks. Today the whole cell
is a link, so there is no way to tick a row at all.

v3 did this with a double press on the row rather than an underlined word. The
owner asked for the underline, which is the clearer promise, so this is not a
verbatim port of that part.

TICKED ROWS MAKE A GROUP. With rows ticked, one control files them into a
bucket, and a bucket is the person's own name for a group.

A BUCKET DOES NOT MOVE THE WORK. The status stays exactly as it was and only
the grouping changes. That is the whole difference between a bucket and a
state, and it is why the view groups by if(bucket, bucket, status).

THE BUCKET IS MADE FIRST AND NAMED AFTERWARDS. A webview refuses a browser
prompt, so v3's control that asked for a name did nothing at all when pressed.
An empty name asks the engine for a fresh one, because the engine knows what is
already taken and the client would have to guess.

RENAMING NEEDS A BUCKET AND NOT MERELY A SELECTION. A row grouped by its status
has no bucket to rename, and a status is the system's word rather than the
person's.

Ported from v3 engine/workclient.ts, the ticking and the two acts that need a
selection, lines 190 to 345.

## evidence: a bucket does not move the work

The status stays exactly as it was and only the grouping changes, which is the whole difference between a bucket and a state. The view groups by if(bucket, bucket, status), so a token carrying a bucket groups under it.

## evidence: a status is not a bucket

RenameBucket refuses to rename a status and says why: a status is the system's word for where work stands, the pull moves it, and the way in is to file the rows into a bucket of your own first. It also refuses to name a bucket after a status, because two things with one name is two things a reader cannot tell apart.

## evidence: checked in Go

source/engine/bucket_test.go, five tests: filing leaves the status alone, an empty name asks the engine and two of them differ and neither is a status, an agent cannot make a bucket, a status is not a bucket in either direction, and renaming moves every token in the bucket and nothing else, and refuses a bucket nobody is in.

## evidence: the controls say what they can do

The bar carries a count of what is ticked, a Group button and a Rename button, all hidden until something is ticked. RENAMING NEEDS A BUCKET, NOT MERELY A SELECTION: rename is disabled when the ticked rows are grouped by a declared group, and its tooltip says a status is not yours to rename.

## evidence: the door swallows its press

The door's handler calls stopPropagation, so opening a note never ticks the row underneath it.

## evidence: the engine side

source/engine/bucket.go. FileInBucket writes one bucket on every id and answers its name; an empty name asks freeBucketName, which knows what is taken and skips any name that is a status. RenameBucket writes one name over another on every token carrying it. Both go through WriteFieldBy, which already refuses a bucket from anybody but a person.

## evidence: the name is typed on the bar

No dialog. A webview refuses a browser prompt, which is why v3's control that asked for a name did nothing at all when pressed. So the group is made first and named afterwards: the button sends no name, the engine hands back a free one, and Rename opens a field on the bar with Enter to commit and Escape to drop.

## evidence: the press ticks, the text opens

editor.ts rowHtml wraps an opening cell's value in a span.door, and only that span carries the click and the underline. Every row carries a click that toggles class ticked. So every column ticks, the first one included, and somebody ticking four rows does not have to aim at the second column. Before this the whole cell was a link and there was no way to tick a row at all.

## evidence: the verbs

se work --file <ids> --by person, with optional --named. se work --rename <name> --to <name> --by person. Both write a record line naming who did it and what moved.

## evidence: what is not built

Dragging a row into a group. The drag handler that exists drops a row into a group heading and writes a field, and it predates this token. Dragging a user group onto a state is the owner's later work and is not here.
