## detail

The person presses the update button to ask what is happening. The agent answers. The button stays down.

It is a toggle, and a toggle draws what it last was pressed to. This one is a request rather than a state, so nothing puts it back up when the request is served.

So the panel says an update is being asked for long after it was given, and the only way back is to press it again.

The shape to reuse is already there. The hold button moves on what the engine says rather than on what was pressed, so the panel can already be told to redraw a control from outside. The signal is the answer landing in the record.

## proposed action

Put the button back up when the answer lands.

Read it off the record rather than off a timer: the engine writes the answer, and the panel already watches what the engine writes.

Leave the pressing half as it is. What is missing is the release.

## done when

- the update button is up again once an answer is in the record: a check drives the panel, presses it, writes an answer and reads the control state
- the button stays down while no answer has landed: the same check reads it before the answer
