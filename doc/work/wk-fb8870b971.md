## detail

Nothing on a token says how long the work takes, so nothing can size a claim. A claim lasts a set number of hours, and the batch a box claims has to be what its hands can finish inside that.

The ruling: the agent estimates at the mint. The retro reads git for how long the token took, between the began and ended hashes the engine already writes, and calibrates from the difference. Both numbers live on the token.

So the token gains an estimate the minter gives, and an actual the retro derives. The calibration is a factor over an agent's estimates rather than a number typed anywhere.

## approach

An estimate field on the work token schema, given at the mint and refused where it is missing. The retro reads each token's began and ended commits for the wall clock between them, and writes the actual beside the estimate.

A calibration factor per agent comes from the two numbers. The claim then sizes a batch by summing calibrated estimates until the claim hours are full.

## done when

- the schema carries an estimate field, decided by: read the work token schema
- a mint without an estimate is refused, decided by: mint one without it and read the answer
- the retro writes an actual onto a closed token, decided by: run the retro over a token carrying began and ended hashes
- a claim sizes its batch from calibrated estimates, decided by: a test over tokens whose estimates run past the claim hours
