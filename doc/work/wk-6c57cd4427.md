## detail

From the verdict on wk-30821724fc, spawns take a context.

handOver in src/engine/swap.go gained a refusal at its top: `if err := ctx.Err(); err != nil { return fmt.Errorf("this engine is ending, so it starts no successor: %w", err) }`. Nothing can reach it. The only caller is main.go's swap arm, and the context it hands over is the one main makes at the top of main(); the only thing that cancels it is `defer cancel()`, which runs after main's loop has already returned. release() stops the indexer and closes the hook listener, it does not cancel. So the branch cannot fire in production, and no test drives it: the two tests the token added cover realGit and ProbeTools, not handOver.

The dead weight is an error path a reader has to reason about and a behaviour the suite cannot see. The token's approach says handOver "starts nothing once it is cancelled, and says so" — this is not an argument with that approach, it is that the sentence is currently unverifiable.

Either give it a test that calls handOver with a cancelled context and sees it refuse without starting a process, or take the guard out and say in the comment that main never cancels before the swap.
