## detail

A CLOSED NOTE LIVES BEHIND A TAG, AND A CLOUD PUSH CARRIES NO TAG. When a token closes, the archive writes its note into a commit under refs/tags/archive/<id> and the row in doc/work/archive.jsonl names that tag. The row travels with the branch and the tag does not, because a push to refs/tags answers HTTP 403 on a cloud box. Measured on this box at 19:50: 237 rows in the archive, 238 tags here, and 148 of those notes had never been on the branch. Any clone but this one could open none of them. aa19106e put the 148 back under doc/work as recovery, which the sweep will take out again. wk-808abd40a4 made the row carry a blob hash as well as a tag, and a hash written in a text file makes nothing reachable: a fresh clone fetches the branch and the object is not in it. So the durable half is missing. The note has to sit in a tree the branch reaches.

## proposed action

Keep the closed note in a tree the branch carries, so the object travels with every fetch. One shape is a folder such as doc/work/archive/<id>.md written by the close in the same commit as the row, so the row and the note land together and the sweep never sees it. Another is the claims branch pattern, a branch of its own for archived notes. Pick one on the token before the work, and measure it with a fresh clone that opens a note closed on another box.

WORKER-MAPLE LEANS TO THE FOLDER, and the finding below says why and what it costs. The pick fixes the shape of the record every box reads, so it is the owner's.

## evidence: the finding

THE WORK WAITS ON A PICK THAT IS NOT A WORKER'S.

Origin's archive already carries two copies per row. The blob is exact and
reachable from nothing. The on_branch copy is the note as the branch last
committed it, one close behind. So a fresh clone opens a closed note today,
minus the lines the close wrote. What the ask adds is the exact copy in a tree
the branch reaches, and it offers two shapes for that.

THE FOLDER SHAPE keeps the list's own reasoning: archive.go says the list is a
file on the branch so that archiving needs no ref and no push a box might be
refused. A folder beside it needs the same nothing. Its cost is one file per
closed token under doc/work/archive, 237 today, and the sweep has to be taught
to leave that folder alone.

A BRANCH OF ITS OWN keeps doc/work small, and needs a second push per close on
the boxes where the tag push answered 403, which is the fault the detail names.

So the folder is the safer of the two, and the pick is written here for the
owner to confirm or overturn before anybody writes the test.
