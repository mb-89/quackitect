## detail

.se/undo records, per se_apply, the file's pre-write content under "was" and only a sha256 of the result under "applied". The text an author applied is never stored. Combined with .se/work being untracked by git, a token file wiped by the resident engine's submit is unrecoverable. The one exception is a later se_apply that happened to journal the wiped text as its own "was". That is why wk-024bb669f0 was dropped: wk-eabe5523ab's only journal entry holds the blank template, and wk-641e205a7a's holds a state one apply short of final. Storing the applied result, or a reversible diff, next to the hash would make these recoveries possible.

## proposed action

Read the src/engine writer that emits .se/undo records. Add the post-write content, or a reversible diff, next to the applied hash. Write the reconstruction test first and watch it go red.

## done when

- an undo record carries enough to reconstruct the file as it stood after the apply, not only a sha256 of it
- a test applies twice to one file and rebuilds the intermediate state from the journal alone
- the existing undo path still reverts as it does today
