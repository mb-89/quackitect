## detail

wk-0a418a53ac gave every archive row the copy that travels where the branch has one. Six rows have none, and nothing in the archive's present design can give them one. The answer is a decision, so a person reads this first.

MEASURED. doc/work/archive.jsonl holds 85 rows. A clone made with `git clone --no-tags --no-local file:///home/user/quackitect` carries the objects of 79 and none of the objects of wk-3bad905ec0, wk-5002ef7c5f, wk-59f957dc38, wk-781c94fff2, wk-97e8bd9f38 and wk-f7153c420e. util/checks/archive-rows-travel.mjs reads the same off the branch and names the same six.

WHY THEY CANNOT BE FOLDED. `git rev-list --full-history HEAD -- doc/work/<id>.md` answers nothing for each. Their notes were committed only on refs/se/steps, which nothing pushes, so no commit a clone is sent carried the file. The copies left are the blob the close wrote and a tag the git proxy refuses to push.

THE DECISION, and none of the three is the worker's to pick. The row could carry the note's bytes, so the list that travels carries the content. The notes could be committed onto the branch once, which puts the engine in a person's history. Or a note the branch never carried could be accepted as box-local and the check taught to say so.

util/checks/archive-rows-travel.mjs is out of util/checks/battery.sh today, because a check that lands red holds up every agent here.

The archive row gains one optional field, carrying the note's bytes. It is written only where the branch holds no copy, so seventy-nine rows are untouched and six carry their own text. A reader in a fresh clone reads the row and has the note.

The check stays the one that already names them. archive-rows-travel asks git for the objects a row names, and it passes a row that carries its own bytes instead.

The other two answers are the person's to prefer. Committing the six notes onto the branch puts engine writes into a person's history. Accepting them as box-local keeps the archive honest and gives the reader nothing.
