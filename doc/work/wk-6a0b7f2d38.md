## detail

Two readers parse a filter. One is src/viewer/filter.go, which reads the syntax of the log, in module quackitect/viewer. The other is src/engine/internal/expr/expr.go, which reads a second syntax, and query and view import it.

The heading line is to carry a filter box, and what a person types there narrows what the panes draw without writing the view file. Whichever reader answers that box, the other one stays, and one of the two syntaxes is a second thing a person has to learn.

The ruling: there is one implementation, in a module that both import.

Two things stand between the tree and that, and neither is deep. A package under internal cannot be imported outside its own module, and expr sits under internal. The extension is TypeScript, so it imports no Go package at all.

Level 0 rules that an invalid expression does not empty the view, that it says so, and that it keeps the last good filter.

## approach

The reader becomes a module of its own, which the engine and the viewer both require. It comes out of internal, because internal is the marker saying no other module may import it.

The syntax of the log is the one that survives. A person types it, and the Level 0 rulings are written against it. The callers of expr move over to it.

The extension stays a caller rather than an importer. It builds its arguments in engineargs.ts and reaches the reader through the engine, so there is still one implementation and one syntax.

## done when

- one Go package parses a filter, decided by: search the tree for a second parser, which answers nothing
- the engine and the viewer both require the module holding it, decided by: read the two go.mod files
- the reader sits outside any internal folder, decided by: read the path it lives at
- an invalid expression keeps the last good filter and says so, decided by: type one into the box and read the panes
