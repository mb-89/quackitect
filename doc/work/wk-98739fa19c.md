## detail

Found reviewing wk-c698d46866. Publish in src/engine/claim.go recovers from a failed push by fetching the remote's claims onto refs/se/remote-claims, moving refs/se/claims to that head with update-ref, and writing the claim again on top. The comment beside the update-ref says moving the local ref loses nothing, because what it held is these same files.

That holds for one claim. It does not hold when the push fails for a reason that is not a race and stays failed: this box's pushes answer HTTP 403 from the proxy on every claim. Then each Publish drops the commit the previous claim wrote, because the local ref is moved to the remote's head and only this call's files are added back. A box claiming A, then B, then C carries only C on the ref when the push finally works. Measured here: the claim of wk-4cb6df2b99 answered rebased true and pushed false, on a box that had claimed before.

The token files carry claimed_by on the branch, so the claim itself is not lost, only the fast channel, and other boxes read the ref.

## proposed action

Before moving refs/se/claims to the remote's head, list the files the local ref carries past the merge base, git diff --name-only remote-claims..claims, and hand them to writeTheClaims along with this call's files. A fed-git test drives two publishes whose pushes both fail, then one that succeeds, and asserts the pushed ref carries all three files.

## done when

- a Publish after two failed publishes carries all three claim files on refs/se/claims, decided by: go test -C src/engine -run 'Publish.*Earlier' . answers ok
- the update-ref comment in src/engine/claim.go says what is kept and how, rather than that nothing is lost
- go vet -C src/engine ./... is green
