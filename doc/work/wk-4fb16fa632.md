## detail

The indexer is the engine's longest-lived goroutine. startIndexer in src/engine/indexwatch.go opens the index twice, listens on the model socket, starts serveModel and runIndexer, and hands back a stop function that closes a channel and the listener and waits. Nothing it starts takes a context, so a test that starts it has nothing to hand t.Context to, and a test that forgets stop leaves the index handles and the socket open past its own cleanup. Two tests on the record failed their TempDir cleanup that way.

This is the first part of wk-697f9876cf: the watcher and the socket server it owns. The spawned processes and the git and probe calls are the second part.

## proposed action

StartIndexer and startIndexer take a context as their first parameter. The context's end does what stop does today, once, through a sync.Once, and stop stays as the way a caller waits for the shutdown to finish. serveModel ends when its listener closes, which the same shutdown does, so the socket server has the same owner. Every caller in the engine passes the engine's context, and every test passes t.Context. One new test cancels the context, waits, and asserts the socket file is gone and the index handles are closed, by opening the tree's TempDir cleanup with nothing left behind.

## done when

- a cancelled context stops the indexer and closes the socket and both index handles, decided by: go test -C src/engine -run 'TheIndexerStopsWithItsContext' ./... answers ok
- every StartIndexer and startIndexer call passes a context first, decided by: se find --regex 'start[Ii]ndexer\((r|roots|ctx|t\.Context)' --path 'src/engine/**' answers only calls whose first argument is a context
- the existing indexer, live engine and bench tests pass unchanged in what they assert, decided by: go test -C src/engine -run 'Indexer|LiveEngine|AVerbRuns' ./... answers ok
- sh util/checks/battery.sh reports no new failure against the run before the change

## note

StartIndexer and startIndexer in src/engine/indexwatch.go take a context first. Its end runs the shutdown once, through a sync.Once, and the stop function a caller gets back runs the same shutdown and waits for the loop to end. Closing the listener ends serveModel, so the socket server has the same owner as the loop. main.go makes the engine's context with the one context.Background the engine keeps, and cancels it on the way out. The three tests that start an indexer pass t.Context or b.Context. The new test cancels, waits, and finds the socket file gone and the socket refusing a dial. It was red first as a compile error, because nothing took a context to hand.
