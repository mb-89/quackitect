## detail

batteryShell asks exec.LookPath for sh then bash. On a Windows without WSL installed, LookPath("bash") answers C:\Windows\System32\bash.exe, the WSL stub, because System32 is on PATH. It starts, prints "This application requires the Windows Subsystem for Linux Optional Component", and exits 1. So se_run answers shell sh and every command on this machine dies with that sentence, including `go version` and `cat doc/guidance/work-token.md`, while a working sh sits in Git's bin folder that shellsBesideGit already knows how to find. A lookup reaching a shell that cannot run anything is worse than one reaching none: the walk beside git is never tried and the cmd fallback never fires, so the machine has no working door at all. Smallest case: se_run with command `go version` answers exit 1 and that sentence.

## proposed action

Pass over a bash whose path is under the Windows system folder, or one that answers the WSL optional-component sentence when asked to run true, and carry on to shellsBesideGit.

## done when

- a bash that is only the WSL stub is passed over and the walk beside git answers Git's sh instead: go test -C src/engine -run TestTheShellSkipsTheStub
- a real sh on PATH is still the answer, and a machine with neither still answers cmd: the same test's other cases
- the places it looked name the stub it passed over, so a machine left with no shell says why: the same test's looked case
