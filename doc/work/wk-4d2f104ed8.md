## detail

A panel change can be green everywhere and absent from the window a person is looking at.

The extension runs src/extension/out/extension.js, built by src/extension/build.mjs. Nothing runs that build when a source file changes. A person reloading the window reloads the same stale bundle, so the reload they reach for is the one thing that cannot help.

The checks cannot see it. Every panel check imports panel.ts and bundles it fresh with esbuild, so each one tests the source and none tests the artifact. tooltips-name-their-keywords, drive-panel and render-check are all built this way.

The one measured here, on 2026-09-06. The keyword lines landed in panel.ts at 11:25. The bundle on disk was built at 11:21 and carried the string keywords zero times. Seven checks and eleven Go tests were green, the engine answered all thirty-two lines, and the owner hovered a button and saw nothing. They reloaded the window, which changed nothing, and asked what else they had to do.

So the report said the work was done, and it was, everywhere except the one file a person runs.

## proposed action

Say it out loud rather than fixing it quietly.

1. A check compares out/extension.js against every source under src/extension. A bundle older than what it was built from is a failure that names the file and the command.
2. It sits beside binaries-live-in-bin, which holds the same rule for the engine. The engine already refuses a stale binary and says swap first, so the shape exists.
3. Whether the build should also run by itself is a second question. Read how the engine's own rebuild is triggered before answering it.

Do not have the checks stop bundling the source. Bundling is what makes them fast and it is not the defect. The gap is that nobody compares the two.

## done when

- a bundle older than any file under src/extension fails a check that names the file and the build command, decided by: touch a source, run the check, read the failure
- the same check passes on a bundle built after every source, decided by: run the build, then the check
- the check is in the battery, decided by: se test, which lists it among the checks it knows
