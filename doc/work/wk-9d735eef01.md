## detail

A finding from the verdict on [[wk-fa90ae2cdf]], which it blocks nothing of. theStagingEscape in src/engine/stagestrangers.go walks every part of the pipeline and every word of each part, and takes any word beginning SE_STAGE_ANYWAY= as the escape. Its own comment says the escape is an assignment, and an assignment is a word before the program. Nothing here checks that. So `echo SE_STAGE_ANYWAY=x && git add theirs.md` opens the stage in a part that carries no assignment at all, and `git add theirs.md SE_STAGE_ANYWAY=x` opens it with a pathspec. The recorded reason then belongs to a command other than the one that staged.

## approach

Read the escape the way gitVerbAt reads a program: only from a leading assignment of the part that carries the git command, not from any word anywhere. Drive it with rows for the compound and the trailing-word shapes in TestTheStagingEscapeIsRecorded, both expecting a refusal.

## done when

- an escape word outside a leading assignment of the staging part does not open the stage: se test --propose TestTheStagingEscapeIsRecorded
