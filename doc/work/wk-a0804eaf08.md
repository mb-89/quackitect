## detail

The MCP schema for se_work carries no tracked field, so a lane call cannot say where a token is born. The engine refuses every mint of a trivial or standard token without it, saying to name where the token is born.

The shell door has the flag. So the lane can mint notes and nothing else, and every tracked token this session was minted through the shell.

That is one instance of a wider gap. The tool schemas are generated from structs in src/mcp/schema.go, and a field the shell door has can be missing there with nothing saying so.

So the fix has two halves. The missing field, and the check that says when the next one goes missing.

## proposed action

Add tracked to the se_work payload struct, then add a check that every engine verb flag has a field on its lane tool.

## approach

THE FIRST HALF IS ON THE BRANCH. se_work carries tracked, and the schemas are
read off the handler structs, so TestToolSchemasComeFromTheirStructs holds a
struct and its schema together. What nothing holds is the other drift: a flag
the engine verb has and the lane tool never grew a field for, which is how
--assignee and --as once got through.

THE CHECK IS COLD. It reads the tree and builds nothing.

    engine flags   the fs.String, fs.Bool, fs.Int and fs.Var calls between
                   flag.NewFlagSet("<verb>") and the next flag set
    lane fields    the properties of se_<verb> in util/cage/tools.json, which
                   colddoor_test keeps in step with the structs

A flag whose name, dashes read as underscores, has no property on its tool
fails, naming verb, flag and tool.

WHAT IS PASSED OVER, AND WHY. The shell's own flags: work, method, stdin, from,
template. One rename, by on the shell and actor on the lane. And a flag whose
own help says instead of minting, because that is a door of its own the lane
never claimed.

## approach

The field first. tracked goes on the se_work payload struct in src/mcp, so the generated schema carries it and the lane forwards it.

Then the check. It reads the engine verb flag sets and the lane tool schemas, and fails on a flag with no field. Seen red by taking tracked back out.

The check reads both sides from what the programs declare, not from a list somebody types. A list is the thing that goes stale, which is the defect this token is about.
