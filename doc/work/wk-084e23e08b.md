## detail

A box answers from .bin/se while the source has moved, and an agent reads that answer as the code's behaviour. Measured 2026-09-06, twice in one session. The pull kept handing out work on an unbound tree after the fix for that had landed, because the binary predated it. And every claim answered that its push did not run, naming refs/se/claims, after the relay had moved to refs/heads/se/claims. Rebuilding at 11:22 made the next claim publish. Both were reported to the owner as live defects and neither was one. The cloud-runner card already warns that the source you read may not be the program that ran. A session read the source, found the new constant, and still believed the old binary. Warning is not enough, because the agent has no way to tell the two apart at the moment it reads an answer.

## proposed action

Have the engine say when it is older than its source, in the answers agents actually read, rather than only in a card at session start. A stale engine that names itself stale cannot be quoted as the code's behaviour.

## done when

- An engine older than its source says so in what a tool call answers, and a test drives a tree whose source is newer and reads that line.
- An engine as new as its source says nothing, and a test drives that and reads the line absent.
- The line names the built time and the newer file, so a reader knows what to rebuild.
