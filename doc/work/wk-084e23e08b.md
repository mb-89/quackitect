## detail

A box answers from .bin/se while the source has moved, and an agent reads that answer as the code's behaviour. Measured 2026-09-06, twice in one session. The pull kept handing out work on an unbound tree after the fix for that had landed, because the binary predated it. And every claim answered that its push did not run, naming refs/se/claims, after the relay had moved to refs/heads/se/claims. Rebuilding at 11:22 made the next claim publish. Both were reported to the owner as live defects and neither was one. The cloud-runner card already warns that the source you read may not be the program that ran. A session read the source, found the new constant, and still believed the old binary. Warning is not enough, because the agent has no way to tell the two apart at the moment it reads an answer.

## proposed action

Have the engine say when it is older than its source, in the answers agents actually read, rather than only in a card at session start. A stale engine that names itself stale cannot be quoted as the code's behaviour.

## approach

Every tool answer is written by one function, `(*call).answerJSON` in src/engine/lane.go. The socket door proves it. `engineCall` sends the verb to the engine that lives, `runVerbInside` builds a `call` around a buffer, and the verb fills it. One seam covers every verb through both doors.

The measure is the running program, not .bin/se. `residentStale` compares .bin/se against the source, and the resident answers in-process, so a rebuild reads fresh while the old code still answers. A package var in enginefresh.go takes the executable's build time once at start, before a rebuild can overwrite it, and

    staleSays(r Roots, built, now time.Time) string

reads `newestSource` against it and answers `whyBuilt`'s sentence, which names the newer file, the binary and how old the build is. As new as its source, it answers nothing.

answerJSON marshals as it does now. Where the value is a JSON object and the sentence is not empty, it inserts that sentence as the first member, `stale`. Anything else passes through untouched.

Not this: se_ask and the model half of se_find answer through socket.go rather than through a verb, so they carry no line.

## note

Every verb's answer came through one function, and that function now dates it. staleSays in enginefresh.go read the newest source under src/engine against the running program's build time. answerJSON put the sentence on any answer that was a JSON object, as a member named stale.

The build time was read once, at start. .bin/se was the wrong subject to measure. The engine that lives answers every tool call in its own process. So a rebuild of that file left the old code answering while the file on disk read new.

The two doors met at this seam, because the lane sent its verb to that engine and runVerbInside built the call this fills. se_ask and the model half of se_find answered elsewhere, and carry no line.
