## detail

Every kind of note gets a schema, and everything about the note derives from it. That is the template a new note starts from, the comment on each field, validation, the dropdown for an enumerated field, and the note defining each allowed value. Start with the work token, whose fields are the frontmatter keys in src/engine/store.go and the four headings it reads. The size limits now in util/parameters.json, detail_bytes and section_bytes, become field constraints in the schema. The rulings are in doc/cross-cutting/cross-cutting-design.md, section 4d.

- se work mints a token from the generated template and every field carries its comment
- a frontmatter value outside its enumeration is refused at the save, naming the field and the allowed values
- doc/guidance/work-token.md loses every rule the schema now enforces
