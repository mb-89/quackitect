## detail

Archiving a closed tracked token writes refs/tags/archive/<id> and pushes it. A cloud box cannot push that namespace: measured on this branch, refs/tags answers HTTP 403 from the session's git proxy. archive.go:189 discards the push result with a bare assignment, and Archive then calls forget, which deletes the file from doc/work. So on a cloud box the tag is written locally, the push is refused silently, the file leaves the tree, and the next branch commit takes it off v4. The content then exists only in a local tag on a machine that is destroyed. Nothing is lost yet, because 122 tags stand locally and 122 on origin, so every close so far ran on a desk. The cloud is about to do the main work. THE TAG IS NOT THE ONLY COPY. The file was on the branch and its content stays reachable in history through the commit before the deletion. The tag is a stable name for something already there.

## proposed action

Stop making a tag. Record the blob in the archive list, which already travels on the branch, and retrieve with git cat-file. Nothing is pushed, so no namespace is refused and any box can archive. Where a push is still attempted anywhere, its failure is read rather than discarded, and the file stays on disk when it fails. The list is what a reader opens either way.

## done when

- a closed tracked token is archived on a box that cannot push a tag, and its content is retrievable afterwards from the branch alone
- no archive path creates or pushes a ref, decided by a search over src/engine for the archive namespace
- a push whose failure would lose content leaves the file on disk, watched red first against a stubbed git that refuses
- the 122 tags standing today are readable through the new list, or the change says why they are left alone
- sh util/checks/battery.sh reports no new failure against the run before the change
