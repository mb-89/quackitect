## detail

CLASS: A GUARD STANDING IN FRONT OF ANOTHER GUARD, WITH A CHECK THAT ONLY ASKS
WHETHER IT WAS REFUSED.

Two refusals sit one after the other and the second one catches, by accident,
everything the first one was written for. The first refuses the empty case with
a message that says what to do; the second refuses the malformed case, and an
empty value is also malformed, so it falls through and is refused anyway. The
test asserts that the call was refused. It is refused either way. Delete the
first guard and every check in the tree stays green, so nothing in the suite is
holding the message a person actually reads.

AND THE ASSERTION THAT WAS MEANT TO TELL THEM APART CAN BE FOOLED BY A WORD.
Where the test does look at the text, it looks for a fragment:
strings.Contains(wrong+satisfies, "mint"). The fall-through refusal says "the id
of a token you minted for the lesson", and "minted" contains "mint". So the one
assertion aimed at the message passes on the wrong message.

FOUND ON wk-c22f29af7b, whose entire subject is the refusal of a rejection that
names no token. Measured against the tree: take the
strings.TrimSpace(p.Learned) == "" block out of rejectionIsWhole,
src/engine/pull.go, and go test ./... on the whole engine answers ok. What the
reviewer is told degrades from "the lesson names no token, so it is a sentence
on a note somebody has to remember to act on / mint a token for the lesson with
se work, backlogged or open as you judge, and name its id in learned" to
"learned names , which is not a token: no such token: " -- a sentence with a
hole where the id should be and no instruction in it -- and no check anywhere
notices.

WHAT TO DO INSTEAD. When you add a guard, ask what the caller sees if you delete
it, and run the suite with it deleted before you believe the check. If the suite
is green, the guard is not guarded, and either the check has to assert on the
thing that changed or the guard is not earning its lines. A refusal's VALUE is
its message, so a check on a refusal asserts on the message: the distinguishing
phrase, not a fragment that a neighbouring refusal also contains, and one case
per refusal rather than one case that any refusal satisfies.

THE SAME QUESTION IN ONE SENTENCE: what would I have to break for this check to
go red, and is that the thing I just wrote.

THE CHECK, RED TODAY: give TestARejectionNamesTheLessonsToken two cases that
assert on the refusal's own words -- the empty-id case on "names no token" and
the not-a-token case on the id it was handed -- and it goes red the moment the
empty-id block is removed, which it does not today.
