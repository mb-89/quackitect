## detail

A finding from the verdict on wk-7c41d9e206, which made a build failure answer as a build and name the hand that wrote the breaking file.

Only the first chosen test in a package gets that name. In src/engine/tests.go, runChosen remembers a failed package as an empty binary in bins, and every later test in the same folder is answered by aBuildFailure with an empty said. With no compiler output, filesBuildNamed in src/engine/nored.go finds no file, so theHandsThatBrokeIt answers that the record cannot say whose write it was.

Seen at the door on this box. Two tests proposed over one broken package: the first answer named src/engine/snapshotnevertravelled_test.go and the token that wrote it, the second named no file and no hand. Both were refused as reds, so the rule itself holds and only the attribution is lost.

The fix is to carry the first build error for the package beside the empty binary, and to hand it to every later test in that folder.

- a test drives two chosen tests over one broken package and asserts the hand is named in both, decided by: se test on the new test
