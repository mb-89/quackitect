## detail

Found reviewing wk-808abd40a4 (archive without a ref), which made doc/work/archive.jsonl the only home for a row naming a blob.

src/engine/archive.go TheArchive reads that list with `if b, err := os.ReadFile(ArchiveList(r)); err == nil { read(string(b)) }` (archive.go:224) and drops any line that will not unmarshal as "a line nothing here wrote" (archive.go:213). Both failures answer the same as an empty list. WriteArchiveList (archive.go:241) then rebuilds the whole file from what TheArchive answered, and SweepClosed calls it with no rows to add at all (archive.go:400).

So a permission error, a short read, or one corrupt line does not fail the close: it silently shrinks the record on the next write, and a row naming a blob has no tag to be rebuilt from. That is the shape of the bug wk-808abd40a4 was written to remove, where the push result was discarded and the note deleted anyway. A missing file is the normal first-time case and must stay quiet; every other error must not.

## proposed action

In TheArchive, check the ReadFile error with errors.Is(err, fs.ErrNotExist): not-exist means no rows, anything else is returned. Have the line reader report that it dropped a line so WriteArchiveList refuses to rewrite from a partial read. Cover with a Go test in src/engine that makes the list unreadable and asserts the close fails with the note still on the disk.
