## detail

Every agent bound to the queue claims for itself, one token at a time. A claim is cross-box mutual exclusion written into git, so one claim per token per agent is one write to the constrained transport for every piece of work anybody starts. It is also more contention than the work needs: a claim lasts a window, and an agent that will do several pieces inside that window claims several times. The engine already has the shape. se claim --next 3 takes what the queue would hand you on three pulls, and --these takes a named set. Nothing needs building. What is missing is the rule that says to use it, and the reason.

## proposed action

Guidance, not code. An agent bound to the queue claims a block sized to what it can finish before the claim window closes, and works the block. Items that belong together are claimed together. Inside a box the agents take up what the box already holds and never claim for themselves, which is what the two levels are already for: a claim is between boxes and a hold is inside one. The bound is written down, because over-claiming parks work no other box can take until the window lapses.

## done when

- the guidance says an agent bound to the queue claims a block, and says what bounds its size
- the guidance says an agent inside a box takes up what the box holds rather than claiming again
- the standing layer carries it, decided by reading the projection rather than the source
- se lint answers clean over the guidance, and the standing-rule count moves by what was added
