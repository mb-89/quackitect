CLASS: A CRITERION THAT IS ALREADY TRUE WHEN THE DRAFT IS AGREED, HIDDEN BECAUSE ITS COMMAND IS RED FOR THE CHECK BEING ABSENT RATHER THAN FOR THE WORK BEING ABSENT. The engine already refuses a draft whose command criteria exit zero before anybody has worked, and the shape that walks past it is the two-part command: a search for the test function, and then the test. The search fails because nobody has written the test yet, so the whole command is red and the gate is satisfied, and nothing on the token ever asked whether the thing the sentence is about is already in the tree. The moment the worker writes the check it goes green over a file nobody had to touch. It is worse than an ordinary redundant criterion where the sentence walks two places and fails naming the one that is short, because one of the two arms is then inert on the day it is written and the failure message can only ever name the other. MEASURED ON wk-02e17b9eb4, round 3. Four criteria assert eight properties of one section of doc/guidance/specifying.md. I checked the eight strings against the section one at a time rather than reading it for an impression, and all eight are there, landed at 694def52, the same commit that wrote the redraft the previous round reviewed. INSTEAD, AND THE FIRST HALF IS WHAT STOPS IT BEING MADE: before writing a criterion, open the file it names and read the part it names, and where any of the claim is already true say so in the detail with the commit the reading was taken at, then narrow the criterion to what is owed. That costs a sentence, and it is the sentence that lets the next reader tell work already done from work still owed. THE SECOND HALF IS THE CHECK THAT CATCHES IT, and it is one command: run the content half of the criterion on its own, without the test-exists guard in front of it, against the tree as it stands. For a prose deliverable that is one search over the named section per property. Where it exits zero the criterion is asserting something already true, and where the criterion walks several places, run it once per place so you can see which arm can still fail. Paste what each answered into the draft.
