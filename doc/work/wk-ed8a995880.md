## detail

The tool lane has not been there when the agent started, six times over. The causes differ and the class is one: a server that must be spawned, answer a handshake and list its tools before the first turn. Measured on this branch. A config naming a build artefact a clone does not carry. A build run on the protocol path, so the harness timed the server out. A handshake answered in milliseconds with the tool list held behind it, so the harness took an empty set as the tool set for the whole session. Each fix made the window smaller and none made it impossible. Claude Code can register tools from a plugin inside its own process. A tool registered at session start is listed on turn one, with no server to spawn and no handshake to lose. The runtime is in the build here and a plugin loads, confirmed on this account. The shape this belongs to is doc/spec/one-core-many-satellites.md.

## proposed action

Level 0 becomes a plugin that registers the se_ tools in the harness process and answers each by asking the engine. It holds no rules. Where the engine does not answer inside the budget, the call goes on unchanged, which is the same fail-open the hook door has today.

## done when

- the se_ tools are listed on the first turn of a cold clone, with no server started, decided by a check that drives a plugin over a tree carrying no .bin
- a tool call made while no engine runs answers that none is running and refuses nothing
- a ruling the engine gives is applied, and one it does not give inside the budget leaves the call unchanged
- sh util/checks/battery.sh reports no new failure against the run before the change
