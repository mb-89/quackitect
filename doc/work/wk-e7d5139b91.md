## detail

Found reviewing wk-8797959d3c.

Its first criterion reads: a pull on an unbound tree hands out no token, and a test drives a close through an unbound tree and reads no token back.

src/engine/unboundqueue_test.go calls Pull with an empty Payload in both halves of its table. Nothing anywhere in it submits a payload carrying an id, so the close is never driven. The whole seam of the guard is that a submission settles above it, and that stands in a comment and in no check.

Measured on the tree at a2c87a9e, by a probe: a worker that is handed a token, ticks its step, is then unbound, and submits, leaves the token at status done with holder empty and is handed no token back. So the behaviour is right and it is the check that is missing.

## proposed action

Drive the close in the unbound case of TestUnboundTakesTheQueueOffEveryPathThatIsTheQueue: hand out, tick, unbind, submit the id, and read status done with no token back.
