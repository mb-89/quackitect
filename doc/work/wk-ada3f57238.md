## detail

THE CHECKLIST GATE NEVER READS THE EVIDENCE A SUBMISSION BRINGS.

se pull takes an evidence map, one chapter per step, and the notice on a handed token says to walk the checklist and answer every line, then submit. So an agent answers the lines in the submission itself.

In submit (src/engine/pull.go) checkEvidence(r, t, p) runs before t.Submission = keepingWhatWasNotSent(t.Submission, p.Evidence). checkEvidence reads only the tables the note already holds, and of the payload it reads nothing but the disposition. So a first submission whose answers are only in the payload is always refused, naming the first unanswered line, and the refusal returns before the merge, so the answers it carried are dropped as well.

Measured on wk-dab7999f44. A submission carrying both step tables, every line ticked with a sentence, was refused with: step 1, ask: this is not answered: the ask is small enough to review whole, or it is split first. The same answers written onto the note with se apply, and the same submission sent with no evidence at all, closed the token.

So the only way in is to edit the note first, and the evidence argument on the door is decoration.

## proposed action

Either the gate reads the submission and the note together, checkEvidence taking the merged tables so a payload answer counts; or the door stops taking evidence and says the note is where answers go. One of the two, not both.

## done when

- a submission whose answers are only in its evidence map closes a token whose note carries the blank checklist, decided by: a test in src/engine sends Payload with every line answered and sees the token close
- the note afterwards carries the answers the submission brought, decided by: the same test reads the note
- a submission that leaves a line unanswered in both the payload and the note is still refused, naming that line, decided by: the same test with one line blank

## evidence: the finding

THE MERGE MOVED AHEAD OF THE GATE, AND NOTHING ELSE MOVED.

Of the two ways the proposed action offers, the first is taken. The notice on
a handed token tells the agent to answer every line and submit, and the door
takes an evidence map, so the gate reading both is the one that keeps the
engine's own words true. Stopping the door taking evidence would have meant
changing the notice, the payload and every lane that sends one.

A submission's chapter stands in for the note's wherever both have one, which
is what keepingWhatWasNotSent already did after the gate. A refusal saves
nothing, so a merge that is then refused leaves the note as it was. The
refusal still names the first line blank on both, decided by the second test.
