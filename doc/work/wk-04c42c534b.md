## detail

The second pane shows when it should not, its button does nothing, and there is
no line between the two panes.

WHAT THE OWNER SEES: the right pane is on screen at boot. The button that
should show and hide it does nothing when pressed. When both are on screen
nothing marks where one ends and the other begins.

THE MARKUP SHIPS IT HIDDEN. Both the pane and the seam render with hidden set,
so something removes it after the page loads. Find what, rather than adding a
second thing that hides it.

THE SEAM IS ALREADY IN THE MARKUP and it is hidden too. v3 drew an upright seam
a person drags to set the width, which is where this came from.

## evidence: the checks

drive-editor.mjs presses the button and requires the pane and the seam to start hidden, to open together, and to close again, and it requires the seam to be drawn wide enough to see. one-look.mjs requires the shared sheet to set display on a control and to say what hidden means with an important, and it goes red when either half is missing: with the rule too quiet to win it reports that the sheet does not say what hidden means.

## evidence: the fix, in one line

The shared stylesheet now says what hidden means, louder than the browser does. That closes it for the pane, for the seam, and for every other control that ships hidden: the group and rename buttons in the toolbar were drawn for the same reason, clipped and out of line in a bar with no room for them.

## evidence: the seam a person can see

One pixel is a hairline, which is why nothing marked where one pane ended and the other began. It is four pixels of the panel border colour now, with a resize cursor, and the driver requires it to be at least three.

## evidence: what removed the hidden

Nothing removed it. The markup ships both the second pane and the seam with hidden set, and the page displayed them anyway, because an author's display rule beats the browser's own [hidden] before specificity is even looked at. .pane-wrap sets display flex and .seam sets flex, so both were drawn whatever the attribute said.

## evidence: what this does not do

The seam does not drag yet. v3 drew one a person drags to set the width and that is worth having, and it belongs with wk-cff23cb661, which rebuilds the editor as two instances of a generic editor with the shell around them. This token was about the pane showing when it should not, its button, and the line between them.

## evidence: where that check lives, and why not in the DOM

jsdom answers not-displayed for a hidden element whether or not the page says so, so a DOM assertion about it stayed green with the rule taken out. A check that cannot fail for the defect it names is not evidence, so the rule is checked over the stylesheet where it is written.

## evidence: which is why the button did nothing

The button was working the whole time. It toggles the hidden attribute, and the driven check proved that before this round. What it could not do was change what anybody saw, because the attribute had no effect on the page.
