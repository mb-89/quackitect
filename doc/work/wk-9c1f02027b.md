## detail

startBattery SPAWNS AND TAKES NO CONTEXT.

wk-697f9876cf asks that every spawn take the context that owns it. startBattery is the last one, at src/engine/battery.go. It starts the whole battery detached and answers where the output will be.

Its caller is TestTheDelta in src/engine/tests.go, which is a verb handler and has no context of its own, so the parameter cannot be added without giving the verb layer one. Four tests call it as well.

WHAT THE CONTEXT MEANS HERE IS NOT WHAT IT MEANS FOR A SERVER. The battery is started detached on purpose: it builds the engine and puts a new one over this tree, so waiting for it inside the process it replaces is waiting for itself. A context that killed the child would undo that. The context decides whether to start one, the way the handover's does, and it does not follow the child.

That distinction is why this is its own token rather than a line in a wider one.

## proposed action

startBattery takes a context as its first parameter and starts nothing when it has already ended, answering the cancellation. The verb layer passes the one it is given. The started battery is not killed by it, and the comment says so.

## done when

- startBattery takes a context as its first parameter, decided by: se find --regex 'func startBattery' answers a signature naming context.Context first
- a cancelled context starts no battery, decided by: a test in src/engine cancels and sees startBattery answer the cancellation with no run marker written
