## detail

src/mcp/mcp.exe is tracked in git at HEAD, and util/checks/binaries-live-in-bin fails on it: "a built program sits beside source. It belongs under .bin, and the installer, util/setup, is the one way to build".

It is the second of the two strays that check named. The first, src/engine/%S%/se-new.exe, is gone under wk-64421f7772. With that one removed the check still fails on this one alone: 335 file(s) looked at, 1 failed, run through se_test. So the check cannot pass over the tree while this file is where it is. Every token whose done-when asks for a clean run of it inherits this failure.

.bin already carries the lane's binary as se-mcp.exe, so nothing needs a copy beside the source. Unlike the other stray this one is in version control. Removing it changes what the project ships rather than sweeping a leftover. That is why it is its own token and not part of wk-64421f7772.

Whoever takes it decides between removing it from git and naming it in the check's notAStray list with the reason it stays, the way util/checks/trycmd/try.exe is excluded there.

## proposed action

Remove src/mcp/mcp.exe from git, since util/setup builds the lane's binary into .bin and se-mcp.exe is already there. If something does read it beside its source, exclude it in notAStray with that reason written down instead.

- util/checks/binaries-live-in-bin passes over the whole tree with 0 failed, run through se_test and the run named
