## detail

A finding on wk-4ad15a5c86, engine dies under load.

src/engine/tests.go:249 appends ran{ID: "the run", Kind: "landing", OK: true} when a run outlives theTestBudget, and tests.go:206 then sets out.OK = okOf(out.Ran). So the test verb answers ok true, and runTest exits zero, at a moment when no test has finished and the result is still landing in a file.

THE DAMAGE. The standard process grades the work step by "se test --on this token answered ok, and what it ran is named". A run cut at forty-five seconds answers ok before one test has finished, so that criterion can be ticked off an answer that ran nothing and whose landed result may be red. The whole-battery path at tests.go:201 carries the same shape, so one rule serves both.

THE CHECK. src/engine/engineload_test.go TestALongTestAnswersWhereItLands already drives the landing path and asserts got.Lands is set. It asserts nothing about got.OK, so the class is unguarded.

## proposed action

An answer that has finished nothing is not ok. Either leave OK false while Lands is set, or give the landing its own state the lane reads, and hold the same rule for the battery's answer at tests.go:201.
