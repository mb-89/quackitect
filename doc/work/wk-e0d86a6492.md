## detail

The engine reads the harness's event name into hookIn.Event, declared string at src/engine/hook.go:28, and switches on it: thirteen cases in the switch at line 523, a second switch at 443, and if-comparisons at 425, 431, 465, 485, 488 and 500. The same names are written back out as bare literals at hook.go:98, hook.go:1257 and guards.go:70. A typo in any of them is silent. The case never fires, the compiler says nothing, and the event falls through to the default.

writing-go rule 4 says a set of known strings is a named type with constants. So hookIn.Event takes a named string type, every event the engine handles is a constant of it, every case and comparison names a constant, and json.Unmarshal stays the one edge where an unchecked string arrives.

This is the src/engine half of wk-191014c633, which is two refactors in two packages and was put back three times for being one token.

## proposed action

Declare a named type, HookEvent string, with one constant per event the engine handles. Change hookIn.Event's type to it, replace every case and comparison with its constant, and leave the decode as the single place an unknown string arrives. Write TestHookEventsAreOneType first and watch it go red.
