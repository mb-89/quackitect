## detail

A fifth session-scoped store still compares against currentSession itself rather than through ofThisSession: the stop-claim register in src/engine/stop.go. This is NOT the token-claim relay (claim.go, claimsync.go, claimverb.go, refs/se/claims), which is somebody else's work.

src/engine/stop.go:178, StandingClaim: `c.Session == currentSession(r)` decides whether an actor's claim is still standing. wk-3dbfe11bbd taught the rule to loadStops, loadOwed, loadGrace and loadHolds; wk-38c4d9e04c taught it to the rung, the hold and the ask. This one was in neither.

The judgement lives in ofThisSession, src/engine/unbound.go: a log that names no session decides nothing, so the stored value stands. A rotation sets the full log aside and opens a fresh current that holds nothing until the next record lands, and the session name lives in the first record, so through that window currentSession answers the placeholder and matches no stored claim.

So a stop claimed a moment earlier reads as not standing through a rotation, and the agent is refused its stop with no claim standing when one was made. The claim is written with Session: currentSession(r) at stop.go:159, so in that same window a fresh claim is filed under the placeholder and is dropped once the log names a session again.

The smallest case: claim a stop in a named session, empty .se/log/session.jsonl the way a rotation does, and ask StandingClaim.
