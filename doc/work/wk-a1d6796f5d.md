## detail

standard.process.yaml declares three dispositions: done, became ('it turned out larger, and the successors carry it') and dropped. Nothing can write became except a verdict.

Found on wk-191014c633, which is exactly what became describes. It is two refactors in two packages, was put back three times for it, and was split into wk-e0d86a6492 and wk-3747494a3c. Ending it as became needs one of:
- se_pull with a disposition, which is refused off an open token: 'this step leaves the token at done, which standard does not end, so it cannot carry an ending'. Only the verdict step ends a standard token, and a verdict is a reviewer reading a diff that does not exist.
- se work --set --field disposition, refused with 'this program does not write "disposition"'.
- se work --abort, which hard-codes Dropped at src/engine/abort.go:65: t.Disposition, t.Reason = Dropped, a.Why.

So a token that turned out larger can only be ended as dropped, 'it is not wanted after all', which is not what happened. The disposition the process offers for a split is unreachable, and the record loses the difference between work abandoned and work carried on by successors.

## proposed action

Let an abort carry which ending it is. Add a disposition to Aborting, defaulting to Dropped, and let se work --abort take --disposition became with --successors, refusing became when no successor is named. Then the split that ends a token reads as a split.

## done when

- se work --abort with --disposition became --successors <ids> ends the token with disposition became and those successors on it, and is refused when became names no successor: go test -C src/engine -run TestAbortCarriesBecame
