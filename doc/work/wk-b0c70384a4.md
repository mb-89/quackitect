## detail

The panel is the desk's surface for a control, and a cloud box has none. KEYWORD:NAME=VALUE reaches eighteen controls through KeywordSaid, and keywordsFor in src/engine/keywordmoves.go answers the exact string the matcher takes, which the panel copies rather than composes. A cloud box has no panel, so nobody there is ever shown the word, and a control reachable by a keyword on a desk is unreachable in the cloud. A slash command is the handle a cloud box can reach: the harness lists .claude/commands in its own menu and completes it, and the file is in the tree, so a clone carries it. The generator holds no judgment. It writes what keywordsFor already answers, the same way the panel draws what it is answered, so the word cannot differ by a character between the two surfaces.

## proposed action

Walk the parameter tree. Write one file under .claude/commands for every line keywordsFor answers, named after that line.

THE BODY IS THE MESSAGE AND NOTHING ELSE. keyword.Parse matches only when the whole trimmed message is one. A mark in the body would stop the line matching, so the mark goes in the frontmatter description. That is what the harness draws beside the command in its menu.

A BRACKETED VALUE IS NOT SENDABLE AS IT STANDS, which is why boundsSay writes brackets. Such a line carries $ARGUMENTS in their place, and the bracketed text becomes its argument hint. A line sendable whole carries no argument, so a rung is two files and needs nothing typed.

The files are tracked, and a check proves they still match what the tree answers.
