## detail

The panel is the desk's surface for a control, and a cloud box has none. KEYWORD:NAME=VALUE reaches eighteen controls through KeywordSaid, and keywordsFor in src/engine/keywordmoves.go answers the exact string the matcher takes, which the panel copies rather than composes. A cloud box has no panel, so nobody there is ever shown the word, and a control reachable by a keyword on a desk is unreachable in the cloud. A slash command is the handle a cloud box can reach: the harness lists .claude/commands in its own menu and completes it, and the file is in the tree, so a clone carries it. The generator holds no judgment. It writes what keywordsFor already answers, the same way the panel draws what it is answered, so the word cannot differ by a character between the two surfaces.

## proposed action

Walk the parameter tree, and for every node keywordsFor answers a line for, write .claude/commands/&lt;name&gt;.md carrying that exact line. Each file says in its own body that it is generated and will be overwritten, so nobody edits one. The files are tracked, because parameters.json is tracked and the answer is therefore the same on every box, and a check proves the written files still match what the tree answers.

## done when

- every node keywordsFor answers a line for has exactly one file under .claude/commands, and no other file is there, decided by: a Go test in src/engine comparing the names the engine answers with the files written
- each written file carries the keyword message character for character as keywordsFor answers it, decided by: the same Go test
- each written file says in its body that it is generated and will be overwritten, decided by: the same Go test
- a command file hand-edited away from what the tree answers fails a check, decided by: node util/checks/commands-mirror-the-keywords.mjs run from the root against that edited file
