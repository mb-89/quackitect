## detail

A token that closes is archived: the engine writes its text to a tag under archive, and deletes the file from doc/work. On a cloud box that loses the answers.

The proxy on a cloud box takes pushes to refs/heads and nothing else. So the tag stays on the box, and the branch carries only the deletion. The last version of the note that reaches the remote is the one committed before the work was done.

Measured here on wk-6f6a0044bb. Its answers were written, the token was submitted done, and the engine archived it in the same call. The push carried a deletion of the unanswered note, and every sentence of the answer stayed in the tag.

A worker cannot commit between the two, because one call writes the answers and closes the token.

The desk does not see this: there the tag is written into the same clone the person reads.

## proposed action

Make the closing write reach the branch on a box that can only push branches. Either commit the answered note before the archive takes the file, or write the archive where a branch push carries it.

## done when

- a token closed on a cloud box has its answered text in the branch that box pushes, proved by git show on the pushed commit
- the box that closed it needs no second call to make that happen
- a desk closing a token keeps the archive it has today
