## detail

AN AGENT CANNOT RUN A BENCHMARK, SO A CRITERION THAT NAMES ONE CANNOT BE ANSWERED.

Benchmarks live in src/engine/bench_test.go and are run by util/checks/benchmark.sh, never by the battery, because a number that depends on the machine is not an answer to whether the program behaves. That is the right split, and there is no door on the agent's side of it.

se test discovers tests only, so a proposal naming a benchmark comes back unreached and nothing runs. se run refuses anything reading as a test run: go test, sh util/checks/benchmark.sh, and even cat util/checks/benchmark.sh are all answered with THE ENGINE OWNS THE TESTS. That refusal says outside this tree the tests are yours to run, but it reads the command text and not the folder, so a copy of src/engine under /tmp is refused the same way.

Measured on wk-36a1648730 in September 2026. That token's third criterion is a benchmark over a folder of several hundred entries, naming go test -bench . -run x ./src/engine. The benchmark was written into bench_test.go, se test answered unreached, and all three ways of running it by hand were refused. The token closed with the number owed.

So a token may ask for a measurement its worker has no way to take, and the checklist line has to be answered with why rather than with a number.

## proposed action

Give the agent one door to the benchmarks: se test taking a benchmark by name and running it the way benchmark.sh does, or se run letting a command through when it runs outside the tree, which is what its own refusal already promises.

## done when

- se test proposing a benchmark by name runs it and answers its numbers, decided by: a test in src/engine proposes BenchmarkThePathsWrittenOn and sees it in ran rather than in unreached
- the battery still runs no benchmark, decided by: the same test asks for the whole battery and sees no benchmark among what it chose
