## detail

util/checks/open-tokens-carry-their-sections.mjs reads what each process declares as required and refuses an open token carrying none of it. It is in the battery list, and it is red. This token is what makes it green.

Run over the branch tip it named twenty-four open standard tokens with no approach heading. Two were the halves it was written for, and they carry one now. Twenty-two are left, and each is a token nobody has read.

Measured with `node util/checks/open-tokens-carry-their-sections.mjs .`, which answered one hundred and eighty-three open tokens read, twenty-two failed. Every failure is the same shape: an open standard token with a detail and a done-when list, and no shape a reader could disagree with before the work.

The names are in the check's own output, so they are not copied here and cannot go stale.

An approach is not a thing to invent for work one has not studied. Each of the twenty-two wants its own reading, so this is a token that splits before it is worked, one for each token or one per cluster.

Note also that util/checks/notes-say-each-heading-once.mjs names doc/work/wk-ac42b15fb3.md, which carries two approach sections. That one is a separate defect of the same family and is not this token.


## proposed action

Split it, and write an approach onto each of the twenty-two from what its own detail and done-when already say. Then add the check to the battery list, so the next one written without an approach is refused where it is written.
