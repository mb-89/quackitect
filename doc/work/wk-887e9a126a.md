## detail

A closed token stays on disk for ever. The tree holds hundreds of them, and the point of a token is the work rather than the record of it.

Where it goes is the folder it is in when it closes, which is the same fact every other door already reads. A token in doc/work travels, so it goes into the archive. A token in .se/work does not, so it is deleted.

Level 2 already ruled the archive. Archived content lives in git only, not in the working tree, because a tree grows without bound with material nobody walks. One tag per closed thing, pushed by the engine on closing. The human never sees git.

Two things are not built. The engine does none of this on close, and nothing can search what git holds, so an archive today would be write-only.

The owner asks for a list carrying a tag, a title and later a type. Level 2 ruled against a list it has to keep in step, naming a file that drifts as what breaks. A list derived from the tags rather than kept beside them answers both.

## proposed action

The close does it, not the agent. On a close the engine reads the folder the token is in.

Tracked: commit the token, tag it with its id, remove the file, and write the list. Local: delete the file.

The list is derived. It is written from the tags, never edited, and one command rebuilds it from git if it is lost.

Add the ref door, so se find can read a committed ref. Without it the archive cannot be searched and closed work vanishes from every answer.

## approach

The close is the moment, and the folder is the answer. SaveToken already reads the token as it was before it writes, so it knows the save that ends one. That is where this hangs.

A token in .se/work is removed and forgotten. Nothing else happens.

A token in doc/work is written into git without touching the branch, the index or anybody staging, the way a snapshot already is.

    blob   git hash-object -w <the file>
    tree   git mktree, one entry
    commit git commit-tree, message carries the id, title, process and disposition as JSON
    tag    git update-ref refs/tags/archive/<id>

Then the file is removed and the index row dropped.

The list is doc/work/archive.jsonl, one JSON object a line. It is written from the tags and never read as a source. git for-each-ref over refs/tags/archive gives back every field, because the commit message carries them.

So the list can be deleted and rebuilt byte for byte, which is the criterion that keeps it derived rather than kept.

Reading one back is git show refs/tags/archive/<id>:<path>. se find grows a ref, and it reads that.

## note

Built and working, and it changes a contract nine tests rest on.

What works. A tracked token that closes goes into git under a tag, comes off the disk, and reads back through that tag. A local one is deleted. The list is written from the tags and rebuilds byte for byte. A tree with no history keeps its tokens. No agent calls anything.

What it costs. A closed token is not on the disk. For a tracked one the archive answers and a reader never notices. For a local one there is nothing to answer with, which is what local means.

Nine tests close a token and read it back off the disk. Each fails saying no such token. They assert the old contract rather than a defect in the new one.
