## detail

Unbound is the queue off and every other rule on. The staffing guard asks Unleashed. The pull's hand-out and the stop judge do not, and both are queue behaviour.

Measured on 2026-09-06 on an unbound cloud box. A pull that closed one token handed out another. The stop judge then refused a stop twice over that same token.

So an unbound session was handed work it never asked for, then held by the work it was handed.

## approach

Ask Unleashed at the two places that are the queue, as the staffing guard already does.

In answerFor, after a submission has settled and before whatComesNext. Closing work is the record rather than the queue, so it still runs. Only the hand-out stops.

In AskToStop, before it walks what the actor holds. The queue did not choose that work and will not choose the next.

Nothing else moves. The write gate, the voice rules and the schema caps all stand, and a bound tree behaves as it did.

## done when

- A pull on an unbound tree hands out no token, and a test drives a close through an unbound tree and reads no token back.
- A stop on an unbound tree is granted while a token is held, and a test drives it and reads the grant.
- A pull on a bound tree hands out a token as today, and a test drives it and reads one back.
- A stop on a bound tree with work held is refused as today, and a test drives it and reads the refusal.
