## detail

A finding on wk-7783c03017, controls last one session.

ofThisSession in src/engine/unbound.go:51 compares a stored session against currentSession(r), and currentSession reads the first record of .se/log/current through sessionOf, log.go:219. When that file cannot be read, or carries no first record yet, sessionOf answers the constant "current".

A rotation makes exactly that file. Say sets the full log aside with l.retire and opens a fresh current, log.go:172, and the new file is empty until the next record lands. In that window currentSession answers "current", no stored control matches it, and all three read as another session's: the rung falls back to bound, the hold to off, the ask to nothing owed.

The direction that matters is the hold. A hold is a person stopping the engine, and a guard is a fresh process per event, so a guard firing in that window reads the hold as off and lets through calls nobody lifted the hold on.

Measured, not guessed. Against a clean copy of origin/v4, a probe that sets the hold and the rung in a named session and then truncates log/current: currentSession reads "current", the hold reads off and the rung reads bound.

The fix is one line of judgement: an unreadable or unnamed session is not this session. Answer "" from sessionOf where it now answers "current", or have ofThisSession refuse to match on the fallback, so a control that cannot be placed keeps what a person set rather than resetting under them.
