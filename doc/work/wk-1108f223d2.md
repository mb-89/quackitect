## detail

Found reviewing wk-084e23e08b, which makes an answer say when the engine that wrote it is older than its source. Two readings now exist and neither covers the case this box is in.

staleSays compares the running process against src/engine. residentStale compares .bin/se against src/engine. Nothing compares the running process against .bin/se, and that is what a rebuild leaves behind: the file is replaced, the process is not.

Measured on 2026-09-06. .se/engine.json says the engine that lives is pid 28920, started 11:37:16, build 0e09b4b.113702. .bin/se was rebuilt at 11:47 and again at 11:58, carrying 1a84269, which is this token's own change. So every tool call today was answered by a process that predates the sentence.

I dated src/engine/pull.go two hours ahead and asked three ways: .bin/se state --json, .bin/se find, and a copy of the binary outside the tree with --work naming it. None carried a stale member, because the answer is the living engine's.

So on the box where the defect was measured the new sentence stays silent, residentStale is quiet too now that .bin/se is fresh, and nothing tells anyone to restart the engine.

Nothing catches the class: no test and no check reads engine.json's build against the binary on disk.

## proposed action

An answer says when the engine that wrote it is older than the binary on disk, not only when it is older than the source.

## done when

- an answer written by a process older than .bin/se says so, and names the build it is running. Decided by: se test --on this id --propose TestAnEngineOlderThanTheBinItRanFromSaysSo
- an engine as new as the binary on disk says nothing. Decided by the same test
- the sentence names what to do about it, which is restarting the engine rather than rebuilding again. Decided by the same test reading the words back
