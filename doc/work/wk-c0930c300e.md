## detail

Two measuring scripts sit beside the battery's checks: count-standing.py and count-voice-breaks.py. Neither is a battery check, and each carries the command that runs it in its own docstring.

The tests-via-engine guard refuses any command whose text names that folder, and it refuses more than a run: a cat of one of them and a copy of one out of the tree are both refused with the same words. The engine cannot run them either, because it only knows the .mjs names the battery lists.

So a script kept there for a person to run by hand can be written and never run. The measurement it exists for is taken with a copy made outside the tree, and the tree's copy is never exercised.

## proposed action

Decide where a measuring script that is not a battery check belongs, or let the guard pass a command it can see is not a test run.

The guard is guards.tests_via_engine. The battery's own list of checks is read out of battery.sh by checks-live-in-the-method, which counts only the .mjs files, so a .py beside them is already outside that rule.

## done when

- a measuring script that is not a battery check can be run from the tree, and the command that runs it is the one its docstring names
- a battery check is still refused when run outside the engine: the tests-via-engine guard stays on for the .mjs the battery lists
