## detail

The battery answers about the working tree, and what every other box gets is git, so a change that is half committed is green here and broken everywhere else.

util/checks/battery.sh runs `go vet -C src/engine ./...` over the folder it is started in. An agent whose working tree holds both halves of a signature change sees it pass, commits one half, and the branch stops compiling for everyone who clones it.

Twice in one day on v4:

- 559fc4a6: `vet: ./main.go:46:43: too many arguments in call to callTheEngine`, have (context.Context, string, []string), want (string, []string). Fixed at 50bc1b2e, "The branch compiles: client.go carries the context again".
- d84810eb: `vet: ./archivetravels_test.go:100:55: rows[0].Blob undefined (type Archived has no field or method Blob)`.

Both are decided by the same reading: git archive <commit> into an empty folder, then go vet -C src/engine ./... there. Neither could be seen from the working tree that made it.

It is the same shape as [[wk-874de0fedb]], which is the checks half: a check present on disk and absent from git reads green here too. The tree the battery judges is not the tree anyone else receives.

The smallest case: stage and commit a caller without its callee, then run the battery.

## done when

- the battery still exits zero over a tree whose commit and working tree agree, decided by: sh util/checks/battery.sh from the root of a clean archive of HEAD, which reports no new failure against the run before the change
- the reading is over what git carries and not over an uncommitted folder, decided by: the check reports the same answer whether or not the working tree holds the missing half
