## detail

Handing a token out opens a stretch and then saves it. The stretch is opened first, so a token the save refuses has already had a began snapshot written into git and appended to the token in memory.

The token is never written, so that snapshot is a tree object nothing on the record names. The queue now passes over an unwritable token instead of stopping at it, so every pull past one writes another, for as long as it sits there.

## proposed action

Decide whether the save is asked first, so a stretch is opened only for a token that will be written, or the snapshot is cheap enough to leave as it is.

take is in src/engine/pull.go. The two doors that measure a token are proseThatFits and overCaps in src/engine/store.go.

## done when

- a pull that passes over an unwritable token writes no git object: count the objects in the snapshot store either side of one such pull
- a pull that hands a token out still writes its began snapshot: go test -run TestAChangeIsBracketedByTwoSnapshotsOutsideTheHistory
