## detail

Every icon in one table, and nothing else carries a glyph.

A control, a heading or a button names an icon, and util/icons.json decides
what that name looks like. So the same mark is the same mark in the sidebar and
in the editor, and changing one is one edit in one file.

A NAME THAT RESOLVES TO A GLYPH TODAY CAN RESOLVE TO A FILE TOMORROW, and
nothing that uses the name has to change. That is the point of the name.

A NAME NOBODY DECLARED DRAWS ITSELF. A blank leaves a button a person cannot
see, and the name on the face says which entry is missing from the table.

THE FACE IS AN ICON AND THE WORD MOVES INTO THE TOOLTIP. A tooltip reads
"<the word that was on the button> / <what it already said>", so the word a
person loses from the face is the first thing they find on hover.

The owner named the marks: the power ring for start and stop, stacked lines for
the log, a house for home, a full-width plus for init, a hand and the robot it
stops for the hold, and a hammer for work. Not gears, which belong to
configuration.

## lesson 1 · round 3 · by reviewer

**the class:** A remedy applied to the instance a finding pointed at, while its siblings in the same submission keep the defect. The finding names one file, one line, one number, because a finding is a sample; the fix lands exactly there and stops. What makes it hard to see from the inside is that the submission is then true about everything it says: the guard it names really did get the rule, the number it corrected really is corrected. What it does not say is that two other guards named in the same sentence did not get it, and that correcting one copy of a number left two copies behind.

**instead:** Read the finding as a description of a class and then go looking for the rest of it before fixing anything. When a rule is added to one check, list every check of that kind in the project and say, in the evidence, which ones now carry it and which do not and why. When a number in prose disagrees with the code, do not correct the number: find every copy of it and delete all but the one the program computes, because a fact written down twice is a fact that will disagree with itself, and this queue has now watched it disagree three rounds running.

## lesson 2 · round 4 · by reviewer

**the class:** An evidence section that names the whole set a finding was about and reports on the one member that was already fine. The finding said a rule had reached one of three; the evidence is headed three guards, lists all three, and attaches the rule to the third, the one that had it before the round started. Every sentence is true, the finding's subject appears in the writing, and a reader scanning for whether it was answered sees the words and moves on. It is harder to catch than saying nothing, because saying nothing at least leaves a gap where a section should be.

**instead:** When a finding says a rule reached some members of a set and not the others, answer per member and not per set. Name each one and say, of each, whether it now has the rule, or that it does not and why. A sentence about the set is not an answer about its members, and the member you can honestly write a sentence about is usually the one that needed no work. The same test applies while you are writing: if the section you just wrote would still be true with the defect in place, it is not evidence that the defect is gone.

## lesson 3 · round 5 · by reviewer3

**the class:** A guard that searches for the known-good when the rule is about everything outside it. The check reads the registry, builds a set from it, and refuses members of that set found in the wrong place. It reads as thorough and its reach is exactly the registry: the closer the registry is to complete, the more the check finds, and the one case it can never find is the mark that was never registered - which is the case the rule exists for. The registry doing double duty, as the allowlist and as the search list, is what hides it, because both uses look like the same list.

**instead:** Derive the search from the property the rule names, not from the list of things that already obey it. Here the property is a mark drawn in a file that draws, so the search is every character above U+007F in those files, and the registry becomes the exemption. Say the rule out loud as a sentence with a negative in it - nothing else carries a glyph - and check that the code's loop runs over the everything, not over the else. And when the file being searched is a file that generates another language, search the forms that language allows: an HTML entity, a unicode escape, a codepoint built at runtime are the same mark to a reader and different bytes to a grep, so a check that only matches the literal has a hole shaped like the output format.
