## detail

Blocked in src/engine/token.go reads depends_on with LoadToken. A close archives the note and takes it off the disk, so LoadToken then errors and the dependency is reported as one that does not exist.

A token whose dependency is finished is therefore blocked for ever, and the queue passes over it in silence.

MEASURED in bucket tests. wk-c02a6d51e4 waits on wk-4e91c7b3f8, which doc/work/archive.jsonl carries as done. The queue called the group empty with that token open, and nothing said why.

The archive is the record of what ended, and it is not read here. An id in neither place is a real absence and stays one.

## proposed action

Where LoadToken cannot find a dependency, ask the archive before calling it absent. A row there is an ended token and blocks nothing. An id in neither place keeps the wording it has.

## done when

- a dependency the archive carries as done blocks nothing: se test --propose TestAnArchivedDependencyBlocksNothing
- a dependency in neither doc/work nor the archive still blocks, and the refusal says it does not exist: the same test reads both
