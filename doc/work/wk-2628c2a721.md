## detail

THE NARROW RULE WAS WRITTEN AND MEASURED, AND IT REFUSES SIX COMMENTS THAT READ RIGHT.

wk-0edd71fa3e asked for a check refusing a comment in src that names the token whose change it ships in. That rule was implemented and run over the tip, d1aa9e3: for every id in a src Go file that is not a test, git log --reverse -S over that path says which commit first put it there, and it fails where that commit's subject names the same id. 24 pairs looked at, 7 failed.

Six of the seven are provenance a reader wants. removal.go:96 says "See wk-9875cf128f." and cee4279, wk-9875cf128f, is the commit that put it there. That is the code pointing at the evidence that explains it. The same shape is in investigate.go, proxy.go, pull.go, schema.go and search.go.

The seventh was wrong for another reason. testedgate.go named wk-5c682f1a25 as carrying work still to come, and that token had closed deferring it. a2c6b96 fixed the word.

So the rule does not tell the two apart, and a check built on it reddens the battery over six deliberate comments. What is always wrong is narrower: a comment naming a token as work still to come, where the record says that token has ended. The record decides that, and git decides nothing.

## proposed action

Write the check against the record rather than git history. Read each src Go file that is not a test, and for each id it names ask the tokens and the archive whether that id has ended. Refuse it only where the sentence around it says the token carries work still to come. Then run it over the tip, where it exits zero, and over a fixture naming an ended token that way, where it fails and names the file and the id.
