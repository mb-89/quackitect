## detail

The standard process declares the verdict activity as from done, to closed, by a reviewer. The engine refuses it, so every standard token reaching done is stranded there.

Submitting a done token as a reviewer answers refused. The finding is clause status, wrong that the token is already closed, satisfies a token that is open or in work. Naming the same token on se run is refused the same way, so a reviewer cannot run a criterion command against what it reviews.

The guard reads open or in work where the process says done. A token also carries a disposition while its status is still done, which the process reserves for an ended token.

Two notes described this, one from each door. This carries both.

## proposed action

Read the status guard that the submit and run paths share. Make it take the from state each activity declares, rather than a fixed open-or-in-work set.

Check whether the disposition is written on the do step. If it is, write it only on the closing step.

## done when

- a reviewer can run a command naming a standard token at status done: se run on that token answers output rather than already ended
- submitting a done standard token as a reviewer with disposition done leaves its status reading closed
- a genuinely closed token is still refused: a test names one and reads the refusal
- a test covers the verdict transition from done to closed
