## detail

SPIKE. The portable hook set was measured on the command-line hosts. The in-editor integrations are a different surface and Level 0 ruled the answer is not assumed.

WHERE IT STANDS. util/cage/claude-settings.json declares fourteen events. Nothing has established which of them the editor integration actually fires. A cage that is measured on one surface and shipped on another is a cage with an unmeasured wall.

THIS IS THE SAME SOFT SPOT AS THE COPILOT WALK. Both are about a cage file that lands and is never read. A hook that does not fire looks exactly like a hook that fired and found nothing wrong, and that is the failure mode worth designing the measurement around.

WHAT TO MEASURE. For each declared event, in the editor, on each harness: does it fire. Prove it by the record rather than by the settings file, because the settings file is what is in question. An event that fires writes a line. An event that does not write no line, and the absence is the result.

WHERE THE ANSWER GOES. Into the Level 0 design as a ruling naming which events are enforced in the editor and which are declared and not enforced. If the answer is that the editor carries fewer, that is a finding for the person, because the launch would be promising a cage the editor cannot hold.
