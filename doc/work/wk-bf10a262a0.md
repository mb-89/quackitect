## detail

A close writes the archive row and deletes the note, and the branch gets only the row. So origin/v4 carries an open note and an archive row for the same token, and every reader after that sees work that is finished as work that is open.

MEASURED, September 2026, over a detached worktree of origin/v4. Of the 32 notes there carrying bucket claims, 25 already have an archive row saying done. Seven are genuinely open. The queue, the burndown and every count taken off doc/work read 32.

The engine's own pull says so and cannot fix it. It answers "Passed over, because origin/v4 has archived them and this clone is behind it" and asks a person to bring doc/work into step. The clone is not behind. It deleted the notes when it closed them, and the deletion never travelled.

WHY IT TRAVELS BADLY. land.sh removes a path the tree no longer holds, so the door works. The hand landing a close names doc/work/archive.jsonl and forgets the note it just deleted, because the note is gone and nothing lists it.

## proposed action

Have the close name both paths. The archive step already knows the note it deleted, so it writes both into the same landing rather than leaving one to be remembered. A check over the branch tip then asserts no note carries an archive row, which is the state that cannot come back.
