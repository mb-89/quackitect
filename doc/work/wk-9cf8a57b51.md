## detail

A finding on wk-97a144fdc6, staffing counts ghosts.

StaffingOf gained two guards in the loop over ActorsThatPulled, src/engine/staffing.go. One reads the register's gone list, the other the stop claim:

	if _, stopped := StandingClaim(r, actor); stopped {
		continue
	}

Nothing exercises the second one. Measured on a clean copy of origin/v4: go test with a coverage profile over the staffing tests reports count 0 for that continue, while every other new statement in the change reports 1. ClaimStop appears once in the whole engine suite in a staffing setting, staffinghands_test.go:51, and the helper it stops is registered with NoteAgent, so the registered path catches it in the first loop and this branch is never reached.

The damage is that the untested branch is the one the token's own detail says matters most. The register is filled by SessionStart and SubagentStart, and on a harness where SubagentStart never arrives a spawned helper is only ever a name that pulled. That helper's only sanctioned end is the stop claim, so an unregistered helper that stopped is the commonest ghost there is, and the line that drops it is the one line nothing proves.

The check: extend TestAHandThatWentHomeIsNotAHand with a third helper that pulls, with ArrivedAs and no NoteAgent, and then claims a stop. WorkersHere must not count it.

Also seen, and older than this change: every staffing test asserts ReviewersHere is 0, so neither of the two ReviewersHere increments has a test that reaches it.

## done when

- a test drives an actor that pulled without being registered and then claimed a stop, and StaffingOf does not count it
- that test is seen red against a build with the StandingClaim guard removed
- a coverage profile over the staffing tests reports a non-zero count for the continue after StandingClaim in staffing.go
