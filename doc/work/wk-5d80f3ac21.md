## detail

Hold is a boolean read at the harness door, so every tool call is refused while it is on. That is one degree where the owner wants two.

One press finishes up. No token is handed out and none may be taken up, while an agent finishes what it holds and puts it down. A token put down mid-process stays where it is and is picked up when work is allowed again.

Five presses hold. The agent stops at its next tool call and everything is blocked, which is what hold does today.

The gesture is already generic. The panel reads a gesture and a gesture command off any node and counts presses, and the unbind button is its only user.

## approach

Hold becomes a state word rather than a boolean.

Held keeps the check where it already is, at the harness door, refusing every call.

Finishing is a different door. The take-up is refused and the pull hands nothing out. A put-down, a submit, a close and every evidence write go through, because finishing up means finishing what is in hand.

The staffing demand goes quiet while finishing. Without that the main agent is told to spawn hands who are then forbidden to take anything up. That is a session with no legal move.

The panel node gains the gesture and a third state, and that part is data.

## done when

- the hold state is a word with three values, decided by: read the file the engine writes it to
- a take-up while finishing is refused and a put-down is not, decided by: a test that drives both
- the staffing guard asks for no hands while finishing, decided by: a test with a main agent and no workers
- the gesture reaches the hold command and one press does not, decided by: the panel check
