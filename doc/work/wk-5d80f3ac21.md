## detail

Hold is a boolean read at the harness door, so every tool call is refused while it is on. That is one degree where the owner wants two.

One press finishes up. No token is handed out and none may be taken up, while an agent finishes what it holds and puts it down. A token put down mid-process stays where it is and is picked up when work is allowed again.

Five presses hold. The agent stops at its next tool call and everything is blocked, which is what hold does today.

The gesture is already generic. The panel reads a gesture and a gesture command off any node and counts presses, and the unbind button is its only user.

## approach

Hold becomes a state word rather than a boolean. Held keeps the check where it is, at the harness door, refusing every call.

Finishing is a different door. No tracked token goes out and none may be taken up. A put-down, a submit, a close and every evidence write go through, because finishing means finishing what is in hand.

And the pull hands out this actor's own notes, one at a time. The owner's rule, September 2026: an agent told to finish up works every note, then stops. A note is private and outside git, so one left on a cloud box dies with it.

The drain rides on finishing rather than on a rank, because the queue hands a note out at no other time. Each note ends in a drop or a tracked token.

With no note left the pull says so and the stop is allowed. Before then it is refused, because a finishing that may stop early is a slower hold.

The staffing demand goes quiet while finishing. Without it the main agent spawns hands forbidden to take anything up.

The panel node gains the gesture and a third state, which is data.
