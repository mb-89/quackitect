## detail

A reviewer that stopped holding a token blocks it forever, and nothing notices.

WHAT THE OWNER SAW: every group pins sat in review for a long time with a
holder named on it and no reviewer running. The refusal built for this covers
tokens that are SUBMITTED with nothing in review. It does not cover a token
already IN REVIEW whose reviewer is gone, and that is the case that actually
happened.

THE HOLE: one token in review is read as a reviewer reading, and that is what
clears the refusal. A dead reviewer's token therefore clears it permanently.

WHAT WOULD SETTLE IT. Reclaim already exists and it works on arrival: whoever
held this actor's work before is gone, so what they held comes back. It only
runs for the actor that arrives, so a reviewer that never comes back never
reclaims. The engine needs to notice that in_review is not the same as being
read, without inventing a clock, because an arrival is a fact and a clock
guesses.

ONE ANSWER THAT NEEDS NO CLOCK: the refusal counts a token in review as being
read only while its holder has pulled in this session. A holder that has not
pulled at all is not reading, so the token counts as waiting and the refusal
fires. That uses the arrival record the engine already keeps.
