## detail

From the verdict on wk-4f8e7e7ebe, tests build their engine.

src/engine/enginebin_test.go now caches the suite's engine at os.TempDir()/se-engine-<stamp>, where the stamp is the newest Go file under src/engine. After a build, sweepOlderEngines removes every directory in os.TempDir() whose name starts with se-engine- and is not the one just made.

The file's own comment says two agents run this suite on one box at once, and that is why the build lands by rename. The sweep undoes that care. It does not ask whose directory it is or whether anything is using it.

Two ways it bites. On one box with two trees the stamps differ, so each agent's build deletes the other's, and since the engine runs every selected test as its own process, both sides pay the full link on every test rather than the 0.03 seconds the cache is for. On one tree, a source touched mid-run changes the stamp, and the sweep can remove the binary a test process has already stat'd and is about to run, which fails that test with a missing file rather than anything about the test.

Wanted is a sweep that leaves what is in use: an age floor, or a directory this run can prove nobody else holds.

## proposed action

Give sweepOlderEngines an age floor: remove an se-engine- directory only when nothing in it has been touched for an hour, and touch the kept directory on every run that finds its build already there. That keeps a live tree's build alive whoever is running against it, and still empties the folder of trees nobody has built for.

## done when

- a build for one stamp leaves a recently touched directory for another stamp alone, decided by: a test in src/engine that makes a second se-engine- directory, calls the sweep, and finds it still there
- a stale directory is still taken away, decided by: the same test backdates one an hour and finds it gone after the sweep
- the suite still drives this tree's engine, decided by: go test -C src/engine -run 'EngineOlderThanTheTree|EngineNewerThanTheTree|TheSuiteSaysWhichEngineItDrives' ./... answers ok

## evidence: note

sweepOlderEngines now has an age floor. A build folder under the temporary directory is taken away only when nothing in it, the folder itself included, has been touched for an hour, which theNewestTouchUnder answers. A run that finds its build already there touches the folder, so a tree being worked keeps its cache alive whoever else sweeps. The binary is not touched, because its time is what says it is newer than the source it came from. A folder that cannot be read answers the zero time and is swept as before. Red first: with the old sweep the new test said a build touched a moment ago was swept. Green after, with the five engine fixture tests beside it. The whole battery stays owed.
