## detail

The engine starts the whole battery as a child shell and writes .se/tests/battery.running with its pid. When the battery ends, the marker stays, and every later se_test that owes a battery answers "a battery started at <time> is still going" and runs nothing.

Measured on this box, 2026-09-05, session 20260905-103015. The battery started at 10:37:19 for wk-239cae9216 wrote its last line, "2 failed, 112s wall clock", at 10:39. At 11:03 the marker still named pid 21386, and `ps -p 21386` answered `[sh] <defunct>`, a zombie the engine never reaped. se_test on wk-0086ed9e9b, a token whose delta changed a file under util/checks, answered whole true and ran the battery as "still going", twice, 24 minutes after it had ended. The marker was removed by hand to let a battery run.

## proposed action

The engine waits on the child it started, so the process is reaped and the marker is removed when the battery's shell exits. A se_test that finds a marker whose pid is gone or defunct treats it as stale, says so, and starts the battery.

## done when

- a battery.running whose pid is no process, or a zombie, does not stop the next battery, decided by: go test -C src/engine -run 'AStaleBatteryMarker' ./... answers ok
- the shell a battery ran in is reaped when it ends, decided by: the same test, which finds /proc/<pid> gone after the run
