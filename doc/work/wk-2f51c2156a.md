## detail

The panel draws one session as two agents, and the staffing count reads two where one process is.

Measured on this box at 07:31. The register holds one agent for run 11de6d9ae3, keyed by session id 41d2115e-56d6-4244-ac5a-7d43c66c1607 and named main-41d2115e. It pulls as main: .se/holds.json has wk-4bdfe925aa held by main, and .se/arrivals.json orders one actor, main.

Nothing joins the two names. .se/actors.json is the alias table, keyed by the harness agent name, and every row in it is a general-purpose subagent. A main session is not a subagent, so it never gets a row there, and its two names stay strangers.

So AgentsPresent draws a row under main-41d2115e with nothing in hand. Then WhatIsHappening walks Actors, finds main holding a token, asks answersTo, is told no, and appends a second row.

wk-bd6c665ee8 closed on this shape and oneprocessonerow_test.go holds it. That test passes, because its fixture writes the alias the gate writes for a subagent. The main session's path is the one nothing covers.

The count is the part that bites. oneprocessonerow_test.go asserts WorkersHere plus ReviewersHere equals len(Present), so an inflated Present is an inflated staffing count. The guard can then ask for hands that are already here.

## proposed action

Write the main session's pulling name into the alias table the way the gate writes a subagent's, so the register name and the pulling name are one agent.

## done when

- a session registered under one name and pulling under another draws one row, decided by: a test that registers main-x, pulls as main, and counts Present
- that one row names the token it holds, decided by: the same test
- the staffing count equals the number of processes, decided by: the same test, against WorkersHere plus ReviewersHere
- a subagent still draws one row, decided by: oneprocessonerow_test.go stays green
