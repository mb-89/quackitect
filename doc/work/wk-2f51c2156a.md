## approach

THE LANE INVENTS A NAME BECAUSE IT HAS NOTHING ELSE TO SAY.

orMain at src/mcp/lane.go:690 answers the literal "main" when no actor is named, and nothing in the lane names one. TheActorOf at evidence.go:306 answers TheSessionName, which the register wrote. Here that is main-41d2115e. So the hook records one name and the lane pulls under another.

aSessionName gives main to a run's first session and main plus a short id to the next. A session keeps that name, and a moving name would strand its tokens.

The alias table cannot close the gap. The gate writes a link when it reads --actor in a command, and the lane fills its default after the guard saw the call.

THE LANE CANNOT BE HANDED A SESSION. roots.go reads no session id, and .mcp.json is generated and static. The rest is a choice, written here rather than guessed at.

ONE: the engine fills an unnamed actor with the live session's name. It must break a tie when two are live.

TWO: the register gives back a name it granted for a collision, once that collision clears.

Two looks right, and it argues with a rule already written down, so a person picks.
