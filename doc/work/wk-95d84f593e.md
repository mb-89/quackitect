## detail

CLASS: AN ALLOW LIST WHOSE PERMIT BRANCH RESTS ON A QUESTION THAT CAN FAIL
SILENTLY, AND WHOSE SILENCE MEANS YES.

The default is turned round properly. Anything the check cannot read is
refused, and that is the right change. Then one of the permitting branches asks
a question of its own -- does this name hold a flag, does this file declare
that, does this call reach the engine -- and answers it with an instrument that
can break. When the instrument breaks it answers no, no means nothing was
found, and nothing was found means permitted. So the top-level default refuses
and the branch under it permits, and the branch is where the defect lives.

THE INSTRUMENT THAT BREAKS QUIETEST IS A PATTERN BUILT FROM A STRING. Every
backslash has to be written twice, a pattern assembled by concatenation loses
one, and a pattern that lost one matches nothing rather than throwing. Nothing
in the run says so. The same file usually gets it right somewhere else, which
is what makes it invisible to a reader: the shape is familiar and correct three
lines away.

MEASURED ON wk-1412093cd8, round 6. The round turned the check into an allow
list, which was the finding and is right, and the branch for a value the caller
owns builds its pattern with new RegExp("\b(?:const|let|var)\s+" + one + ...)
inside a double-quoted string. \b is the backspace character there and \s is
the letter s, so the pattern matches nothing, the branch answers no flag, and
the element is permitted. A local variable holding --form and spread into the
spawn is passed at 9 spawns read and 0 failed. The same file builds two other
patterns correctly with doubled backslashes.

WHAT TO DO INSTEAD.

WHAT WOULD HAVE STOPPED IT BEING MADE. A branch that permits on the strength of
a question has three answers and not two: yes, no, and I could not tell. Write
the third one out and give it the refusing side, so an instrument that has
stopped working refuses rather than permits. And build a regular expression as
a literal wherever the pattern is constant, because a literal cannot lose an
escape to a string. Where a name has to be spliced in, escape the name and
leave the rest of the pattern a literal.

WHAT WOULD HAVE CAUGHT IT. Give every pattern a check builds one input it MUST
match, asserted inside the check itself, so a pattern that has stopped matching
fails loudly instead of permitting. That costs one line per pattern and it is
the only thing that can tell a pattern matching nothing from a tree with
nothing in it. And re-take every recorded red against the code as submitted
rather than carrying the row forward from the round that took it, because the
rewrite that answers a finding is exactly the change most likely to break a red
somebody else already watched.
