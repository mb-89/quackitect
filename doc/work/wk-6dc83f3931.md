## detail

Not ready, design under discussion. The schema owns which fields a note has and where each draws its values. The process owns which values exist and how they change. The template is generated from both. A schema never lists a value something else owns, so status draws its values from the step names of the defined processes. A file that does not parse fails only the operation that touches it, naming the file and the place. A broken definition stops the engine: a schema, a process definition, util/parameters.json, util/projections.json. Open: the schema file format, whether conditions and validators are two things, whether the engine-stopping list is declared, and when a template is rendered.
