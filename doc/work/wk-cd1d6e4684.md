## detail

In util/checks/battery.sh the function gofmt_clean opens with bad="" and the battery's failure counter is also called bad. Today it does no harm because gofmt_clean is only ever reached through start. start runs it in a background subshell, so the assignment cannot reach the parent's counter. Move it to the one-at-a-time run lane, as the build and engine-up lanes are. Then the battery's count of failures is silently reset to the empty string on every run. A trap that is armed and waiting for the next edit. Rename the local to something of its own.

## done when

- gofmt_clean in util/checks/battery.sh no longer assigns to a variable named bad
- a battery run over a tree with a gofmt finding still reports the correct total count of failures
