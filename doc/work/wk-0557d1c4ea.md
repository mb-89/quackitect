## detail

writing-go rule 14 asks a test to be a table under t.Run. Counted over the 110 test files under src: t.Run in 16, t.Parallel in 98, t.TempDir in 63. The suite is one case per function, so a new case means a new function and the shared setup is copied.

The rule stands as written. What is owed is the suite catching up to it.

The hazard is the sweep, not the change. src/engine alone holds 130 test files, and the package is the compilation unit. A half-landed rewrite there stops every other hand from building any test in the package, which is wk-1bb23ea110.

## proposed action

Convert the suite to tables under t.Run, one package at a time, each package a sub-token of this one.

- every _test.go file under src/engine runs its cases as a table under t.Run

## approach

One package at a time, and each package is a sub-token of this one. The queue hands sub-tokens out before their parent, and the parent cannot close while one is open.

Order is smallest first: src/mcp with three files, util/setup with two, src/viewer with seven, then src/engine with a hundred and thirty.

Inside a package the unit is a file. A file is converted, built and tested before the next one starts. A package left half converted stops every other hand from building any test in it, and that is the cost this order exists to avoid.

A table earns its place where cases share setup. A single case stays a single function, and each sub-token says which files it left alone and why.
