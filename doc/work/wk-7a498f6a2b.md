## detail

A NOTE OVER A SECTION BOUND CANNOT BE SAVED AT ALL, SO THE ENGINE CANNOT MOVE IT.

The write door refuses a write that pushes a section further past its bound. That refusal is right for a hand editing prose. It also catches every write the engine makes about the token, because those rewrite the whole note.

Measured here on 2026-09-06. wk-963dbf6898 carries an approach of 206 words where the schema allows 200. It is held by an agent, silent for 9h21m, so the queue asked another hand to rule on the hold. The ruling would not land: se pull answered "wk-963dbf6898 would not save, so the hold still stands". A claim on the same token answered the reason plainly: "the approach runs to 206 words and the schema allows 200".

So the token cannot be claimed, cannot be put down, and its hold cannot be taken back. It is stranded, and the investigate notice repeats for ever because the ruling has nowhere to go.

The bound belongs on what a hand writes. It should not stop the engine recording who holds a token.

## proposed action

Take the hold back without going through the save. The hold is not in the note, so releasing one changes no prose at all, and it can be written where the engine keeps it. The cap does not move: the save goes on refusing an over-bound section, which is what TestAnOversizedChapterDoesNotStopTheQueue asks for.
