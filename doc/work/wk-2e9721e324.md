## detail

The battery still runs gofmt beside se lint, and that line is the last Go tool the verb does not cover.

Its siblings went. The four go vet lines came out because LintGo runs go vet over every folder carrying a go.mod, so the second pass learned nothing. gofmt is not the same case, and taking it out with them would have lost a guard rather than stopped a duplicate.

Measured on this box. LintGo runs go vet and golangci-lint, and neither formats. golangci-lint answered version two point five point zero, and `golangci-lint help linters` lists its default set as errcheck, govet, ineffassign, staticcheck and unused. No formatter is among them, and the tree carries no golangci config to add one.

So a file gofmt would rewrite is reported by the battery and by nothing else. se format rewrites such a file, and the battery never runs se format, because a check does not change the tree it judges.

What is wanted is the reading half of the formatter behind the same verb as the rest. LintGo already shapes a Finding per tool line, and FormatGo already knows the folders and the program. A finding per file the formatter would change, named the way the others are, lets the gofmt line come out of the battery the way the vet lines did.

## proposed action

Add the reading half of the formatter to LintGo, one finding per file gofmt would rewrite, and then take the gofmt line out of the battery.

## done when

- se lint names a file that gofmt would change, decided by a test that plants a crooked file and reads the findings
- se lint over a straight tree names no such finding, decided by the same test with a straight file
- util/checks/battery.sh carries no gofmt line beside the se lint line, decided by reading it
- the battery reports the same failures it did before, decided by running it and comparing
