## detail

Found reviewing wk-db6bdc8872, which moved the log syntax reader into a module of its own.

src/filter holds filter.go and go.mod and nothing else, on origin/v4 and in the tree. Four hundred and two lines of parser, and no test file in the module that owns them.

What exercises the reader today is src/viewer/model_test.go, through the alias in src/viewer/filter.go and a viewer Record as the row. So the module is tested only through one caller, and only for the one Row it happens to use.

That matters now rather than later. The point of the move, said on wk-6a0b7f2d38, is that the engine imports this module next, with a row of its own. A change to the parser made for that caller reaches no test inside src/filter, and se test maps a changed file to the tests of its module, so it will name the file uncovered and run the viewer's tests only if the viewer changed too.

Nothing catches the class. No check asks that a module under src carries a test, and the battery cannot fail over a module that declares none.

The fix is a filter_test.go beside the parser: a table over the syntax in the comment at the top of the file, driven against a row the test defines itself rather than a viewer Record.

## proposed action

The filter module carries its own tests, over its own row, so the parser is tested where it lives.

## done when

- src/filter carries a test file. Decided by: se find --path 'src/filter/*_test.go', which lists nothing today and must list one
- the test drives the parser over a row the test defines, not a viewer Record, and covers each shape the comment at the top of filter.go names. Decided by: se test --on this id --propose src/filter/TestTheLogSyntaxReadsWhatItDocuments
- the viewer tests that name a filter still pass. Decided by: se test --propose TestFilterShapes
