## detail

A cloud box cannot push refs/se/claims: the session git proxy answers 403 on every ref outside refs/heads/*. So a cloud box cannot publish a claim, and two boxes running at once can take the same token. That is live now, not hypothetical.

doc/spec/claims-relay-trial.md proposes a way round it. A GitHub Actions workflow runs on GitHub's infrastructure, not in the sandbox, and authenticates with the repository's own GITHUB_TOKEN rather than the proxy's scoped credential. So it can push refs the box cannot. The box would not push the claim; it would ask a workflow to push it and wait for the ref to move.

This token runs the three probes in that brief, in order, stopping at the first that fails. It does not build the relay, does not change how claims are published, and does not touch refs/se/claims. Its output decides wk-4759d90994 between the two designs left there: a leased branch, or the relay.

## proposed action

Run probe one: dispatch a workflow that does not exist and read the error, on every credential path this box holds. A 404 means the path is permitted and only the workflow is missing; a 403 in the proxy's wording means it is refused. Run probe two only if probe one permits: land a probe workflow with contents: write that pushes one throwaway ref under refs/se/ and deletes it, and check the workflow_dispatch default-branch requirement before blaming the token. Run probe three only if probe two pushed: time the round trip. Report exact status codes and bodies, name every ref created and whether it is gone, and say which design the result chooses.
