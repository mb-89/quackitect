## detail

The standing checks move out of .se/scratchpad and into util/checks, so a sweep
of the scratchpad cannot take them.

WHY IT IS A PRECONDITION AND NOT A DETAIL. The scratchpad holds two unrelated
lifetimes: one-off scripts an agent wrote for one afternoon, which is what a
retro wants to read, and the standing checks every submission runs, which is
what a retro must not touch. A rule written by place cannot tell them apart, so
the retro's sweep is either too greedy or carries a keep list that goes stale
the first time somebody adds a check without reading this token.

MOVING THEM MAKES THE SWEEP SAFE BY CONSTRUCTION. After this the scratchpad
holds only scratch, and the retro can have all of it.

WHAT MOVES. battery.sh and everything it runs, and run-criteria.py, which is how
a reviewer runs a draft's own criteria. What stays is what one agent wrote for
one piece of work.

WHAT HAS TO FOLLOW THEM. battery.sh's own paths, AGENTS.md and
doc/guidance/behaviour.md, which both tell every agent where to put a script,
and the token notes citing sh .se/scratchpad/battery.sh as their evidence.
se move is the verb for that and it already reports what it declined to rewrite.

A CHECK THAT IS NOT THERE IS ALREADY A FAILURE. battery.sh fails on a check it
cannot find rather than skipping past it, so a half-done move is red rather than
a battery that quietly shrinks. That part is done and this token does not redo
it.


WHAT MOVES, ENUMERATED. The rule is what a thing IS and not where it sits: a
standing check is one every submission runs or one a reviewer runs on somebody
else's work. Scratch is what one agent wrote for one piece of work.

    util/checks/battery.sh                 the runner
    util/checks/render-check.mjs           and the nine it runs
    util/checks/drive-editor.mjs
    util/checks/engine-args.mjs
    util/checks/engine-args-lifecycle.mjs
    util/checks/engine-spawns.mjs
    util/checks/one-look.mjs
    util/checks/panel-icons.mjs
    util/checks/no-loose-glyphs.mjs
    util/checks/no-loose-spawns.mjs
    util/checks/run-criteria.py            how a reviewer runs a draft's criteria
    util/checks/trycmd/                    which run-criteria.py execs

EVERYTHING ELSE STAYS, and that is most of the folder. observe-red.py names the
tests of one token in its own CASES list, so it is scratch by the rule even
though it was used on four tokens. Same for carry-red.py, count-verdicts.py,
watch-red.py, rename-states.py and the rest.

WHAT FOLLOWS THEM. battery.sh's own path to the .mjs it runs, and
run-criteria.py's path to trycmd. Both are one line each.

THE GUIDANCE DOES NOT CHANGE, and that is the point rather than an omission.
AGENTS.md, .github/copilot-instructions.md, .claude/output-styles/quackitect.md
and doc/guidance/behaviour.md all say to put a helper script in .se/scratchpad,
and that stays true: scratch stays scratch. What behaviour.md gains is one
sentence saying where the standing checks live and that a retro does not touch
them, because a reader who only knows the scratchpad will put the next check
there.

THE CLOSED NOTES ARE NOT REWRITTEN. Twenty token notes cite
sh .se/scratchpad/battery.sh as their evidence. That is what was run on the day,
and rewriting a closed token's evidence to name a path that did not exist then
is falsifying the record to make a search come out clean. A reader following one
of those finds nothing at that path and finds the battery one directory over,
which is a smaller cost than a record that lies.

AND A WORKTREE THEN HAS THE CHECKS, which is the second thing this fixes and it
was found in use. .se is ignored by git, so a git worktree gets no
.se/scratchpad and none of the checks come with it. Doing wk-1412093cd8 in a
worktree meant running every check from the main tree pointing at the worktree
root, building the engine into it by hand, and junctioning node_modules across.
util/checks is in version control, so a worktree gets it.
