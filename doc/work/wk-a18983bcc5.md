## detail

A finding on wk-711bbd91ec, checks read stale engines.

In runChosen, src/engine/tests.go, the check case sets the child's environment only when suiteEngine named an engine:

	if engine != "" {
		cmd.Env = append(os.Environ(), "SE_ENGINE="+engine)
	}

suiteEngine answers "" for a tree with no src/engine, and for one whose toolchain builds no engine. In that case cmd.Env is left nil, so the check inherits the parent process's environment whole, SE_ENGINE included. util/checks/lib/engine.mjs now prefers SE_ENGINE over .bin/se, so the check silently drives whatever binary an outer run, or a person's shell, left in that variable.

The run's answer does not say so. checkEngineNote builds "handed " + handed, and handed is "" here, so the engine field reads "handed " with nothing after it while the check in fact drove an inherited engine. The whole point of the token is that a check names the engine that answered it, and this is the one path where it names nothing and drives something.

The fix is one line: set SE_ENGINE on the child unconditionally, clearing it when no engine was chosen, so a check with nothing handed drives .bin/se as the comment in engine.mjs promises.

## done when

- the check case sets SE_ENGINE on the child in both branches, clearing it when suiteEngine named no engine
- a test that exports SE_ENGINE in the parent, over a tree with no src/engine, sees the check not handed that value
- the run's engine field never reads as a bare "handed " with nothing named
