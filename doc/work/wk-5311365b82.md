## detail

TestPublishKeepsEarlierClaimsWhenThePushKeepsFailing is red on origin/v4, measured at 7395c3b1. aClaimNote writes claimed_at as a fixed midnight, and a claim lapses after limits.claim_hours, three by default. So the fixture is a live claim for three hours of the day it was written and a lapsed one for the other twenty-one. The next write to the claims ref drops a lapsed claim, which is right.

The test asks which ids the claims file names after a push refused twice and then granted. It read one, wk-earlier-c, because the three before it had lapsed under the fixture rather than because Publish threw them away. So the test reads the clock rather than the code, and it is red on every box after 03:00 UTC. That behaviour is still worth holding: a push refused three times must not eat the claims made before it. The question the test asks does not change, only where it reads the answer.

## proposed action

Stamp the fixture with time.Now, so the claim the test makes is one the engine keeps. Then check that the test still bites, by taking the carry-forward line out of Publish and watching it fail.
