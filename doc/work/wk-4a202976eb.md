## detail

An agent that finds a small bug while working a bucket has no written permission to fix it, so it files the bug somewhere tidy and moves on. The next hand then rediscovers everything the finder already knew.

THE OWNER'S RULING, September 2026, in their words. A bug fix created while working on a certain bucket goes into the same bucket. If you find a bug fix and it makes sense to fix it early, you may put it in the bucket you are working and pull it instantly and fix it first. That is allowed, and it is preferred over putting it somewhere else for somebody else to do. If the bug is big and non-trivial, do not.

WHAT IT SETTLES. Two questions an agent asks and the guidance answers neither. Which bucket does a token minted mid-work carry, and may the finder drop what it holds to work it now.

WHY THE BUCKET MATTERS HERE. A person narrows the queue to one bucket and an agent drains it. A token minted with no bucket is invisible to that queue, so work found inside the bucket falls out of it. That was measured on this box: three tokens minted while draining claims could not be handed back to the hand that wrote them.

MEASURED THE OTHER WAY TOO. The pull's notice bug was found while proving an unrelated fix, and fixing it took one edit. Filed for another hand it would have cost that hand the whole reading first.

## proposed action

A section in the work-token guidance, where an agent already reads about minting. Four sentences.

A bug found while working a bucket is filed into that bucket, not a tidier one. The finder may put down what it holds, pull the new token at once, and fix it first. That is preferred over leaving it for a hand that has to rediscover it. The bound is triviality: a fix you can make right away, and a big or non-trivial one is filed and left.

It goes in the guidance rather than in a card, because a card is read once at session start and this is needed mid-work.
