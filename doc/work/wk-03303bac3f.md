## detail

A finding on wk-4bede61b24, which put the merge ban into rule 12 of doc/guidance/behaviour.md.

Rule 12 now tells every agent to push through the cherry-pick door. That door is cherrypush.sh, with land.sh beside it, and both sit in .se/scratchpad. The root gitignore holds .se on its second line, so neither is in any commit and neither reaches another box.

So a rule that travels names a door that does not. An agent on a fresh clone reads rule 12, finds no such script, and is left with the merge the rule just banned. The retired berg-commit.sh and berg-push.sh point at the same two names, and they do not travel either.

Driving-the-engine rule seven already says where this belongs. A script that earns its place moves to util/checks, which git carries. A standing rule naming a script is that script earning its place.

## proposed action

Move cherrypush.sh and land.sh out of the scratchpad into a folder git carries, and commit them. Then let rule 12 name that path, so the door is where the rule says it is on every box.

- the cherry-pick door is in a commit rather than under .se, decided by git ls-files naming it
- rule 12 of doc/guidance/behaviour.md names where the door is, decided by reading the rule beside the tracked path
