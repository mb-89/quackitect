## detail

THE GATE READS AN ESCAPED QUOTE AS THE END OF THE QUOTED SPAN.

Measured here in September 2026. Three engine calls through RUNME.sh were refused, and none of them could write.

The first carried an se apply payload naming a closing tag, and was told a redirection took it out. The second parted python statements with a semicolon inside the quoted script, and was told a second command. The third spread that script over lines inside quotes, and each newline was read as another command.

theQuotings in src/engine/hook.go walks the command in bash's own state machine, and that walk reads no backslash. A quote with a backslash before it closed the span here, while bash keeps it open. Everything after it was then read as syntax rather than as text.

IT CUTS THE OTHER WAY TOO. The same misreading leaves a span open that bash has closed, so a redirection standing after an escaped quote was inside the exception. That is an ungated write, and the new test catches it.

## proposed action

Honour the backslash in theQuotings. Outside quotes and inside double ones it hands the character after it through as text, so both scans read a space in its place. Inside single quotes it stays an ordinary character, which is what bash does.

## done when

- a command whose quoted argument holds an angle bracket is allowed through, decided by: a test in src/engine hands the gate that command and sees it allowed
- a redirection outside quotes is still refused, decided by: the same test with an unquoted arrow sees it refused
- a semicolon or a newline inside a quoted argument is not read as a second command, decided by: the same test with each inside quotes sees it allowed
- a bar outside quotes is still refused, decided by: the same test with an unquoted bar sees it refused
