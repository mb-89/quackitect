## detail

THE WRITE GATE READS SHELL SYNTAX INSIDE A QUOTED ARGUMENT.

Measured here on 2026-09-05. Three engine calls through RUNME.sh were refused, and none of them could write.

The first carried an se apply payload naming a closing tag. The gate answered that a redirection took the command out of the exception. Every angle bracket in it sat inside a quoted JSON string.

The second parted python statements with a semicolon inside a quoted script. The gate answered that a second command took it out.

The third spread that script over several lines, again inside quotes. The gate read each newline as another command.

So the gate scans the raw text rather than parting it into words. An arrow, a bar, a semicolon or a newline is read as syntax wherever it stands.

The cost is that no engine call can carry a payload naming those characters. That includes every token whose detail quotes a tag, and every table, because a table row is bars.

The same class of fault was fixed in src/engine/search.go this session. There a word beginning with an arrow was read as a redirection, and the fix asks whether the arrow stands alone.

## proposed action

Part the command into words the way a shell does, honouring single and double quotes, before looking for an operator. A character inside a quoted word is text. Outside one it is syntax, and the gate refuses as now.

## done when

- a command whose quoted argument holds an angle bracket is allowed through, decided by: a test in src/engine hands the gate that command and sees it allowed
- a redirection outside quotes is still refused, decided by: the same test with an unquoted arrow sees it refused
- a semicolon or a newline inside a quoted argument is not read as a second command, decided by: the same test with each inside quotes sees it allowed
- a bar outside quotes is still refused, decided by: the same test with an unquoted bar sees it refused
