## detail

The VS Code adapter retypes the engine's argument lists, and two standing checks exist only to catch the drift.

Measured at 4f4c83c0, by `grep -rn -- '"--[a-z]' src/extension/*.ts` and `wc -l`:

- src/extension/engineargs.ts, all 220 lines: 26 builders over 5 verb names and 30 flag literals.
- src/extension/extension.ts lines 1411 and 1427: the verb hold, written inline at the call site.
- src/extension/extension.ts, 9 spawn sites: --work appended by hand.

util/checks/engine-args.mjs (344 lines) and util/checks/engine-args-lifecycle.mjs (111 lines) bundle that module and drive every list against the real binary. A check that guards a copy would not exist if there were no copy.

The rest of src/extension is 4189 lines of drawing, key bindings, dialogs, watchers and spawning. VS Code brings the editor, git, the terminal and the agent host, and no engine change moves any of it. This token touches none of it.

wk-9f1d1d0a2d is the basic this stands on: without a catalog to fill there is nothing to fill it from.

## proposed action

engineargs.ts becomes a fetch and an expander, and stops naming verbs and flags.

  callTheEngine(name, params)  ->  string[]

It reads the catalog wk-9f1d1d0a2d answers, substitutes the {name} holes from params, keeps each when segment whose parameter is not empty, and appends always. Call sites pass named parameters, so the two inline hold verbs and the nine --work appends go with them.

THE ONE SEAM, NAMED RATHER THAN HIDDEN. Something must be said to get the catalog, so the adapter holds exactly one argument list: the one that fetches it. That list is an entry in the catalog it fetches, so the engine hands back the only thing the adapter names.

engine-args.mjs and engine-args-lifecycle.mjs are deleted with their line in util/checks/battery.sh. One check replaces them, over the built bundle rather than the source.
