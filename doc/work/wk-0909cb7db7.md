## detail

The staffing guard does not count the main agent as a hand. StaffingOf in src/engine/staffing.go skips an agent of kind session, with the comment that the main agent is the one being asked to spawn, not a hand.

So limits.parallel_agents of 3 asks for 3 spawned workers on top of the main agent. That is 4 hands for a number that says 3. Measured here: with two spawned workers and the main agent working, the guard still refused every call and asked for a third spawn.

The owner ruled that the number is how many workers there are, counting the main agent. At 3 that is 2 spawns. Reviewers are all spawned, because the main agent is a worker and never a reviewer, so 3 means 3 reviewer spawns.

The default is wrong for what he wants too. util/parameters.json declares limits.parallel_agents at 5, and he wants 3 as the default rather than as this tree's value. TheFloor in src/engine/config.go carries the same 5, so both copies move together or they disagree.

## proposed action

Count an agent of kind session as one worker in StaffingOf, and leave reviewers as they are. Change the default in util/parameters.json from 5 to 3, and TheFloor in src/engine/config.go with it. Update TestTheQueueIsStaffed to the ruling, and add a case that fails when the main agent is not counted.

## note

StaffingOf counted every agent but the session one. So the number the queue wanted was that many spawned workers beside a main agent already working. Three bought four, and the guard asked for a third helper while two were here.

The session agent was counted as one worker, and never as a reviewer, because a verdict is never the author's. So three still meant three reviewer spawns and only two worker spawns.

The default moved with it, from five to three, in both places that declared it: util/parameters.json and TheFloor. The linter was taught to hold those two to each other, so the pair cannot drift again. It already held the heartbeat and the ready budget that way.

## approach

Count the session agent where the roles are counted, so it lands in WorkersHere and never in ReviewersHere.
The main agent is a worker and never a reviewer, so the worker branch of the role switch changes and the reviewer branch does not.
The number stays one maximum for every role. What changes is who is counted against it.

The default moves in both places that declare it: the tree in util/parameters.json and TheFloor in src/engine/config.go.
They are one datum in two files. Moving one alone leaves a box with no tree answering 5.

The test drives the count rather than the refusal message.
With two spawned workers and the session agent present, WorkersHere is 3, and the same case with the session agent skipped is the red.
