## detail

Two agents rebuild and swap the engine when their change lands. se test with a whole ruling runs the battery inside the living engine, which stops that engine. Every swap rotates the log, severs the other agent's in-flight socket calls, and with tests via the engine makes tests impossible to finish. On 2026-09-03 three se test runs were severed unrecorded and the owner read a log window that kept starting over. The six-step rebuild ritual was typed by hand thirty-four times because Windows locks a running binary. Consumes wk-b8fd638ad7, wk-747d6019d6 and wk-a29aecd059.

## approach

The engine is the one door to its own replacement. A swap is a queued engine act. The caller asks, and the engine builds the next binary beside the current one. It checks the binary answers --version, drains in-flight calls, records the swap, and hands over to the new process. The new process reopens the same log session rather than rotating it. se test with a whole ruling does not run the battery inside the engine. It answers the plan at once, runs the battery detached with its output to a file under .se/tests/, and the next engine records the outcome at start. A go build aimed at .bin inside the tree is refused and told the door.

## done when

- a swap through the engine keeps the log session and severs no in-flight call: go test -C src/engine -run TestASwapKeepsTheSessionAndTheCalls
- se test with a whole ruling answers before the battery runs and the outcome lands in the record: go test -C src/engine -run TestTheBatteryRunsOutsideTheEngine
- a go build aimed at .bin inside the tree is refused and told the door: go test -C src/engine -run TestTheBuildDoorIsTheEngines
- the battery itself uses the door rather than stopping the engine by hand: grep -c 'se.exe --stop' util/checks/battery.sh answers 0
