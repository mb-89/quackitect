## detail

A claim is published on the ref refs/se/claims, and a cloud box cannot push that ref. Measured on 51b0d06, 2026-09-05, on Claude Code on the web: `git push origin refs/se/claims:refs/se/claims` answers `error: RPC failed; HTTP 403 curl 22` from the session's git proxy, while `git push origin refs/se/claims:refs/heads/se/claims` answers `* [new branch]` and `git ls-remote origin refs/heads/se/claims` then answers fd17555e. So the credential the cloud proxy injects pushes branches and refuses a ref outside refs/heads, and every claim a cloud box makes stays on that box: the remote's refs/se/claims only ever carries what a desk wrote, and a second box takes the same tokens.

This is the successor of the note wk-0c448a895c, which recorded the measurement and asked for the decision. The decision is: claims travel on a branch, because a branch is what every box may push.

## proposed action

The remote side of every claims refspec in src/engine/claim.go and src/engine/claimsync.go becomes refs/heads/se/claims. The local side stays refs/se/claims, so the ref is out of the local branch list and every reader of it is unchanged: push `refs/se/claims:refs/heads/se/claims`, fetch `+refs/heads/se/claims:refs/se/remote-claims` as wk-c698d46866 lays it out. A desk that still holds an old refs/se/claims on origin is read once more as a fallback until it is gone. The test that feeds a fake git asserts the refspecs, and the one that drives the real git pushes to a bare repository and lists refs/heads/se/claims on it.

## done when

- every git push and fetch the engine runs for claims names refs/heads/se/claims on the remote side, decided by: go test -C src/engine -run 'ClaimsRideABranch' ./... answers ok
- a claim published against a bare repository is listed by git ls-remote <bare> refs/heads/se/claims, decided by: go test -C src/engine -run 'ClaimReachesTheBareBranch' ./... answers ok
- a claim on origin's old refs/se/claims is still read, decided by: go test -C src/engine -run 'OldClaimsRefIsStillRead' ./... answers ok
- sh util/checks/battery.sh reports no new failure against the run before the change
