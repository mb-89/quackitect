## detail

TestAMoveReportsTheFileItCouldNotRewrite in src/engine/move_test.go is red in the battery on this box: `move_test.go:72: the file that could not be saved is not reported: []`. It appeared between .se/tests/battery-20260905-160529.out and battery-20260905-162527.out.

The fixture makes a file 0444 and its folder 0555 and expects writeAtomic to fail. The battery runs as root on the cloud boxes, and root ignores both. Measured here: id -u answers 0, a write through a 0444 file succeeds, and a create in a 0555 folder succeeds. So the save goes through, nothing is unwritten, and the test fails saying the verb swallowed a failure it was never handed.

The verb is right. What it promises is that a save it could not make is reported, and no save failed.

writeAtomic puts its temp file beside the target, named after it, with a dot, a random number and .tmp added. A target whose own name is 250 characters leaves no room for that suffix under the 255 a name may hold, so the create fails with a name too long, for root as for anybody.</detail>
