## detail

The owner's words: when a human submits, the reaction time has to be under a second. Today runEvidence runs every criterion command synchronously inside the submitting pull, so a submission can hold the terminal for over 80 seconds. Keep the cheap gates inline (the note exists, every finding of the current round answered, evidence keys present) and answer in under a second. Run the criterion commands after the answer, with the token in a state that says its checks are still running. The reviewer queue hands it out only once every criterion is green. A red criterion sends it back to in-work with the failure on the note. Decide in the spec where the async run lives, since the next pull by anybody can drive outstanding runs without a daemon. Also decide what the reviewer sees mid-run, and that abort still works.
