## detail

Two sessions ran at once and both were the actor main. TakeUp puts back everything else that actor holds. So every time one session named a token, the other session's token left its hands. That happened three times in the log, each followed by refused: no token in hand. An agent spent fifteen turns locked out. The name main is a word, and two sessions can say it. Consumes wk-52271812a5.

## approach

An actor is a session, not a word. The session id the harness sends on every hook names the session. main becomes main-<the id's short form> for a second session over the same tree, with the first keeping main. A take-up by a name that a live session of another id already holds is refused, naming the session. The register already knows the sessions. The gate reads it.

## done when

- two sessions over one tree hold two tokens under two names and neither puts back the other's: go test -C src/engine -run TestTwoSessionsAreTwoActors
- a take-up under a name a live session of another id holds is refused naming that session: go test -C src/engine -run TestANameAnotherSessionHoldsIsRefused
- the header and the table draw the second session under its own name: node util/checks/panel-draws-the-register.mjs .
