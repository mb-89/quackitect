## detail

AN OBSERVATION RECORDS A LINE NUMBER, WHICH IS AN ASSERTION ABOUT SOMETHING NOBODY CONTROLS. THE OWNER'S WORDS: why are you even baking line numbers into assertions, that is insane, this is again that thing where you make assertions about something that you have no control over and then somebody changes line numbers and then it is not fixed anymore. HOW IT GOT THERE. The Go runner prints file, line and message on one line, and the recorded red is a copy of that whole line. The line number was never chosen, it was carried along, which is how a fragile claim gets into a record without anybody deciding to put it there. WHAT IS DURABLE AND WHAT IS NOT. The message is durable, because it is a string in the source. The test name is durable. The file is nearly durable. The line number moves whenever anybody adds a function above it, and it moved twice in one session while this token's own work was going on. IT BUYS NOTHING. The line exists so a reader can find the assertion. A reader can find the assertion by searching for the message, which is what a person actually does, and which keeps working after an edit. AND I MADE IT WORSE. TestEveryRedSaidResolves, added on wk-2b78b911b1, requires every recorded red to name a line that carries an assertion. That check institutionalises the fragile half: it goes red on an edit that changed nothing, which is a check that cries about the tree rather than about the work. THE SHAPE THAT MAY WORK. A recorded red names the test and what it said. The checker finds the assertion by its words rather than by its address, and fails when no test in the tree says that. wk-2b78b911b1's own criterion 6 is rewritten the same way. WHAT IS UNCERTAIN. Whether the file name stays, which is nearly free and helps a reader, and what to do with the observations already recorded with line numbers in them, since rewriting a record is not something this project does lightly.
