## detail

Finding from the verdict on wk-00c162f56e (Strip dead process comments). Not a child of it.

At that token's ended commit 8626f69f, doc/work/wk-00c162f56e.md carried three sections, "## evidence: step 1. ask", "## evidence: step 2. do" and "## evidence: step 3. verdict", the first two fully ticked with the author's sentences. git diff --stat 04307267 8626f69f shows the note gaining 43 lines, which is those tables.

By the time the token reached a reviewer the live file had all three gone, and everything below "## approach" was absent. Its frontmatter was current: status done, holder reviewer-quill, both began hashes and the ended hash. So the engine wrote that file after the tables vanished and did not restore them.

The damage is twofold. The author's evidence is destroyed in the live tree, surviving only because the ended commit still holds it. And no verdict can be given: checkEvidence at src/engine/pull.go:313 finds an empty submission through evidenceTable at :371, every row reads unticked, and the submission is refused at :354. A reviewer cannot honestly tick steps 1 and 2, since those are the author's answers. I unblocked this one by restoring both sections verbatim from git, which is auditable but is not a fix.

A smaller trap sits beside it. The note freezes its criterion wording at mint while checkEvidence loads the process fresh, so a criterion renamed since mint can never match. This token renamed one.

## proposed action

Teach the save that a section it did not author is not its to delete. Teach the gate to say which of three things is wrong with a checklist.

keepingWhatWasNotSent lays a submission's evidence over the note's own rather than replacing it, so a payload carrying no evidence deletes none. evidenceFor answers whether a row exists apart from whether it is ticked. checkEvidence uses that twice: a lost section is refused by name, and a criterion no row matches is refused by name. Neither reads as a row somebody forgot to tick.

The engine that refused this submission has been replaced. The resident one now carries the answered-not-ticked gate. So step 2 line 4 closes as what it is: answered, and unticked.
