## lesson 1 · round 1 · by reviewer5

**the class:** A criterion's sentence and the command under it are about different things, so the command exits zero while the sentence is false. Two shapes: BORROWED, the command was copied from a neighbouring token and still checks that token's deliverable; PROXIED, a unit test stands in for an event having happened.

**instead:** Read the sentence and the command as a pair and ask what state would make the sentence false. If the command still exits zero in that state it is not this criterion's command. A criterion about a document's content greps the content it names; a criterion about an event checks the artefact the event leaves behind, not a test that the code for it passes.

## lesson 2 · round 2 · by reviewer5

**the class:** A criterion demoted to prose because the fact it checks is live, when a command criterion is exactly the instrument for a live fact: the engine runs it once, at the submission gate, so it reads the world at the moment of submission and nowhere else. wk-967b04b877 warns against a live fact written as a STANDING rule that outlives the token, and its remedy was to pin the assertion, not to drop the command.

**instead:** Before demoting a criterion to prose, write the command and run it through the engine's own door - .se/scratchpad/trycmd/try.exe, or run-criteria.py which uses it - in BOTH directions: the state that must fail and a state that must pass. A form that answers green in both is a quoting failure, not proof that the criterion cannot be a command. Demote only when no form works, and say which forms were tried. And ask who reads a prose criterion and when: where nothing reviews the submission before the effect is irreversible, a prose criterion is not a check at all.
