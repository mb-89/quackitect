## detail

Not ready, a design under discussion and not work to pick up. A token has no schema, so each agent invents the shape of its submission and the reviewer has no fixed place to look. Proposal: a work token follows a process, a graph of steps each naming suppliers, inputs, outputs, customers and enablers, checked once per definition. The token bakes in the checklist instance, references the process class by digest, and each entry is a chapter with submission and reviewer subchapters. Statuses become the union of step names across defined processes, each step declares a role, and the engine and views reason on roles. Not decided: which columns survive, which roles the engine knows, where a definition is stored, whether the graph is stored or rendered, and the migration.
