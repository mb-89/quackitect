## detail

A finding on wk-808abd40a4, archive without a ref.

keepInGit in src/engine/archive.go writes the note with git hash-object -w and nothing points at the object it makes. The old archive hung a tag off it, so it was reachable and a gc left it alone. Now no ref and no tree reaches it, and git gc --prune=now, git prune or git repack -ad is free to sweep it.

Where the note was committed the row also names on_branch, which the branch keeps reachable, so the loss is invisible. Where it was not, on_branch is empty by onBranch's own rule and the unreachable blob is the only copy there is. A tracked token minted and closed before anybody committed doc/work is exactly that case, and the close deletes the file from the disk.

The comment on OnBranch says a gc is free to sweep the blob, so the hole is known and nothing holds it.
