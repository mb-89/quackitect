## detail

Nothing stops a test that calls t.Parallel from swapping a package-level seam. gitRuns in src/engine/claim.go is one such seam, and aFedGit in gitfed_test.go swaps it for every caller. Two parallel tests in gitfedcancel_test.go held it while three other parallel tests drove the real git, and those three failed as a group with git answering that refs/se/claims is not a valid object name. wk-00e4785e51 took the two out of parallel, which fixes the instance and leaves the rule unwritten. Go refuses t.Setenv inside a parallel test for exactly this reason and has no such refusal for a plain variable.

## proposed action

A check under util/checks that reads the engine's test files, finds every function that assigns a package-level variable or calls a helper which does, and names any that also calls t.Parallel. The seams are few, so the helper list can be found by reading the assignments rather than guessing.

- the check names a test made parallel and swapping gitRuns, decided by: add t.Parallel back to TestALiveContextStillReachesGit and run the check
- the check answers clean over the tree as it stands, decided by: run it from the root with the tree unchanged
