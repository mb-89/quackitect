## detail

A person edits guidance and the projected layer stays stale, with nothing said.

.claude/output-styles/quackitect.md and .github/copilot-instructions.md are outputs. They are written from doc/guidance and util/cage by se -project, declared in util/projections.json.

Nothing runs it when a source changes. An agent that edits a chapter and does not know the command leaves the projection behind, and the next session reads the old layer while the chapter says something else.

THE OWNER SAW IT: make sure whatever you write is actually projected to the right place. I think last time you had to do it by hand, this should be a projection. You should not have to do it by hand.

Measured in September 2026. The stop protocol was rewritten three times in one session, and each time the projection was run by hand. Once it was forgotten, and the layer in force disagreed with the chapter for the rest of that turn.

The engine already projects on startup, so a session that restarts is current. What is missing is anything between one startup and the next.

## proposed action

Read how the engine projects on startup and what watches the tree. The index watcher already sees every file change, so a projection when a declared source changes is a small step from what is there. Failing that, a check that the outputs are not older than their sources says it out loud instead, which is the same shape as the stale bundle in wk-4d2f104ed8.

## done when

- editing a projected source updates its output without anybody running a command, decided by: touch a chapter and read the output style
- or an output older than its sources fails a check that names the file and the command, decided by: touch a source and run it
