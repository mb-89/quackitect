## detail

The engine is reachable four ways: the HTTP hook door, the verb socket, the command line flags, and the lane's tools. Four grammars over one engine, and two of them have already drifted apart. mcp-tools exists because the lane built calls the engine had no flags for, so every mint an agent made through that door was refused for a field it could not send. With the lane retired, three are left, and level 0 need not keep a second HTTP door when the verb socket already carries every verb. A protocol with many clients turns a new client from a new grammar into one more caller. The shape this belongs to is doc/spec/one-core-many-satellites.md.

## proposed action

One protocol over one address, and every client speaks it: level 0, the command line and the editor. The engine's own pid file carries the address, so nothing is projected into a settings file and no port is committed. The HTTP hook door goes when level 0 no longer needs it.

## done when

- one protocol carries every call the engine answers, and a second grammar reaching it is a failure a check names
- the address is read from the engine's pid file at call time, and no port is written into a file git carries
- each client is driven against the real engine over that protocol, the way engine-args drives the extension today
- sh util/checks/battery.sh reports no new failure against the run before the change
