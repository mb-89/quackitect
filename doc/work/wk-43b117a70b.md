## detail

A busy index makes se_test answer that the package did not compile, and it compiled.

Measured on this box in September 2026, across four hands over one tree. Roughly two calls in three answered either "database is locked" outright or "THE PACKAGE DID NOT COMPILE, SO THIS IS NO RED" with "database is locked" as the build error. Waits of ninety and then a hundred and eighty seconds did not clear it.

coverBinary in src/engine/testmap.go:308 calls setMeta on .se/index.db under a five second busy timeout. A long-lived lsp process and the daemon keep the write lock busy, so that one meta write times out. The cover binary itself builds.

So the answer names the wrong thing. A hand reads that its package will not compile, goes looking for a compile error, and finds a healthy package. One hand lost about fifteen minutes to it here, and another reported the same.

It also blocks the rule that a test is watched red before the change. A hand that cannot run a test cannot see one go red, and the honest move is to wait, which is where the time went.

## proposed action

Say a busy index is a busy index. Where setMeta times out, answer that the index is busy and the tests did not run, rather than that the package did not compile.

## done when

- a build whose note cannot be written still answers the binary, decided by: a test holding the index write lock across coverBinary
- that answer carries no error, decided by: the same test
- a test whose map cannot be written still answers what it did, decided by: a test holding the lock across writeRegions
- a real compile error still answers that the package did not compile, decided by: the existing nored test

## approach

A NOTE ABOUT A BUILD IS NOT THE BUILD.

coverBinary builds the binary, then writes one row saying which source hash it was built from. It returns that write's error as its own. So a locked index makes a binary that is on disk and correct report that it will not build.

The caller reads any error from coverBinary as a build failure, and aBuildFailure says the package did not compile. That is how a busy index becomes a compile error nobody can find.

The write is bookkeeping. Losing it costs the next run a rebuild and nothing else. So the note stops being able to fail the thing it describes, and the engine records that it could not write it.

writeRegions is the same shape. A test that ran and passed must not be reported as failed because its map could not be saved.

Where a lock does stop work, the answer names a busy index rather than a compile error.
