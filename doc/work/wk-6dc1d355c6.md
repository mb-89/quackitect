## detail

Found reviewing wk-5bba8e497a, which made the state of play the surface where a person finds parked work.

src/engine/stateofplay.go:65 builds each parked line as t.ID + title + "ready when " + the field. Several tokens write the field starting with the same two words, so `se state` prints them twice.

Measured on this box on 2026-09-06: `.bin/se state` names 22 parked tokens, and five read "ready when ready when ...", among them wk-5feb2d8738, wk-8e1d18c21a, wk-a0804eaf08 and wk-ac42b15fb3.

The queue hands out nothing carrying a ready_when, so this screen is the only place the parker finds the token again. A line that stutters on its condition is the one line a reader has to read.

Nothing catches the class. No check reads the field, and the schema puts no shape on it.

Either half is a fix: trim a leading "ready when" off the field where the line is built, or refuse the prefix in the field. Trimming at the render fixes the twenty-two notes already written without touching them.

## proposed action

A parked line names its condition once, whatever the field starts with.
