## detail

Found while closing wk-5f8dda7870, which this token names.

util/checks/the-branch-head-builds.mjs reads the head into a folder of its own and runs go build -gcflags=-e ./... in src/engine. go build never compiles a file ending in _test.go, so the check cannot see a test file naming a symbol that is gone.

That is the exact way the branch broke. sessiontakesmainback_test.go landed calling OpenLog and Yes after both left package main. The check was green over that head, and a clean worktree of it answered two undefined errors for every test in the engine.

The cost the check's own comment names is paid by whoever clones: a reviewer told to test against a clean copy of the head reads a package-wide setup failure instead of the token's answer. A build that skips the test files leaves that cost exactly where it was for half the source.

## proposed action

Build the test binaries too, over the same clean copy. go vet ./... compiles them and asserts nothing else, and go test -run TestNothingAtAll ./... does the same while running no case. Take one, say which on the token, and leave the existing go build line as it is so a plain build failure still reads as one.

## done when

- the check compiles the engine's test files over the clean copy, decided by reading the-branch-head-builds.mjs for a command that reads _test.go
- a head whose test file names a symbol that is gone fails the check, decided by planting such a file, committing it and running node util/checks/the-branch-head-builds.mjs over the tree
- a head that builds and whose tests compile still passes, decided by the same command over the branch tip answering nought failed
