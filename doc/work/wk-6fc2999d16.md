## detail

A FINDING FROM THE VERDICT ON wk-fc6b6c5aa7.

src/engine/hookserve.go:91. theSameFolderEveryTime decides a path is Windows by a colon in the second place, `len(path) >= 2 && path[1] == ':'`. A UNC root has no drive letter, so `\\server\share\tree` fails that test and is left alone on both counts: its backslashes are not folded and its case is not folded.

THAT IS THE MEASURED OUTAGE, ONE SPELLING FAMILY OVER. A share is case-insensitive the way a drive letter is, so `\\SERVER\share\tree` and `\\server\share\tree` are one folder and hash to two ports. The engine binds the second, the settings file the harness read once names the first, and every guard rides on that door: all of them absent, and nothing saying so. The token was written to shut exactly this, and it is still open for a work root on a network share.

The rest of the function already reads the same test twice, so the fix is that test, not a new one: a path that starts with two separators is Windows too.

## proposed action

Widen the Windows test in theSameFolderEveryTime so a UNC root counts: a colon in the second place, or a path beginning with two separators. Both folds then read the one test, as they do now.
