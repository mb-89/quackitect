## detail

The VS Code adapter holds knowledge that goes stale. The engine changes and the adapter does not follow.

Measured: the engine grew a tracked flag. The lane did not follow. Every non-note mint through the tool was refused while the same mint at the shell worked.

Two standing checks exist only to catch that drift.

- util/checks/engine-args.mjs: drives the extension argument builders against the real binary.
- util/checks/mcp-tools.mjs: drives the lane for its tool list.

A check that guards a copy would not exist if there were no copy.

Where the knowledge sits: src/extension/engineargs.ts, 220 lines, builds argv from verb and flag names it holds itself. The extension is 4439 lines and how much of the rest is knowledge is unmeasured.

What the adapter keeps: how to draw a table, how to bind a key, how to open a dialog. VS Code is the workbench. It brings the editor, git, the terminal and the agent host, and none of that moves.

The engine already describes part of the screen. se query --view work answers the columns, their names, their widths, and which cell opens something.

## proposed action

Move what can go stale out of the adapter. It names no verb and no flag the engine did not hand it.

## approach

Measure first. Split src/extension into what renders and what knows. That number says whether this is one token or a scope with sub-tokens under it.

MEASURED at 4f4c83c0, in the note below: 250 of 4439 lines are the engine's, in three mechanisms. So it is a scope, carried by wk-9f1d1d0a2d, wk-36c8a26220 and wk-0086ed9e9b.

THE INTERFACE. The engine answers a catalog of the calls a caller makes, beside the dispatch it describes:

    se query --calls ->
    {"always":["--work","{work}"],
     "calls":{"calls":{"argv":["query","--calls"]},
              "mint":{"argv":["work","--title","{title}"],
                      "when":[{"given":"detail","argv":["--detail","{detail}"]}]}}}

Two forms only: a {name} hole, and a when segment kept where its parameter is not empty.

THE ONE SEAM. The adapter holds one argument list: the one that fetches the catalog. That list is an entry in the catalog it fetches.

The test is the one ODBC uses. The adapter interface is the engine interface. Anything the adapter names that the engine did not hand it is a second implementation.

No TUI and no browser UI are built here. A second workbench would bring its own editor, git and terminal, and none of that is what this token moves.
