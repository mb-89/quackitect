## lesson 1 · round 1 · by reviewer

**the class:** A check reported as passing without its output being read, and the thing that made it easy to skip: an assertion that names a value out of the data it was written against rather than the rule it means. When the data legitimately changes, the check goes red for a reason that has nothing to do with the code, everybody who looks at it knows that, and the red gets carried forward unmentioned until the whole check is discounted. The submission is then honest about its intent and wrong about its facts, which is worse than saying nothing, because a stated 0 failed is read as a run.

**instead:** Derive the subject of an assertion from the same declaration the code derives it from. If the code asks the view which column is last, the check asks the view too, and neither one has a column name written into it. And before writing that a check passed, read its last line and its exit code, and paste them. A number in a submission is a measurement or it is a memory, and the reader cannot tell which from the way it is typed, so make every one of them come from a run.
