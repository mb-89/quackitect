## detail

The adapter still decides two things about a column that the engine owns.

WHICH CELL MAY BE EDITED. src/extension/editor.ts, function locked(), lines 504 to 519, holds 8 property names and the engine's reason for refusing an edit on each: id, seq and type say "the engine decides this", status and holder say "a pull moves this", subs, depends_on and successors say "a list is edited in the note". The engine already owns the ruling: extension.ts sends the edit to `work --set --field` and the engine refuses it. So the refusal is decided twice, and a property renamed in the engine leaves the editor offering an edit the engine will reject.

A COLUMN WIDTH. src/extension/panel.ts, `.table th.actor, .table td.actor { width: 34% }`. A width for a named column, written in a stylesheet.

Everything else about a column already comes from the engine. The pane answer carries columns, heads, widths and opens, and editor.ts draws all four from it: `t.widths?.[c]`, `t.heads?.[c]`, `t.opens?.[c]`.

READ THE PARENT'S SECOND CRITERION THIS WAY, and disagree here if you read it otherwise. util/checks/panel-draws-the-register.mjs rules that the DECLARATION chooses the sidebar table's columns: "a widget with the columns written into it is a second place the panel is decided, and util/parameters.json would no longer say what the panel shows." That ruling stands, so the sidebar's columns and titles stay in util/parameters.json and are not moved to an engine answer. What is left is the two decisions above, which the declaration does not make either.

## proposed action

The pane answer grows locked, beside opens, which it is the mirror of: opens says a cell is a door, locked says a cell is not an edit and why.

  Table.Locked map[string]string  `json:"locked,omitempty"`

Filled in src/engine/view.go where Opens already is, from the one place that rules on an edit today, so the editor's copy has nothing left to say. editor.ts deletes locked() and reads t.locked?.[c].

The width moves to the declaration that owns the column beside it, as a field on the entry in util/parameters.json, and panel.ts draws it the way editor.ts draws a width instead of carrying a rule for a column name.

A check holds the editor to it: rendered from two different pane answers, no property name and no width appears in the page that was not in the answer that drew it. That is the shape panel-draws-the-register.mjs already uses.
