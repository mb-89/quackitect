## detail

CLASS: ONE RED PER CRITERION, TAKEN ON THE HALF THAT WAS EASIEST TO BREAK, ON A
SENTENCE THAT NAMES TWO THINGS.

A criterion's sentence carries two properties joined by an and. The worker
watches it fail once, records what was taken away and what it said, and the
observation is true. It establishes the half that was broken and says nothing
about the other, and the half that gets broken is always the cheap one, because
that is what makes it a quick thing to watch.

THIS MATTERS MORE THAN IT USED TO. The spec gate now lets a green command
criterion through when it carries **red without** and **red said**, on the
ground that a recorded observation answers the same question as running it red:
has anybody watched this fail. That trade is sound and it moves the whole weight
onto the observation. A red taken on the easy half is then not a weaker piece of
evidence than a red the engine ran, it is a claim about a different sentence.

MEASURED ON wk-2b78b911b1, "drain the backlog", round 2, whose three command
criteria are all green and all carried through the gate on their reds.

Criterion 1 says every id on the list is named in the detail beside what
happened to it, and the token's whole design is that the list is the backlog as
it stood at commit 6418d6a4 across both stores. The red is a verdict taken out
of the detail. Nothing was ever taken off the list, nothing derives the list
from that commit, and drain_test.go names no sha at all, so the guard against
the list being SHORT -- which is the failure round 1 rejected this token for --
was never watched and is not checked.

Criterion 2 says a settlement names a file and line that exists, a heading that
is IN THE FILE IT NAMES, or a token id that is a token. The red is a citation
pointed at src/engine/nosuchfile.go:484. I probed the resolver rather than
reading it: a reason naming doc/guidance/behaviour.md and a heading that lives
in specifying.md resolves clean, a quoted section attributed to the wrong file
resolves clean because the resolver walks all of doc/guidance and ignores the
file named, and section "the" resolves clean because it is a substring search.
The half about the file existing was watched. The half about the heading being
in it cannot fail.

WHAT TO DO INSTEAD. COUNT THE PROPERTIES IN THE SENTENCE AND TAKE ONE RED FOR
EACH. Where the sentence says A and B, break A, watch it, put it back, break B,
watch it. Two observations on one criterion is the honest shape, and where the
field holds one, split the criterion, because a criterion that needs two reds
was two criteria.

AND BREAK THE EXPENSIVE HALF FIRST. The half that is awkward to break is the
half the check is least likely to be looking at, which is the whole reason it is
awkward: the cheap break is cheap because the code already has a branch for it.

AND AN OBSERVATION IS A CITATION, SO IT RESOLVES. wk-2b78b911b1's criterion 4
records drain_test.go:201 and the assertion it quotes is at drain_test.go:241 in
the only committed version of that file, which is clean and 267 lines. The
message is right and the line is forty out. Write the file and line the assertion
is at when you record it, and re-read it before submitting, because with the gate
resting on the observation an observation nobody can follow is the whole evidence.

THE CHECK, RED TODAY: read each criterion's sentence for its ands, then read its
**red without**. On wk-2b78b911b1 two of three name one property and the sentence
names two.
