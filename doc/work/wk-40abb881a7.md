## detail

src/engine is one flat package: 80 non-test files and 23193 lines, and 184 files and 38199 lines counted with tests. Every name in it shares one namespace, so writing a helper needs a tree-wide search first.

Three build failures came from collisions: firstLine, mustJSON, and fs against the io/fs import.

The guidance already gives the method. A folder whose files only call each other is a package under internal, named for what it holds. The call graph shows the seams. The test of a bad seam is an import cycle, so a cycle found is a seam drawn wrong.

The seams are measured rather than chosen.

## proposed action

Compute the call graph over src/engine and name the groups it shows, with a file count and a line count each. Move nothing until that is written down.

Then each named group moves to its own package under src/engine/internal, named for what it holds. Build and vet after every move.

## done when

- the call graph over src/engine is computed, and the groups that reach nothing outside themselves are named with a file and line count each
- each named group is a package under src/engine/internal named for what it holds
- no import cycle is introduced: go build and go vet are clean after every move
- firstLine, mustJSON and fs are no longer one namespace problem
- the engine tests pass after the split
