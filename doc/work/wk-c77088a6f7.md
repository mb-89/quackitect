## detail

src/engine/removal.go splits a command with pipeline and reads each part's first word as a program. A quoted argument holding several lines becomes several parts, so a line of prose that begins with a remover is read as a deletion.

Measured in this tree on 2026-09-05. A git commit whose -m body carried the line "rm was allowed" was refused with "This command deletes was". Nothing was being deleted. The word sat inside a quoted commit message.

The guard already knows prose reaches this door. Its own MEASURED comment names a --detail, a commit message and an echo, and TestARemovalNeedsARead asserts three prose cases. All three carry the remover mid-sentence, so none of them goes red on this shape.

The damage is that a worker cannot write what the guard did into the commit that answers it. The refusal names a file the command never held, so the agent guesses at which word it was.

## proposed action

Read a quoted argument as one word rather than splitting it into pipeline parts, or ask that a part's first word stands outside quotes before reading it as a program.

## done when

- a git commit -m whose body has a line beginning with rm is not refused, decided by a case added to TestARemovalNeedsARead in src/engine, seen red first
- a real deletion is still refused: the existing cases in TestARemovalNeedsARead stay green
