## detail

writing-go rule 14 asks a test to be a table under t.Run. util/setup holds 2 test files and 1 of them calls t.Run nowhere.

Counted at HEAD by `find util/setup -name '*_test.go' -exec grep -L 't\.Run(' {} + | wc -l`, which answers 1. The whole file count comes from `find util/setup -name '*_test.go' | wc -l`, which answers 2.

What is gained is that a new case becomes a row rather than a new function carrying a copy of the setup. The file that already uses t.Run shows the shape, so this token settles the one that does not.

What breaks if nobody does it is that the module drifts further from rule 14 with every case added. The standing check that would hold the rule stays impossible to turn on.

The package is the compilation unit. A file converted, built and tested before the next one starts leaves the package building for every other hand.

A table earns its place where cases share setup. A single case stays a single function, and this token names each file it leaves alone and why.

## proposed action

Convert each _test.go file under util/setup to a table under t.Run, one file at a time, building and testing the module after each file.

## note

util/setup/quiet_test.go now runs its cases as a table under t.Run. The rows are the source files the guard scans, one row for each. A failure names the file as a subtest rather than burying it in one report.

The whole scan happens once, before the subtests, and each row keeps the lines it read. The same pass counts the processes the module starts. The guard against a scan that finds nothing now sits in its own subtest.

setup_test.go already runs its cases under t.Run, so it stays as it is. No file in the module stays a single function.

What the guard forbids does not change. It still refuses a SysProcAttr written outside quiet_windows.go, and any exec.Cmd built outside Quietly.
