## detail

The owner's rule, September 2026: every box works on a branch of its own, and finishing up merges it back.

Today every box commits and pushes to v4 directly. Measured on this box in one session: nine pushes, four refused as non-fast-forward, three merges, and one conflict resolved by hand in doc/work/archive.jsonl. Another hand reported the same clone sitting 37 commits behind, so the queue passed over 39 tokens that origin had already archived, and answered wait to a backlog of 194.

THE GAIN. A hand spends its whole turn on the token it holds, and the queue it reads agrees with the branch. THE BREAK. Without it a hand spends that turn merging, and the queue hands out work another box has finished.

The shape the owner asked for. A box takes a branch of its own when it starts, off the trunk as it stands. It works and pushes there, so a push never races another box. Finishing up drains its notes, then the branch merges back to trunk. Fetching trunk is a thing a person asks for, and not a thing that happens under a hand mid-token.

THE CLAIMS DO NOT MOVE. They already ride refs/heads/se/claims, which every box reads whatever branch it works on. The owner's constraint: two branches must never work one claim. So that ref stays shared, and a box's branch carries its commits and nothing else.

This rides on [[wk-5d80f3ac21]], where finishing up lives.

## proposed action

Give each box its own branch at session start, push only there, and make finishing up merge it back to trunk once the notes are drained.

## approach

THE ENGINE TAKES THE BRANCH AT START. It reads HEAD. On trunk it creates and checks out `box/<id>`, where the id is what `Box` answers in claim.go. On a box branch already it does nothing, so a restart moves nothing.

IT IS NEVER FATAL. No git, a detached HEAD, or a checkout git refuses leaves the box where it stands, and the engine says why.

THE NAME SITS OUTSIDE `se/`. Claims ride `refs/heads/se/claims`, which claim.go says is swept on purpose. A reader who wants one prefix can disagree here.

NOTHING NEW PUSHES. No engine code pushes a work commit today, so pushing only to the branch is a refusal rather than a call. A `git push` naming trunk is refused at the two doors that already refuse a commit taking the index. Those are hook.go and runverb.go.

THE MERGE HANGS OFF ONE POINT. `theNotesLeft` in pull.go answers that nothing is left to finish, and the merge belongs there. That code is [[wk-5d80f3ac21]], open, and another hand holds it.

THE FETCH RULE STANDS ALREADY, so it becomes a check rather than a one-time criterion.
