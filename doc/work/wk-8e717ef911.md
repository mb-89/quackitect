## detail

Found reviewing wk-711bbd91ec, "checks read stale engines".

src/engine/tests.go:783, in checkEngineNote, ends the stale-engine warning with:

    "Swap first: se --swap --built"

--built is the one flag that cannot cure the condition the sentence has just diagnosed. src/engine/main.go:79 declares it as "with swap: hand over to the program already in .bin rather than building one", and planSwap (src/engine/swap.go:236-249) honours that: with built set it skips buildNext entirely and hands over to the binary already at engineAt(r).

The condition being reported is exactly that .bin/se is OLDER than the source it was built from. So a reader who follows the advice either hands over to the same stale binary, or, when the running engine already is that build, gets planSwap's refusal "the program on disk is this same build, so there is nothing to hand over to". Either way the tree is still stale and the reader has been told the cure was applied.

The cure is a plain se --swap, which builds from the tree and then hands over. That is what the token's own detail used and what I ran while reviewing.

TestACheckOverAStaleEngineSaysSo (src/engine/checkengine_test.go) asserts only strings.Contains(runs[0].Engine, "se --swap"), which "se --swap --built" satisfies, so the test does not see this.
