## detail

The cloud has no panel. The only surface a person has on a box they are not sitting at is the chat. Nothing the sidebar offers can be reached there.

The engine already receives what the person wrote, and from the harness rather than from the agent. A message that starts a turn arrives in the hook payload. One written mid-turn is copied out of the harness transcript on the next tool call, or at the stop if the agent goes quiet.

Both are written to the record as user and prompt, and nothing else in the record carries that pair. So the engine can tell what a person said from what an agent said, without trusting the agent to be honest about it.

## done when

- a message that is only the keyword changes the control it names, decided by: send one and read the state
- the same keyword inside a sentence changes nothing, decided by: send one and read the state
- the change names the keyword and what it moved in the record, decided by: read the record after
- a keyword an agent writes rather than a person changes nothing, decided by: a test that plants one in a tool call

## approach

The engine matches a keyword against what the person said, and against nothing else. A record of user and prompt is the only input it reads.

The whole trimmed message has to be the keyword. A mention inside a sentence is not one, which is what keeps the guidance describing these from firing them.

What matched and what it moved goes in the record, so a change nobody expected can be attributed rather than guessed at.

Nothing is relayed by the agent. The text comes from the harness, so an agent cannot forge one, and no guard has to be written to stop it trying.
