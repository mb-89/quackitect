## detail

Most engine tests build a temporary tree of their own. Files are written, a git repository is initialised, and an index is opened. A search of the test files for TempDir is the command that counts them.

There is no fixture layer. Each test file carries a builder of its own, and the helper names differ from file to file. A search for the functions those files declare answers how many there are.

The cost is not only the duplication. A fixture written in many places cannot have its backing changed. So the question of whether a fixture should be rows rather than files cannot be answered while this stands.

Two tests failed their own TempDir cleanup during earlier work, because a handle was still open. That is the shape of the defect the duplication hides.

## approach

One builder for the suite. A test says what tree it wants, and the builder answers the roots.

The seam is the interface rather than the storage. Nothing in a test names a temporary folder or a git command, so the builder is free to decide how a tree is made.

The per-file helpers move behind it one at a time, and each keeps the tree its own tests expect. A test wanting something no other test wants asks the builder for it, rather than writing files beside it.

Nothing about the backing changes here. The builder writes files exactly as the helpers do now, so this is a move and not a rewrite.

## done when

- one builder answers the roots the engine tests use, decided by: search the test files for TempDir
- no test file carries a fixture builder of its own, decided by: search the test files for a function answering Roots
- the engine tests pass with the builder in place, decided by: the test door over the engine package
- the builder writes files the way the helpers did, decided by: read the builder for a call that writes a file
