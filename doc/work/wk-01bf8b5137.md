## detail

The read half of the session rule is taught. The write half is not, and it loses what the read half was fixed to keep.

A session-scoped store writes Session: currentSession(r). Through a rotation the log names no session and currentSession answers the placeholder, so the file is stamped "current". ofThisSession then compares "current" against the real name the next record brings, they differ, and the store is read as another session's. What was written in the window is dropped a moment later, silently.

Found while working wk-5477e00b39, which taught StandingClaim to read through ofThisSession. Reading is now right and writing is still wrong, so a stop claimed in the window stands until the log names a session and then does not.

MEASURED, on 69dc3aed: se find --regex "Session: *currentSession" --path "src/engine/*.go" answers four writers outside tests, at owed.go:280, stop.go:159, unbound.go:147 and unbound.go:229.

Named says which answers are a session at all, and it is already the judgement the read half uses.

## proposed action

Give the write half the same judgement the read half has. A writer that cannot name a session writes nothing on the file, and a file with no session on it is read by the rule already in ofThisSession.

Then drive it through the store table in src/engine/foursessionstores_test.go rather than teaching one store, because it is one rule.

## done when

- a value written while the log names no session is still read back once the log names one: a Go test in src/engine that enters theRotationWindow, writes a store, calls theSessionNowIs with a later name, and reads it
- no writer stamps the placeholder on a session-scoped file: se find --regex "Session: *currentSession" --path "src/engine/*.go" answers only the tests
- the stores already taught the read half stay green: se test --on this token --propose TestARotationDoesNotEmptyTheFourStores --propose TestTheFourStoresEndWithTheirSession
