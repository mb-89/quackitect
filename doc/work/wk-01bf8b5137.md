## detail

The read half of the session rule is taught. The write half is not, and it loses what the read half was fixed to keep.

A session-scoped store writes Session: currentSession(r). Through a rotation the log names no session and currentSession answers the placeholder, so the file is stamped "current". ofThisSession then compares "current" against the real name the next record brings, they differ, and the store is read as another session's. What was written in the window is dropped a moment later, silently.

Found while working wk-5477e00b39, which taught StandingClaim to read through ofThisSession. Reading is now right and writing is still wrong, so a stop claimed in the window stands until the log names a session and then does not.

MEASURED again, on 5786a138: se find --regex "Session: *currentSession" --path "src/engine/*.go" answers eight writers outside tests, at guards.go:206, hold.go:47, holdstore.go:46, owed.go:152, owed.go:280, stop.go:159, unbound.go:147 and unbound.go:229. The four on the first reading were a stale index.

WHAT IS NOT SETTLED. Writing the empty string instead reads as another session's, which drops the value sooner. Reading a stored placeholder as this session's keeps it. A placeholder written in a session that has ended then stands in the next one. Writing the session into the fresh log as it opens shuts the window at its source. The editor calls RetireCurrent with no engine behind it to do that.

Three shapes, and this token cannot pick one for the owner.
