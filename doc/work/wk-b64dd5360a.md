## detail

A finding on wk-40abb881a7, engine splits at seams.

src/engine/yaml.go lines 32 to 227 define ParseYAML, ymap, ylist, ystr and ystrs in package main, and src/engine/version.go line 4 defines var Build. Every caller in the tree reads quackitect/engine/internal/yaml and internal/version instead: se find over src/engine answers no call to any of the five and no bare read of Build. The two files are dead twins of the packages the token moved them into.

They came back in commit cf8e1d4e, Put back yaml.go and version.go, deleted by a shared index, which landed at 11:11 while the move sat uncommitted in the same tree and its internal packages were untracked. HEAD on its own needed them; the tree with the move does not.

The damage is two definitions of one thing, which is the namespace problem the token exists to end, and a stamper still written -X main.Build would stamp a variable nothing reads and the engine would report unstamped.

The order matters: the internal packages and the rewired callers land first, and then these two files go. Deleting them before that breaks HEAD's own build, which is how they came to be put back.

## proposed action

Once src/engine/internal/yaml and src/engine/internal/version are committed with their callers, git rm src/engine/yaml.go and src/engine/version.go. Then add a check, no-flat-twins, that fails when a file under src/engine/internal/*/ shares its basename with a file in src/engine/, so the class is caught the next time a shared index or a put-back reintroduces one.

## done when

- src/engine/yaml.go and src/engine/version.go are gone: ls src/engine/yaml.go src/engine/version.go answers no such file
- the engine builds and vets without them: go build -C src/engine ./... and go vet -C src/engine ./...
- a check refuses a file under src/engine/internal/*/ whose basename is also a file in src/engine/: run it against a copy with yaml.go put back and it fails
