## detail

The cage that travels was found rewritten twice in one session, carrying node and a placeholder where the substituted path belongs. A cage naming a placeholder fires nothing, so every hook in it stops and none of them says why.

The substitution was partial, and that is what names the cause. The method name was replaced and the hook lane name was not. So whatever wrote it held a variable map with one of them in it and not the other.

The hook lane name entered the map at d271cc5d. The program at .bin/se answers 4f4c83c0, which is older than that commit. A projection run by that program substitutes what it knows and leaves what it does not.

Nothing refuses the result. expand replaces the keys the map holds and returns the rest untouched, and the write goes ahead with a placeholder still in it.

## approach

A projection whose body still holds a placeholder is refused rather than written. An unexpanded name means the writer does not know what it is writing, and a half-written cage is worse than one that was never written.

The refusal names the placeholder and the projection that carried it, so a stale program is named rather than guessed at.

This covers every projection and every variable rather than this one variable. A name added to a source and forgotten in the map fails the same way, and so does the next stale binary.

A standing check reads the projected files for the same thing, so a file already on disk cannot sit corrupted between runs.

## done when

- a projection whose body still holds a placeholder is refused, decided by: project a source naming a variable the map does not hold
- the refusal names the placeholder and the projection, decided by: read the answer it gives
- a check fails when a projected file holds an unexpanded name, decided by: plant one and run the check
- no projected file in the tree holds an unexpanded name, decided by: run that check over the tree
