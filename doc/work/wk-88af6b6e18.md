## detail

Level 0 and Level 1 are built and their rulings still read as intended behaviour. Nothing says which of them is proven.

Every accepted ruling in a shipped level should name its proof, a test the way the coverage table does, or carry the not-built mark. Nothing walks the ruling tables to check that.

The tables are live rather than abandoned: dev_guide is on disk and a ruling was recorded into the cross-cutting design recently.

One thing to settle while doing it: the guidance tree has moved into doc/guidance while dev_guide holds the level designs, so the check has to know which is which.

## proposed action

Read the ruling tables in dev_guide as they stand on disk.

Then a check walks them and refuses an accepted ruling that names neither a test nor the not-built mark.

## done when

- a ruling planted with neither a test nor the not-built mark turns the check red
- repairing that same ruling turns it green
- the check runs over dev_guide as it stands and its findings are listed on this token
