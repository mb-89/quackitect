## detail

Five built programs are sitting in the source folders: src/engine/engine, src/engine/engine.exe, src/viewer/viewer, src/viewer/viewer.exe, src/mcp/mcp.exe. Built programs belong under .bin.

IS IT A GO THING. Partly, and it is avoidable. go build with no -o writes the program into the folder it was run in, named after that folder. The installer does it right and passes -o into .bin. A person or an agent who types a bare go build in a source folder to see whether it compiles gets a binary next to the source, and it stays there.

THE GITIGNORE DOES NOT HOLD. It names src/engine/engine, src/engine/engine.exe, src/viewer/viewer and src/viewer/viewer.exe. It does not name src/mcp/mcp.exe, so that one is a candidate to be committed. A list of programs kept by hand needs a new line every time a program is added, and it has already missed one. The mcp lane is the third program and the list stopped at two.

WHAT TO DO. One way to build, that the installer and a person both call, so nobody has a reason to type a bare go build. Then a check that fails when an executable exists anywhere outside .bin, and names the ones it found. That is the part that holds: it needs nothing added when a fourth program arrives, and the ignore list becomes a convenience rather than the guard.

If a compile check is what the bare build was for, go build -o /dev/null and go vet both answer it without leaving anything behind.

NOT AN EDIT. Changing how this tree builds while somebody is working in it breaks their run, which is why this is written down rather than done.
