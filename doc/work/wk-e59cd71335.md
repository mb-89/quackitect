## detail

A finding on wk-6d74c93848, count wrong results.

Its fourth done-when line is "the two numbers appear together with what is already reported by se_status", and its step 1 evidence names mcp-tools as the command that decides it. mcp-tools does not decide it. util/checks/mcp-tools.mjs:115 calls se_status with empty arguments and only reads the answer for the malformed-argument shapes every call is read for. It asserts nothing about the text that comes back.

So the block src/mcp/roots.go status() now appends — a blank line, then the trimmed output of `se state` — is guarded by nothing. Delete those four lines and the whole battery stays green while the criterion this token was written for is silently false again. The state of play line itself, results N, M wrong, is guarded by TestTheStateOfPlayReadsOneScreen and by results_test.go; only its arrival in the lane's status is not.

Verified here: `./.bin/se state` prints "results 310, 30 wrong", and driving the built .bin/se-mcp with a tools/call for se_status returns an answer ending in the same line, so the change works. The live lane on this box is se-mcp.lane built before the change, which is wk-65c53d4b97, and is why se_status through the tool still answers without it.
