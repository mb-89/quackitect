## detail

A system's complexity follows its connections, not its parts. Point to point wiring grows as n(n-1)/2 and a star grows as n, so the rule that bounds this system is that every part reaches the engine and nothing else. The rule is true today and nothing holds it. engine-spawns.mjs is this rule already written for one part: it enumerates every place the extension starts the engine and fails when one builds its arguments at the call site rather than going through a door. Widen that to every part. It comes after the three tokens before it because each of them changes which parts exist, and a check that enumerates parts written earlier is written three times. The shape this belongs to is doc/spec/one-core-many-satellites.md.

## proposed action

A standing check that enumerates the parts and the connection each one makes, and fails when any part reaches anything but the engine. The one allowed exception is a file: the viewer tails the record, which is what lets a person read the log when the engine is dead, and the exception is named with that reason.

## approach

engine-spawns.mjs is the shape, widened from one part to all of them. It keeps its form: enumerate, then refuse.

The parts come from the tree. A part is a folder that builds or runs on its own, under src and under util/cage. A part added with no connection is a failure, because the enumeration finds it and the connection list does not.

A connection is what one part uses to reach another: an import, a spawn, or an address it dials. The rule is that the other end is the engine. A part naming another part is the red, watched first against a deliberate sideways call.

The one allowance is data, not code. The viewer tails the record file, which is what lets a person read the log while the engine is dead. It is written into the check as an allowance carrying that reason, so a reader sees why rather than finding a hole.

It comes after the three tokens before it, because each changes which parts exist.

## done when

- the check enumerates the parts from the tree rather than from a list typed into it, so a part added without a connection is a failure
- a part reaching another part is refused, watched red first against a deliberate sideways call
- the viewer reading the record file is an allowance named with its reason, not an oversight the check missed
- sh util/checks/battery.sh reports no new failure against the run before the change
