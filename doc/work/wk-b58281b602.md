## detail

Who holds a token is written twice, in .se/holds.json and in the token's own frontmatter. Nothing asserts the two agree, so they can disagree and each reader believes a different one.

This is conflict six of doc/spec/one-box-many-agents.md, measured over sixteen agents on one box. The owner ruled on that spec: one agent per role, and separate instances rather than more agents on one tree. That ruling settles conflicts one to four, because they only bite when several agents share a tree. Six survives it, because one agent putting work down and taking it up again writes both records on its own.

The two disagreeing is how a token reads held to the queue and free to the record, or the other way about. A hand is then refused work it holds, or handed work somebody else has.

## proposed action

Assert in a test that the two agree, in both directions. A hold written to one is readable from the other, and a hold dropped from one is gone from the other. Drive take-up, put-down and submit, because each writes both and any of them can write one.

## done when

- a take-up writes both records and a Go test reads the same holder from each
- a put-down clears both, proved by the same test
- a submit clears both, proved by the same test, because that is the path that drops a hold without anybody asking
