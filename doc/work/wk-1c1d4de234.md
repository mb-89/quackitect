## detail

RUNME is meant to wrap the command line and add nothing: check dependencies, build what is missing, then run the same command and arguments. On a project it runs `exec "$engine" --work "$here" "$@"`, so the verb is no longer os.Args[1], dispatch misses it, and the stray-argument guard refuses. The vehicle path runs `exec "$cmd" "$@"` and is right, and RUNME.ps1 composes the same line as the project path. Fix: carry the work root out of band, in an environment variable the engine reads when --work is absent, so argv is untouched. Do not change the working directory, because that changes what a relative path in the person's arguments means. Add a test that runs a verb through RUNME on a project, not only on a vehicle.

## done when

- RUNME leaves argv untouched, work root in an env var read when --work is absent. A reader checks both scripts.
- A verb through RUNME on a project reaches dispatch as os.Args[1]: go test -C src/engine, red then green.
