## detail

From the verdict on wk-887e9a126a, the engine archives.

src/engine/store.go SaveToken ends with return Archive(r, t). By then the note is already written to disk as closed and noteMove has already run. So a git failure inside Archive is reported as a save failure for a save that succeeded.

src/engine/pull.go turns that into a refusal reading "the record ... a writable .se/work", which names neither git nor the archive, so the agent is told the close did not happen when it did.

Then the retry makes it permanent. The second SaveToken sees was.Ended() && ClosingState(r, was) is already true, takes the not-newly-ended arm, and returns nil without archiving. The token is closed, on the disk, and nothing will ever archive it again except a sweep nobody knows to run.

The archive is a consequence of the close and not a condition of it. A close that cannot reach git should say what could not be archived and stay closed, the way keepInGit already treats a push it cannot make.
