## detail

From the verdict on wk-239cae9216, which put a claim gate in TakeUp (src/engine/gate.go:185, NoClaimHere in src/engine/claim.go:228).

The queue does not go through that gate. next() hands a token out with take() at src/engine/pull.go:760, which writes t.Holder and calls SaveToken directly. next() skips a token another box has claimed (pull.go:696) but hands out an unclaimed tracked one.

So se pull still hands a tracked token nobody has claimed to whoever pulls first, on any box, and writes the holder into doc/work/<id>.md, which git carries. The refusal only arrives one call later, on the agent's first se run or se apply, and it does not say the pull was the thing that should have stopped.

Seen live: this box pulled wk-239cae9216 as reviewer-elm, was handed it, and the next se run answered "wk-239cae9216 travels, and this box holds no claim on it".

That is the collision the ruling set out to close: two boxes can each be handed the same open tracked token before either is refused.

## proposed action

Decide what the pull does with an unclaimed tracked token, and make it do that. It can claim the token as it hands it out, or refuse the hand-out and name the door NoClaimHere names. Either way, the pull and TakeUp answer the same question the same way.
