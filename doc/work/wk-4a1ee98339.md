## detail

CLASS: a criterion's sentence and the command under it are about different
things, so the command can exit zero while the sentence is false. Two shapes of
it, both seen on wk-e59b1f134b.

BORROWED. The command was copied from a neighbouring token and still checks
that token's deliverable. wk-e59b1f134b's second criterion says "The field
report is written and says what was done and what was left" and runs
`rg -q THE.VERDICT.ON.UPSTREAM .se/scratchpad/field-report.md`, which is
wk-c6247665a3's first criterion byte for byte:
`rg -n "rg -q THE.VERDICT.ON.UPSTREAM" doc/work/*.md` prints both lines. So
this criterion turns green the moment a DIFFERENT token is finished, and it
goes green on a file that says nothing about what was done or left: a file
holding only the line THE VERDICT ON UPSTREAM passes it, which I ran.

PROXIED. A unit test standing in for an event. The same token's third criterion
says "The retro has been run, so nothing this session learned is left only in a
log the shutdown ends" and runs
`rg -q func.TestARetroCollectsAndDrains src/engine && go test ... -run
TestARetroCollectsAndDrains$ .`. A test that exists and passes says the retro
code works. It says nothing about whether any retro was run in this session,
which is the thing the sentence is about, and it will be green in every session
after the first.

WHAT TO DO INSTEAD: read the sentence and the command as a pair, and ask what
state would make the sentence false. If the command still exits zero in that
state, it is not this criterion's command. A criterion about a document's
CONTENT greps the content it names, not a heading that belongs to another
token. A criterion about an EVENT having happened checks the artefact the event
leaves behind - a written record, a dated entry, a drained queue - not a test
that the code for the event compiles and passes.

A CHEAP TELL: the same command string appearing under two different tokens'
criteria. `rg -N '  `' doc/work/*.md | sort | uniq -d` names them.
