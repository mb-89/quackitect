## detail

A note that says who holds a token is stale the moment the session rolls. Holds are dropped when a session ends, so every such line becomes a lie and nobody rereads it.

This is not a new rule. The schema already says the holder is the engine and not a field on the token, and work-token rule 14 already says an observation names the check rather than a thing that moves. Prose is the same defect through a back door.

Seen today: a note recorded that a token was held by worker-mira on 2026-09-03. The session rolled at 16:44 and every hold changed hands, so the line was read out to the owner as current and was wrong. Three evidence cells written this same day said a token was unheld, which went stale within the hour.

## proposed action

Have se lint name a finding where a token prose says who holds something. It reads every work token already, so this is one more finding and no new check file.

## done when

- se lint names a finding for a token whose prose says held by, is held, or the holder is
- se lint names a finding for a token whose prose says unheld
- the finding says why: a hold ends with the session, so the record goes stale
- se lint answers clean on a token that names an actor without saying it holds anything
