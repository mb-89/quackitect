## detail

Found reviewing wk-a46c014566. The trial report at doc/spec/claims-relay-trial.md says "The relay runs on the GitHub MCP server's credential, not on curl".

That credential belongs to an agent's tool, not to the box. Publish at src/engine/claim.go:495 shells out to git push origin refs/se/claims:refs/se/claims from inside the engine process. The engine has no MCP client, and the proxy credential it does hold answers 403 on the dispatch. I reproduced that 403 today: Server github.com, X-Accepted-Github-Permissions actions=write.

So probe one holds for the agent and fails for the caller that has to use it. The report reads all three probes as holding and rules that wk-4759d90994 takes the relay. That ruling rests on a credential the publishing code cannot reach.

Probes two and three are unaffected. A workflow does push and delete a ref under refs/se/, measured on run 33971164027, and the round trip is tens of seconds.

The gap to close is the dispatch. Either the engine gets a credential with actions write, or something outside the engine dispatches for it, or the branch design wins after all.

## proposed action

Before wk-4759d90994 takes the relay, measure the dispatch from where the claim is published, or name what dispatches for the engine.
