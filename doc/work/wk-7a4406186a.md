## detail

util/checks holds six checks the battery never names, so nobody runs them and nothing went red at the moment each was added.

They are archive-rows-travel, commits-carry-one-token, lane-carries-every-flag, no-flat-twins, the-cage-cites-what-is-here and the-flat-engine-only-shrinks.

This is already caught and already red. util/checks/checks-live-in-the-method.mjs walks the folder and names every file the battery's list leaves out, and its own comment says why: a check nobody runs is a check that has quietly stopped working.

Measured over the branch tip on a Linux box. `node util/checks/checks-live-in-the-method.mjs .` answered forty-two checks named, one failed, and the failing half was this one. The folder holds forty-eight.

So the guard is doing its job and the finding has sat there. Each of the six is either wanted, in which case its name goes in the battery list and whatever it says is dealt with, or it is not, in which case the file goes.

Note that adding a name to the list is not free. Two of the six may be red over this tree, and a red check in the battery is a wall every agent waits behind. Read each one's answer before listing it.


## proposed action

Run each of the six by hand and read what it answers. List the ones that are wanted and green, and for a wanted one that is red, mint a token for what it found before listing it. Delete the ones nothing wants.

## done when

- checks-live-in-the-method names no unlisted check, decided by running it and reading its report
- each of the six is either in the battery list or gone from util/checks, decided by reading both
- the battery reports no new failure, decided by running it and comparing
