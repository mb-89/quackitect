## detail

Found working wk-7ecc51b3f3, which fed three slow tests. The wait they paid is the engine's, not theirs.

loadRunning in src/engine/watch.go reads engine.json twenty times, twenty five milliseconds apart, before it answers that no engine is running. The loop is for the instant a replace leaves no file on disk, and its comment says so. A tree that never had an engine meets the same loop. It pays half a second for an answer that was never in doubt.

MEASURED. A probe over a test tree timed NoteSession at 507ms, NoteAgent at 507ms, and StaffingOf at 1.017s, which is two of them. Each one is TheRunNow calling LoadRunning. Four tests in the engine suite ran between 8.7 and 15.3 seconds, and almost all of it was this.

IT IS NOT ONLY TESTS. Every cold client pays it. A hook firing over a tree with no engine pays it, and so does a command run before the engine starts.

THE CARE NEEDED. The retry exists so a reader does not believe a miss during a write. writeAtomic renames a temp over the target and never removes it first.

## proposed action

Answer at once when the record has never been there, and keep a short retry for a read that fails another way. Decide the budget against what a rename window costs, which is milliseconds.

## done when

- a LoadRunning over a tree with no engine.json answers in under 50ms, decided by a test that times it
- a read that misses during a write is believed only after a retry, decided by a test that takes the file away between tries
- no test in the engine suite spends over a second in LoadRunning, decided by se ask over the test table
