## detail

Found reviewing wk-212909368a, one build door. batteryPassed at src/engine/battery.go:139 answers true only when the battery output ends in a line beginning with the words zero failed. battery.sh, the battery script the engine starts, prints "all ok, Ns wall clock" at line 406 when nothing failed, and prints the failed wording only when something did. So the one line the real battery prints on a green run is the one line batteryPassed does not accept, and RecordFinishedBattery at src/engine/battery.go:130 writes every passing battery into the record with ok false. That record is now the only place a whole-ruling run lands, because this change starts the battery detached and nobody waits for its answer, so a green battery is written down as a failure with a tail beside it that says all ok. The check that should have caught it agrees with the code rather than with the tree: aTreeWithABattery at src/engine/battery_test.go:79 writes a fixture whose last line is one the real battery never prints. Either teach batteryPassed the all ok line, or have the script print the zero failed wording on its green path too. Whichever way, the check has to read the real script.
