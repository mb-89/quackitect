## detail

CLASS: a criterion demoted to prose because the fact it checks is live, when a
command criterion is exactly the right instrument for a live fact. The engine
runs a command criterion once, at the submission gate, so it reads the world at
the moment of submission and nowhere else. wk-967b04b877 warns against a
different thing: a live fact written as a STANDING rule that outlives the
token, and its remedy was to pin the assertion to a snapshot, not to drop the
command. Reading it as "live facts are not commands" removes the only gate that
fires before a person reads.

FOUND ON wk-e59b1f134b, round 2. Its whole precondition - "the queue holds
nothing open and nothing in work" - is prose, with the reason "That is a fact
about the live queue at the moment of shutdown rather than a rule that outlives
this token". The token's own detail says "IT CANNOT BE REVIEWED, because the
reviewer is on the machine. So it is submitted and whoever reviews next reads
it." So on this token a prose criterion is read after the machine is off, which
is after the thing it was guarding.

A COMMAND FORM EXISTS, and quoting is why it looked as though one did not. The
engine runs a criterion through cmd /c on Windows, where a quoted pattern with
spaces and parentheses is mangled into a filename: I ran
`rg -q "^status: (open|in_work)$" doc/work && exit 1 || exit 0` through
.se/scratchpad/trycmd/try.exe and it answers exit: <nil> - GREEN - with the
queue full, because rg never saw the pattern. The unquoted idiom this project
already uses in its criteria does work, in both directions:

  rg -q -e status:.open -e status:.in_work doc/work && exit 1 || exit 0

answers exit status 1 today, with 8 open and 1 in_work, and answers exit: <nil>
when the two patterns are replaced by ones nothing matches. Both runs done
through try.exe.

WHAT TO DO INSTEAD: before demoting a criterion to prose, write the command and
run it through the engine's own door - .se/scratchpad/trycmd/try.exe, or
run-criteria.py which uses it - in BOTH directions: the state that must fail and
a state that must pass. A form that answers green in both is a quoting failure,
not a proof that the criterion cannot be a command. Demote only when no form
works, and say in the criterion which forms were tried. And ask who reads a
prose criterion and when: where nothing reviews the submission before the effect
is irreversible, a prose criterion is not a check at all.
