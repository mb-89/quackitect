## detail

CLASS: A REMEDY ADDED BESIDE THE PATH THAT CARRIED THE DEFECT, LEAVING THE OLD
PATH REACHABLE.

A reviewer names a defect in one path. The redraft builds a second, correct path
next to it, points the new data at the new path, and leaves the old one in the
code with nothing routed away from it. Every named example goes green, so the
finding reads as answered, and the defect is alive for any input that still
takes the first branch. It is worse than an unfixed defect, because the record
now says this one was looked at.

WHAT MAKES IT HARD TO SEE. The new path is real work and it is right. A reviewer
checking the finding's examples finds them fixed. Only a reviewer who re-runs the
finding's own DECOYS finds that they still pass, and a decoy is the one thing a
redraft never re-runs, because it was written to fail.

MEASURED, TWICE ON wk-2b78b911b1 IN ONE ROUND. Round 2 said the citation
resolver matched a heading against all of doc/guidance rather than against the
file named beside it, and gave two decoys. The redraft added a pair citation, a
path and the heading claimed of it, resolved against that file, and it works and
five real settlements use it. The bare section branch was left exactly as it
was, so both decoys still pass: doc/guidance/voice.md section "The command
decides the sentence above it" resolves although that heading is in
specifying.md, and section "the" resolves because the match is a prefix on any
line rather than a heading. The same round said the snapshot must be pinned
rather than read live. The redraft pinned WHICH ids by asking git at a commit,
and left every criterion reading what those ids say TODAY, so the check decays
on the same data as before.

WHAT TO DO INSTEAD.

WHAT WOULD HAVE STOPPED IT BEING MADE. When you add a path to answer a finding,
delete or route away the path the finding was about, in the same change. Ask
which inputs still reach the old branch and name them: if the answer is any
input at all, the finding is not answered. Where the old branch has to stay,
because real data uses it, fix that branch and let the new one be an addition
rather than a replacement.

WHAT WOULD HAVE CAUGHT IT. Copy every decoy out of the finding into the check's
own table before writing the fix, with the answer each one must give, and watch
them fail. A finding's decoys are the specification of the fix, and they are the
only part of it written to be red. A redraft that cannot name what each decoy
answers now has tested the path it built and not the defect it was given.
