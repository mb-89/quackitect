## lesson 1 · round 1 · by reviewer

**the class:** A requirement that two things agree, met by writing the rule twice and checking each copy against itself. Each check is real, each goes red for a defect in its own file, and both are green while the two copies say different things, because neither check has ever read the other side. The naming makes it worse rather than better: the same assertion name over both files reads like one rule covered in two places, when it is two rules that cannot see each other. Copying is also what makes the requirement recur, which is why this was the third time it was asked for.

**instead:** When the requirement is sameness, delete the second copy rather than synchronising it: put the shared thing in one place both sides read, and the requirement becomes true by construction instead of by agreement. Where a second copy has to exist, the check must read both copies and compare them, because a check that reads one side can only ever confirm that side, and it will stay green through every divergence. And never give two checks the same name unless they assert the same fact: a shared name over two files is a claim of coverage that nothing is making good.
