## detail

A finding on wk-4bd6379304, which made StaffingOf count an actor that pulled but that the register never heard of. The loop it added is right. The list it walks is empty on any real session.

src/engine/pull.go:103 records an arrival under ArrivalSession(r). src/engine/doing.go:199 answers ActorsThatPulled only when the record's session equals currentSession(r), and returns nil otherwise. ArrivalSession reads the last non-compact session record in the log and answers the HARNESS session id; currentSession answers the ENGINE RUN id. They agree only where the log carries no such record, which is why the token's test passes: its log has an engine start line and no session line.

MEASURED. A probe that wrote the startup record hook.go:572 writes on every SessionStart, then pulled one worker:
  ArrivalSession="harness-a" currentSession="20260905-155215" pulled=[]
  WorkersHere=1, wanted 2
So on this box the loop counts nobody, the guard goes on refusing the main agent's work, and spawning does not move the number. That is exactly the wall wk-4bd6379304 was minted to remove.

This tree happens to escape it because its only session records carry source "compact", which ArrivalSession skips, so it falls back to currentSession and the two agree by accident.

## proposed action

Have ActorsThatPulled gate on the same session key the arrival record is written under. pull.go writes with ArrivalSession(r); doing.go reads with currentSession(r). Make the read use ArrivalSession(r), and cover it with a case that puts a startup session record in the log.
