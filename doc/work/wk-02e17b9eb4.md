## detail

TWO SHAPES, ONE CLASS, AND wk-c15a6a80a3 IS SETTLED AS THE SAME THING. It named
a pattern standing in for an enumeration: a check told to count from the side
that produces the thing searches the source with a regular expression, and a
regular expression matches a SHAPE while the set is defined by a BEHAVIOUR.

THE TELL IS THE SAME IN BOTH. The check describes the set instead of asking it.
A hand list describes it by typing it out. A pattern describes it by saying what
its members look like. Both are complete on the day they are written and neither
knows when it stops being.

AND BOTH WERE MEASURED HERE. engine-spawns.mjs matched a spawn whose arguments
are an inline array and read eight of nine, and the ninth was the one that wrote
the engine's flags at its call site. A hand list of nine fields on this note's
structs would have missed the tenth, which is the moment the token about losing
data exists for.

WHAT TO DO INSTEAD, and it differs by shape. Where the language can enumerate,
ask it: reflect over the struct, read the map, walk the registered list. Where
it cannot, because the set is a behaviour in somebody else's source, the count
is compared with something the check did not produce, and a check that finds a
different number than it expected says so rather than reporting what it found.



CLASS: A HAND-WRITTEN LIST STANDING IN FOR A SET THE LANGUAGE CAN ENUMERATE.

A check is written over every member of a set, and the members are typed into
the check. It is complete on the day it is written, it iterates and fails on the
first miss, and it looks like the remedy for the sample-instead-of-a-set
mistake -- wk-10d3cf13cd, doc/guidance/specifying.md, "A SET COVERED BY ONE
MEMBER". It is that mistake one step out. The command walks a set, but not the
set the sentence is about: it walks the list, and the list is a photograph of
the set taken once.

WHAT IT COSTS. The check stays green when a member is added, which is the only
moment it was ever needed. Nothing goes red, nobody is told, and the person
adding the member has no way to learn that a rule existed. An anti-vacuity guard
does not help: refusing an empty list catches the list being deleted and says
nothing about the list being short.

THE TELL. Ask where the set is defined. If it is a struct, an enum, a directory,
a JSON list or a switch, the language or the tree can hand you its members and
the check should ask for them. If the answer is "in the check", the check is the
only place that knows, and it will go on being right about a world that has
moved.

FOUND ON wk-24be1c06ae, whose whole subject is a field added to a record without
anybody asking what happens to a value that does not fit. Its round 2 criteria
say "One check walks every field the note writes and reads back, names each one
and the shape it is, and refuses if it finds none to walk, so it cannot pass by
the list having gone", and the detail lists nine fields in three shapes. Nine is
right today. The next field added to Criterion, Rejection or Lesson is not in
the list, is not walked, and is exactly the event the token exists to stop --
the token would fail at its own purpose one field later, silently, which is the
same silence it was minted about. The structs already carry a field the list
does not name, Criterion.Ran, and although that one is dead the list has no way
to say so.

WHAT TO DO INSTEAD. Where the set is a Go struct, walk it with reflect: take
every exported string field of Criterion, Rejection and Lesson, require each to
appear in the shape table, and fail naming any that does not. The check then
goes red on the commit that adds the field rather than on the incident that
follows, and the message tells the author which of the three shapes they have to
choose. Where reflection is not available, derive the list from wherever the set
really lives -- read the directory, read the JSON, parse the switch -- and never
from memory. And when a member is deliberately out of scope, put it in the table
with that answer written down, so a reader can tell an exclusion from an
oversight.

THE CHECK, RED TODAY: add a field to Criterion, or to Rejection, and require the
walk to name it. With a typed list of nine, nothing goes red. With a reflective
walk, it does, and that difference is the whole of this lesson.
