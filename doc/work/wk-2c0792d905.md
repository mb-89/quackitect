## detail

An agent that holds nothing when finishing is switched on cannot act at all, including to clean up after itself.

Every write and every shell command needs a token in hand. Finishing refuses take-up of anything: a tracked token, a claimed token, and a local note alike. An agent holding nothing when the switch flips has no legal move that touches the tree, and nothing it can do to get one.

Measured in September 2026. An agent submitted its last token, then found a file it had written that would not compile and would break the build of the whole src/engine test package. It could mint a token to delete the file and could not take that token up. It could not delete the file, repair it, or run a command to prove either. The tree was left broken by the guard meant to bring work to a tidy close.

The rule it exists for is right: while finishing, do not start new work. Taking up a token to undo your own mess is not new work. Neither is a local note, which travels to nobody and cannot be started by anyone else.

The refusal names an escape it does not give: finish what you already hold and put it down. An agent holding nothing has nothing to finish.

## proposed action

Let an agent holding nothing take up something, so it can tidy up.

## approach

Decide what finishing is for, then let that through and nothing else.

The candidates are: a local note, which travels to nobody; a token this box already holds a claim on; and a take-up whose only writes are to paths the agent wrote this session. The first is the smallest and probably enough, and it is what an agent needs to tidy up.

Whichever is chosen, the refusal names it, so an agent that meets the wall is told the way round rather than left to find one. One test drives it: finishing on, holding nothing, and the door that is allowed opens while a fresh tracked token still does not.

## done when

- with finishing on and nothing in hand, the door the approach picks opens, decided by: se test on the new test
- with finishing on, a fresh tracked token is still refused, so the rule is narrowed and not removed, decided by: the same test
- the refusal names the door that is open, decided by: util/checks/refusals-name-a-door over the finishing refusal
