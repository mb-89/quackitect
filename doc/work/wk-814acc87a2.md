## detail

HOW DO WE MAKE SURE NOTHING BROKEN LANDS IN GIT?

The owner's question, and the owner's first answer: a hook that refuses a push while the battery is red. It does not survive contact with this tree, for three reasons measured here today. They are argued in doc/spec/nothing-broken-lands.md, and the short of each is below.

Some pushes must never be gated. A claim first: a box that cannot publish one is invisible, and two boxes take the same token. Work tokens and notes are records rather than code, and on a cloud box a record that is not pushed dies with the box.

Absolute red gates the wrong agent. The battery here was red all afternoon for other hands' reasons, three to six failures at a time, none of them the pusher's.

The battery takes two minutes, so running it on every push is a tax nobody pays for long.

So the question is not whether to gate. It is what to gate on, and what goes through regardless.</detail>
<proposed_action>The owner decides the shape, so needs_human is set. What this session would propose, to accept or replace: gate on a new failure against a recorded baseline rather than on absolute red, so a shared box does not punish the innocent. Exempt claim refs, doc/work and notes by path, because they carry records rather than code. Read the last recorded battery run rather than starting one, so the push path stays fast. For details, see doc/spec/nothing-broken-lands.md.</proposed_action>

- a push carrying source is refused when it adds a failure the recorded baseline did not have, and names that failure, decided by: a test that adds one failure to a fixture baseline and reads the refusal
- a push carrying source is not refused when the battery is red only with failures the baseline already had, decided by: the same test with an unchanged baseline
- the gate does not run the battery on the push path, decided by: the test asserts the gate reads a recorded run rather than starting one
- the battery reports no new failure against the run before the change
