## detail

Found reviewing wk-2ef79848eb. src/engine/removal.go removerAt walks past a word only while runner() says so, and returns -1 at the first word that is neither a runner nor a remover. Every flag is such a word, so one flag between the runner and the remover turns the guard off. Verified live in this tree: `xargs rm unseen.go` is refused (the test asserts it), and `xargs -n1 rm src/engine/no-such-file-xyz.go` ran, exit 123, with no refusal at all. `xargs -I{} rm {}`, `sudo -u me rm f`, `git -C dir rm f` and `sh -c "rm f"` are the same class, and `xargs -I{}` is the ordinary spelling. The damage is that the guard's own named door is one flag from open, so nothing stops the incident it was written for. The walk should skip a flag while looking for the program, and sh/bash/powershell -c should have its argument read as a command.

## done when

- xargs -n1 rm and xargs -I{} rm on an unread file inside the tree are refused naming the file: go test -C src/engine -run TestARemovalNeedsARead
- sudo -u someone rm and git -C dir rm on an unread file are refused: the same test
- the allowed cases still pass: git status, git add, and a sentence carrying the word rm are not refused
