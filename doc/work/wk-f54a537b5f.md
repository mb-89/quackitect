## detail

Which rules an agent is held to depends on which door it writes through. The engine tells agents to use the door with no check on it.

The voice check has one enforcement caller, at src/engine/hook.go:777, gated on the harness write tool names and on isProse. So it reaches the harness editor and nothing else. src/engine/retro.go:422 counts breaches after the fact and refuses nothing.

Nothing in apply.go or applyverb.go names the voice, so text written through Apply goes in unchecked.

The pieces to reuse exist: LoadVoiceRules and Check in voice.go, and isProse in hook.go.

## proposed action

Check text written through the apply door against the same voice rules the harness editor is held to. Both doors decide what counts through isProse.

Keep two behaviours the hook door has. A checker that will not load says so loudly and lets the write through. And a refusal is of a form, never of a place, so the same file written properly goes through.

## done when

- prose written through the apply door is refused for a known voice breach: a test writes one and reads the refusal
- clean prose through the same door is not refused: the same test writes it and reads the write
- voice rules that will not load are reported and the apply still goes through: a test breaks the rules file and reads both
