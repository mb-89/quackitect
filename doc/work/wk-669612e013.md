## detail

This box handed out wk-a463727d87 as open work. The branch had it closed and archived hours before: the change is commit 2218cabe, the note on the branch carries both checklists answered, and doc/work/archive.jsonl names the token.

The queue reads doc/work in the tree it runs over. A clone that is behind carries the note as it stood before the close, so the token reads open here whatever the branch says, and the pull hands it to somebody who then does the work again. The claim published on refs/heads/se/claims says nothing about it, because a claim says who holds a token and not whether it has ended.

Two hands on one box were three hours behind the branch today, which is how long the same work stayed available to be redone.

## proposed action

Decide where the close is read from. Either the pull refuses a token the archive on the branch already names, read from the fetched branch rather than from the working tree, or the engine brings doc/work into step before it answers a pull.
