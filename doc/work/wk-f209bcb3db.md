## detail

AN AGENT THAT HAS STOPPED PULLING HEARS NOTHING, AND A BLOCKED CLAIM IS JUDGED ONCE. THE OWNER'S WORDS: how can we get you out of a waiting situation like this, because that is exactly what I fear, that you are waiting for the reviewer and then everything stalls, and I want to kick you out of this if it takes too long. MEASURED, AND IT IS WHY THIS EXISTS. I claimed blocked because all three tokens I held waited on a reviewer. It was true when I claimed it. Within about a minute the reviewer had rejected four specs and they were back in my queue, and I did not look, because I had decided I was waiting. The owner noticed before I did. THE NUDGE CANNOT REACH THIS. It rides on the pull, which is right for a queue that is filling, and useless for an agent that has stopped pulling. A nudge that only reaches somebody who is already asking is no use to somebody who has stopped asking. THE CLAIM IS THE OTHER HALF. It is judged at the moment it is made and nothing asks again. blocked means every piece of work I hold waits on somebody else, which is a fact about a moment, and the claim outlives the moment. WHAT RUNS WITHOUT BEING ASKED. The guard, which fires on every tool call whatever the agent is doing. It could hold the moment a claim was made, and on the next stop compare the queue against that moment: a token that has come back, a review that has landed, anything at all, and refuse the stop naming what changed. THE SHAPE THAT MAY WORK, and it wants agreeing before it is built. A blocked claim carries the state it was made against. The next stop is refused if that state has moved, and the refusal names what moved. A claim that is still true passes, so an agent genuinely waiting is not harassed. WHAT IS UNCERTAIN. What counts as the state, and whether a claim should also expire on time rather than only on change. Time is the thing this engine has avoided everywhere else, so it is the owner's call whether it belongs here. AND THE ENGINE NEEDS A MOUTH, WHICH IS THE OWNER'S SECOND HALF. Their words: how do we get the system out of a stuck situation like this mechanically, we have already figured out a way how to write stuff into the chat, but it is very very brittle, and if nothing else helps I want the engine to be able to do that. TWO MECHANISMS, AND THEY ARE NOT THE SAME ONE. The refusal reaches an agent that is still calling tools, and it is sound, because the guard already runs on every call. Speaking into the chat reaches an agent that has stopped calling anything at all, and it is the only thing that does, which is why it is worth having even though it is brittle. Build the refusal first and the mouth as the last resort. MEASURED AGAIN, THE SECOND TIME IN ONE SESSION. The owner looked at the queue and saw five specs open and three implementations open, all mine, and no reviewer anywhere. Two of those three facts were true. A reviewer was running as a background agent and had not pulled it yet, so the work sat submitted rather than in review, and that is what the queue showed. NOTHING WAS BLOCKING ME EITHER TIME, and both times the queue held work I could do. AND THE OPPOSITE GAP, MET TWICE IN THE SAME HOUR AND WORTH THE SAME DISCUSSION. The engine does raise an investigate when a holder stops pulling, and it raised one on a reviewer that was working perfectly well. The count is in pulls, not in time, so an agent that pulls quickly makes every other agent look stopped: fourteen of my pulls went past while one reviewer was reading one token, and the notice said it had stopped. THERE IS NO ANSWER THAT MEANS IT IS FINE. The notice offers two, take the token back or judge it yourself, and both are wrong when the holder is alive. So every pull returns the same investigate and no work can be handed out until the other agent happens to pull again, which is the stall this note is about arriving from the other direction. WHAT IS UNCERTAIN, and it is the owner's call: whether the measure should be time rather than other agents' pulls, and whether an investigate should take a ruling of it is still working, recorded, so the same one is not raised again for a while.
