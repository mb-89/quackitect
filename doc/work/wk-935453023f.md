## detail

Found reviewing wk-2ef79848eb. src/engine/removal.go ALoopThatRemoves sets loop and deletes over the whole pipeline and never asks whether the removal is inside the loop. pipeline splits on ; && || | & and newlines, so any loop anywhere in the command plus any removal anywhere else is refused. Verified live in this tree: `for f in a; do echo $f; done; rm -f "C:/Users/mb/AppData/Local/Temp/claude/nope-xyz-not-here.txt"` was refused with A LOOP THAT DELETES IS REFUSED, though the rm is not in the loop and names a path outside the tree, which the rule says it does not touch. The damage is that the refusal says something untrue about the command it stops, and the remedy it offers, list what you mean and delete those files by name, is what the command already did, so there is no door. A removal should count only when it is inside the loop's body: between the do or brace that opens it and the done or brace that closes it.

## done when

- a loop followed by a separate named removal is not refused: go test -C src/engine -run TestALoopThatDeletesIsRefused
- a removal inside the loop body is still refused, for each of for, while, until and the case that ate live code: the same test
- a loop that removes nothing is still allowed: the same test
