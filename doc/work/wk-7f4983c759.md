## detail

Every markdown this system creates comes from a template for its type, and the
engine refuses one that does not fit.

THE OWNER'S WORDS: every markdown we use needs to adhere to quality standards,
and that means it is created from a template. A note whose frontmatter says
type: work has to keep the work template's shape.

WHY IT IS A REFUSAL AND NOT A CONVENTION. A shape an agent remembers is a shape
an agent forgets. Everything that has held in this system holds because the
engine refuses: the hold, the owed answer, the reviewer that cannot leave, the
criteria a submission has to meet.

WHAT STARTED IT: the owner does not like the specs written so far, and the
right answer is not a better sentence but an agreed shape. Nothing writes
another spec format until this is settled.

TO SETTLE BEFORE BUILDING:
- what a template is. A markdown file with the headings and the frontmatter a
  type must carry, kept where the method keeps its other declarations.
- what refuses. The mint, so a bad note is never written, and the lint, so one
  edited by hand is caught.
- what a template may demand: a heading present, a heading non-empty, a
  frontmatter field, a field from a list.
- and what it must not demand, because a template that dictates prose produces
  prose nobody reads.

RESEARCH IT PROPERLY FIRST. There is prior art in issue templates, in
architecture decision records, and in the documentation frameworks the voice
already cites. The owner asked for research rather than invention.
