## detail

A headless Linux box cannot run this system, and line endings are the whole of the reason. This was measured, not reasoned.

WHAT HAPPENS. sh util/setup/install.sh --profile headless --no-open dies immediately:

    util/setup/install.sh: 10: set: Illegal option -

Line 10 is 'set -eu'. The file carries CRLF, so the shell reads the option as '-eu<CR>' and refuses it. The same holds for RUNME.sh, so nothing on that machine can start either.

WHICH FILES. RUNME.sh, util/setup/install.sh, util/cage/session-start.sh, and its projection .claude/hooks/session-start.sh. Every script an agent wrote into .se/scratchpad is LF, and util/checks/battery.sh is LF. So the CRLF is on the version-controlled scripts, which is where a checkout decides the endings and nothing in the tree tells it to leave them alone. There is no .gitattributes.

The cage hook is on that list. On Linux the session-start hook cannot run either, so the cage does not close.

WHAT IT IS NOT. Nothing else blocks headless. With the two files converted the install ran clean end to end: git, go, node and ripgrep found, se, logview and se-mcp built as ELF binaries under .bin, the copy registered, the folder seeded. RUNME.sh --version answered, and RUNME.sh work --help answered, so the verb form works through RUNME on a vehicle. The Windows binaries sitting in .bin under Linux names are local contamination rather than a shipping fault: .bin is gitignored and --produce leaves it behind, so a clone builds its own.

WHAT TO DO. A .gitattributes that pins the endings, so the decision lives in the tree rather than in whichever machine checked it out. Every executable script is LF. Then normalise what is already there. A check that fails on a CR in any file the system executes is worth more than the fix, because this came back once already and nothing saw it.
