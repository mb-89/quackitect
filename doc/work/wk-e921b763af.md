## detail

Found reviewing wk-963dbf6898, which this token names.

The engine decides whether a pull came from a lane or a shell by comparing one string. src/engine/client.go declares DoorLane as the word lane, and src/engine/pullverb.go reads it at line 89.

The lane writes that word as a bare literal. src/mcp/lane.go line 530 sends Door set to the string lane, in a package that cannot see the engine constant.

Nothing holds the two together. Rename or retype either side and the lane starts arriving as a shell. Every lane submission would then be answered settled and handed no next token, and every agent would stall after one close. The tests in shellsubmits_test.go all sit inside package main and use the constant, so none of them would redden.

The house already has the pattern for this. src/mcp/payload_test.go compares the engine payload against what this door forwards, by reflection, and refuses a field either side drops.

## proposed action

A check in src/mcp that reads the door string the lane sends and compares it against the word the engine treats as the lane. The engine already prints things about itself for a caller, so the constant can be reached without importing package main.

## done when

- a Go check in src/mcp fails when the lane door literal stops matching the engine word for a lane
- the check is watched reddening by changing one of the two, and greening again when both agree
