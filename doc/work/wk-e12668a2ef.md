## detail

wk-2b8f45c1e7 added two criteria to the ask of both tracked processes. Its approach section says "Tokens minted before this are grandfathered." Nothing grandfathers them. The gate refuses a submission whose checklist has no row for a criterion, so every token already open was refused at its next submission. wk-8821332a9a recorded that refusal met twice on wk-4fbce27e2e and had to write two lines into 125 files by hand.

The backfill did not finish. Counted over doc/work today: 32 open tracked tokens carry neither row, 24 trivial and 8 standard, among them wk-01bf8b5137, wk-0557d1c4ea, wk-2a0d33d3be and wk-36b8ea59dc. Each is a worker who pulls, works, submits and is refused.

What is gained by doing it is that a criterion added to a process is caught against the open queue before it lands, instead of one worker at a time discovering the refusal.

What breaks if it is never done is that the next criterion added to any activity repeats this, and a worker who reads the refusal as a bug removes the criterion rather than answering it, which wk-8821332a9a already named as the risk.

## proposed action

Add a check under util/checks that walks doc/work and, for every token not ended, compares its checklist rows against the criteria its process declares for each activity, naming any token missing a row. Run it, and backfill the 32 it names.

## done when

- the check names every open token whose checklist lacks a row a process criterion declares, decided by: run it before the backfill and read the 32 names
- the check passes over doc/work after the backfill, decided by: run the check
- the check is in the battery, decided by: read util/checks and se test --plan on a doc/work change
