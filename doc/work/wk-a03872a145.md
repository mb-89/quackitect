## detail

Some tokens read status noted while carrying a disposition. Three are in the tree today, each saying noted and dropped at once.

The engine treats them as ended, because Ended reads the disposition rather than the status. So a submission against one is refused as already closed, and so is a set of its status field.

A person reading the file sees noted. The editor and any view keyed on status see noted. Only the engine knows it has ended.

So the field cannot be repaired through the verb that repairs fields, and the two answers stay apart.

## proposed action

Decide which field is the truth and make the other follow it at the one place that writes them.

Then repair the tokens that disagree. The set verb refuses them today, so either it takes a status write on an ended token, or a repair runs once over the tree.

## done when

- no token in the tree reads a status the process reserves for an open one while carrying a disposition
- a token that disagrees can be repaired without editing the file by hand: a test drives the repair and reads the result
- a test covers a token whose status and disposition disagree and asserts what the engine answers about it
