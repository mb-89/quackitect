## detail

Found reviewing wk-fc6b6c5aa7.

TestAStartLeavesTheSettingsAsTheyWere in src/engine/onedoorperfolder_test.go is the guard wk-fc6b6c5aa7 put up against writing an ephemeral value into the file the harness reads once. It cannot fail for that class.

It calls Project(r) twice in one process over one Roots and compares the two bytes. Every projection variable is a function of the roots, so {{hooks}} expands to the same string on both calls. The value the test exists to keep out is constant across exactly the two starts it compares.

MEASURED. A clean copy of HEAD with one line added to util/cage/claude-settings.json, "door": "{{hooks}}", puts the port straight back into the travelling, version-controlled cage file. The test still answers PASS. That is the original defect restored, and the guard written against it says nothing.

So criterion 4 of wk-fc6b6c5aa7, "an engine start writes nothing into .claude/settings.json", reads as met by a test that would go on reading as met after the defect returned. The behaviour itself is right: .claude/settings.json carries no port, and the door lives in the untracked .claude/settings.local.json. It is the check that is dead weight.
