## detail

Three tests in src/engine fail under the whole package run and pass when run by name. They fail as a group, and each drives a real git repository.

TestAClaimIsWrittenOnTheFarCommit, TestAFetchToARemoteThatIsNotThereLeavesItsReason and TestTheClaimsRefHoldsOneFileAndNoNote.

Measured on a Linux box at ec046246, with CGO_ENABLED one and the sqlite_fts5 tag. `go test -C src/engine ./...` answered eleven failures. The same tree one commit earlier answered eight, and the three above were the difference. Running only those three by name in the same worktree answered ok, all three passing, in three seconds.

So the same code answers two ways depending on what else runs beside it. The whole-suite run is the one a person reads before landing a change, and three names that come and go in it teach a reader to skip failures rather than read them.

The eight that fail either way are a separate matter and are not this token. They name the retro, the verb door, the fixture builders and the work-token guidance.

Two shapes worth checking. The three may be contending for one git resource under t.Parallel, such as a shared home, a shared config or one temporary remote. Or they may be slow enough under load that a deadline inside them lapses.

## proposed action

Find what the three share. Run them together with the parallel count at one and see whether they pass, which separates contention from a lapsed deadline. Then give whatever they contend for a per-test copy.
