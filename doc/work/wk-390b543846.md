## detail

A finding from the verdict on wk-0086ed9e9b, "adapter decides no column".

util/checks/adapter-decides-no-column.mjs line 62 looks for a property name one way only:

  new RegExp('"' + literal(p) + '[."]').test(code)

A double-quoted string. src/extension writes single-quoted and template strings too: rg -c "'" counts 253 in editor.ts, 67 in panel.ts, 23 in extension.ts. So 'status', `status`, and "sta" + "tus" all pass a check whose first line reads "no token property name is written in src/extension".

THE DEAD WEIGHT is the gap between what the check says it guards and what it looks at. The next hand to put a column rule back in the adapter will most likely reach for the quote style beside it, and the check will stay green.

THE FIX is to accept all three quotes in the pattern, and to prove it: the check's own suite should hold a fixture that writes a property name in a single-quoted string and go red on it.
