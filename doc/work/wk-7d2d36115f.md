## detail

The lint now asks whether a token id written into a note still opens, and over this tree it answers 53 times. Each finding names a live note and an id that reaches neither a note on the disk nor a row in the archive. Measured at the tip: se lint answers 58 findings, 53 of them of this shape, over about 30 notes.

The ids were not invented. Sampling four of them, each had a note under doc/work that a commit deleted without writing an archive row, so the note is only in history and nothing on the branch names it. One sample was deleted in the commit titled "cloud ready 4". A reader following the reference today gets nothing, and cannot tell a finished piece of work from one that was dropped.

Two shapes are mixed together here and a worker has to tell them apart. An id whose note is in history wants an archive row, so the reference resolves and says what happened to it. An id nothing ever minted wants the sentence naming it corrected, because there is no work to point at.

This is the cleanup the rule revealed, and it is a token of its own because it is a walk over the record rather than a change to the engine.

Where one exists, write the archive row that names the object, so the id resolves the way every other closed token does. Where none exists, correct the sentence in the live note that names it. Finish when se lint answers no finding of this shape.
