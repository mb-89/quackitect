## detail

A closed local token is deleted the moment it closes. So the next retro has nothing to read about what happened, and a retro that cannot read what happened is a retro about nothing.

The tracked half is right and stays. Closed and tracked goes into git under its tag, and a retro can read a tag.

The local half is wrong. It should stay where it is, marked closed, until a retro has looked at it.

The retro already drains the scratchpad and the undo journal into its own folder. So this is one more thing it collects rather than a new mechanism.

The owner widened it: the retro takes everything in the private folder, reads it, and clears it.

One boundary belongs in that, and the retro settles it. The retro writes into that same folder, so it cannot drain what it is standing in.

So the split belongs in the structure rather than in a rule somebody remembers. Records are closed local tokens, the scratchpad, the undo journal and transcripts. Runtime is the index, the session log, the holds, the configuration and the retro's own folder.

A retro takes the first and never touches the second. Where a file lives says which it is.

## proposed action

Take the deletion out of the close. A closed local token stays in the private folder.

Give the retro the step that collects them. Every closed token in the private folder moves into the retro folder, and the open ones stay.

Name the two halves in the folder itself, so a reader sees which is a record and which is runtime without being told.

The tracked half is untouched. The deletion is already out, so what is left here is the retro step and the structure.

## done when

- the record half and the runtime half are named places under .se, and every file there is in one of them
- a closed local token stays where it is: a test closes one and finds the file still there
- a retro moves every closed local token into its folder: a test closes two, runs a retro, and finds both in the retro folder
- a retro leaves the open ones alone: the same test finds an open local token still in the private folder
