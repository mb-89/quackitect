## detail

CLASS: A TABLE WHOSE MEMBERS ARE DERIVED AND WHOSE ANSWERS ARE STILL GUESSED.

A round asks for the set to be derived rather than typed, and the next draft
does it: the walk runs, the count is in the note, and the two numbers agree. So
the table stops being a photograph and every member is there. Then each member
is given a row by reading the name and the page, and no row is run. The check
that holds the two counts against each other cannot see a wrong answer, because
it counts rows rather than trying them, and the answers are what the work will
be built from.

WHAT A WRONG ROW COSTS, AND IT IS TWO THINGS. A field filed under a stricter
shape than it has gets a refusal for a value the record can hold, so somebody
loses a save and learns a rule that is not true. A field filed under a looser
shape keeps the loss the table was written to end. Both read as decided,
because the row is there and the count agrees.

THE TELL. Ask, of each row, what was run to put the field there. If the answer
is the field's name, or where it sits on the page, or which other field it
looks like, nothing was run. A shape is a fact about the parser and not about
how the value looks when a person types it.

MEASURED ON wk-24be1c06ae, round 6. The walk arrives at 36 and the table
answers for 36, which I ran and both are right. Token.GuidanceRef is filed
under one line by design: I saved a two-line GuidanceRef and it came back byte
identical, and I saved one whose second paragraph opens a section and it came
back as its first line, which is the block signature and not the one-line one.
And the two map rows answer for the value the note writes under the heading and
say nothing about the key written into it: a Submission key of two lines comes
back as its first line with the rest moved into the value.

WHAT TO DO INSTEAD.

WHAT WOULD HAVE STOPPED IT BEING MADE. Write each row from a run rather than
from a reading. For every member the walk arrives at, feed it the value its
candidate row says it cannot hold, save, load, and put what came back beside
the row. That is one loop over the set you have already derived, and it costs
less than the round the wrong row buys. Where a member is written to the page
in more than one place, a map key and its value, a heading and the block under
it, it needs an answer for each place rather than one for the field.

WHAT WOULD HAVE CAUGHT IT. Two counts that agree prove the table is the right
size and say nothing about it being right. So the check that holds them has a
sibling: one case per row, feeding the field what the row forbids and requiring
what the row promises, so a member under the wrong shape goes red by name. A
row nothing has tried is a decision nobody made.
