## detail

A finding on wk-5e2c601cce, "two engines one tree".

handOver in src/engine/swap.go:333 calls LetGoOfTheTree before cmd.Start, so the successor can take the lock. Between those two lines the tree is held by nobody. Any other start in that window takes it, and then the successor reaches HoldTheTree, reads it held, prints "already up" and leaves. The predecessor has already released and goes on to Release its child and end. The tree is left with a squatter that was never meant to be the engine, or with none at all.

The window is not theoretical on this box. The bug this token was written for is exactly two starts racing, a session hook's wake and the lane's se_start, one second apart. A swap during that second meets it.

The recovery that exists covers only the other case: line 336 takes the tree back when cmd.Start itself fails. A start that succeeds and a successor that is turned away is not covered.

The check that catches the class: a test that holds the lock from a third process across a handover and asserts the tree still has one engine that answers.
