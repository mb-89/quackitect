## detail

se_work in the MCP lane cannot mint a standard token, so no agent in an editor can.

The engine requires an approach on a standard token. The lane refuses the field: it answers that the arguments will not read, and lists what it takes. approach is not among them.

So the door an agent is told to use is shut, and the refusal names the field the same door will not accept. A cloud agent meeting this has no way through and no way to know why.

The shell door works, because it carries --approach. Nothing tells an agent to reach for it, and the lane is what the guidance names.

Measured in September 2026, minting the token that deletes the stop argument.

## proposed action

Add approach to the lane's se_work, beside proposed_action, and pass it through. Then read the mint's other required fields against what the lane accepts, because approach may not be the only one that drifted.

## done when

- se_work mints a standard token with an approach through the lane, decided by: minting one
- every field the mint requires is one the lane accepts, decided by: se work --help against the lane's declared arguments
