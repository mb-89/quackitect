## detail

CLASS: THE GENERAL CASE IS WRITTEN AND ONLY THE DEGENERATE ONE IS EVER REACHED,
BECAUSE THE CALL SITE'S GUARD MAKES THE CALLEE'S ANSWER CONSTANT.

A helper is written to do the general thing. Its one call site sits inside a
branch whose condition guarantees the argument is the trivial case, so the
general computation inside the helper can only ever produce the trivial answer.
Nothing is dead in the sense a compiler or a coverage tool would notice: the
function runs, the line is covered, the expression is evaluated. It is just that
one of its inputs is pinned.

WHY IT SURVIVES A CAREFUL READER. The helper's name and its comment describe the
general behaviour, and they are true of the code inside it. The reader checks
that the helper does what it says, sees that it does, and moves on. The mistake
is one level up, at the call site, in a condition that reads like a guard
against nonsense rather than like a restriction on meaning.

AND THE TEST AGREES, BECAUSE IT WAS WRITTEN FROM THE SAME PICTURE. Whoever wrote
the helper wrote the case, and the case they had in mind is the one the call site
allows. So the code and the check agree about a world neither of them visits,
which is a green suite over a sentence in the specification that has never once
been true.

MEASURED ON wk-d1b585b7b9, "the engine nudges". Its detail says the engine
"forgets a step once the count falls below it". src/engine/nudge.go has
forgetAbove(r, role, waiting), which sets the remembered step to
stepFor(waiting) -- the general partial forget, written out. Its only call is
inside `if step == 0`, and step is stepFor(waiting), so forgetAbove is called
only when stepFor(waiting) is already zero. The general assignment can only ever
assign zero. I drove it: a queue nudged at six, drained to four and refilled to
six, is not nudged again, and the suite is green because
TestAQueueThatEmptiesIsNudgedAgain drains to zero, which is the one case the call
site permits.

WHAT TO DO INSTEAD. ASK WHAT VALUES A HELPER'S ARGUMENT CAN ACTUALLY TAKE AT THE
CALL SITE, not what its parameter's type allows. Where a guard above the call
pins the argument, either move the call out of the guard or replace the general
computation with the constant, so the code stops claiming something it does not
do. A helper whose body simplifies to a constant under its own call site is the
tell, and it is a five-second check: substitute the branch condition into the
body and see what is left.

AND FEED THE TEST THE CASE THE CALL SITE FORBIDS. The test that would have found
this is the one nobody writes, because it is the case the picture in your head
does not contain: not zero and not the step, but between two steps. When a rule
is about crossing a threshold, drive it above, below, back above, and part of
the way down, and assert on each.

THE CHECK, RED TODAY: nudge a queue at six, drop it to four, put it back to six,
and require a second nudge. It is silent. Move forgetAbove above the `if step ==
0` return and it speaks.
