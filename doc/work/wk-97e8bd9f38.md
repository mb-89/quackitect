## detail

Split from wk-30821724fc. ensureEngine in src/engine/guards.go starts a detached engine and then waits up to engineUpBudget for its record to name a socket, polling with time.Sleep. Nothing can end that wait early, and a test cannot hand it t.Context. It is reached only through answerHook in src/engine/hook.go, which two doors call, hook.go and hookserve.go, and twenty-two test files call as answerHook(body, args, out, log). So a context for ensureEngine is a context for answerHook and serveHooks, and that is a change across every hook test rather than one beside the git and probe work, which is why it is split off.

## proposed action

answerHook and serveHooks take a context first, from main's, and hand it to ensureEngine, whose wait selects on ctx.Done() beside its poll. The context governs the start and the wait for the child to report, never the child, and the comment says so. Every test call of answerHook passes t.Context().

## done when

- a cancelled context ends ensureEngine's wait before engineUpBudget, decided by: go test -C src/engine -run ACancelledContextEndsTheWaitForAnEngine ./... answers ok
- se find --regex 'answerHook\(' --path 'src/engine/*.go' answers no call without a context as its first argument
