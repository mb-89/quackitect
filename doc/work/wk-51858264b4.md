## detail

Two faults, seen by the owner in a running UI and marked on a screenshot.

LIVENESS. Parts of the UI do not repaint when the state behind them changes. The owner has to open and close the sidebar, or open and close the work editor, before the new value appears. The panels named are the sidebar and the work editor. Look for a panel that reads state once at mount instead of subscribing to the stream the rest of the UI uses. Such a panel holds whatever was true at mount until it is torn down and built again.

RENDERING. Two clipping faults are visible in the same screenshot.

Text is cut off at the left edge of the agent and engine control panel. The first row's agent name is "main" and it renders as "hain": the leading glyph is outside the panel's box.

The counter at the top right is cut off at the right edge. It reads "ID: 98/182/5" and then stops mid-number, so the third figure cannot be read at all.

The owner circled these regions:

- the toast strip carrying the "worker-<name> working wk-<id> <title>" lines
- the agent against working on table
- the work mint row holding the button
- the "four words / the whole instruction" field
- the dropdown
- the top right counter

## proposed action

Find every place in the UI source that reads engine state once rather than subscribing to it. The sidebar and the work editor are the two known cases. Start from them, then check the rest of the panels for the same shape. Make each one subscribe, so it repaints when the state changes and never needs opening and closing.

Then fix the two clipping faults. The left edge of the agent and engine control panel eats the first glyph of an agent name. The top right counter is cut off mid-number.
