## detail

The shell has a door for putting a token down and the tool lane does not. work.go:50 takes --put-down. The se_work tool takes actor, detail, done_when, on, parent, process, proposed_action, title and tracked, and no put_down.

So an agent at a prompt can set work back and an agent in a lane cannot. The lane is where every cloud agent lives.

Measured three times in September 2026. Told to put work down, a session reached for se claim --release, which frees a claim and leaves the hold. Its answer says freed, which reads as though the token were back. The stop judge went on naming it as work in hand.

A reviewer that finished and left kept its hold. The next hand was then refused with one token has one holder, while nobody was holding it.

An earlier reading of this said no verb clears a hold. That was wrong: the verb exists and the lane does not carry it.

## proposed action

Carry put-down into the lane, so an agent in a lane has the door the shell already has. And have release say what it did and did not do, since freed reads as a token given back.

## done when

- se_work takes a put_down, and a check over the lane's tools reads it there.
- An agent in a lane puts a held token down without closing it, and a test reads the holder gone.
- The answer to release names the hold it did not free, and a test reads that wording.
