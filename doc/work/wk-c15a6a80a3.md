## detail

CLASS: A PATTERN STANDING IN FOR AN ENUMERATION, WITH A COUNT NOBODY COMPARES
WITH ANYTHING.

A check is told to count from the side that produces the thing -- which is the
right instruction, and it is wk-1412093cd8's round 1 lesson -- so it searches
the source for the calls. The search is a regular expression, and a regular
expression matches a SHAPE while the set is defined by a BEHAVIOUR. The two
agree on the day it is written. Then one ordinary refactoring, hoisting an
argument into a variable on the line above, changes the shape and not the
behaviour, and the member leaves the set without anybody deciding that it
should.

WHAT MAKES IT INVISIBLE. The check prints a count -- "8 spawn(s) read" -- which
reads as a measurement. Nothing compares that number with anything, so it is a
tally of what the pattern matched and not of what exists. Its anti-vacuity guard
asks whether the count is more than zero, which catches the pattern matching
nothing and never the pattern matching most.

FOUND ON wk-1412093cd8. engine-spawns.mjs matches
/spawn(?:Raw)?\s*\(\s*([A-Za-z_$][\w$]*)\s*,\s*(\[[^\]]*\])/ -- a spawn
whose second argument is an inline array literal. src/extension/extension.ts:570
is spawn(exe, args, ...) with the array built on line 569, so it is invisible.
The tree has nine spawns of the engine and the check reads eight. The one it
misses writes "--set" and "--method" at the call site, which is the exact shape
the token exists to stop, and no builder covers it so the lifecycle check cannot
see it either. I put "--form" there, the very flag the owner's defect was, and
the check answered 8 spawn(s) read, 0 failed.

AND THE FILE SAYS SO ITSELF. Its comment reads "if it ever is somewhere else
this check reports fewer spawns than the tree has, which is the next assertion."
The next assertion is found.length > 0. The guard was described and not written,
and the case it was described for was already in the tree.

WHAT TO DO INSTEAD. When a check enumerates by pattern, give it a second,
coarser count of the same thing and fail on the difference: count every
occurrence of spawn( and spawnRaw( in those files, subtract the ones deliberately
skipped by name, and require it to equal what the detailed pattern matched. The
coarse count is allowed to be stupid; its whole job is to disagree.

AND MAKE THE UNMATCHED CASE LOUD RATHER THAN ABSENT. A spawn whose flags are not
an inline array is not a spawn that passes, it is a spawn the check cannot read,
and that is a failure with its own message: "extension.ts:570 spawns with a
variable, so this check cannot see what flags it sends."

THE CHECK, RED TODAY: add the coarse count. Nine against eight, and it names
extension.ts:570.
