## detail

Every Go test runs under coverage, and most of them have nothing to learn from it.

The map from a test to the source it reaches is what selects tests, and it is built by watching a test run instrumented. testmap.go says a test is mapped when it has no map or its file changed, and mapped again as a side effect of being run. The second clause is the cost.

So a test that is already mapped at its current hash still runs off an instrumented binary, writes a coverage profile, has that profile parsed, and has its regions deleted and rewritten in a transaction. The map that comes out is the map that went in.

That transaction is what meets the lock. writeRegions opens a transaction on the index for every test, on every run, and the index allows one writer.

The owner asked in September 2026 why a single test asks for coverage. It does not need to. It needs to when its map is missing or stale, which is what the header already says.

Measure before choosing. Dropping instrumentation may mean a second binary per package, and two builds can cost more than the instrumentation saves. The number decides it.</detail>
<parameter name="proposed_action">Run a test under coverage when its map is missing or stale, and plain otherwise.

## done when

- a test named outright runs plain and writes no region, decided by: name one, run it, count the writes
- a run that asks what a change reaches builds the map, decided by: clear a map, ask for a delta, read the regions
- a test run to answer a map question is mapped as it runs, decided by: the same run, reading the mapped hash
- the time for a named run is measured against an instrumented one, decided by: run both and name the seconds

SO INSTRUMENTATION IS NOT THE COST. A second binary per package would buy nothing and pay for another build. The saving is the index write that no longer happens, which is what met the lock.

## approach

THE MAP IS BUILT WHEN THE ANSWER DEPENDS ON IT, and never otherwise.

The owner's rule, September 2026. The map traces a test to the source it reaches, and it exists to select tests. So the question decides whether it is needed, rather than the age of a row.

An agent naming one test by name is asking for that test. Whoever asked made the selection, so no map is consulted and none is built. It runs plain.

An agent asking what its change reaches is asking the map. So is one asking for the battery. There the map has to exist, and building it earns its cost.

That gives a broad ask a better shape too. Where somebody asks for everything, the engine builds the map, says what it would run and what that costs, and lets them decide.

A test run to answer a map question is mapped as it runs, which is free once it is instrumented. A test named outright is not, so its map ages. That is the right way round: the map is only ever stale for tests nobody selects by.
