## detail

Every Go test runs under coverage, and most of them have nothing to learn from it.

The map from a test to the source it reaches is what selects tests, and it is built by watching a test run instrumented. testmap.go says a test is mapped when it has no map or its file changed, and mapped again as a side effect of being run. The second clause is the cost.

So a test that is already mapped at its current hash still runs off an instrumented binary, writes a coverage profile, has that profile parsed, and has its regions deleted and rewritten in a transaction. The map that comes out is the map that went in.

That transaction is what meets the lock. writeRegions opens a transaction on the index for every test, on every run, and the index allows one writer.

The owner asked in September 2026 why a single test asks for coverage. It does not need to. It needs to when its map is missing or stale, which is what the header already says.

Measure before choosing. Dropping instrumentation may mean a second binary per package, and two builds can cost more than the instrumentation saves. The number decides it.</detail>
<parameter name="proposed_action">Run a test under coverage when its map is missing or stale, and plain otherwise.

## done when

- a test already mapped at its own hash writes no region, decided by: run one twice and count the writes
- a test with no map is mapped by running it, decided by: clear its map, run it, read the regions
- a test whose file changed is mapped again, decided by: change the file, run it, read the mapped hash
- the time for a mapped run is measured against an instrumented one, decided by: run both and name the seconds
