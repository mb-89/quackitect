## detail

A trivial token whose whole change is note text, such as putting back an evidence table the engine wiped, cannot close as done. src/processes/trivial.process.yaml gives the do activity two criteria. The first is "one test was written first and seen red for the reason expected". The second is "the same test was seen green after the change". The gate refuses the submission while either is unticked. There is no test for restoring prose, so only two ways through remain. One is to tick a line that is not met, which work-token rule 15 exists to forbid. The other is to close as dropped, which reads as "it is not wanted after all" when the repair was wanted and was made. Several such repairs ran tonight: wk-ddb9edee8b, wk-7887984486, wk-2cdaae953c. The process needs a truthful way to close a change that carries no code.

## proposed action

Decide with the owner between two shapes. The do checklist gains a not-applicable answer the gate accepts, or the process gains a repair activity with its own criteria. Write the gate test first and watch it go red on a note-only token.

## done when

- a trivial token whose change is note text only can close as done without ticking a criterion that is not met
- a token that does change code still cannot close with the red-first line unticked
- the wording the gate refuses with names which of the two cases it is in
