## detail

A CRITERION CANNOT NAME THE CHECK THAT DECIDES IT, FROM A SHELL. ATestRunByHand in src/engine/tests.go refuses any Bash command holding a word whose path contains the checks folder, whatever the command is. It reads the whole se work call as a test run by hand. Measured here: a se work mint whose done-when lines named node and a check under that folder was refused twice with THE ENGINE OWNS THE TESTS, and the refusal quoted the mint back as what was run. The work-token guidance, rule 3, asks that where a command decides a criterion the criterion write that command. So the guard refuses the spelling the guidance asks for, and a no-lane session that cannot use se_work has no way to mint one. The token was only minted after every check path was reworded out of it.

## proposed action

The guard asks whether a command RUNS the tests, so it reads the first word of each part of the pipeline and then falls back to scanning every word for the checks path. That fallback is what catches a mint. Narrow it: a word naming a check counts only where the part's first word could run it, which is the interpreter or the check itself. A se work call whose first word is the engine runs nothing, and runsTheEngine already answers that question for the write gate.

## done when

- a se work mint whose done-when text names a check under the checks folder is not refused, decided by: that mint at a shell prints a token id
- a command that does run a check under that folder is still refused, decided by: node plus that check path at a shell is refused with THE ENGINE OWNS THE TESTS
- both cases are a test over ATestRunByHand in src/engine, seen red first on the mint case
- the battery reports no new failure against the run before the change
