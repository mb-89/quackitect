## detail

SPLIT OUT OF wk-19c445440b, which made the diagnosis say when HTTPS_PROXY names a dead port. Saying it is not curing it.

A container restart moves the agent proxy to a new port and leaves HTTPS_PROXY naming the old one. Every git call the engine makes inherits that variable, so it reaches a port nothing listens on.

Measured on this box. se claim answered, on four claims in a row: the push did not run, git fetch, unable to access, failed to connect to 127.0.0.1 port 33243. Nothing was wrong with the claim or the remote. The same call with HTTPS_PROXY set to the live port answered the branch head.

gitHere in src/engine/archive.go builds a child environment from os.Environ already, and the claim publish is the caller that pays for this. The live port is in /root/.ccr/README.md and its status endpoint confirms it, which is what util/cage/diagnose.mjs now does in theProxy.
