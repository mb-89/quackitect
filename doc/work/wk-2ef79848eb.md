## approach

A command that removes a source file under the tree is refused unless the turn has read that file, naming the file. The removing commands are rm, del, git rm and a redirection over it. A loop construct carrying a removal is refused outright, because a loop deleting what it has not read is the case. The remedy names se_apply's delete op, which is checked before any write.

## note

src/engine/removal.go is new and holds the rule. src/engine/hook.go asks it on PreToolUse for a Bash command. src/engine/removal_test.go drives both cases through answerHook, the door the harness fires.

WHY TWO QUESTIONS. A removal naming its files is judged file by file, and the read set already says who looked. A loop names no files, because the ones it deletes come out of its own output. So the shape itself is refused.

WHERE IT STOPS. Outside the tree the disk is the agent's own, and the scratchpad is out of it too. A remover is found where a command starts, so xargs rm is caught and a sentence carrying rm is not.
