## detail

One command was a sixty-iteration loop that ran go vet, took a filename out of the first error, deleted that file and went round again. It ate live code four times. The engine sees the command before it runs and knows which files the turn has read. Consumes wk-94a864ff0b.

## done when

- a removal of a file the turn has not read is refused naming the file: go test -C src/engine -run TestARemovalNeedsARead
- a shell loop carrying a removal is refused outright: go test -C src/engine -run TestALoopThatDeletesIsRefused
- a removal of a file read this turn is allowed: the same test's allowed case

## approach

A command that removes a source file under the tree, rm, del, git rm or a redirection over it, is refused unless the turn has read that file, naming the file. A loop construct carrying a removal is refused outright, because a loop deleting what it has not read is the case. The remedy names se_apply's delete op, which is checked before any write.
