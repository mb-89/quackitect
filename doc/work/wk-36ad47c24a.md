## detail

A finding on wk-c698d46866, "claims fetch forces nothing".

Publish in src/engine/claim.go:510 moves refs/se/claims to the remote's head when the first push loses, then writes this box's claim again on top. The comment at 507 says moving the local ref loses nothing, because what it held is these same files. That holds for one publish and not for the next. writeTheClaims carries forward only what the new parent holds, plus the files of this call, so every earlier claim this box wrote and could not push is dropped when the ref is moved back to the remote.

Measured here, where the push is refused by the proxy on every claim. refs/se/claims carries one line, wk-0016f540ed for worker-glass, written a minute ago. se claim --list reads about thirty live claims on this same box, all of them out of the token frontmatter and none of them in the ref. refs/se/remote-claims still stands at ec254bab.

The damage lands the moment the push works again. The other boxes are handed one claim where thirty are live, and take work this box is already on.

The check that catches the class: two Publish calls with different files, both losing the push, and the ref then carrying both claims.
