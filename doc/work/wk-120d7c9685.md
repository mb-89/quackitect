## detail

Rule 13 says datetimes do not go into git. It has no mechanism and no agreed reading.

The ruling: no date in prose that travels. Where a time is needed, a month and a year. A machine field that needs a stamp keeps it, because a claim is compared against a clock.

Caught today: a whole-file copy of a private original, at hook.go:1139.

Caught by nobody: identity material. Three classes, each with what it needs.

- dates: a pattern, and the ruling above. Easy.
- usernames: the machine knows its own user, and the tree knows its actor names. Easy.
- personal names: a list, because no pattern finds them. The list is itself identity material, so it lives under .se. Hard.

Measured: one tracked file carries a datetime, which is doc/work/wk-b166fb07eb.md. The tree is nearly clean already, so the check holds it there rather than cleaning it up.

## proposed action

Refuse identity material at the door that already refuses a private copy. Take dates and usernames first, because neither needs a list.

THE INTERFACE. A new src/engine/identity.go answers one question:

    identityMaterial(content, user string) (rule, matched string, found bool)

It is pure, so a table drives it. hook.go asks it beside copyOfAPrivateOriginal, under the same conditions: a write, prose, and not under .se.

WHAT IT READS. A machine field keeps its stamp, so a YAML key line is skipped and a frontmatter block is skipped whole. The rest is prose.

WHAT IT MATCHES. An ISO date, an ISO datetime, a clock with seconds, and a day beside a month name. A month and a year is taken. The machine's own username is matched whole, so a path carrying it is caught.

Personal names need a list, which is itself identity material, and that is not here.
