## detail

A control a person reaches for is on for the session they are in. The rung, the hold and the ask are all that kind of thing. None of them is a parameter, and none should survive a restart.

The engine holds two concepts for this and the controls use neither.

Session scoping is built and load-bearing. holds.json, grace.json, stops.json and owed.json each carry a session, and holdstore.go:56 drops a store that belongs to a session that has ended.

The second concept is a timer. Emergency mode arms with a person, a reason and an expiry, and ends on its own. It is a second answer to the same question and it goes: see the token that removes it.

What persists that should not: binding.json carries at and since with no session, and hold.json carries on with no session. So a tree unbound yesterday is unbound today, and god comes back armed with nobody having said so.

There is no timer on any of this. God lasts as long as the session lasts.

## proposed action

Move the rung, the hold and the ask onto the session-scoped store the hold store already uses, and keep one concept for it.

## approach

One store answers whether a control belongs to this session, and every control reads it. holdstore.go already carries the shape: a session field on the file, and a store from another session read as absent.

binding.json and hold.json gain that field, and the ask is answered the same way. A control left by an ended session is not migrated and not warned about. It belongs to a session that has ended.

Bound and hold-off are the resting values, so a control that does not answer is at rest. That is what a fresh tree is and what a box with nobody at it stays.

## note

Each of the three controls now carries the session it was set in. Each read answers the resting value when that session is not the one running now.

One function decides it. `ofThisSession` is in unbound.go, above the rung it first serves. LoadBinding, LoadHold and LoadAsked call it, and nothing else compares. SetBinding, SetHold and SetAsked write `currentSession(r)`, so the write and the read are two halves of one mechanism.

A file with no session on it is another session's, so the first read after this change drops what each was holding.

Why this rather than a clock. A timer guesses how long a person stays at the desk. The session does not guess, and four stores already use it.

A swap continues the session, so a handover does not bind a person again.
