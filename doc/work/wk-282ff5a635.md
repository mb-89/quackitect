## detail

util/checks/battery.sh calls the engine --link and then builds the tool lane. The link gives every built program both its names, so it hands the plain name whatever the lane build wrote last time.

MEASURED, September 2026, on this box. The battery built .bin/se-mcp.exe at 18:22 and .bin/se-mcp stayed at 16:13, two hours older. mcp-tools.mjs reads the plain name on every platform but Windows. So it drove a lane built before the flags it checks existed. It said util/cage/tools.json differs from the lane own list. The file was right and the binary was old.

The same staleness reaches an agent. util/cage/mcp-lane.mjs runs the plain name too, so a cold session is handed a lane one battery behind.

## proposed action

Move the --link call in util/checks/battery.sh to after the line that builds src/mcp, so it names what was just built.

- util/checks/battery.sh runs --link after the lane build, and the file carries no earlier --link
- the two names are one file after a battery: ls -i .bin/se-mcp .bin/se-mcp.exe answers one inode
