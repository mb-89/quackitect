## detail

A tracked token carries its began and ended hashes across boxes, and the snapshots they name do not come with it. A snapshot is a commit under refs/se/steps, which no push carries (src/engine/snapshot.go). So a token taken up on one box and claimed on another names a began that the second box has never seen.

Seen while working wk-1c9dc4ef28: its third began is 05adfb8a10366d136a5f5c1967b76bc2c7fc2c06, and on box aeaf7bd9 both `se test --on wk-1c9dc4ef28` and `se test --plan` answer only "git diff: fatal: bad object 05adfb8a…", with no remedy. TestTheDelta in src/engine/tests.go takes the last began as since and hands it to git diff unchecked. A reviewer's `git diff began..ended` on that box fails the same way, so the reviewing step cannot read the change either.

The engine either carries the snapshots with the claim (push refs/se/steps for the hashes a travelling token names, fetch them when a claim is taken), or it notices the hash is not here and says so with a remedy, falling back to what it can diff and naming the fallback in the answer.

## approach

A snapshot is a commit under refs/se/steps, and no push carries that ref. So a travelled token names hashes this box never had.

The test door already falls back. theSnapshotHere walks began from the newest and answers the first hash this box holds, or HEAD. Since names what it measured against, and TestASnapshotThisBoxNeverHadStillTests proves it.

The half still missing is the hand-over. A reviewer is handed the token and runs git diff began..ended itself, and that answers bad object with no remedy.

So the engine says it as it hands the token over. snapshotsNotHere answers the began and ended hashes git cat-file cannot find here. travelNotice turns those into a sentence. It names the hashes that are gone, says the ref travels with no push, and gives what to read instead. That is the newest snapshot here, or HEAD. handed appends it, so a worker hears it too.

Pushing refs/se/steps with a claim is the other answer, and this token does not take it. It would put the steps of every travelling token on the remote with nothing to prune them.

## proposed action

In TestTheDelta and wherever a reviewer's began..ended diff is built, verify each snapshot hash with git cat-file -e before using it; when one is missing, answer a refusal that names the hash and the remedy, or fall back to HEAD and say so in `since`. Consider pushing refs/se/steps for a token's hashes when se_claim publishes.
