## detail

A token's state travels at the speed of code review, and it should travel at the speed of work.

doc/work rides the code branch, so a box learns that another box closed a token only when somebody merges code. This clone sat behind for a morning. The pull now reaches into git and asks what the branch archived, which patches the coupling rather than fixing it.

The owner's proposal, September 2026: expand the claims branch into a queue branch carrying every tracked token. A mint, a claim and a close each push there. The claims branch already proves the mechanism, publishing without touching the working tree.

Two decisions settle it, and both are the owner's. One authority: doc/work leaves the code branch, or two writers drift again. And the shared archive list goes, because one file every close appends to conflicts on every concurrent write, and one was hand-merged already.

The branch belongs to the work root, never the method. A method carried into three projects would otherwise gather three queues onto one branch. A work root outside git is a real case and has to keep working.</detail>
<parameter name="proposed_action">Move every tracked token onto a queue branch of the work root, pushed on mint, claim and close, with no shared archive file.

## done when

- a token closed on one box reads closed on another without a code merge, decided by: close on one, fetch on the other, pull there
- two boxes closing two tokens at once both land, decided by: close both offline, then push each
- a work root outside git still mints and works a tracked token, decided by: point the method at a folder with no repository
- the branch a box reads is the work root's, decided by: a test with the two roots in different folders
