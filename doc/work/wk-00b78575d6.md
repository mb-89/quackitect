## detail

se_apply with undo: true reverted a file this actor had never touched, on a token this actor does not hold.

What happened, at 20:15 on 2026-09-03. worker-bell applied one edit to src/engine/tests.go on wk-840c81485d, and the answer named its journal, .se/undo/20260903-201439.696650100.json. Wanting that edit back, worker-bell called se_apply on: wk-840c81485d, undo: true. The answer was "undone: restored src/engine/runmestale_test.go". src/engine/tests.go still carries the edit, checked by se_find for func batteryShell, and the journal 20260903-201439 is still the newest file in .se/undo, so the undo popped a journal newer than it and deleted it.

So the stack is one stack for the whole tree, last write first. It is not keyed to the caller or to the token the call names. Another actor's most recent apply was rolled back under them. Both files are untracked, so git cannot give the lost version back. Only the agent that wrote it still has it.

The damage is that undo is the one verb an agent reaches for when it has just made a mistake. That is exactly when it is least ready to check whether somebody else wrote in the last few seconds. With several workers on one tree it will take the wrong write most of the time it is used. The tool's own sentence, "undo alone reverts", says nothing about whose apply, so the door reads as personal and behaves as global.

## proposed action

Key the journal to the token and the actor that wrote it. Have undo pop the newest entry belonging to the token the call names. Where there is none, answer that rather than reaching further down the stack. Then say so in the tool's sentence.

## done when

- se_apply undo reverts only an apply made on the token the call names, and leaves another actor's newer apply alone. A test makes two applies from two tokens, undoes the second, and asserts the first file is untouched, seen red before the fix
- an undo with nothing of its own to revert says so and changes nothing, naming the token it looked at. The same test asserts the answer and that no file moved
- the sentence the agent reads says whose apply comes back, so the door and its description agree: the undo wording in se_apply's own text
