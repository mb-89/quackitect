## detail

Nothing in the tree says why a cloud box writes refs/heads and nothing else, so the next hand will spend a session rediscovering it. Found 2026-09-06. Anthropic's sandboxing note says the proxy verifies the credential and the contents of the git interaction, and that it validates branch names. So it parses the receive-pack body and matches each ref update against a branch-name policy. A tag, a note and a custom ref are not in that vocabulary, so they fail closed. It is not a Cloudflare rule: claude-code issue 57829 guessed that, drew no corroboration, and was closed as a duplicate. The GitHub proxy applies independently of the environment's network access level, which is why the egress relay logged nothing while the pushes 403ed. Issue 65923 reports the same split, branch pushes working and refs/tags rejected in one session, closed as not planned with no reply. Issue 85454 reports the same refusal for deletes.
