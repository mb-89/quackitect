## detail

A finding on wk-4fb16fa632, "indexer takes a context", which made the context the indexer's owner.

In src/engine/indexwatch.go the watcher goroutine is

	go func() {
		select {
		case <-ctx.Done():
			shutdown()
		case <-stopped:
		}
	}()

The `case <-stopped:` branch means that once runIndexer returns of its own accord the goroutine exits and the context can never run the shutdown again. runIndexer returns early on four supported paths, all of them logged-and-continue by design: open() fails, Reindex fails, watchTree fails, and the watcher's Events or Errors channel closes. In every one of those, `stopped` closes, db and ro close on the defers, and `ln` is never closed and the socket file is never removed. So on exactly the degraded runs the file's own comment covers ("the engine goes on without an index"), a cancelled context no longer closes the listener or removes the socket, and serveModel keeps answering on a closed read-only handle. A caller that relies on the context alone, which is the pattern the token was written to make possible, leaks the socket file past its cleanup.

context.AfterFunc(ctx, shutdown) is the same behaviour in one line, needs no goroutine and no `stopped` select, and does not stop owning the socket when the loop ends early. Go 1.24 is the toolchain here.
