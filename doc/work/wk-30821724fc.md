## detail

The second part of wk-697f9876cf. realGit in src/engine/claim.go and ProbeTools in src/engine/tools.go each call context.Background inside a timeout, so a caller cannot end them early and a test cannot hand them t.Context. ensureEngine in guards.go, handOver in swap.go and startBattery in battery.go start detached processes that are meant to outlive the engine, so a context there bounds the start and not the life, and the token that asks for a context on every spawn has to say so or the successor engine dies with the test that started it.

That question is this token's first: which of the spawns a context may govern, and which it may only start. The answer goes on the token before the change.

## proposed action

gitIn and its callers take a context first, and the caller's context, bounded by gitBudget, replaces context.Background. ProbeTools takes a context. The three detached starts take a context that governs the start and the wait for the child to report, and never the child itself, and each says so in its comment. A test cancels a git call and a probe and sees them end. src/engine has no call to context.Background outside main after this.

## done when

- a cancelled context ends a git call and a probe, decided by: go test -C src/engine -run 'ACancelledContextEndsAGitCall|ACancelledContextEndsTheProbe' ./... answers ok
- src/engine has no call to context.Background outside main.go, decided by: se find --regex 'context\.Background' --path 'src/engine/*.go' answers main.go alone
- sh util/checks/battery.sh reports no new failure against the run before the change
