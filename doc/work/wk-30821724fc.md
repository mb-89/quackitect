## detail

The second part of wk-697f9876cf. realGit in src/engine/claim.go and ProbeTools in src/engine/tools.go each call context.Background inside a timeout, so a caller cannot end them early and a test cannot hand them t.Context. ensureEngine in guards.go, handOver in swap.go and startBattery in battery.go start detached processes that are meant to outlive the engine, so a context there bounds the start and not the life, and the token that asks for a context on every spawn has to say so or the successor engine dies with the test that started it.

That question is this token's first: which of the spawns a context may govern, and which it may only start. The answer goes on the token before the change.

## proposed action

The three detached starts take a context that governs the start and the wait for the child to report, and never the child itself, and each says so in its comment. A test cancels a git call and a probe and sees them end. src/engine has no call to context.Background outside main after this.

## approach

Two kinds of spawn, and the context means a different thing for each.

Governed: a git call and a probe. realGit and askOne run exec.CommandContext on the caller's context, bounded by gitBudget or probeWait, so a cancel ends the child. gitIn, the gitRuns seam, Publish, writeTheClaims, SyncClaims and WatchForClaims take it first, and WatchForClaims ends on it instead of a done channel. ProbeTools takes it first.

Only started: handOver, startBattery and ensureEngine. The child outlives the engine on purpose, so it never runs under a context. handOver takes main's and starts nothing once it is cancelled, and says so. startBattery waits for nothing, so a context there would govern nothing, and it takes none. ensureEngine waits for its child to report. It is reached only through answerHook, which two doors and twenty-two test files call, so its context is wk-97e8bd9f38.

How a context reaches a verb: call carries one. runVerbInside takes the model's, kept by startIndexer from its own, and callTheEngine's help-only call takes main's. Tests building a call, a model or a git fake hand t.Context.

main keeps context.Background, made once at the top.

## note

Two spawns are governed now. realGit runs git under the caller's context, bounded by gitBudget, and askOne runs each probe under it, bounded by probeWait. A cancel ends the child, and TestACancelledContextEndsAGitCall and TestACancelledContextEndsTheProbe hold that.

The context comes from main, made once at the top of main() so the client, the probe and the engine loop all take it. Publish, writeTheClaims, SyncClaims and the gitRuns seam take it first. WatchForClaims ends on it instead of a done channel. A verb carries it on call: runVerbInside takes the model's, kept by startIndexer, and callTheEngine's help-only call takes main's.

handOver takes it and starts no successor once it is cancelled, and never runs the successor under it. startBattery waits for nothing and takes none. ensureEngine is wk-97e8bd9f38, because its context is answerHook's and twenty-two test files build that call.
