## detail

A retro moves everything it collects into .se/retro, and nothing pushes that folder. On a desk this is right, because the disk outlives the session. On a cloud box it is the loss. The container is reclaimed and the whole folder goes with it. So the collection a desk retro depends on is, on a cloud box, the same as throwing the period away. Six archived notes already name an object no clone can read, each closed on a box that never pushed. The only output that survives a cloud box is a tracked token and a push.

## proposed action

A retro on a group branch mints and pushes, and does neither of the other two.

The retro still collects on a group branch. The folder is this session's own reading, and it is meant to die with the box.

WHAT CHANGES IS WHAT THE BOX IS TOLD. The tidy gains a part saying nothing under .se travels. So the collection does not survive, and a tracked token is the only output that does.

IT GOES IN THE TIDY BECAUSE THE VOCABULARY IS THERE. TidyPart carries Could and Why, which its own comment calls what a desk reads to find the work a cloud box could not finish. A second place to say it would drift from the first.

The alternative was a retro that reads without moving. It was not taken. The folder being lost is not a defect once the tokens carry what mattered.
