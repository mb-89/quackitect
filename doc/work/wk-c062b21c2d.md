## detail

A retro on a desk may delete and archive, because the disk outlives the session. On a cloud box neither is safe. Closing a token writes an archive row naming an object the box never pushed. Six such rows exist. The work was done, the record says so, and no clone can read it. Deleting is worse, because it removes the only copy of something nothing else carries. So a cloud retro that archives or deletes destroys work rather than filing it, and it does so quietly.

## proposed action

A retro on a group branch mints and pushes, and does neither of the other two.

What it can fix here it fixes. Everything else becomes a tracked token under doc/work, which git carries. Then it pushes and ends.

Its done-when is three lines. The note count is zero. Every note was fixed here or is a tracked token. Everything is pushed.

The desk retro is unchanged. The disk outlives the session there, so deleting and archiving are safe and useful.

## done when

- a retro on a group branch writes no archive row, decided by: a Go test in src/engine
- a retro on a group branch deletes no note, decided by: the same Go test
- every note it does not fix here becomes a tracked token under doc/work, decided by: the same Go test
- a retro on an ordinary branch still archives and deletes, decided by: the same Go test
