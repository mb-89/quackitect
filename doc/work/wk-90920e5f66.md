## detail

CLASS: THE SURVIVING DIRECTION IS ANSWERED BY MOVING THE EXAMPLE OUT OF THE
SWEEP'S REACH, SO THE CRITERION MEANT TO CONSTRAIN THE SWEEP CONSTRAINS NOTHING.

A reviewer asks for a criterion in the surviving direction: name one thing
inside the swept folder that must still be there and still answer afterwards.
The example the reviewer used was a real one, so it gets rescued -- moved
somewhere the sweep cannot go -- and a criterion is written saying it is still
there. Both halves are true. The criterion passes. And it now asserts that a
sweep of one folder left a different folder alone, which was never in doubt, so
the folder that is actually swept has nothing standing over it at all.

WHY IT LOOKS LIKE THE REMEDY. Relocating the valuable thing IS a good answer to
the risk the reviewer described, and often the better one, because it stays right
when somebody adds the next valuable thing without reading the token. What it is
not is an answer to the question the criterion was asked to decide. The finding
said the sweep is unconstrained; the fix removed one thing from its path and left
it unconstrained.

THE TELL IS THE PREPOSITION. Read the criterion and ask whether the thing it
names is INSIDE the thing being swept. If it is outside, the criterion is a
boundary check and there is already one of those; the surviving direction is
still empty.

MEASURED ON wk-339068932c, "one command per retro", round 2. Round 1 and round 2
both asked for something inside .se/scratchpad that must survive. The answer moved
the standing checks to util/checks and added "After a retro the battery still runs

WHAT TO DO INSTEAD. WHEN YOU RESCUE THE EXAMPLE, ASK WHAT ELSE IS STANDING WHERE
IT STOOD. The example was a sample of the class, not the class: the reviewer
named battery.sh because it was the loudest thing in the folder, not because it
was the only thing worth keeping.

AND KEEP ONE CRITERION POINTED INSIDE. Name something in the swept folder that
must survive -- or, better, a property: nothing another token's evidence cites is
taken, nothing a folder named for another actor holds is taken. A criterion whose
subject sits outside the sweep can never go red for the sweep being too greedy,
which is the only failure it was written for.

THE CHECK, RED TODAY: run the retro over a fixture whose scratchpad holds a file
some open token's evidence names, and require the file to still be there. Nothing
in this token does that, and the criterion that reads like it does is about
util/checks.
