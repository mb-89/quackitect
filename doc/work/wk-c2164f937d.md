## detail

More open tokens than the limit with nobody working on them, and the pull
refuses. The same shape as the reviewer rule, for the same reason.

WORK PILING UP WITH NOBODY ON IT is the same failure as work piling up with
nobody judging it. One agent working a queue of twelve is a queue that stays
twelve.

WHAT COUNTS: tokens that are open, which is here in the editor's words, and not
held by anybody. A token in_work is somebody working, and that is enough.

WHAT IT REFUSES: the pull, and nothing else. THE REVIEWER RULE IS SAFE BECAUSE
THE REVIEWER CLEARS IT AND IS NEVER REFUSED. A worker has no such escape:
refusing every call would block the very call that spawns the worker. So this
refuses the pull and lets the rest through.

WHAT IT SAYS: how many are open, which ones, and that spawning a worker clears
it. It clears the moment one moves to in_work under anybody.

THE NUMBER IS A PARAMETER, limits.open_before_blocked, beside the review one.
Zero turns it off. It may be made smaller and never larger, like every other
guard limit, so a person tightens it here and loosens it by changing the
declared default.

THE OWNER ASKED FOR 9999 AS THE OFF SWITCH. Zero is the off switch instead,
because narrow smaller means the declared default is the ceiling and 9999 would
have to be that default. Say so and it changes.
