## detail

A note asks why it is a problem, and not only what happened, and it requires evidence for the answer. It asks as well whether the instance is a symptom of something bigger.

A tracked token asks nothing of the kind. The standard ask wants an approach, decidable criteria, a change small enough to review whole, and the basics under it. The trivial ask wants three of those. Every one of them is about the shape of the work rather than its worth.

So the private note that costs nothing interrogates value, and the tracked token that spends real work does not.

Two questions are owed before a tracked token exists. What is gained by doing it, and what breaks if it is never done.

Both have one failure mode, which is an answer that restates the ask. The note process guards that shape already, with the words and not only what happened, and by requiring evidence beside them.

## approach

Two criteria on the ask activity, on both tracked processes, each requiring evidence.

The first says what is gained by doing it, in a sentence a reader can disagree with. The second says what breaks if it is never done, and not a restatement of the ask.

Nothing moves into the schema. The detail section is already described as what is asked, and why it matters, so the two questions are that clause made explicit. A new section would have to be named by every process, because the body order is strict and an extra section is refused.

Tokens minted before this are grandfathered. A backfill over the open ones is its own token where it is wanted.
