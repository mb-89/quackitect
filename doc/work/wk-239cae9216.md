## detail

Claiming is opt-in and work is not. A box takes a tracked token, works it and closes it, with nothing in git saying so. Another box reading the tree sees an open token and takes the same one.

The ruling: work is refused on a tracked token this box has not claimed. A local token is exempt, because .se/work is not in git and no other box can see or take it.

se claim already publishes a claim to git by itself, and takes next or these. The mechanism is there and nothing makes an agent use it.

Measured: one token in the whole tree carries a claim. Every other tracked token is open to whoever pulls first, on any box.

Sizing a batch by summing estimates waits on the estimate work. The shortcut does not: one call claims a named token and takes it up.

## proposed action

Refuse a take-up of a tracked token this box holds no claim on, name se_claim in the refusal, and add the claim-and-take shortcut.

## note

A tracked token now needs a claim from this box before anyone can work it. The check sits in TakeUp, so it catches se apply and se run as well as a person picking work up. A local token is exempt.

Two questions were one comparison in the code and had to be split. Whether this box may touch a token is the box's, and ClaimedHere answers it. Who is handed it first is still the agent's, because a claim is an agent naming what it is working through. Reading both as the box's handed one agent's live work to another, which happened here during the change.

se claim gained --take, so an agent refused for want of a claim needs one call and not two.

mintStandard and mintTask now take the claim their tokens need. mintUnclaimed is the raw one, for tests about claiming.

## approach

The refusal goes where the take-up happens, beside the checks next() already makes. It reads the claim store the sync writes, not the network.

Tracked and local are told apart by where the token lives. doc/work is tracked and .se/work is not, and the mint already decides that.

The refusal names se_claim and the id, so the agent next call is the fix rather than a search.

The shortcut is one call: claim this token and take it up. It exists because an agent that has just been refused should not need two.

Batch sizing by estimate is not here. It waits on the estimate work, and the shortcut carries the load until then.
