## detail

A cloud box finishes work it cannot always archive, and the record has one word for both. So a hand either closes a token it may not be able to publish, or leaves finished work reading open.

THE OWNER'S RULING, September 2026. A tracked token may be pushed at done and left unclosed. The next retro collects the done ones and finishes them. A box that cannot archive is fine, and the archiving happens later.

WHAT THE ARCHIVE COSTS ON A BOX THAT CANNOT PUSH. Closing writes a row and deletes the note. The row is a claim that the work is finished and the note is the evidence for it. A close on a box that never pushes leaves neither: six archived rows already name an object no clone can read.

WHAT THE QUEUE MUST UNDERSTAND. A token that is done and unarchived is not open work, so it is handed to nobody. It is not a verdict owed either, where the verdict is already given. It is finished and waiting for a retro, and the count has to say so rather than folding it into open.</detail>


## proposed action

Read what the engine does today with a token at done and unarchived, and make the three answers agree with the ruling.

The queue hands it out to nobody. The staffing count reads it as neither open work nor a verdict owed. The status line says how many are finished and waiting for a retro, so a person can see the pile grow.

Where the engine already does one of these, the evidence says so and nothing changes there. This is one token, so anything it turns up that is larger becomes its own.</proposed_action>
