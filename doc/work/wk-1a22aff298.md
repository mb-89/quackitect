## detail

wk-5d144a5ec0 made a run plain when nothing in it asks the map. The decision is taken once for the whole run: runChosen in src/engine/tests.go builds wantMap at lines 643 to 648 by walking every pick, and hands that one flag to every runOneGoTest at line 688 and to every writeRegions at line 693. The loop it sits in is for _, p := range picks, so p.Why is in hand at the call and the per-pick decision costs one expression.

Measured on this box through se test. TestWritingGoNamesNoProgram alone, picked named outright: 0.0126 seconds, and its row untouched at 0.895078156. The same test proposed beside the pattern TestBoundAsksForAToken*, still picked named outright: 0.0404 seconds, and its row rewritten to 0.040358794. So one delta pick in the run puts the instrumented binary and the index write back on every named test beside it.

There is no test. The change carries no _test.go, and se test --plan reports src/engine/tests.go uncovered, so nothing selects a test when runChosen changes.

What is gained by doing it is that the write the token exists to remove stays removed on a mixed run, which is what a proposal narrowing inside a delta produces.

What breaks if it is never done is that the saving holds only for a run whose every pick is named, and the next edit to runChosen can undo the whole decision with the suite green.
