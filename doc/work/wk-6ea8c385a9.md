## detail

A cloud box is cut for one bucket and is told which one by nobody. work.queue_filter already narrows the pull, and theQueueFilter in src/engine/queuefilter.go already reads it, but somebody has to type the keyword on every box every time. On a cloud box nobody is there to type it, so the box either works the whole trunk or waits to be told. Both are wrong. The branch name is the one fact that cannot drift from the branch, because it is the branch. A generated brief file on the branch is the obvious alternative and is worse: it is a second writer over a fact the bucket already owns, and it is how two branches learn to conflict. For details, see [[dev_guide/onebranchonegroup]] section 3.</detail>
<parameter name="proposed_action">A branch named group/&lt;name&gt; stands for the filter bucket: &lt;name&gt;.

THE PARAMETER OUTRANKS THE BRANCH. The keyword stays the manual override, so a person who types one gets what they typed. The branch answers only when nothing was typed, which is every cloud box and no desk that asked for something else.

NOTHING IS STORED TWICE. The name is read from the branch at the moment the filter is read, and no value is written into the parameter. So a checkout of another branch changes the queue and nothing has to be cleared.

A branch by any other name derives nothing, so trunk stays the whole queue. The pull says which filter is in force and whether the branch or a person put it there.

## done when

- on a branch named group/x with no filter typed, the queue filter is bucket: x, decided by: a Go test in src/engine
- a filter typed by hand outranks the branch, decided by: the same Go test
- a branch not named group/anything derives no filter, so trunk is the whole queue, decided by: the same Go test
- a pull under a derived filter says the branch put it there, decided by: the same Go test
