## detail

A token held too long sends somebody to investigate. It is not a timeout.

THE OWNER'S WORDS: if an item in review has not changed for ten minutes, the
walker is sent to investigate. The same for a sub-walker: an item held for the
limit and somebody investigates.

A TIMEOUT KILLS WORK. This raises an alarm and sends somebody to look, and a
person looking is what a stuck token actually needs. So a held token does not
move, expire, or come back on its own. It stays exactly where it is until
somebody rules on it.

WHAT THE ENGINE DOES: the next pull hands the walker an instruction to
investigate rather than new work, naming who is holding what and for how long.

WHERE THE DURATION COMES FROM, and this cuts against a rule already in force. A
TOKEN CARRIES NO TIMES: the lint refuses any time in a note. So the engine
cannot ask a token how long it has been held. It asks the record, which does
carry times, for when the token last moved. That is a duration without a clock
in the note.

ONE NUMBER, TWO CASES. limits.held_before_investigating, beside the other
limits, covering a token in review whose reviewer has gone quiet and a token in
work whose sub-walker has. Same rule, same number, one mechanism.

WHY THIS AND NOT ONLY THE STOP HOOK. The stop hook stops a reviewer LEAVING
with a token. It cannot help when a process dies without reaching its stop
hook, which is what happened. One stops it happening and this one stops it
lasting.
