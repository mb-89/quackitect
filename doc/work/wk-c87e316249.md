## detail

Behaviour is specified in prose and enforced in Go, and the project already has a format for state machines.

A process is a state machine. It declares states, the moves between them, and who may make each move. Processes are read from src/processes and the engine walks them.

More state machines are coming. And the binding rungs are one already: bound, unbound and god, with a person as the only mover, and a different set of rules true in each. So is the hold: off, finishing, held. So is the ask.

None of those is written as a process. They are Go, with prose beside them in guidance, and a table somebody keeps by hand in the-three-rungs.md. Three surfaces for one machine, and this session watched all three disagree with each other.

THE OWNER SAID IT PLAINLY: I do not want three different formats for that.

The question is whether behaviour like the rungs should be declared the way a process is, and read by both the engine and whatever draws the table.

## proposed action

Think about it before building anything. Read what the process format can already say, and hold the rungs and the hold against it: states, moves, movers, and which rules are true in each state. If it fits, the rungs become a declaration and the table draws itself. If it does not fit, the gap is worth writing down, because the next state machine meets it too.
