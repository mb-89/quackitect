## detail

A parameter reachable by keyword has to say so where a person reads about it, which is the tooltip.

Writing the keyword into each title by hand would put one fact in two places. The tooltip would then drift from the command it names, which is the defect the lane already carries and has a token of its own.

Some controls make no sense away from a desk. Opening the work editor or the homes does nothing for a person with only a chat. Those carry no keyword and should say nothing about one.

## done when

- a flagged node draws its keyword line in the tooltip, decided by: read the panel
- no title in the declaration names a keyword, decided by: search the declaration for one
- the work editor and the homes carry no flag and draw no line, decided by: read the panel
- the line the tooltip draws is the text the engine matches, decided by: a check that sends the drawn line and reads the state

## approach

A node says whether it is reachable from a console. That flag is the only thing anybody writes.

The engine owns the keywords and answers what they are. The panel draws what it was answered, so the line a person reads is the exact string the matcher takes. It is copied rather than composed, so the two cannot differ by a character.

A control that makes no sense away from a desk carries no flag and draws no line.

The flag also answers which parameters have keywords at all, mechanically, which is what the check in the last criterion reads.
