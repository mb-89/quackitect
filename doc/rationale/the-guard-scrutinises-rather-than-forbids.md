## decided

A write outside the roots is not guarded, because the machine belongs to the user. A write inside is scrutinised. Exactly one destination is forbidden, a projection, and that refusal names the original. Every other refusal is about form and never about place.

## why

Roots were made locations rather than a fence. v3 made the user declare them, which was a ceremony that bought nothing, so nothing is declared or registered here.

Told to write a file to the desktop, the agent writes it. The cage was never there to police the user's disk, and a cage that stops ordinary work is one the user walks around.

One destination was forbidden with no override. A projection is output, so an edit to it is lost on the next write. Losing a person's work is not something to be talked into. That refusal names the original, because a writer wants an effect rather than a file.

Every other refusal was made about form. The same file written properly goes through, so a check on wording never becomes a ban on a folder. A destination refusal ends the attempt. A form refusal bounces it and says what to change.

Only the mechanical tiers refuse. Pattern and vocabulary are reproducible and judgement is not, so a refusal nobody could reproduce would be an obstacle rather than a rule.

The agent may write its own machinery, because forbidding that forbids the work.

## costs

The rules mean nothing outside the roots, so an agent told to work in a folder elsewhere carries none of them. A guard that cannot reach an answer refuses, which stops work whenever a guard is broken. And judgement stays unenforced: anything needing a person to weigh it is asked and never decided at this layer.

## revisit when

- a guard is wanted for something no pattern can decide
- work moves outside the roots often enough that the rules stop covering it
- a projection gains a form a person is meant to edit
